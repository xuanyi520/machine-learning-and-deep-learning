# 模块 14 · 文献精读与复现

**核心问题：怎么读一篇论文，怎么把它做出来？**

**建议用时：24 小时以上（贯穿全程，每周 3-4 小时；其中完整复现一次另算 3-5 天）**

---

## 〇、先说清楚这一章要解决你哪个问题

评估文档里有一句你自己的话：

> 看懂是识别，写出来是生成。难度完全不同。

这句话精确描述了当前状态。你能跑通代码、能用手算验证概念、能发现 `device = "cude"` 这种错误。但**你从来没有独立复现过一篇论文**，也几乎没有写过"我判断这篇论文哪里不行"这类文字。

这一章没有需要你跑通的新模型。它的全部产出是四样东西：

| 产出 | 形式 | 验收方式 |
|---|---|---|
| 精读笔记 | markdown，一页 | 9 个小节全填，且"局限"不是套话 |
| 文献对比表 | 表格，按维度组织 | 能从中直接写出一段综述 |
| 复现报告 | markdown，8 节 | 有数字、有偏差分析、有可检验的假设 |
| 判断 | 口头/文字 | 能说出任何一篇论文的三个局限 |

**这一章的训练量在"写"，不在"读"。** 读十篇不写笔记，等于没读。

### 关于数字的规矩（先立这条）

评估文档第 11.1 节记录过一次事故：用推算的小时数去修正另一个推算的小时数，越改越偏。所以这份讲义里出现的每一个数字，都标来源：

| 标记 | 含义 | 例子 |
|---|---|---|
| **论文报告值** | 原论文写的，我没验证 | U-Net 在 ISBI 挑战赛的 warping error |
| **实测值** | 我在本机跑出来的 | 你的 MNIST 98.80% |
| **经验值** | 常见范围，不是统计结论 | "复现差异通常 2-5 个点" |
| **假设示例** | 为了讲清楚编的，不是真论文 | 6.3 里的 0.890 vs 0.861 |

**你写复现报告时必须沿用这套标记。** 混用这四类数字，是科研写作里最容易犯、也最难被自己发现的错误。

## 一、三遍读法

**本节核心问题：一篇 10 页的论文，怎么在 40 分钟内决定要不要为它花 2 小时？**

### 1.1 为什么必须分遍，而不能从头读到尾

论文的信息密度极不均匀。一篇典型的 MICCAI 论文，按字数分配大致是：

| 部分 | 占比 | 信息价值 |
|---|---|---|
| Introduction | 20% | 低。大部分是领域套话和引用堆叠 |
| Related Work | 10% | 中。只在找 gap 时有用 |
| Method | 30% | 高 |
| Experiments | 30% | 最高。复现的全部细节在这里 |
| Conclusion | 5% | 中。局限常藏在这里 |

**从头读到尾的问题不是慢，是"前 20% 消耗了注意力，读到实验部分已经累了"。** 三遍读法把最需要脑力的部分放在最清醒的时候。

另一个理由更实际：**大部分论文不值得读第三遍。** 经验值：10 篇里大约 2-3 篇值得第二遍，1 篇值得第三遍。如果你每篇都读三遍，一周只能读两篇，而且读到的大部分是垃圾。

### 1.2 第一遍：5 分钟，判断值不值得读

**只看六样东西，按这个顺序：**

1. **标题**：能不能看出任务、数据、方法三要素
2. **摘要的最后两句**：结论和具体数字通常在这里，不在第一句
3. **图 1**：通常是方法总览图。只看图能不能说出流程
4. **表 1**：通常是主结果表。最好的数字有没有加粗，比 baseline 高多少
5. **结论的最后一段**：作者自己承认的局限
6. **代码链接**：有没有 GitHub，在不在正文或脚注里

**为什么不先看引言**：引言的功能是"说服你这个问题重要"，不是"告诉你他做了什么"。先读引言会被作者的框架带走，失去独立判断。

#### 第一遍检查清单

- [ ] 标题里的任务、数据、方法，我能各说出一个词吗
- [ ] 摘要最后一句是结论还是"具有重要意义"这类空话
- [ ] 摘要里有没有具体数字（提升多少、在什么数据上）
- [ ] 图 1 我能只看图说出输入到输出的流程吗
- [ ] 表 1 里最强的方法是不是作者自己的
- [ ] 提升幅度是 0.5 个点还是 5 个点
- [ ] 有没有外部验证（另一个中心/另一个数据集）
- [ ] 有没有代码链接
- [ ] 发表年份和出处（决定要不要用最新标准要求它）

#### 三种结论，必须选一个

| 结论 | 判据 | 后续动作 |
|---|---|---|
| **精读** | 与你的课题直接相关，或方法可迁移，且有代码 | 安排 30 分钟第二遍 |
| **存档** | 相关但方法普通，或没有代码 | 只记进对比表，不读第二遍 |
| **放弃** | 问题不相关，或数据私有且方法无新意 | 不记录，不要有负罪感 |

**第一遍最常见的错误是"舍不得放弃"。** 判断标准不是"这篇论文好不好"，是"这篇论文对我当前的问题有没有用"。

### 1.3 第二遍：30 分钟，抓住核心贡献

这一遍只回答三个问题：

1. 它解决什么问题（不是"肝脏肿瘤分割很重要"，是"小目标在 3D CT 里容易被漏检"）
2. 它怎么解决（方法的核心机制，一句话）
3. 它凭什么说解决了（在什么数据上、和谁比、用什么指标、高多少）

#### 一句话公式

读完之后，强迫自己填这个句子：

> 为了【具体问题】，作者提出【核心方法】，在【数据集】上与【baseline】比较【指标】，从【数值】提升到【数值】，证明【结论】。

填不出来，说明没读懂。填出来但全是形容词，说明读的是摘要不是论文。

#### 第二遍检查清单

- [ ] 输入是什么（图像？表格？多模态？），输出是什么（分割图？分类概率？）
- [ ] 标签怎么来的（病理金标准？随访？放射科医生标注？几个医生？）
- [ ] 核心方法能用三句话讲给同组同学听
- [ ] 与之前方法的关键差别，能用一句话说清
- [ ] 用了几个数据集，各多大，公开还是私有
- [ ] 划分方式：官方划分、随机划分、还是交叉验证
- [ ] 主指标是什么，为什么用这个而不是另一个
- [ ] 提升幅度多少，有没有做统计检验
- [ ] 消融实验证明了哪个模块有用
- [ ] 有没有失败案例分析（error analysis）

#### 读不懂的时候怎么办

**三次法则**：同一个点卡住 10 分钟，就标记跳过，不要纠缠。具体处理：

| 卡在哪 | 处理 |
|---|---|
| 公式 | 先看公式的输入输出维度，再看代码里对应的几行 |
| 方法描述 | 先看图 1，再回读文字；图比文字准确 |
| 术语 | 查这篇论文引用的上一篇文章，不要查百科 |
| 实验结果 | 先看表注，表注里常写"± 是 std over 3 runs"这类关键信息 |

**第二遍不要求看懂公式。** 公式是第三遍的事。

#### 第二遍的产出

半页笔记，至少包含：问题、方法一句话、数据集、主结果、一个疑问。

**"一个疑问"是硬性要求。** 没有问题说明你只是在接收，没有在判断。疑问可以是"为什么用 Dice 不用 HD95"、"为什么不做外部验证"、"这个消融的 baseline 是不是太弱"。

### 1.4 第三遍：2 小时，准备复现

第三遍的目标不是"理解"，是**判断这篇论文能不能被做出来**。

要提取六类信息：

| 类别 | 具体要找什么 |
|---|---|
| 数据 | 来源、样本量、划分文件、license、预处理后的尺寸与 spacing |
| 预处理 | resize 还是 crop、强度归一化方式、HU 窗、几何重采样 |
| 模型 | 输入通道、输出通道、参数量、是否用预训练权重 |
| 训练 | loss 的每一项、优化器、lr、batch size、epoch 数、schedule、增强策略 |
| 评价 | 指标的精确定义（smooth 项、空掩码处理、后处理） |
| 算力 | GPU 型号、训练时长、显存占用 |

#### 第三遍检查清单（复现可行性 12 项）

- [ ] 数据集能拿到（公开，或作者提供，或有公认替代）
- [ ] 划分文件能拿到（不是"随机 8:2"这种描述）
- [ ] 预处理链条每一步都能还原
- [ ] 图像 spacing 和方向是否统一，论文有没有说
- [ ] loss 的每一项都有定义，权重给了具体数
- [ ] 优化器、lr、batch size、epoch 数齐全
- [ ] lr schedule 的类型和参数齐全
- [ ] 数据增强的每一种及其概率/幅度齐全
- [ ] 评价指标有精确定义，不是只写"Dice"
- [ ] 有没有后处理（最大连通域、阈值搜索、形态学）
- [ ] 代码仓库能跑，且有对应的 commit
- [ ] 训练所需显存我这边够

**判断规则**：12 项里有 4 项以上既不在论文里、也不在代码里，这篇论文**不可复现**，换一篇。不是你的问题。

### 1.5 本节的常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 从引言第一句开始读 | 读了 20 分钟还在背景介绍 | 先标题、摘要末句、图 1、表 1 |
| 把摘要当全文 | 笔记内容和摘要几乎一样 | 第二遍必须看方法图和实验表 |
| 每篇都读三遍 | 一周读两篇，还很累 | 第一遍就淘汰 70% |
| 读不懂就死磕 | 一个公式卡一小时 | 三次法则，标记跳过 |
| 不做判断 | 读完说不出好坏 | 每篇必须写一个疑问 |
| 只看论文不看代码 | 第三遍结束后仍不知道超参 | 第三遍必须打开仓库 |

## 二、期刊与会议分层

**本节核心问题：这篇论文该用什么标准读，它的结论能信到什么程度？**

### 2.1 一句话区别

> **会议看方法新不新，期刊看临床有没有用。**

这句话不是贬低会议。会议论文的贡献是"提出了一个以前没有的机制"，期刊论文的贡献是"证明了这个机制在真实临床场景里有用"。两者的审稿人、评价标准、失败模式都不同。

### 2.2 四层结构

| 层级 | 代表 | 审稿关注 | 读的时候重点看 | 对你的用途 |
|---|---|---|---|---|
| **顶会** | MICCAI、CVPR、NeurIPS、ICLR、MIDL、IPMI | 方法创新、SOTA、ablation 是否充分 | 方法机制、消融设计、和 SOTA 的差距 | 学技术，找可复现代码 |
| **顶刊** | Radiology、Nature Medicine、Lancet Digital Health、JAMA、JAMA Oncology | 临床价值、研究设计、外部验证、对决策的影响 | 研究设计、终点定义、外部验证、和医生的对比 | 学怎么把方法讲成临床问题 |
| **专科刊** | Hepatology、Journal of Hepatology、Gut、Clinical Gastroenterology and Hepatology | 领域深度、队列质量、与指南的关系 | 人群定义、金标准、随访时长、分层分析 | 学领域知识和数据口径 |
| **综述刊** | Nature Reviews Gastroenterology & Hepatology、CA Cancer J Clin、Lancet Oncology | 覆盖是否全面、框架是否有解释力 | 分类框架、作者指出的未解问题 | 找 gap，建立全局地图 |
| **预印本** | arXiv、medRxiv、bioRxiv | 没有同行评议 | 只当情报，不当结论 | 追最新动态 |

**补充一类不是期刊但必须知道的来源**：AASLD、EASL、APASL 的肝癌指南。它们定义了什么算"高危人群"、用什么做监测、金标准是什么。你读任何一篇肝癌早筛论文，人群定义都必须和指南对得上，否则结果不可比。

### 2.3 同一项工作，投会议和投期刊的差别

**以下是假设的示例，不是真实论文**，只用来说明评价标准的差异：

| 维度 | 假设投 MICCAI | 假设投 Radiology |
|---|---|---|
| 标题重心 | 网络结构名 + 机制 | 临床场景 + 决策价值 |
| 数据 | 单中心，公开数据集为主 | 多中心，含前瞻性队列 |
| 对比对象 | 其他分割网络 | 放射科医生、现有指南策略 |
| 主指标 | Dice、HD95 | 敏感度、特异度、决策曲线 |
| 必须有的分析 | ablation | 外部验证、亚组分析、reader study |

**对你的实际意义**：面试医疗 AI 算法岗，一篇 MICCAI 证明你懂技术；一篇 Radiology 证明你懂问题。**两样都缺的时候，先补技术那篇，因为你现在的短板是动手。**

### 2.4 找论文的顺序

不要从"最新综述"开始读全文，按这个顺序：

1. 找 1 篇 2 年内的综述，只读分类框架和"future directions"
2. 从中挑 5-8 篇高频引用的原始论文，各做第一遍（5 分钟）
3. 挑 2 篇做第二遍，顺着引用链往前找奠基工作，往后找"谁引用了它"（Google Scholar 的 Cited by）
4. 往后找的这批里，最新且引用增长快的，就是当前活跃方向

**为什么往后找比往前找重要**：往前找是补历史，往后找是找现在谁在接着做、做到哪了。找 gap 靠的是后者。

### 2.5 三个预警

| 情况 | 信号 | 处理 |
|---|---|---|
| 预印本 | 只有 arXiv 编号，没有期刊/会议 | 可以读，不能引用为"已证明" |
| Workshop paper | 挂在顶会名下，但是 workshop | 不等于顶会正刊，审稿标准低得多 |
| 掠夺性期刊 | 审稿一周接收、版面费高、不在 PubMed/DOAJ | 直接放弃，别浪费时间 |

### 2.6 本节的常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 用会议标准读期刊 | 嫌 Radiology 方法不够新 | 期刊看临床验证是否扎实 |
| 用期刊标准读会议 | 嫌 MICCAI 没有外部验证 | 会议本来就不要求 |
| 把 arXiv 当定论 | 引用了一个后来被撤稿的结论 | 预印本只当情报 |
| 只看顶刊 | 方法细节全在会议里，读不到 | 两条线都要跟 |
| 不看指南 | 人群定义和领域不一致 | 先读 AASLD/EASL 指南的相关章节 |

## 三、复现流程

**本节核心问题：一篇有代码的论文，怎么在 5 天内变成你机器上跑得出来的数字？**

### 3.1 六步，顺序不能乱

```
第 0 步  选论文          ← 选错，后面全白做
第 1 步  找代码          ← 没有代码的论文，第一轮不要碰
第 2 步  配环境          ← 隔离环境，记录版本
第 3 步  下载数据        ← 核对的不是数据，是划分
第 4 步  跑通作者结果    ← 先 inference，后 training
第 5 步  换自己的数据    ← 最小改动
第 6 步  记录所有偏差    ← 这步决定报告的质量
```

**一条铁律：先跑通作者的，再改自己的。**

顺序反了会怎样：你换了数据，结果不对，此时你无法判断是"方法不适合我的数据"还是"我环境配错了"还是"我预处理写错了"。三个未知数，一个方程，解不出来。

### 3.2 第 0 步：选论文

第一次复现，选论文比努力重要。用这张表打分：

| 维度 | 加分 | 减分 |
|---|---|---|
| 代码公开且能跑 | +2 | 无代码 -3 |
| 数据公开，或有公认替代 | +2 | 私有数据 -2 |
| 主结果集中在 1-2 个指标 | +1 | 十几个数据集、二十张表 -1 |
| 方法不含私有预训练权重 | +1 | 依赖未公开的预训练模型 -2 |
| 仓库近期有 commit 或 issue 回复 | +1 | 三年没更新 -1 |
| 单卡 8G（你的显存）能训完 | +2 | 需要 8 卡 -2 |
| 论文写清了划分和超参 | +1 | 关键细节缺失 -2 |

**总分 ≥ 4 才开工。** 低于 4 分不是不能做，是第一次复现不该做。

**给第一次的具体建议**：

| 选择 | 理由 |
|---|---|
| 任务选分割或分类，不选检测/生成 | 指标简单，失败模式少 |
| 数据选公开的（如 LiTS、MSD、BraTS） | 排除数据获取这个变量 |
| 方法选 2018-2021 年的经典工作 | 代码成熟，issue 里坑都被踩过 |
| 不要选最新 SOTA | 代码往往是赶论文写的，跑不通 |

### 3.3 第 1 步：找代码

按这个顺序找，找到就停：

1. **Papers with Code**：搜论文标题，看有没有官方实现
2. **GitHub 搜标题 + 第一作者姓**：`"U-Net" Ronneberger`
3. **作者个人主页 / 实验室主页**
4. **OpenReview 的 supplementary material**（会议论文常放这里）
5. **论文正文的脚注**：很多代码链接只写在第一页脚注里

#### 判断代码质量

| 信号 | 好 | 坏 |
|---|---|---|
| README | 有完整训练和测试命令 | 只有一句 "coming soon" |
| 依赖 | requirements 有具体版本 | 只有包名没有版本 |
| 权重 | 提供 pretrained checkpoint | 只给代码 |
| issue | 有人提问且作者回复 | 全是"跑不通"，无人回复 |
| 最后 commit | 一年内 | 三年前 |
| 划分文件 | 仓库里有 train/val/test 列表 | 让你自己随机分 |
| LICENSE | 明确 | 没有（不能用于发表） |

**经验值**：GitHub 上标称"official implementation"的仓库，大约一半无法按 README 一次跑通。这不是你的问题，是常态。

### 3.4 第 2 步：配环境

**按优先级找安装方式：README 安装段落 → requirements.txt → environment.yml → Dockerfile → Issues 里别人成功的步骤。前面的能用，就不要用后面的。**

#### 标准操作

```bash
conda create -n repro_unet python=3.9 -y
conda activate repro_unet
pip install -r requirements.txt

# 第一件事：确认框架和 GPU
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"

# 锁定环境，写进报告
pip freeze > env_lock.txt
```

**为什么必须新建环境**：你现有的 `ai` 环境里 PyTorch 是 2.9.1。老代码可能要求 1.x。在 base 或 `ai` 里升降级，会把你正在学的课程代码搞坏。

#### 五个高频坑

| 坑 | 现象 | 处理 |
|---|---|---|
| numpy 2.x | 老代码 `np.float`、`np.int` 报 AttributeError | 装 `numpy<2` |
| torch 与 CUDA 不匹配 | `cuda.is_available()` 返回 False | 按 PyTorch 官网的版本矩阵重装 |
| sklearn 版本漂移 | 同样的 `random_state` 划分结果不同 | 锁定 requirements 里的版本 |
| albumentations API 变更 | 旧参数名报 TypeError | 装 requirements 指定的版本，不要装最新 |
| 路径硬编码 | `/home/author/data/...` 找不到 | 全仓库 grep 绝对路径，改成配置项 |

**记录要求**：报告里必须写 Python 版本、PyTorch 版本、CUDA 版本、GPU 型号。写"PyTorch 环境"等于没写。

### 3.5 第 3 步：下载数据

**核心认知：复现时，划分文件比数据本身重要。**

论文写"按 8:2 随机划分"，和"用官方 split 0"，是两件完全不同的事。前者你永远对不上，后者可以精确复现。

#### 必须核对的六项

| 项 | 怎么核 | 不符的后果 |
|---|---|---|
| 样本总数 | 数文件数 / 读 csv 行数 | 少了说明下载不全或过滤条件不同 |
| 类别分布 | `value_counts()` | 分布不同说明划分或纳入标准不同 |
| 划分文件 | 有没有 train/val/test 的 ID 列表 | 没有就无法复现到小数点 |
| 图像-标签配对 | 随机抽 5 例，可视化叠加 | 错位是最致命的 bug，指标会接近随机 |
| spacing 与尺寸 | 读 header，统计分布 | 不统一会导致重采样结果不同 |
| license | 能不能用于你的研究 | 不能商用/不能再分发 |

拿到数据后，**先做一件事**：随机抽 3 例，把图像和标签画在一起。

- 分割任务：标签轮廓叠在图像上，看是否贴合
- 分类任务：每个类别各看 3 张，看标签是否合理

**这一步 10 分钟，能排掉后面 3 天的诡异问题。**

### 3.6 第 4 步：跑通作者的结果

#### 复现的三级标准

| 级别 | 标准 | 能不能写进简历 |
|---|---|---|
| **L1 能跑通** | 代码不报错，能出预测结果 | 不能 |
| **L2 数值接近** | 主指标差距 < 2%，或落在论文报告的 std 内 | 可以 |
| **L3 结论一致** | 消融实验的相对排序和论文一致 | 可以，且是高质量复现 |

**大部分人的"复现成功"其实只到 L1。** 面试官问"复现到什么程度"，答"跑通了"是减分项。

#### 执行顺序

1. **先跑 inference**：用作者提供的权重，在测试集上算指标。这一步不涉及训练，变量最少
2. **再 overfit 一个小 batch**：取 2-4 个样本，训练 100 步，loss 应该接近 0，Dice 接近 1
3. **再跑完整训练**：先用论文 1/10 的 epoch 看曲线是否正常
4. **最后跑完整配置**

**第 2 步是最有价值的 sanity check。** 如果 4 个样本都 overfit 不了，问题一定在数据管道或 loss，不在模型容量，也不在超参。这一步能省掉几小时的盲目调参。

#### 记录什么

- 完整命令：`python train.py --config configs/unet_lits.yaml --seed 42`
- commit hash：`git rev-parse HEAD`
- 环境与硬件：`env_lock.txt`、GPU 型号与显存
- 耗时与日志：每个 epoch 多少秒，日志重定向到文件

### 3.7 第 5 步：换自己的数据

**第一轮只做最小改动。**

| 改 | 不改 |
|---|---|
| Dataset 类（读你的文件格式） | loss 函数 |
| 输入通道数（如 1→3） | 优化器和 lr |
| 输出类别数 | lr schedule |
| 归一化统计量（用你训练集算） | 网络结构 |
| 评价指标的输入格式 | 数据增强策略 |

**为什么第一轮不改结构**：这一轮要验证的是"这个方法能不能迁移到我的数据"，不是"我能不能刷到更高分"。改了结构，指标变化就无法归因。

**换数据后必做的一件事**：在新数据上再 overfit 一个小 batch。新数据的管道是全新写的，必须重新验证。

### 3.8 第 6 步：记录所有偏差

建一张偏差日志，字段固定：

| 日期 | 项目 | 论文 | 我的 | 差值 | 可能原因 | 怎么验证的 | 结论 |
|---|---|---|---|---|---|---|---|
| 11-06 | 测试集 Dice | 0.890 | 0.861 | -0.029 | 划分不同 | 换成官方 split 重跑 | 提升到 0.884，主因确认 |

**关键在"怎么验证的"这一列。** 只写"可能原因"不写验证，等于没分析。报告里最容易被问倒的就是这一列。

### 3.9 时间预算

一篇中等难度的分割论文，第一次复现按 5 天排（详细日程见第七章）。

**经验值：第一次复现，环境和数据会吃掉 40% 的时间。** 这不是能力问题，是常态。第二次会降到 20%。

#### 止损规则

| 卡住时长 | 动作 |
|---|---|
| 同一个报错 1 小时 | 完整读一遍报错栈，搜 Issues |
| 2 小时 | 在仓库提 issue，同时找替代实现 |
| 4 小时 | 降级目标：只复现 inference，不训练 |
| 1 天 | 换论文。记录"为什么放弃"，这也是报告的一部分 |

### 3.10 本节的常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 先改数据再跑通 | 出问题无法归因 | 先跑通作者结果 |
| 在 base 环境装依赖 | 把学习环境搞坏 | 新建 conda 环境 |
| 不记录版本 | 一周后自己都跑不起来 | `pip freeze` |
| 用随机划分代替官方划分 | 数值永远对不上 | 找划分文件，找不到就说明 |
| 跳过 overfit 小 batch | 调参三天不知道问题在管道 | 先过拟合 4 个样本 |
| 第一轮就改网络结构 | 指标变化无法解释 | 最小改动 |
| 只跑一次就下结论 | 把随机波动当成方法差异 | 3 个种子 |

## 四、复现失败的五大原因

**本节核心问题：差的那 8 个点，到底是哪来的？**

### 4.0 先定义什么叫复现成功

绝对相等不存在。合理标准是下面两条同时满足：

1. 主指标差距 < 2%，**或**落在论文报告的 std 范围内
2. 结论方向一致：论文说 A 比 B 好，你也得到 A 比 B 好

**如果论文只报了一个数、没报 std、也没给划分文件，那它本身就不具备被精确复现的条件。** 这时候你能做的是 L3（结论一致），不是 L2。

下面的频率排序是**经验值**，来自常见的复现报告和 issue 讨论，不是统计调查。

### 4.1 原因一：数据划分不同（差 3-10%）

**为什么排第一**：它影响最大，而且最不容易被发现——因为两边都"看起来合理"。

#### 三种划分，结果完全不同

| 划分方式 | 说明 | 可比性 |
|---|---|---|
| 官方划分 | 作者给了 train/val/test 的 ID 列表 | 最高，能精确复现 |
| 固定随机划分 | 作者写了 seed 和比例 | 中，seed 对得上才行 |
| 交叉验证 | 5 折，报均值 | 中，折的划分方式必须一致 |

#### 医学影像特有的坑：划分粒度

| 粒度 | 做法 | 后果 |
|---|---|---|
| **病人级** | 同一病人的所有切片只在一边 | 正确 |
| **切片级** | 每张切片独立随机分 | **同一病人的相邻切片跨训练/测试，Dice 虚高 5-15 个点（经验值）** |
| **病灶级** | 同一病灶的不同切片分开 | 同样泄露 |

**这是医学影像复现里最隐蔽、后果最严重的一类错误。** 切片级划分在自然图像里没问题（每张图是独立场景），在医学影像里等于把答案泄露给测试集。

#### 排查四步

1. 找划分文件。找不到，看代码里怎么分的
2. 检查划分的键是病人 ID 还是文件名
3. 自己重划一次（病人级），对比指标变化
4. 检查测试集 ID 有没有出现在训练集里

```python
# 一分钟查泄露
train_ids = set(open('splits/train.txt').read().split())
test_ids = set(open('splits/test.txt').read().split())
print(len(train_ids & test_ids))   # 必须是 0
```

### 4.2 原因二：预处理不同（差 2-5%）

预处理是链条最长的环节，每一环都可能不一样。

| 环节 | 常见分歧 | 影响 |
|---|---|---|
| 尺寸 | resize 到 256 vs center crop 256 vs pad 到 256 | 改变目标比例，小目标可能消失 |
| CT 强度 | HU 窗 [-160,240] vs [-100,200] vs 不设窗 | 对比度不同，模型看到的输入不同 |
| 归一化 | per-image z-score vs 数据集 mean/std vs 除以 255 | 分布不同，尤其影响小数据集 |
| 几何 | 重采样到固定 spacing vs 保持原 spacing | 器官形状比例改变 |
| 方向 | 有没有做方向校正（LPS/RAS） | 左右翻转，标签错位 |
| 增强 | 训练时增强 vs 训练测试都增强 | 后者是 bug |

#### 排查方法

**不要读代码猜，要把中间结果存下来看。**

```python
# 在 Dataset 的 __getitem__ 里临时加一段
if idx < 3:
    print(img.shape, img.dtype, float(img.min()), float(img.max()), float(img.mean()))
    save_png(img, f'debug/case{idx}.png')
```

然后做两件事：

1. 和论文图 1 的输入示例对比，看窗宽窗位像不像
2. 检查数值范围：CT 的 HU 应该在 -1000 到 +3000 之间；归一化后应该在 0-1 或均值 0 附近

**经验值**：预处理问题里，一半以上是归一化统计量用错了（用了全量数据的 mean/std，而不是训练集的）。

### 4.3 原因三：指标实现不同（Dice 差 0.02）

Dice 的定义看起来没有歧义，实现上有五个分歧点。

| 细节 | 写法 A | 写法 B | 差异方向 |
|---|---|---|---|
| smooth 项 | 分子分母都加 1e-5 | 不加 | 空掩码时差异巨大，非空时约 0.001 |
| 空掩码 | 记为 1（完全正确） | 记为 0 | 有好几个空病例时，均值差 0.02-0.05 |
| 平均方式 | 每例算 Dice 再平均 | 所有像素累计后算一次 | 小病灶的权重不同，差 0.01-0.03 |
| 二值化 | 阈值 0.5 | argmax | 多类任务里不等价 |
| 后处理 | 取最大连通域 | 不做 | 小目标任务里差 0.01-0.04 |

#### 手算示例（算术，不是论文数字）

```
GT   = [1,1,1,1,0,0,0,0]
Pred = [1,1,0,0,0,0,0,0]

交集 = 2，GT 阳性 = 4，Pred 阳性 = 2
无 smooth：  2*2 / (4+2) = 4/6 = 0.6667
smooth=1：  (2*2+1) / (4+2+1) = 5/7 = 0.7143

空掩码（GT 全 0，Pred 全 0）：
无 smooth：0/0，numpy 给 nan，有的实现直接返回 0
有 smooth：1/1 = 1
```

一个数据集里如果有 20 个空病例，这 20 个的算法不同，整体均值就能差出 0.02 以上。

#### 最省事的做法

**直接用作者仓库里的 metric 函数**，不要自己重写。如果必须重写，先拿作者代码的输出对一遍，在一个小样本上跑到完全一致，再换到全量。

### 4.4 原因四：随机种子（波动 1-2%）

随机性来自四处：

| 来源 | 是否受 seed 控制 |
|---|---|
| 权重初始化 | 是 |
| 数据 shuffle、数据增强 | 是 |
| cuDNN 的非确定性算法 | 部分，需要 `torch.use_deterministic_algorithms(True)` |
| 多卡训练的梯度聚合顺序 | 不完全可控 |

#### 正确做法

- 至少跑 3 个种子，报告 mean ± std
- 比较两个方法时，看差距有没有超过 std
- **不要只跑一个种子就宣布"我比论文高 1%"**，那大概率是种子运气

#### 完全确定性的代价

```python
import torch
torch.manual_seed(42)
torch.use_deterministic_algorithms(True)
torch.backends.cudnn.benchmark = False
```

开了之后速度会降，某些算子会报"没有确定性实现"。**复现时建议开，刷分时关。**

### 4.5 原因五：代码本身有 bug

这一类最少见，但一旦遇上，怎么调参都没用。

#### 去哪找

| 地方 | 搜什么 |
|---|---|
| GitHub Issues（open + closed） | `reproduce`、`result`、`dice`、`lower`、`not matching` |
| Commit history | `fix`、`bug`、`typo`、`correct` |
| Pull requests | 有没有人提过修正但没合并 |
| 论文的 OpenReview 页面 | 审稿人常指出代码和论文不一致 |

**closed issues 比 open 更有价值**，因为问题已经被解决了。

#### 高频 bug 清单

- [ ] 验证集 dataloader 的 `shuffle=True`（导致指标不稳定）
- [ ] 测试时忘了 `model.eval()`（BatchNorm 用了 batch 统计）
- [ ] 忘了 `torch.no_grad()`（显存爆，但不影响指标）
- [ ] 标签通道顺序反了（背景和前景互换）
- [ ] 多类任务里 sigmoid 和 softmax 用混
- [ ] 保存的是最后一个 epoch，不是 best（论文报的是 best）
- [ ] 归一化用了全量数据的统计量（轻微泄露）
- [ ] 数据增强在验证集上也开了

### 4.6 排查决策树

```
结果不对
│
├─ 根本跑不起来
│   └─ 环境/依赖 → 见 3.4
│
├─ 跑起来但指标接近随机（Dice≈0.5，AUC≈0.5）
│   ├─ 图像和标签是否对齐？→ 可视化 3 例
│   ├─ loss 有没有下降？→ 看训练日志前 10 个 epoch
│   ├─ 输出通道/激活函数是否匹配任务？
│   └─ 测试时是否 model.eval()？
│
├─ 指标差 > 10%
│   ├─ 划分不同？（最常见）→ 找划分文件，查病人泄露
│   ├─ 预处理不同？→ 存中间图对比
│   └─ 指标算错？→ 用作者 metric 对一遍
│
├─ 指标差 2%-10%
│   ├─ 预处理细节（归一化、窗宽）
│   ├─ 训练轮数/学习率是否一致
│   ├─ 指标实现（smooth、空掩码、per-case vs global）
│   └─ 后处理有没有做
│
└─ 指标差 < 2%
    ├─ 正常波动
    └─ 跑 3 个种子确认是否落在 std 内
```

### 4.7 症状对照表

| 症状 | 最可能原因 | 第一步查什么 |
|---|---|---|
| Dice 恰好 0.5 左右 | 输出全 0 或全 1 | 预测图的像素分布 |
| Dice 0.99 但图很难看 | 标签泄露或指标算错 | 测试集 ID 是否在训练集 |
| loss 不下降 | lr 太大 / 标签错位 / loss 用错 | 先 overfit 4 个样本 |
| loss 下降但验证指标不涨 | 过拟合 / 验证集分布不同 | 看训练验证曲线 |
| 每次跑结果差很多 | 种子 / shuffle / 数据顺序 | 固定种子重跑两次 |
| 训练正常，测试崩 | 忘了 eval / 预处理不一致 | 检查 test transform |
| 显存刚好爆 | batch size 或 patch size | 减半试一次 |

### 4.8 本节的常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 一出差异就调参 | 调了三天，原因在划分 | 先按 4.6 的顺序排查 |
| 把随机波动当提升 | 只跑一个种子 | 3 seeds，报 mean±std |
| 自己重写 Dice | 和论文差 0.02 | 用作者的 metric |
| 不看 Issues | 重复踩别人踩过的坑 | 先搜 closed issues |
| 报告写"可能是环境不同" | 无法检验 | 提出可检验的假设并验证 |

### 5.1 笔记的三个层次

| 层次 | 内容 | 有没有用 |
|---|---|---|
| 摘抄 | 把摘要和结论复制下来 | 没用 |

### 5.3 示范：U-Net 精读笔记

下面是一份完整的样板。U-Net 是医学图像分割的奠基工作，也是你模块 11 会亲手实现的结构。**这篇笔记里的论文数字是原论文报告值，我没有本地复现。**

```markdown
# U-Net: Convolutional Networks for Biomedical Image Segmentation

- 出处：MICCAI 2015
- 年份：2015
- 代码：原作者提供了 caffe 版本，社区有大量 PyTorch 复现
- 读的遍次：第三遍

## 1. 一句话概括
为了在少量标注的医学图像上做像素级分割，提出全卷积的
encoder-decoder 加 skip connection，在 ISBI 2015 EM 分割挑战赛上
取得 warping error 0.000353，优于同期 sliding-window 方法。

## 2. 要解决的问题
医学图像分割的训练样本很少（几十张），而分割要求每个像素都分类，
且同类物体在不同图像里位置、尺度差异大。当时的 CNN 做分割需要
大量标注。

## 3. 之前的方法差在哪
1. sliding-window CNN（Ciresan 2012）：每个像素取一个 patch 单独预测，
   相邻 patch 重叠区域被重复计算，推理慢。
2. patch 大小是个两难：patch 大→上下文多但定位差；patch 小→定位准但
   看不到全局结构。
3. 需要大量标注，而医学数据标注成本极高。

## 4. 核心方法
全卷积网络，分两半。左半边（contracting path）反复 3x3 卷积 + ReLU +
2x2 max pooling，每次下采样通道数翻倍，提取语义。右半边（expansive
path）上采样，每步和左半边同层特征 concat，再卷积，恢复分辨率。
关键是 skip connection：把高分辨率的浅层特征直接送到深层，弥补下采样
丢掉的定位信息。输出层 1x1 卷积得到每个像素的类别。因为用的是 valid
卷积，特征图会缩小，所以 concat 前要 crop。训练时用弹性形变做增强，
并用加权 loss 让边界像素权重更高。

## 5. 实验设置
| 项 | 内容 |
|---|---|
| 数据 | ISBI 2015 EM 分割（30 张 512x512 训练）、ISBI 细胞追踪（PhC/DIC） |
| 划分 | 挑战赛官方划分 |
| 指标 | warping error、Rand error、pixel error；细胞追踪用 IoU |
| 对比 | sliding-window CNN、当时挑战赛排名方法 |
| 训练 | SGD，momentum 0.99，batch 1，大量弹性形变增强 |

## 6. 主要结果
| 指标 | 本文 | 说明 |
|---|---|---|
| warping error | 0.000353 | EM 挑战赛，原论文报告值 |
| Rand error | 0.0382 | 同上 |
| pixel error | 0.0611 | 同上 |
| IoU（PhC） | 0.9203 | 细胞追踪，原论文报告值 |
| IoU（DIC） | 0.7756 | 同上 |

消融：本文没有现代意义上的逐模块 ablation table，只有与同期方法的
整体对比和少量变体讨论。这是 2015 年论文的普遍写法，不能按现在的
标准要求它。

## 7. 局限
1. 只有 2D。对 3D CT/MRI 需要逐切片处理，丢失层间信息，各向异性
   spacing 无法处理。
2. valid 卷积导致每层特征图缩小，concat 前必须 crop，输入尺寸受限，
   且边缘像素的上下文不完整。后续工作用 same padding 解决了这点。
3. 只在两个小数据集上验证，没有外部验证，也没有和放射科医生对比。
4. 加权 loss 的边界权重是手工设的，论文没有给系统的调参依据。

## 8. 我的想法
把 U-Net 用到肝脏肿瘤分割时，最直接的问题是 3D 信息和各向异性 spacing。
一个可做的实验：把 2D U-Net 的 encoder 换成在 3D patch 上训练，
decoder 保持 2D，比较层间信息带来的提升。另一个方向是边界加权——
肝脏肿瘤的边界比细胞边界模糊得多，原论文的权重图策略未必适用，
可以对比"距离变换加权"和"固定边界权重"两种方案。

## 9. 复现可行性
- [x] 代码可用
- [x] 数据可得（ISBI 挑战赛数据公开）
- [x] 划分明确（官方划分）
- [x] 超参基本齐全
- [x] 单卡可训
结论：可复现。适合作为第一次复现的对象。
```

**这份笔记值得学的地方**：第 4 节全是自己的话；第 6 节标注了"原论文报告值"并指出"没有 ablation"；第 7、8 节落到了具体设计和自己的任务上。

### 5.5 综述：不是罗列，是对比

#### 三组对照

**第一组：罗列 vs 归类**

错误写法：

> 张三等提出了方法 A，在数据集 X 上取得了较好的效果。李四等提出了方法 B，在数据集 Y 上也取得了不错的结果。王五等提出了方法 C……

正确写法：

> 现有工作可分为两类。基于手工特征的方法（A、B）依赖纹理和形状描述子，在样本量小于 50 时仍然稳定，但难以刻画肿瘤的异质性。端到端方法（C、D）在百例级数据上明显更优，代价是需要像素级标注。

**第二组：报数 vs 比条件**

错误写法：

> A 的 Dice 是 0.91，B 的 Dice 是 0.93，所以 B 更好。

正确写法：

> B 比 A 高 0.02，但 B 使用了 3 倍的标注数据，且两项工作都没有报告外部测试集结果，因此这个比较不足以支持"B 更优"的结论。

**第三组：总结 vs 指出空白**

错误写法：

> 深度学习方法在肝脏肿瘤分割上取得了很好的效果。

正确写法：

> 这些方法在单中心数据上 Dice 普遍超过 0.9，但没有一项工作报告跨中心性能下降的幅度。这个空白使得"能否进入临床"无法判断。

#### 判断标准

写完一段，检查：

- [ ] 有没有出现"某某提出了……某某提出了……"的连续句式
- [ ] 有没有至少一处直接比较两个工作
- [ ] 有没有指出一个"没人做"的事
- [ ] 引用的数字有没有附带条件（数据量、验证方式）

### 5.6 找 gap 的三个角度

#### 角度一：所有人都在做什么，没人做什么

做法：把 15-20 篇论文做成"任务 × 方法"矩阵，找空格。

示例矩阵（假设的示例）：

|  | 2D CNN | 3D CNN | Transformer | 多模态 |
|---|---|---|---|---|
| 肝脏分割 | 很多 | 很多 | 少 | 少 |
| 肿瘤分割 | 很多 | 多 | 少 | **空白** |
| 早期 HCC 检测 | 少 | 少 | **空白** | **空白** |

**空格不等于 gap。** 还要问：为什么没人做？是没价值，还是没数据，还是做不动？如果是"没数据"，那数据本身就是你的贡献。

#### 角度二：换个条件会怎样

| 换什么 | 具体问法 |
|---|---|
| 数据集 | 所有人都在 LiTS 上刷，换一个中国人群的数据会掉多少 |
| 中心 | 单中心训练的模型，跨中心性能下降多少 |
| 模态 | CT 上有效的方法，换 MRI 还成立吗 |
| 人群 | 乙肝相关 HCC 的结论，对脂肪肝相关 HCC 成立吗 |
| 标注量 | 全监督需要几百例，少样本条件下排序会变吗 |
| 时间 | 回顾性数据上的性能，在前瞻性筛查里还在吗 |

#### 角度三：论文自己承认的局限

做法：把每篇论文 Limitations 段落抄进一个表，做词频统计。

出现频率最高的三条，就是这个领域公认的、尚未解决的问题。这比自己想更可靠，因为它是领域共识。

**注意**：作者写"未来我们将扩展到多中心"，通常意味着他现在做不到。这类句子是 gap 的直接线索。

### 5.7 综述段落的四句法

一段合格的对比段落，四句话：

1. **这一组工作在解决什么**（收敛范围）
2. **它们的共同做法/共同假设**（找共识）
3. **这个假设在什么条件下不成立**（找裂缝）
4. **所以还缺什么**（落 gap）

示例（假设的示例，数字仅用于演示句式）：

> 近三年的肝脏肿瘤分割工作主要集中在提升单中心数据集上的 Dice。这些方法共同假设训练和测试数据来自同一分布，因此普遍采用随机划分并在同源测试集上报告结果。然而，临床筛查场景中设备、扫描协议和人群构成都会变化，同分布假设不成立。目前尚无工作系统量化这种分布偏移对早期小病灶检出的影响，这是将分割模型用于筛查的主要障碍。

### 5.8 本节的常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 笔记只有摘抄 | 三个月后完全看不懂自己写了什么 | 第 4 节必须用自己的话 |
| 局限写"数据少" | 每篇都一样 | 落到具体设计缺陷 |
| 对比表按论文排行 | 写作时用不上 | 按维度组织 |
| 综述写成流水账 | 全是"某某提出" | 用四句法 |
| gap 写成"可以试试 Transformer" | 不是 gap，是技术清单 | 说清"缺什么证据" |
| 引用数字不带条件 | 无法判断可比性 | 附数据量、验证方式 |

### 6.3 差异分析怎么写

**核心：把"可能"变成"可检验"。**

错误写法：

> 我的结果比论文低 3 个点，可能是环境不同或者数据预处理不一样导致的。

问题：无法检验，无法反驳，等于没说。

正确写法（数字为假设示例，仅演示句式）：

> **现象**：测试集 Dice 0.861，论文 0.890，低 0.029。
>
> **假设 1**：划分不同。论文用官方 5 折，我用了随机 8:2。
> **检验**：下载官方划分文件，用同一份代码重跑。
> **结果**：Dice 升到 0.884，差值缩小到 0.006。
> **结论**：确认，划分是主因。
>
> **假设 2**：归一化方式不同。论文用 per-image z-score，我用了全局 mean/std。
> **检验**：改成 per-image 重跑。
> **结果**：Dice 0.886，变化 +0.002，在种子波动范围内。
> **结论**：排除，不是主因。

**假设要有优先级**：按第 4 节的频率排序，先查划分，再查预处理，最后查指标和种子。

**注意**：当信息不足时（例如论文没报 std），明确写"无法判断"，而不是硬给一个结论。这是科研写作的基本诚实。

### 6.4 本节的常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 只写"结果接近" | 没有数字 | 差值、std、命令都写上 |
| 差异分析全是"可能" | 无法检验 | 每条给检验方法和结果 |
| 把环境差异当万能解释 | 不查就归因 | 环境差异可以检验：换版本重跑 |
| 不写失败的部分 | 只报成功的指标 | 失败和放弃也要写 |
| 局限写成复现的困难 | 混淆两件事 | 第 7 节写论文的局限 |

用下面这组数组，手算三种 Dice：

```
GT   = [1,1,1,1,0,0,0,0]
Pred = [1,1,0,0,0,0,0,0]
```

1. 无 smooth
2. smooth = 1
3. GT 和 Pred 全为 0 时，上面两种写法各得多少

然后用 numpy 写三行代码验证你的手算。

**验收标准**：

- 三个数都算对（0.6667、0.7143、nan 或 1）
- 能解释为什么空掩码时差异最大
- 能说出在什么数据分布下，这个差异会超过 0.02

### 练习 14-D（复现失败归因）

场景：你用作者代码在同一个公开数据集上复现，论文报 Dice 0.89，你得到 0.81。数据、代码都确认是官方的。

**产出**：列出 5 个可能原因，按可能性排序，每个给出 `原因 / 为什么排这个位置 / 怎么检验 / 预期结果`。

**验收标准**：

- 5 个原因覆盖第 4 节的至少 4 类
- 每个检验方法都是可执行的（能写出一条命令或一段代码）
- 不出现"环境不同"这种无法检验的原因
- 排序有理由，不是随便排

### 练习 14-E（文献对比表）

选 3 篇同一任务的论文（例如都是肝脏肿瘤分割），填 5.4 的表 B。

**产出**：一张对比表 + 一段 150 字的对比段落 + 一个 gap。

**验收标准**：

- 表格按维度组织，不是按论文
- "共同点"列至少填 2 项
- 段落里至少有一处直接比较两个工作
- gap 能回答"为什么没人做"

### 练习 14-F（完整复现，3-5 天）

按第七章的流程完整走一遍，产出一份复现报告。

**验收标准**：

- 达到 L2（差距 < 2% 或落在 std 内），或能清楚解释为什么达不到
- 报告 8 节齐全
- 偏差日志至少 5 条，每条有"怎么验证的"
- 失败和放弃的部分也写进去

### 练习 14-G（综述段落改写）

把下面这段改写成对比式：

> 王某某提出了基于 CNN 的肝脏肿瘤分割方法，Dice 达到 0.90。李某某提出了基于 Transformer 的方法，Dice 达到 0.92。张某某提出了多模态融合方法，Dice 达到 0.93。这些方法都取得了很好的效果。

**验收标准**：

- 不再出现"某某提出……某某提出"的连续句式
- 至少指出一个方法间的条件差异（数据量、验证方式、模态）
- 最后一句落到一个空白上
- 不超过 200 字

## 九、自测题（带答案）

**先自己答，再看。**

**Q1. 第一遍 5 分钟应该看什么？不应该看什么？**

<details>
<summary>看答案</summary>

**看**：标题、摘要最后两句、图 1、表 1、结论最后一段、代码链接。

**不看**：引言、相关工作、公式、方法细节。

**理由**：图和表是信息密度最高、最难注水的部分；引言的功能是说服，不是告知。

</details>

**Q2. 会议和期刊的区别，一句话怎么说？**

<details>
<summary>看答案</summary>

**会议看方法新不新，期刊看临床有没有用。** 会议要求方法有创新、ablation 充分、比 SOTA 好；期刊要求研究设计严谨、有外部验证、能改变临床决策。同一项工作投两边，写法完全不同。

</details>

**Q3. 复现的第一步是什么？**

<details>
<summary>看答案</summary>

**选论文，不是配环境。**

选错的代价是整周白做。判断标准：代码公开、数据可得、单卡能训、划分明确。第一次复现不要选最新 SOTA，选 2018-2021 年的经典工作。

</details>

**Q4. 数据划分为什么是复现失败的第一原因？医学影像里最隐蔽的划分错误是什么？**

<details>
<summary>看答案</summary>

因为它影响最大（3-10 个点），而且两边看起来都合理，不容易被发现。

**最隐蔽的错误是切片级划分**：同一病人的相邻切片被随机分到训练和测试两边。切片之间高度相似，等于把答案泄露给测试集，Dice 会虚高 5-15 个点。

正确做法是按病人 ID 划分（`GroupKFold` / `GroupShuffleSplit`）。

</details>

**Q5. Dice 差 0.02，先查什么？**

<details>
<summary>看答案</summary>

**先查指标实现，不要先调模型。**

五个细节：smooth 项有没有、空掩码记 0 还是 1、per-case 平均还是全局累计、二值化阈值、有没有后处理。

最省事的办法是直接用作者仓库里的 metric 函数，在一个小样本上对到完全一致。

</details>

**Q6. 只跑一个种子，结果比论文高 1%，能说复现成功吗？**

<details>
<summary>看答案</summary>

**不能。**

随机种子带来的波动通常是 1-2%。高 1% 完全在噪声范围内，可能是运气。

正确做法：跑 3 个种子，报 mean ± std；比较时看差距有没有超过 std。

</details>

**Q7. 综述里"张三用了 A，李四用了 B"错在哪？**

<details>
<summary>看答案</summary>

**错在没有比较，只有并列。**

读者读完不知道谁更好、在什么条件下更好、还缺什么。这等于把整理工作丢给了读者。

正确写法要归类、比条件、指空白。用四句法：这一组在解决什么 → 共同假设 → 假设何时不成立 → 所以缺什么。

</details>

**Q8. 复现报告里写"可能是环境差异导致的"，为什么是废话？**

<details>
<summary>看答案</summary>

因为**不可检验**。任何差异都可以用这句话解释，因此它解释不了任何东西。

正确写法：提出具体假设（如"论文用 per-image 归一化，我用了全局统计量"），给出检验方法（改成 per-image 重跑），报告结果（Dice 变化 +0.002），给结论（排除）。

**差异分析的每一句都要能被实验证伪。**

</details>

## 十一、常见错误总表

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 从引言开始读 | 20 分钟还在背景介绍 | 标题→摘要末句→图 1→表 1 |
| 每篇都读三遍 | 一周两篇，还很累 | 第一遍淘汰 70% |
| 笔记抄摘要 | 三个月后看不懂 | 第 4 节用自己的话写 |
| 局限写"数据少" | 每篇都一样 | 落到具体设计缺陷 |
| 用会议标准读期刊 | 嫌方法不新 | 期刊看临床验证 |
| 先改数据再跑通 | 出问题无法归因 | 先跑通作者结果 |
| 不建独立环境 | 搞坏学习环境 | 新建 conda 环境 |
| 不记录版本 | 一周后自己都跑不起来 | `pip freeze` |
| 用随机划分代替官方划分 | 数值永远对不上 | 找划分文件 |
| 切片级划分 | Dice 虚高 5-15 点 | 按病人 ID 划分 |
| 跳过 overfit 小 batch | 调参三天找不到原因 | 先过拟合 4 个样本 |
| 自己重写 Dice | 和论文差 0.02 | 用作者的 metric |
| 只跑一个种子 | 把噪声当提升 | 3 seeds，报 mean±std |
| 差异分析写"可能" | 无法检验 | 假设→检验→结果→结论 |
| 对比表按论文排行 | 写作时用不上 | 按维度组织 |
| 综述写成流水账 | 全是"某某提出" | 四句法 |
| 报告只写成功 | 看不出工作量 | 失败和放弃也写 |
| 数字不标来源 | 分不清论文值和自己值 | 论文报告值/实测值/假设示例 |
