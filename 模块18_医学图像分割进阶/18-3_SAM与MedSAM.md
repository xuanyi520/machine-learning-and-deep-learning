## 一、SAM 解决的是什么问题

**传统分割模型的死结：**

```
训一个肝脏分割模型 → 只能分肝脏
换个器官（脾）→ 重新标注、重新训练
再换一个（肾）→ 再来一遍
```

**每换一个目标，就要重新标注几百例。这是医学影像落地的最大成本。**

### SAM 的想法

**Meta 2023 年那篇论文的标题就是：《Segment Anything》——分割一切。**

**核心思路：不学「什么是肝脏」，而是学「什么是一个能被指认的物体」。**

```
你给一个点 → 它把包含这个点的物体圈出来
你给一个框 → 它把框里的物体圈出来
你给一个粗略的掩码 → 它帮你精细修边
```

**它不知道那是什么器官。它只知道「你指的是这一块」。**

**这就是 prompt-based segmentation（提示式分割）。**

### 训练数据

**SAM 用了 11 亿个掩码，从 1100 万张图上采集。**

**关键是采集方式：** 用「数据引擎」——先让模型分，人只需要点一下「对」或「不对」，然后人工修错的地方，再训，再采。

**这个循环跑了三轮，把掩码数从 12 万做到 11 亿。**

## 二、三种 prompt

| 类型 | 给什么 | 适合 |
|---|---|---|
| **点（point）** | 一个坐标 + 标签（前景/背景） | 快速圈单个物体 |
| **框（box）** | 一个矩形 [x1,y1,x2,y2] | **医学最常用**，因为医生习惯画框 |
| **掩码（mask）** | 一个粗略的 0/1 图 | 精修之前的粗分割 |

**可以组合：** 一个框 + 框内几个负样本点，告诉它「框里除了这几个地方都要」。

## 三、为什么 SAM 在医学影像上直接不行

**SAM 论文里报告在 23 个数据集上效果好。但那是自然图像。**

**医学影像上直接跑，效果差很多。原因四个：**

### ① 输入格式不匹配

**SAM 要求 RGB 三通道，HWC 格式的 numpy 数组。**

**医学影像是：**

```
CT     → 单通道灰度，而且原始值范围从 -1024 到 +3000
MRI    → 单通道，强度范围因序列而异
超声   → 单通道，有大量斑点噪声
```

**你要自己把它转成「看起来像自然图像」的样子。**

**关键：怎么转，直接影响效果。**

```python
# 直接归一化到 0-255 —— 往往效果很差
img = (hu - hu.min()) / (hu.max() - hu.min()) * 255

# 按器官窗裁剪再归一化 —— 效果好得多
lo, hi = window_level - window_width/2, window_level + window_width/2
img = np.clip((hu - lo) / (hi - lo) * 255, 0, 255)
```

**这就是为什么模块 4-1 的窗宽窗位这么重要——它决定了 SAM 能看见什么。**

### ② 训练数据里几乎没有医学影像

**SAM 的 1100 万张图，医学影像占比极低。** 它对「CT 上一块灰度略高的区域是不是一个器官」没有概念。

### ③ 边界定义不一样

**自然图像里，「杯子」和「桌子」的边界是视觉上能看到的边缘。**

**医学影像里：**

```
肝脏和脾脏之间 → 灰度几乎一样，靠解剖位置区分
肿瘤和正常组织 → 边界是渐变的，没有清晰边缘
```

**SAM 找的是「视觉边缘」，医学要的是「解剖边界」。这两件事不是一回事。**

### ④ 低对比度

**CT 的软组织窗，肝、脾、肌肉的 HU 值差不了几十。**

**换算成 8 位灰度后，差别可能只有 3-5 个灰阶。** 人眼勉强能分，模型的边缘检测基本失效。

## 四、MedSAM 做了什么

**2024 年，一个团队把 SAM 在医学数据上微调了一遍。**

**做法很朴素：**

```
数据：11 个模态（CT、MRI、超声、X光、眼底、病理等），
      150 万对「图像-掩码」
        ↓
只微调 SAM 的图像编码器和掩码解码器
        ↓
不改变架构，不改 prompt 形式
```

**结果：在多个医学分割任务上，Dice 从 SAM 原版的 0.5-0.7 提到 0.8-0.9。**

**关键发现：**

> **微调后的 MedSAM，用一个框做 prompt，在许多器官上能达到甚至超过专门训练的 U-Net。**

**这句话要是真的，意味着「标注几百例训专用模型」这件事可以被替代。**

**但注意「许多器官」——不是所有。**

## 六、最小可运行代码

```python
import os
import numpy as np
import torch
import cv2
from segment_anything import sam_model_registry, SamPredictor

# ---------- 1. 加载模型 ----------
sam = sam_model_registry["vit_b"](checkpoint=r"F:\AI学习环境\models\sam\sam_vit_b_01ec64.pth")
sam.to("cuda")
predictor = SamPredictor(sam)

# ---------- 2. 准备图像：必须 RGB、HWC、uint8 ----------
import pydicom

ds = pydicom.dcmread(r"E:\AI学习\练习代码\data\CT_small.dcm")
hu = ds.pixel_array.astype(np.float32) * float(ds.RescaleSlope) + float(ds.RescaleIntercept)

# 按肺窗映射到 0-255
ww, wl = 1500, -600
lo, hi = wl - ww/2, wl + ww/2
gray = np.clip((hu - lo) / (hi - lo) * 255, 0, 255).astype(np.uint8)

# 单通道 -> 三通道
rgb = np.stack([gray, gray, gray], axis=-1)          # HWC

# ---------- 3. 设置图像（这一步很慢，会跑编码器）----------
predictor.set_image(rgb)

# ---------- 4. 给提示 ----------
# 方式 A：给一个点
point_coords = np.array([[rgb.shape[1]//2, rgb.shape[0]//2]])   # (x, y)
point_labels = np.array([1])                                     # 1=前景, 0=背景
masks, scores, logits = predictor.predict(
    point_coords=point_coords,
    point_labels=point_labels,
    multimask_output=True,       # 返回 3 个候选，选最好的
)

best = masks[np.argmax(scores)]
print(f"生成 {len(masks)} 个候选，最高分 {scores.max():.3f}，掩码面积 {best.sum()} 像素")
```

### 三个必须注意的地方

**① 输入的格式**

```
要求：numpy 数组，形状 (H, W, 3)，dtype 必须 uint8
不满足会报各种奇怪的错
```

**② `set_image()` 很慢**

**它要跑一遍 ViT 编码器，512×512 的图大约 0.5-2 秒（ViT-B，GPU）。**

**如果要对同一张图问多次，只调一次 `set_image()`，然后反复 `predict()`。** 这是 SAM 设计的用法。

**③ 返回三个掩码**

**`multimask_output=True` 会返回三个粒度的候选：**

- 小：只圈出最确定的核心区域
- 中：一般最合理
- 大：把周边可疑的都圈进来

**选哪个取决于任务。** 肿瘤取小的（宁可漏不可错），器官取中的。

**`multimask_output=False` 只返回一个，适合你已经很确定目标大小的情况。**

## 七、用框做提示（医学最常用）

```python
# 医生画的框：[x1, y1, x2, y2]
box = np.array([120, 80, 320, 300])

masks, scores, logits = predictor.predict(
    box=box,
    multimask_output=False,
)
```

**框比点可靠的三个原因：**

1. **框包含了「多大」这个信息**——点只能说明「在这」，不知道应该圈多大
2. **框能排除干扰**——右下角有个亮的东西，框不给到那边，就不会被圈进来
3. **医生本来就会画框**——标注软件里画框比画精细轮廓快得多

**这也解释了为什么 MedSAM 论文主打「框提示」：它最贴近真实标注流程。**

## 八、3D 怎么处理

**SAM 是 2D 的。CT 是 3D 的。三条路：**

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **逐层跑** | 每层当一张图，各给各的框 | 简单 | 层间不连续，切面跳动 |
| **传播** | 中间层给一次，前后层用掩码当提示 | 快 | 会累积偏差 |
| **MedSAM2** | 原生支持 3D/视频 | 最好 | 权重和依赖更复杂 |

**逐层跑的最简实现：**

```python
masks_3d = []
for z in range(hu.shape[0]):
    rgb = dicom_slice_to_rgb(hu[z], ww, wl)
    predictor.set_image(rgb)          # 每层都要重跑编码器，很慢
    m, s, _ = predictor.predict(box=box_per_slice[z], multimask_output=False)
    masks_3d.append(m[0])

volume = np.stack(masks_3d)
```

**代价：** 200 层 × 1 秒 = 3 分钟。**而且层与层之间可能跳。**

**优化：** 只对关键层跑 SAM，中间层用插值或者拿上一层的结果当 mask prompt。

## 九、SAM 能不能替代你自己训的模型

**这是面试很可能问的问题，答案要清楚。**

| 维度 | 自己训的 U-Net | SAM / MedSAM |
|---|---|---|
| 需要标注 | **几百例** | **零或几个框** |
| 精度 | 高（数据够的话） | 中到高 |
| 速度 | **快**（一次前向） | **慢**（编码器很重） |
| 可控性 | 高 | 低（prompt 敏感） |
| 能区分亚型吗 | 能（多类别） | 不能（只分「物体」） |
| 幻觉 | 少 | **会给不存在的区域画掩码** |

**结论：**

> **SAM 适合「快速拿到一个还行的初始标注」，不适合「上线做精确分割」。**
>
> **真实的工作流是：SAM 出粗结果 → 人工修 → 训专用模型 → 专用模型上线。**

**这句话是这一节最该记住的。** 很多教程把 SAM 吹成「取代一切分割模型」，那是误读。

## 十四、常见错误

| 错误 | 现象 | 原因 | 改法 |
|---|---|---|---|
| 传灰度图 | 报维度错误 | SAM 要 3 通道 | `np.stack` 成 RGB |
| 没转 uint8 | 各种奇怪错误 | dtype 不对 | `.astype(np.uint8)` |
| 每层都 `set_image` | 慢到不可用 | 编码器很重 | 同图只设一次 |
| 用原始 HU 值 | 全黑或全白 | 超出 0-255 | 先按窗裁剪 |
| 选最大面积掩码 | 圈进一堆无关区域 | 三个候选含义不同 | 按任务选 |
| 以为能分亚型 | 只有前景背景 | SAM 不分类别 | 多类要用专用模型 |
| 无脑相信结果 | 空气上也能圈出东西 | 幻觉 | 看分数、目测验证 |

## 十五、下一节要干什么

**到现在为止，你信的都是「我的模型错了」。**

**但有一种情况更常见：模型没错，标注错了。**

手绘的标注有 5-10% 的边界误差，多个标注者之间的一致性（inter-observer agreement）往往只有 0.85 左右。

**如果 Dice 卡在 0.88 上不去，可能不是你模型的问题，是数据的天花板。**

**下一节 18-4 讲标注质量评估——怎么量化标注本身的不确定性。**
