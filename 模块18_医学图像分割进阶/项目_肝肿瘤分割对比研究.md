# 毕业项目 · 肝肿瘤分割对比研究

**建议用时：60 小时（约 3-4 周）**

**这是模块 18 的终点，也是简历上最硬的一块。**

---

## 〇、项目定位

**一句话：在公开数据集上，用同一套评估方式跑三个不同的分割架构，做出一份能说服人的对比报告。**

**不是「我训了一个肝脏分割模型」。是「我验证了新架构到底比 U-Net 强多少、值不值」。**

**两者的区别：前者是课程作业，后者是研究工作。**

---

## 一、为什么选这个题目

| 常见项目 | 问题 |
|---|---|
| MNIST / 猫狗分类 | 和医学无关 |
| 只跑一个 U-Net | 没有对比，说不出所以然 |
| 调参调到 Dice 0.95 | 大概率是过拟合测试集 |
| 用现成的 nnU-Net 交差 | 面试一问内部原理就露馅 |

**这个项目的差异点：**

1. **有对比** —— 三个架构，同一份数据，同一套指标
2. **有分析** —— 不只是「A 比 B 好 0.5 个点」，还要说清「多花了多少代价」
3. **有诚实** —— 跑不动的部分老实写原因，不编数字
4. **和你的方向对得上** —— 肝癌是你接触过的领域

---

## 二、数据

### 首选：LiTS（Liver Tumor Segmentation Challenge）

| 项 | 内容 |
|---|---|
| 来源 | https://competitions.codalab.org/competitions/17094 |
| 规模 | 131 例训练 + 70 例测试 |
| 标注 | 肝脏 + 肿瘤，两个类别 |
| 格式 | NIfTI |
| 大小 | **约 60 GB** |

**⚠️ 分级下载策略（重要）：**

```
第一周：只下 20 例          → 验证完整流程
第二周：下 60 例            → 跑正式实验
第三周（可选）：全量 131 例  → 出最终结果
```

**一次下 60 GB，硬盘和网速都会崩。**

### 备选方案（如果 LiTS 拿不到）

| 数据集 | 规模 | 难度 |
|---|---|---|
| **AMOS22**（腹部多器官） | 300 例 CT | 中，15 个器官 |
| **BTCV**（腹部多器官） | 50 例 | 易，标注质量高 |
| MedMNIST 的 organ 系列 | 小 | 太简单，不太够 |

**建议顺序：LiTS → BTCV → AMOS22。**

**BTCV 只有 50 例，最适合「先跑通再扩规模」。**

## 三、三个对比模型

| 组 | 模型 | 为什么选它 |
|---|---|---|
| **A** | nnU-Net（官方配置） | **基线中的基线**，所有论文都拿它比 |
| **B** | SwinUNETR（MONAI） | Transformer 路线代表 |
| **C** | 自写 3D U-Net | **证明你会从零写**，不是只会调包 |

**为什么不加 Mamba：**

**Windows 装不上 `mamba-ssm`（18-5 验证过）。** 硬塞只会浪费时间。

**替代：在报告的「相关工作」里引用 U-Mamba 的公开结果，做文献对比。诚实说明「未实跑」。**

## 四、四阶段实施

### 阶段一：数据与基线（15 小时）

- [ ] 下载 LiTS 前 20 例
- [ ] 转成 nnU-Net 格式（DatasetXXX_Liver，两个通道：CT + 肝脏掩码）
- [ ] 跑通 nnU-Net 的 2D 配置，拿到第一个 Dice
- [ ] 记录：耗时、显存、Dice、HD95

**验收：**

```
nnUNetv2_train 2 2d 0 跑完
→ 记录一个具体的 Dice 数字
```

**这个数字是整个项目的锚点。后面所有对比都是和它比。**

---

### 阶段二：自写 3D U-Net（20 小时）

- [ ] 用 18-2 的代码搭 3D U-Net
- [ ] **数据划分必须按病人分组**（GroupKFold）
- [ ] 训练，记录 Dice
- [ ] 和 nnU-Net 对比

**这一阶段最容易翻车的地方：**

```
❌ 按切片随机划分 → Dice 虚高 5-10 个点
✅ 按病人划分 → 真实但难看的数字
```

**用虚高的数字写进简历，面试官一问「你怎么划分的」就露馅。**

**验收：**

- [ ] 有明确的划分文件（`split.json`，记录每个病人去了哪一组）
- [ ] Dice 数字低于 nnU-Net（这很正常，**它是自动配置的巅峰**）

---

### 阶段三：SwinUNETR（15 小时）

- [ ] 用 MONAI 建 SwinUNETR
- [ ] 同样的数据、同样的划分、同样的 epoch
- [ ] 记录 Dice + 参数量 + 显存 + 耗时

**8 GB 显存的现实：**

```
patch 96³, batch 2  → 约 2.5 GB，能跑
patch 128³, batch 1 → 约 5 GB，勉强
```

**验收：**

- [ ] 三个模型在同一划分上跑完
- [ ] 有一张完整对比表

---

### 阶段四：分析 + 部署（10 小时）

- [ ] 失败案例分析（至少 8 例）
- [ ] 导出 ONNX，验证数值一致
- [ ] 测推理耗时，算整卷 CT 的处理时间
- [ ] 写报告

**验收：**

- [ ] ONNX 和 PyTorch 的最大误差 < 1e-4
- [ ] 能算出「处理一整卷需要多少秒」

## 五、对比表模板

**这张表是整个项目的核心产出。**

| 模型 | 参数量(M) | 显存(GB) | 单轮耗时 | 肝脏 Dice | 肿瘤 Dice | HD95(mm) | 推理(秒/卷) |
|---|---|---|---|---|---|---|---|
| nnU-Net(2D) | | | | | | | |
| SwinUNETR | 15.70 | 1.26 | | | | | |
| 3D U-Net | 1.19 | 0.3 | | | | | |

**注意排版顺序：从强到弱，还是从简单到复杂？**

**建议按「投入」排序（参数少的在前），这样读者一眼看到「花了更多代价，换来多少」。**

### 必须额外报的数

| 指标 | 为什么 |
|---|---|
| **标注者间一致性** | 说明天花板在哪，如果你的模型已经接近，就不用再调了 |
| **失败案例数** | 8 例以上，要分类 |
| **训练总时长** | 实际跑了几小时 |
| **跑不了的部分** | 诚实写原因 |

## 六、失败分析怎么做

**这是拉开差距的地方。**

**每个失败案例要写四行：**

```
【案例 07】
病人 ID：liver_042
表现：肿瘤 Dice = 0.12，远低于平均
归因：肿瘤紧贴肝包膜，边界与肝实质几乎同密度
层级：数据问题（标注本身就有争议）
能修吗：换更高的窗宽窗位重试，或引入 MRI 辅助
```

**归因要落到具体层级：**

| 层级 | 典型表现 |
|---|---|
| **数据** | 标注有争议、扫描质量差 |
| **预处理** | 重采样后病灶变形、窗宽窗位选错 |
| **模型** | 感受野不够、容量不足 |
| **后处理** | 小病灶被去掉了 |
| **指标** | HD95 对小目标极其敏感 |

**至少要有三个不同层级的失败案例。全是「模型不行」说明你没认真分析。**

## 八、简历怎么写

**不要写成：**

```
肝肿瘤分割项目
- 使用 nnU-Net 和 SwinUNETR 做分割
- 肝脏 Dice 达到 0.93
```

**应该写成：**

```
肝肿瘤 3D 分割架构对比研究（个人项目）
- 在 LiTS 上对比 nnU-Net / SwinUNETR / 自写 3D U-Net 三种架构，
  统一数据划分与训练配置，肝脏 Dice 0.93 / 肿瘤 Dice 0.68
- 定量分析架构代价：SwinUNETR 参数量 13 倍、单轮耗时 13 倍，
  换来的肿瘤 Dice 提升 X.X 个点
- 实现 ONNX 导出与 FP16 量化，单卷推理从 XX s 降至 XX s，
  与 PyTorch 输出最大误差 3e-6
- 完成 8 例失败案例归因，其中 5 例定位到标注争议而非模型缺陷
```

**差别：每个技术点后面跟着数字，而且承认了「代价」。**

## 九、面试怎么讲

### 30 秒版

> 我做过一个肝肿瘤分割的架构对比研究。在同一份数据上跑了 nnU-Net、
> SwinUNETR 和自写的 3D U-Net，不只是比 Dice，还算清了每个架构的
> 参数和算力代价。最后做了 ONNX 部署，量化了推理速度。

### 3 分钟版（按「问题 → 方法 → 发现 → 落地」）

```
问题：医学分割领域新架构层出不穷，但很少有工作系统回答
     「新架构比 U-Net 强多少、代价多大」。
方法：同一份 LiTS 数据，同一套划分，三个架构，控制所有其他变量。
发现：SwinUNETR 参数量是我自写 U-Net 的 13 倍，
     但肿瘤 Dice 只高了 X 个点。而在肝脏这种大器官上差距更小。
     说明：新架构的收益主要体现在小目标和边界复杂的情况。
落地：导出 ONNX，FP16 量化，推理速度提升 X 倍，精度损失 < 0.001。
```

### 必被追问的三个问题

| 问题 | 你要能答 |
|---|---|
| **你怎么保证对比公平？** | 说清划分、epoch、增强、损失函数都一致 |
| **为什么不直接用 nnU-Net？** | 说清它的局限（黑盒、改起来难、不能针对特定问题优化） |
| **Dice 0.93 是什么水平？** | 报出标注者间一致性，说明「已经接近天花板」 |

## 十一、常见失败模式

| 失败 | 表现 | 预防 |
|---|---|---|
| **一直调 Dice** | 卡在 0.90，调了两周 | 先算标注一致性，看是不是到顶了 |
| 按切片划分 | Dice 虚高，面试一问就露馅 | 一开始就用 GroupKFold |
| 三个模型配置不同 | 对比无效 | 写一个配置文件，三个模型共用 |
| 不做失败分析 | 报告空洞 | 阶段四强制留 8 例 |
| 下载 60 GB 卡住 | 一周啥也没干 | 分级下载，20 例起步 |
| 编 Mamba 的结果 | 面试深挖露馅 | 老实写「未实跑」 |

**第一条最常见。** 记着 18-4 那张诊断表。

## 十二、时间不够怎么办

**只剩两周：**

| 优先级 | 做什么 |
|---|---|
| 必做 | nnU-Net 基线 + 自写 3D U-Net 两个对比 |
| 必做 | 一张对比表 + 3 个失败案例 |
| 可砍 | SwinUNETR（只写文献综述部分） |
| 可砍 | ONNX 部署（用 PyTorch 测个耗时就行） |

**砍完之后项目描述改成：**

```
3D U-Net 与 nnU-Net 在肝肿瘤分割上的对比研究
```

**不要写「三架构对比」——说了三个只做两个，一问就穿帮。**
