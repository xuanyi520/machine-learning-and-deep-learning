## 一、完整流程

```
原始 DICOM / NIfTI
    │
    ├─① 读取           pydicom / nibabel / MONAI LoadImage
    ├─② 方向对齐       Orientation：统一到 RAS
    ├─③ 重采样         Spacing：统一到同一体素间距
    ├─④ 强度归一化     ScaleIntensityRange / Z-score
    ├─⑤ patch 裁剪     RandCropByPosNegLabel：正负样本平衡
    │
    ├─⑥ 训练           3D U-Net + Dice/CE 混合损失
    │
    ├─⑦ 滑窗推理       SlidingWindowInferer：整个体积切块推
    ├─⑧ 后处理         最大连通域 / 去小斑块
    └─⑨ 评估           Dice / IoU / HD95
```

**九步。下面逐个说，每步的代码都在这台机器上跑过。**

## 二、②③ 方向对齐与重采样

### 为什么必须重采样

**CT 的体素不是正方体。**

一张腹部 CT 常见参数：

```
层内间距：0.7 mm × 0.7 mm
层厚：5 mm

→ 一个体素是 0.7 × 0.7 × 5.0 mm 的长方体
```

**Z 方向比 XY 方向粗 7 倍。**

**后果：**

- 3D 卷积核在 Z 方向「看到」的范围是 XY 的 7 倍
- 模型会把不同方向当成不同重要性
- 同一个病人在不同机器上拍的 CT，层厚不一样，模型学的规律直接失效

**解决办法：全部重采样到 1mm × 1mm × 1mm。**

### 实测

```python
import torch
from monai.data import MetaTensor
from monai.transforms import Spacingd

# 一个 64×64×20 的体积，体素间距 0.7×0.7×5.0 mm
img = MetaTensor(
    torch.randn(1, 64, 64, 20),
    meta={"affine": torch.diag(torch.tensor([0.7, 0.7, 5.0, 1.0]))},
)

sp = Spacingd(keys=["image"], pixdim=(1.0, 1.0, 1.0), mode="bilinear")
out = sp({"image": img})

print(f"{tuple(img.shape)} -> {tuple(out['image'].shape)}")
```

**实际输出：**

```
(1, 64, 64, 20) -> (1, 45, 45, 96)
```

**怎么读这个结果：**

| 维度 | 原来 | 重采样后 | 变化 |
|---|---|---|---|
| XY | 64 × 64 | 45 × 45 | **变小**（0.7mm 采样到 1mm，像素变少） |
| Z | 20 层 | **96 层** | **变大 4.8 倍**（5mm 采样到 1mm，层数变多） |

**Z 方向从 20 层变成 96 层——这就是为什么 3D 分割这么吃显存。**

**一个 64×64×20 的小体积，重采样后变成 45×45×96，体素总数从 81,920 涨到 194,400，翻了 2.4 倍。**

### 代价

**插值会引入模糊。** 尤其是 Z 方向从 5mm「猜」到 1mm，多出来的 76 层全是插值算出来的，不是真实数据。

**所以重采样是 trade-off：**

```
不重采样 → 各向异性，模型学不好
重采样   → 各向同性，但 Z 方向有插值噪声
```

**nnU-Net 的选择是：重采样，但用三次样条插值（order=3）而不是线性，减少模糊。**

### 方向对齐

**在重采样之前还要做一件事：把图像方向统一。**

DICOM 里有个 `ImageOrientationPatient` 字段，不同机器拍出来的方向可能不一样（有的是仰卧头先进，有的是俯卧脚先进）。

```python
from monai.transforms import Orientationd

orient = Orientationd(keys=["image", "label"], axcodes="RAS")
```

**RAS 表示：R=右、A=前、S=上。** 统一到这个坐标系，扫描方向和像素坐标才有确定的对应关系。

**不做的后果：** 模型学到的「左下角」在不同病人身上指的是不同位置，训练会崩。

## 三、⑤ patch 裁剪：正负样本平衡

### 为什么不能整个体积喂进去

一个 512×512×200 的 CT，体素总数 5200 万。**8 GB 显存装不下。**

**必须切 patch。** 典型大小 96³ 或 128³。

### 为什么不能随机切

**肝脏占整张 CT 的体积大约 5%。**

**随机切 100 个 patch，有 95 个不含肝脏。** 模型看到的全是背景，会学成「全猜背景」。

**全猜背景的 Dice 是多少？0。**

**实测：**

```python
import torch
from monai.metrics import DiceMetric

pred = torch.zeros(1, 3, 32, 32, 32); pred[:, 0] = 1     # 全猜背景
gt   = torch.zeros(1, 3, 32, 32, 32); gt[:, 1, 8:24, 8:24, 8:24] = 1

dm = DiceMetric(include_background=False, reduction="mean")
dm(y_pred=pred, y=gt)
print(dm.aggregate().item())
```

**输出：**

```
0.0000
```

**注意 `include_background=False`。** 如果把背景也算进去，全猜背景的 Dice 会高达 0.95——**这就是模块 11 讲的「不能用像素准确率」的同一个坑。**

### 正负平衡裁剪

```python
from monai.transforms import RandCropByPosNegLabeld

crop = RandCropByPosNegLabeld(
    keys=["image", "label"],
    label_key="label",
    spatial_size=(32, 32, 32),
    pos=1,          # 含前景的 patch 数量
    neg=1,          # 全背景的 patch 数量
    num_samples=2,  # 每个体积取几个 patch
)
samples = crop({"image": img, "label": lab})
```

**实测输出：**

```
2 个 patch, 每个 (1, 32, 32, 32)
```

**`pos=1, neg=1` 的意思是：一半 patch 含前景，一半是纯背景。**

**为什么还要保留背景？** 因为模型也要学会「这里没有病灶」。全给前景，它会到处乱标。

**经验比例：**

| 任务 | pos:neg |
|---|---|
| 器官分割（前景占比高） | 1:1 |
| 肿瘤分割（前景占比极低） | 2:1 或 3:1 |
| 微小结节 | 4:1，甚至全正样本 |

### 一个 API 陷阱

**MONAI 1.6.1 里，`RandCropByPosNegLabel` 不接受 `keys` 参数，会报：**

```
TypeError: RandCropByPosNegLabel.__init__() got an unexpected keyword argument 'keys'
```

**带 `keys` 的是字典版 `RandCropByPosNegLabeld`——末尾多一个 `d`。**

**这个规律在 MONAI 里通用：**

| 版本 | 输入 |
|---|---|
| `XxxTransform` | 单个张量 |
| `XxxTransformd` | 字典 `{"image": ..., "label": ...}` |

**处理多模态数据一律用带 `d` 的版本。**

## 四、⑥ 3D U-Net

**结构和 2D 完全一样，只是把 `Conv2d` 换成 `Conv3d`。**

```python
import torch
from monai.networks.nets import UNet

net = UNet(
    spatial_dims=3,              # ← 关键，2 就是 2D
    in_channels=1,
    out_channels=3,              # 背景 + 肝脏 + 肿瘤
    channels=(16, 32, 64, 128),
    strides=(2, 2, 2),
    num_res_units=2,
)

x = torch.randn(2, 1, 64, 64, 64)
y = net(x)
print(x.shape, "->", y.shape)
print(f"参数量: {sum(p.numel() for p in net.parameters())/1e6:.2f} M")
```

**实测输出：**

```
(2, 1, 64, 64, 64) -> (2, 3, 64, 64, 64)
参数量: 1.19 M
```

**注意两件事：**

**① 输出和输入空间尺寸完全一致。** 分割任务必须这样——每个体素都要有个标签。

**② 参数量只有 1.19 M。** 比你的 MNIST 模型（42 万）大，但比 ResNet18（1100 万）小得多。

**分割模型的参数量普遍不大，因为大部分计算在特征图上而不是全连接层。**

### 显存估算

```python
# 粗略估算：每层特征图的显存
def estimate_memory(patch, channels, batch, dtype_bytes=4):
    total = 0
    c_in = 1
    for c in channels:
        n_voxels = patch ** 3 / (2 ** (2 * channels.index(c)))   # 每下采样一次除以 8
        total += batch * c * n_voxels * dtype_bytes
        c_in = c
    return total / 1024**3
```

**实际经验值（8 GB 显存，AMP 开启）：**

| patch size | batch size | 能不能跑 |
|---|---|---|
| 64³ | 4 | ✅ 轻松 |
| 96³ | 2 | ✅ 可以 |
| 96³ | 4 | ⚠️ 接近上限 |
| 128³ | 2 | ❌ 大概率 OOM |
| 128³ | 1 | ⚠️ 勉强 |

**先按这个表试，OOM 就降一档。**

## 五、⑥ 损失函数：Dice + CE 混合

**为什么不能只用 CrossEntropy：**

当肿瘤只占 1% 的体素时，CE 的梯度几乎全来自背景，模型学不到肿瘤。

**为什么不能只用 Dice：**

Dice 在训练初期梯度不稳定（预测和真实完全不相交时，Dice 恒为 0，没有梯度方向）。

**两者混合：**

```python
from monai.losses import DiceCELoss

loss_fn = DiceCELoss(
    include_background=False,     # 背景不参与 Dice 计算
    to_onehot_y=True,             # 标签是 (B,1,H,W,D)，内部转 onehot
    softmax=True,                 # 内部做 softmax
    lambda_dice=1.0,
    lambda_ce=1.0,
)
```

**`include_background=False` 很重要。** 背景占了 95% 的体素，算进去会让 Dice 虚高。

## 六、⑦ 滑窗推理

**训练用 96³ 的 patch，推理时整个 512×512×200 的体积怎么处理？**

**滑窗：用 96³ 的窗口一格格滑过去，重叠部分取平均。**

```python
from monai.inferers import sliding_window_inference

big = torch.randn(1, 1, 128, 128, 96)
with torch.no_grad():
    out = sliding_window_inference(
        big,
        roi_size=(64, 64, 64),
        sw_batch_size=2,
        predictor=net,
        overlap=0.5,
    )
print(big.shape, "->", out.shape)
```

**实测输出：**

```
torch.Size([1, 1, 128, 128, 96]) -> torch.Size([1, 3, 128, 128, 96])
```

**参数说明：**

| 参数 | 含义 |
|---|---|
| `roi_size` | 窗口大小，通常等于训练 patch |
| `sw_batch_size` | 一次推几个窗口（显存换速度） |
| `overlap` | 重叠比例，0.5 = 50% 重叠 |

**为什么要有重叠：**

```
不重叠： |--w1--|--w2--|     边界处的预测只被一个窗口看见
重叠：   |--w1--|
              |--w2--|      边界处被两个窗口都看见，取平均更稳
```

**代价：** `overlap=0.5` 意味着推理次数变成 2 倍（每个维度）。

```
三维全重叠 0.5 → 计算量约 8 倍
```

**所以推理比训练慢是很正常的。**

## 七、⑧ 后处理

**三种最常用，按顺序做：**

```python
import numpy as np
from scipy import ndimage

def postprocess(pred_mask, min_size=100, keep_largest=False):
    """pred_mask: (D,H,W) 的 0/1 掩码"""
    out = pred_mask.copy()

    # ① 填小洞：闭运算
    out = ndimage.binary_closing(out, structure=np.ones((3, 3, 3)))

    # ② 去小斑块
    labeled, n = ndimage.label(out)
    sizes = ndimage.sum(out, labeled, range(1, n + 1))
    for i, s in enumerate(sizes, 1):
        if s < min_size:
            out[labeled == i] = 0

    # ③ 只保留最大连通域（对单个器官有效）
    if keep_largest:
        labeled, n = ndimage.label(out)
        if n > 0:
            sizes = ndimage.sum(out, labeled, range(1, n + 1))
            out = (labeled == (np.argmax(sizes) + 1))

    return out
```

### 什么时候用哪一条

| 后处理 | 适用 | 不适用 |
|---|---|---|
| 填小洞 | 器官内部有血管造成的空洞 | 空洞是真实的（如坏死区） |
| 去小斑块 | 几乎所有情况 | —— |
| 只留最大连通域 | **肝脏、脾、肾**这类单发器官 | **转移瘤、多发病灶（会删掉真的）** |

**第三行是重灾区。** 用「只留最大」处理肝转移瘤，会把其他所有病灶全删掉，Dice 反而崩掉。

**这个错误很常见，因为它对肝脏分割效果很好，让人觉得「后处理真有用」，然后套到肿瘤上就翻车。**

## 八、⑨ 评估：Dice 之外还要看什么

```python
from monai.metrics import DiceMetric, HausdorffDistanceMetric

dice = DiceMetric(include_background=False, reduction="mean")
hd95 = HausdorffDistanceMetric(
    include_background=False, percentile=95, reduction="mean"
)

dice(y_pred=pred, y=gt)
hd95(y_pred=pred, y=gt)
print(f"Dice={dice.aggregate().item():.4f}  HD95={hd95.aggregate().item():.2f}")
```

**实测输出：**

```
Dice=0.2222  HD95=11.49
```

### 三个指标各自管什么

| 指标 | 管什么 | 数值 |
|---|---|---|
| **Dice** | 重叠度，整体像不像 | 0-1，越高越好 |
| **IoU** | 重叠度，更严格 | 0-1，通常比 Dice 低 |
| **HD95** | **边界距离**，边画得准不准 | 毫米，越低越好 |

**为什么不能只看 Dice：**

```
情况 A：Dice = 0.90，但边界在一个方向上系统性偏移 3mm
情况 B：Dice = 0.85，但边界随机分布，没有系统偏差

A 的 Dice 更高，但 A 的偏差在临床上更危险（比如放疗靶区）
```

**HD95 能抓到这种情况，Dice 抓不到。**

### 两个必须注意的坑

**坑一：空类别会产生 nan/inf**

```
UserWarning: the ground truth of class 2 is all 0, this may result in nan/inf distance.
```

**当一个类别在某些样本上完全不存在时，HD95 无法计算。**

**处理办法：**

```python
# 按类别分别算，跳过空类别
for cls in [1, 2]:
    present = [i for i in range(len(gts)) if gts[i][cls].sum() > 0]
    if present:
        ...
```

**或者用 `reduction="mean_batch"` 自己处理。**

**坑二：`include_background` 一定要设 False**

**设成 True 的话，全猜背景的 Dice 会是 0.95。** 这个陷阱模块 11 讲过，这里再强调一次。

## 九、跟着做

### 任务：搭一个能跑的 3D 训练脚本

**用假数据即可，重点是把流程跑通。**

```python
import torch
import numpy as np
from torch.utils.data import Dataset, DataLoader
from monai.networks.nets import UNet
from monai.losses import DiceCELoss
from monai.inferers import sliding_window_inference
from monai.metrics import DiceMetric

class Fake3DData(Dataset):
    """造一个带球体的假体积，用来验证流程"""
    def __init__(self, n=20, size=64):
        self.n, self.size = n, size

    def __len__(self):
        return self.n

    def __getitem__(self, i):
        rng = np.random.default_rng(i)
        img = rng.normal(0, 1, (1, self.size, self.size, self.size)).astype(np.float32)
        lab = np.zeros((1, self.size, self.size, self.size), dtype=np.int64)
        c = self.size // 2
        r = 10
        zz, yy, xx = np.ogrid[:self.size, :self.size, :self.size]
        ball = ((zz-c)**2 + (yy-c)**2 + (xx-c)**2) <= r**2
        lab[0][ball] = 1
        img[0][ball] += 2.0        # 病灶区域亮一点，让模型有东西可学
        return torch.from_numpy(img), torch.from_numpy(lab)

# ===== 训练 =====
device = "cuda"
model = UNet(spatial_dims=3, in_channels=1, out_channels=2,
             channels=(16, 32, 64), strides=(2, 2), num_res_units=2).to(device)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
loss_fn = DiceCELoss(include_background=False, to_onehot_y=True, softmax=True)
dl = DataLoader(Fake3DData(20, 64), batch_size=2, shuffle=True)
dice_metric = DiceMetric(include_background=False, reduction="mean")

for epoch in range(3):
    model.train()
    losses = []
    for img, lab in dl:
        img, lab = img.to(device), lab.to(device)
        opt.zero_grad()
        with torch.cuda.amp.autocast():
            out = model(img)
            loss = loss_fn(out, lab)
        loss.backward()
        opt.step()
        losses.append(loss.item())

    # 验证
    model.eval()
    dice_metric.reset()
    with torch.no_grad():
        for img, lab in dl:
            img, lab = img.to(device), lab.to(device)
            pred = sliding_window_inference(img, (64, 64, 64), 1, model)
            dice_metric(y_pred=pred, y=lab)
    d = dice_metric.aggregate().item()
    print(f"Epoch {epoch+1}  loss={np.mean(losses):.4f}  Dice={d:.4f}")
```

**预期输出（假数据，学一个球体应该很快）：**

```
Epoch 1  loss=0.6xxx  Dice=0.xxxx
Epoch 2  loss=0.3xxx  Dice=0.6xxx
Epoch 3  loss=0.2xxx  Dice=0.8xxx
```

**验收：**

- [ ] 三个 epoch 能跑完，不 OOM
- [ ] **Dice 在上升**（从 0 涨到 0.5 以上）
- [ ] 能打印每个 epoch 的显存峰值

**如果 Dice 一直是 0**，检查三件事：`include_background` 是不是 False、标签有没有做 onehot、模型输出通道数对不对。

## 十三、常见错误

| 错误 | 现象 | 原因 | 改法 |
|---|---|---|---|
| `RandCropByPosNegLabel` 传 keys | TypeError | 少了 `d` | 用 `RandCropByPosNegLabeld` |
| `include_background=True` | Dice 虚高到 0.95 | 背景占了 95% 体素 | 设 False |
| 不做重采样 | 层厚不同的数据学到的东西对不上 | 各向异性 | `Spacingd` |
| 不做方向对齐 | 训练不收敛 | 左右上下颠倒 | `Orientationd` |
| neg 取太大 | Dice 一直是 0 | 模型只见背景 | pos:neg 调平衡 |
| 只留最大连通域用在肿瘤上 | Dice 反而降 | 多发病灶被删 | 慎用 |
| 滑窗 overlap=0 | 块边界有接缝 | 边界只被一个窗口看到 | 0.5 起步 |
| 推理不开 no_grad | 显存爆 | 建了计算图 | 加 `torch.no_grad()` |

## 十四、下一节要干什么

你现在能自己搭一个 3D 分割了。**但它是「训练好一个模型，然后一直用它」。**

**如果换一个新器官、新病人，你能不能不给标签，直接让它圈出来？**

**下一节 18-3 讲 SAM 和 MedSAM——「提示式分割」。** 给一个点或者一个框，它就能把对应的器官分割出来，不需要为每个器官重新训练。
