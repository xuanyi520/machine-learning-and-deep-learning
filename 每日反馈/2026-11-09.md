## 学到的知识点

### 一、一个函数管训练和验证，靠 `train` 参数切换

以前写训练是两段代码：训练一段、验证一段，重复度很高。今天合成一个：

```python
def run_epoch(model, loader, train=True):
    model.train() if train else model.eval()
    total_loss, correct, total = 0.0, 0, 0

    ctx = torch.enable_grad() if train else torch.no_grad()
    with ctx:
        for xb, yb in loader:
            xb = xb.to(device)
            yb = yb.squeeze().long().to(device)

            if train:
                optimizer.zero_grad()

            out = model(xb)
            loss = criterion(out, yb)

            if train:
                loss.backward()
                optimizer.step()

            total_loss += loss.item() * xb.size(0)
            correct += (out.argmax(1) == yb).sum().item()
            total += xb.size(0)

    return total_loss / total, correct / total
```

**三处开关，全部由 `train` 一个参数控制：**

| 位置 | 训练时 | 验证时 | 为什么 |
|---|---|---|---|
| 第一行 | `model.train()` | `model.eval()` | 控制 Dropout 和 BatchNorm |
| `ctx` | `enable_grad()` | `no_grad()` | 验证不用建计算图，省一半显存 |
| 循环内 | 清零+反向+更新 | 都不做 | 验证不更新参数 |

**这样做的好处**：训练和验证走同一条代码路径，指标口径天然一致。以前分两段写，很容易一边除 batch 数、一边除样本数，两个数对不上。

### 二、`torch.no_grad()` 可以存进变量

以前只会这么写：

```python
if train:
    with torch.no_grad(): ...   # 反了，这是错的例子
```

今天的写法是把上下文管理器存成变量：

```python
ctx = torch.enable_grad() if train else torch.no_grad()
with ctx:
    ...
```

**`with` 后面不一定非要写死一个调用，任何上下文管理器对象都行。** 这样两个分支只写一遍循环体，不用复制粘贴。

### 三、损失要按样本数加权，不能按 batch 平均

```python
total_loss += loss.item() * xb.size(0)
```

**为什么乘 `xb.size(0)`：** `loss.item()` 是这一批的**平均**损失。最后一个 batch 只有 36 张（4708 = 73×64 + 36），如果每个 batch 直接平均，最后那批只有 64 张的零头，权重被高估了。

正确做法是先把每批的损失还原成总和（平均 × 张数），累加完再除以总张数：

```
平均损失 = 累加(每批平均损失 × 该批张数) / 总张数
```

**这就是"加权平均"**——样本多的 batch 权重大，样本少的权重小。

### 四、顺手核查发现一个 bug

第 174 行：

```python
return total_loss / loss, correct / total
```

**`loss` 是最后一个 batch 的损失张量，不是总样本数。** 应该写 `total_loss / total`。

用真实规模算一下差多少：

```
total_loss 累加值 = 平均损失 0.30 × 4708 = 1412.4
正确写法 total_loss / total = 1412.4 / 4708 = 0.3      ← 平均损失，对
现在写法 total_loss / loss  = 1412.4 / 0.31 = 4556.13  ← 数量级完全错
```

**而且返回值类型也不对**：`total_loss` 是浮点数，`loss` 是张量，除出来是个张量，不是数值。打印时会显示 `tensor(4556.13)`。

**这个 bug 现在还没暴露**，因为函数定义了但还没被调用。一旦写训练主循环，第一轮打印 loss 就会看到一个几千的数，而正常应该在 0.3 附近。

## 心得

**1. 参数化成函数，是"会写代码"和"能复用"的分界线**

之前每换一个数据集就要重抄一遍训练代码，改一处漏三处。今天抽成 `run_epoch`，换数据集只改外面那层 `for epoch` 循环。

**但我今天只走到一半。** 函数写完了，主循环没写——文件末尾就停在 `#训练` 这一行注释上。函数定义了不等于能用，必须被调用一次才算验证过。

**2. `train` 这一个参数，串起了三个不同层面的开关**

第一层是模型行为（Dropout），第二层是计算图（要不要存梯度），第三层是参数更新（要不要反向）。

**以前我把这三个当成三件独立的事，今天才看清它们其实是同一个问题的三个面：这一轮到底要不要学习。** 用同一个布尔量控制，就不会出现"切了 eval 但忘了 no_grad"这种半吊子状态。

**3. bug 是写出来的，不是读出来的**

`total_loss / loss` 这个错，读的时候一晃就过去了——两个变量名长得像，都是 loss 开头。但把它代进真实数字一算，立刻露馅：4556 对 0.3，差四个数量级。

**以后凡是写「总和 / 某个数」，都要问一句这个数是分母该有的东西吗。**
