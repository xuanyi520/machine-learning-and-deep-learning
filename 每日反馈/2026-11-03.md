### 二、同一份代码，两次跑结果不一样

| 次数 | Epoch 3 准确率 | loss |
|---|---|---|
| 第一次（10-31） | 98.66% | 0.0811 |
| 第二次（今天） | **98.80%** | 0.0802 |

代码一行没改，结果却不同。**随机性来自两处：网络权重的随机初始化、DataLoader 每轮的打乱顺序。**

想让结果可复现，要在训练前固定随机种子：

```python
torch.manual_seed(0)
```

**教训：报告里写的每个数字都必须能复现——不固定种子的准确率，明天重跑就变了。**

### 三、matplotlib 中文标题变方块的原因

画 loss 曲线时标题是中文，跑出一堆警告：

```
UserWarning: Glyph 31532 (\N{CJK UNIFIED IDEOGRAPH-7B2C}) missing from font(s) DejaVu Sans.
```

**原因**：matplotlib 默认字体 DejaVu Sans 只支持西文，不含汉字——所以不是乱码，是**缺字形**，每个汉字一个警告。

**修法**（画图前设置一次）：

```python
plt.rcParams['font.sans-serif'] = ['SimHei']   # 用黑体
plt.rcParams['axes.unicode_minus'] = False     # 修负号显示
```

### 四、DICOM 标签 = 编号 + 名字 + 值

DICOM 不只是图像，是**图像 + 一张巨大的信息表**。表里每个字段叫"标签（Tag）"，有固定的编号：

| 标签名 | 中文名 | 编号 |
|---|---|---|
| `PatientName` | 患者姓名 | (0010,0010) |
| `Modality` | 模态（设备类型） | (0008,0060) |
| `Rows` / `Columns` | 行数 / 列数 | (0028,0010/0011) |
| `PixelSpacing` | 像素间距 | (0028,0030) |
| `SliceThickness` | 层厚 | (0018,0050) |
| `RescaleSlope` / `RescaleIntercept` | HU 换算斜率 / 截距 | (0028,1053) / (0028,1052) |
| `WindowCenter` / `WindowWidth` | 窗位 / 窗宽 | (0028,1050/1051) |

**编号比名字更可靠**——名字理论上厂商可以改，编号是标准定死的。

## 心得

**1. 一个字母的错误，规模这么大了才发现**

`"cude"` 这个错从 10-31 一直活到今天。它不报错的原因是「那行没执行」——**没被执行的代码里藏着再离谱的错，程序也看起来很正常**。修掉之后立刻拿到两个回报：速度×10，以及第一次真正跑在 GPU 上。

**2. 98.66 → 98.80 不是进步，是波动**

一开始挺高兴"准确率又涨了"，想清楚之后才明白：代码没变，涨的 0.14% 只是随机性。**判断"改进有没有用"的唯一方法，是控制变量——改代码、固定种子、重跑。** 不然就是把噪声当信号。

**3. 警告不是报错，但也不是废话**

`Glyph missing` 警告刷了满屏，图还是画出来了，很容易直接无视。但它说明**中文标题实际没显示出来**——图拿去给别人看就是废的。以后看到 warning 至少要搞清楚它的影响是什么。
