## 学到的知识点

### 一、CNN 拆成两段写，比一整坨清楚

```python
class SmallCNN(nn.Module):
    def __init__(self, in_ch, n_cls):
        super().__init__()
        self.features = nn.Sequential(   # 这段负责"看图"
            nn.Conv2d(in_ch, 16, 3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
        )
        self.classifier = nn.Sequential( # 这段负责"下判断"
            nn.Flatten(),
            nn.Linear(32*7*7, 64),
            nn.ReLU(),
            nn.Linear(64, n_cls),
        )

    def forward(self, x):
        return self.classifier(self.features(x))
```

**`features` 和 `classifier` 是业界通用命名**，不是随便起的：

| 部分 | 干什么 | 输出形状 |
|---|---|---|
| `features` | 从像素里找边缘、纹理、形状 | `(N, 32, 7, 7)` |
| `classifier` | 根据这些特征判断是哪类 | `(N, n_cls)` |

**为什么拆两段**：以后要看"网络学到了什么"，直接取 `model.features` 的中间输出画图；要做迁移学习，也是把 `features` 换成预训练好的，只重训 `classifier`。**一开始写成两段，后面省事。**

### 二、形状一路算下来

```
输入            (N,  1, 28, 28)
Conv(1→16,p=1)  (N, 16, 28, 28)   padding=1 保住尺寸
MaxPool(2)      (N, 16, 14, 14)   砍一半
Conv(16→32,p=1) (N, 32, 14, 14)   通道翻倍，尺寸不变
MaxPool(2)      (N, 32,  7,  7)   再砍一半
Flatten         (N, 1568)         32×7×7 = 1568
Linear          (N, 64)
Linear          (N,  2)            normal 还是 pneumonia
```

**`nn.Linear(32*7*7, 64)` 里的 `32*7*7` 不是拍脑袋写的**，是顺着上面算下来的。**改网络结构就要跟着改这个数**，否则报形状不匹配——这是最常见的错。

### 三、参数量手算 vs 程序报的

| 层 | 算法 | 参数 |
|---|---|---|
| `Conv2d(1,16,3)` | 16×1×3×3 + 16（偏置） | 160 |
| `Conv2d(16,32,3)` | 32×16×3×3 + 32 | 4,640 |
| `Linear(1568,64)` | 1568×64 + 64 | 100,416 |
| `Linear(64,2)` | 64×2 + 2 | 130 |
| | **合计** | **105,346** |

程序输出 `参数量： 105346`。**完全一致。**

**这个核对很有用**：如果哪天手算和程序差了一个数量级，说明网络里某层写错了（比如漏了 `padding=1` 导致尺寸对不上）。

**顺便看清一件事：98% 的参数都在 `Linear(1568, 64)` 这一层。** 卷积层看着复杂，参数其实很少；真正占显存的是全连接层。这是后面做小模型优化时第一个该动的地方。

### 四、训练循环就是五步，反复念

```python
for epoch in range(5):
    model.train()                      # ① 切"训练模式"
    for xb, yb in train_loader:
        optimizer.zero_grad()          # ② 清空上次的梯度
        loss = criterion(model(xb), yb)# ③ 前向 + 算损失
        loss.backward()                # ④ 反向传播，求梯度
        optimizer.step()               # ⑤ 按梯度调参数
```

**顺序不能乱**。最容易漏的是第 ② 步——不清零的话，梯度会在上一个 batch 的基础上累加，训练直接废掉。

**记忆口诀：清空 → 前向 → 算损 → 反向 → 更新。**

### 五、train() 和 eval() 到底差什么

```python
model.train()   # 训练前切
model.eval()    # 验证前切
```

现在这个网络**没有 Dropout、没有 BatchNorm**，所以这两个函数其实不影响结果。**但还是要写**：

- 现在不写没感觉，一旦以后加了 `nn.Dropout` 或 `nn.BatchNorm2d`，忘了切就会出错
- 尤其是 `eval()`：BatchNorm 在训练时用当前 batch 的均值方差，在验证时用滑动平均；不切 `eval()` 验证结果会莫名其妙偏低
- 养成条件反射，比事后排查省时间

**`with torch.no_grad():` 同理**——验证阶段不更新参数，不需要存梯度，省一半显存、快一倍。不写也能跑，但白占资源。

### 六、结果怎么读：epoch 3 就到位了

```
Epoch1 验证准确率 = 0.7424
Epoch2 验证准确率 = 0.9160
Epoch3 验证准确率 = 0.9504
Epoch4 验证准确率 = 0.9485   ← 掉了
Epoch5 验证准确率 = 0.9504   ← 没涨
```

**关键观察：从第 3 个 epoch 起就在 0.95 附近晃，不再上升。**

这不是训练失败，是**已经收敛**。继续跑下去有两种可能：

- 运气好，在原地震荡
- 运气不好，开始**过拟合**（训练集准确率涨、验证集掉）

**结论：这个任务 3 个 epoch 就够了，跑 5 个是浪费。** 后面正式写训练脚本时，要做的是加**早停**——验证准确率连续几个 epoch 不涨就停。

`Epoch4` 掉了一点（0.9504 → 0.9485）是正常的批次噪声，验证集只有 524 张，错 1 张就是 0.19% 的波动。**524 张样本下，1% 以内的起伏都不用当回事。**

### 七、标签为什么要 squeeze 和 long

```python
yb = yb.squeeze().long().to(device)
```

三个动作各有原因：

| 动作 | 为什么 |
|---|---|
| `.squeeze()` | MedMNIST 标签形状是 `(N, 1)`，`CrossEntropyLoss` 要 `(N,)` |
| `.long()` | 标签必须是整数类型，不能是 float |
| `.to(device)` | 网络在 GPU 上，数据也得搬过去 |

**`CrossEntropyLoss` 的输入要求很死**：模型输出 `(N, C)` 的分数，标签 `(N,)` 的整数下标。**错一个就报 `Expected target size...` 那种错误**，以后见到这个报错先查标签形状。
