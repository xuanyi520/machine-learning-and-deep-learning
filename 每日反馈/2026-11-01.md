三个 epoch 里 loss 从 0.3019 掉到 0.0811，准确率从 97.83% 涨到 98.66%——**涨幅在变小**（+0.75% → +0.08%），说明开始接近这个网络结构的上限了。

### 二、参数量拆开看

| 层 | 参数量 | 占比 |
|---|---|---|
| Conv1 (1→32) | 320 | 0.08% |
| Conv2 (32→64) | 18,496 | 4.4% |
| **FC1 (3136→128)** | **401,536** | **95.2%** |
| FC2 (128→10) | 1,290 | 0.3% |
| **合计** | **421,642** | 100% |

**两个卷积层加起来才 18,816 个参数，第一个全连接层一个就吃掉 40 万。**

这就是「卷积省参数、全连接烧参数」的真实数字。跟之前算的 57 vs 4707 是同一件事，只是规模放大了。

### 三、数据加载的四个参数

```python
train_set = datasets.MNIST('./data', train=True, download=False, transform=transform)
```

| 参数 | 意思 |
|---|---|
| `'./data'` | 数据根目录，实际文件在 `./data/MNIST/raw/` |
| `train=True` | 取训练集（60000 张）；`False` 取测试集（10000 张） |
| `download=False` | 本地已有，不联网下载 |
| `transform=transform` | 每读一张图先预处理一遍 |

### 四、`transforms.ToTensor()` 干的三件事

1. **类型**：PIL Image → `torch.Tensor`
2. **维度**：`(H, W, C)` → `(C, H, W)`，通道提到最前（NCHW 约定）
3. **数值**：0–255 整数 → 0.0–1.0 浮点，dtype 变 `float32`

不加它，`ds[0]` 拿到的是 PIL 图片，直接喂 `model()` 会报类型错误。

### 五、六个 import 各自管什么

| 导入 | 作用 |
|---|---|
| `torch` | 张量、自动求导、设备迁移 |
| `torch.nn as nn` | 网络层、损失函数、`nn.Module` 基类 |
| `torch.optim as optim` | 优化器（SGD / Adam …） |
| `torchvision.datasets` | 数据集下载与读取 |
| `torchvision.transforms` | 图像预处理流水线 |
| `DataLoader` | 按 batch 迭代、打乱、并行读取 |
| `matplotlib.pyplot as plt` | 画 loss 曲线、看样本图 |

### 六、训练循环五步

```python
optimizer.zero_grad()              # ① 清空上一轮梯度
loss = criterion(model(xb), yb)    # ② 前向 + 算损失
loss.backward()                    # ③ 反向传播算梯度
optimizer.step()                   # ④ 按梯度更新参数
```

配合外层的 `model.train()` / `model.eval()` 开关。

## 心得

**1. 报错信息其实是在告诉你「第几行错了」**

第一版代码报了 `NameError: name 'transform' is not defined`。看起来莫名其妙，其实就是第 10 行 `transforms = transforms.ToTensor()` 多了个 s——变量名把模块名覆盖了，后面用 `transform` 自然找不到。

**回头看，这个错误一行一行读代码就能发现。但当时第一反应是"代码抄错了"，而不是"我这行写了什么"。**

**2. 不报错的错才最危险**

`nn.Linear(3126, 128)` 写成 3126（正确是 3136），语法完全合法，运行也过了模型定义那一行，直到真正 forward 时才炸：

```
RuntimeError: mat1 and mat2 shapes cannot be multiplied (64x3136 and 3126x128)
```

**这类「数字写错」的错，靠肉眼几乎查不出来，只能靠形状推。** 记住 64×7×7=3136，改网络结构时重新算一遍。

**3. 参数量表比任何解释都直观**

421,642 这个总数没什么感觉。拆成四行之后，401,536 那一行一眼就能看出问题——**95% 的参数都堆在展平后接的第一个全连接层上。**

这也解释了为什么 ResNet 后来用全局平均池化（`AdaptiveAvgPool2d(1)`）替代全连接：把 7×7 压成 1×1，参数直接从 40 万降到 128×类别数。

**4. 训练准确率涨得慢，不一定是模型不行**

三个 epoch 从 97.83% 到 98.66%，涨幅一路收窄。这时候继续堆 epoch 收益很小，该换方向了——加卷积层、加数据增强，或者干脆换个更强的结构。

**这是第一次真实体会到「什么时候该停」这个判断。**
