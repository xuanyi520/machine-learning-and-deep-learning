### 二、从 loss 曲线读出过拟合的起点

完整 10 轮：

```
             train loss    val loss    gap
Epoch  1      0.3010       0.1711      —
Epoch  2      0.1513       0.1293      —
Epoch  3      0.1333       0.1252      —
Epoch  4      0.1219       0.1169      —
Epoch  5      0.1110       0.1089      —
Epoch  6      0.0993       0.0924      —
Epoch  7      0.0913       0.0972      +0.0059  ← val loss 首次回升
Epoch  8      0.0866       0.0850      —        ← 最好（acc 0.9676）
Epoch  9      0.0854       0.0866      +0.0012
Epoch 10      0.0735       0.0883      +0.0148  ← 差距突然拉开
```

**判断过拟合的两个信号：**

| 信号 | 第 10 轮的表现 |
|---|---|
| train loss 还在降 | 0.0854 → 0.0735，降了 0.012 |
| val loss 开始升 | 0.0866 → 0.0883，涨了 0.002 |
| **两者差距扩大** | 从 0.0012 拉到 0.0148 |

**结论：模型从第 9 轮开始背训练集了。**

**如果只训 8 轮，会拿到更好的模型。**

**这验证了一件事：轮数不是越多越好，要多到「验证集开始变差」之前为止。**

### 三、getattr 有两种写法，用途完全不同

**写法一：带第三个参数（防崩）**

```python
getattr(ds, 'SliceThickness', '该文件没有')
```

DICOM 文件的标签是**不一定齐**的。同一个标签，有的文件有，有的没有。直接写 `ds.SliceThickness`，碰上缺标签的文件会抛 `AttributeError`，整个程序崩掉。

**写法二：不带第三个参数（动态取类）**

```python
DataClass = getattr(medmnist, info['python_class'])
```

这里的目的是**把字符串变成类**。

### 四、getattr 最危险的地方：拼错不报错

实测：

```
拼对  RescaleSlope  ->  1
拼错  RescaleSlop   ->  1     ← 不报错，静默给了默认值
```

**差一个字母，程序照样跑，结果悄悄错了。**

**我在单元 70 的注释里已经写过这个问题：**

> 拼错时 getattr 静默返回默认值，算出来的数看着像 HU，其实等于没换算

**这是 `getattr` 把「写错代码」变成「运行时静默错误」。**

**改进办法：关键的换算参数，用 `in` 判断而不是 `getattr`。**

```python
if 'RescaleSlope' not in ds:
    print("⚠️ 缺少换算参数，算出来的不是 HU")
```

**区别：`getattr` 默认值让程序沉默，`in` 判断让程序主动说话。**

### 五、`python_class` 存的是「类名」，不是类

```python
info['python_class'] = 'PneumoniaMNIST'     # 类型是 str
```

**它就是一个普通字符串。**

**为什么必须存字符串：**

| 如果存类对象 | 问题 |
|---|---|
| 循环导入 | `INFO` 在 `__init__.py`，类在 `dataset.py`，互相 import |
| 导入变慢 | 光是 `from medmnist import INFO` 就要加载所有类 |

**它解决的是「字典里的名字」到「代码里的类」之间的转换问题。**

```
字符串 'pneumoniamnist'
   ↓ 查 INFO 字典
档案 {'python_class': 'PneumoniaMNIST', ...}
   ↓ getattr
真正的类 <class 'medmnist.dataset.PneumoniaMNIST'>
```

**用 if/else 硬编码也能实现，但换数据集要改代码，而且新加数据集不会自动支持。**

## 心得

### 1. 判断过拟合不能只看一个数

**我一开始只知道「val loss 上升就是过拟合」。**

**但看完 10 轮才发现，val loss 不是单调上升的——第 7 轮升了，第 8 轮又降回去。**

**真正的信号是「三条线一起看」：**

```
train loss 在降 + val loss 在升 + 差距在扩大  →  才是过拟合
```

**只看其中一条都会被误导。**

第 7 轮 val loss 升了一点，如果那时就停，会错过第 8 轮更好的结果。第 10 轮 train loss 降得最多（0.0735），但那是过拟合最深的时候。

**所以「loss 低了」不等于「模型好了」。**

### 2. 同一行代码，在不同上下文里意思完全不同

**`getattr(ds, 'X', '无')` 和 `getattr(medmnist, 'PneumoniaMNIST')` 长得几乎一样，但目的完全相反：**

| 写法 | 目的 | 找不到时 |
|---|---|---|
| 带默认值 | 容忍缺失 | 用默认值顶替 |
| 不带默认值 | 动态查找 | 抛异常 |

**第一个是「我知道可能没有，给它个兜底」。**

**第二个是「我确信有，只是名字是运行时才确定的」。**

**如果反过来用——该报错的地方给了默认值，bug 就被藏起来了。**

### 3. 数据结构和代码结构是两回事

**`INFO` 里存不了类，只能存类名。**

**这不是 MedMNIST 的设计缺陷，是所有「配置数据」的共性：**

```
配置文件里只能放「值和字符串」，不能放「活的对象」
```

**所以才有 `getattr`、`importlib.import_module`、注册表这些东西。**

**这是「数据」和「代码」之间的一道墙，`getattr` 是墙上的一扇门。**
