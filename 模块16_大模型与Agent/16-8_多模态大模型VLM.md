## 一、VLM 是什么

**Vision-Language Model，视觉语言模型。就是「能看图的对话模型」。**

### 和你的 CNN 的区别

| | 你的肺炎分类模型 | VLM |
|---|---|---|
| 输入 | 一张图 | 图 + 文字 |
| 输出 | 一个概率 | **一段话** |
| 训练目标 | 分类准确 | 预测下一个词 |
| 能回答没见过的问题吗 | **不能** | 能（但可能编） |
| 参数 | 42 万 | 几千亿 |

**关键区别在最后两行。**

> **你的模型只会回答「这张图有多大概率是肺炎」。VLM 能回答「这张图上有什么异常、在哪里、像什么」。**
>
> **但它也可能编。**

---

## 二、图片怎么变成 token

**模型不认识像素，只认识 token。所以图片要先编码成一串 token。**

```
一张 1024×1024 的图
    ↓ 切成小块（patch），比如 14×14
    ↓ 每块编码成一个向量
    ↓ 再映射成 token
约 1000-5000 个 token
```

**这就是为什么图片很贵。**

### 实测的成本参照

| 图片 | 文件大小 | input_tokens |
|---|---|---|
| 你的 HU 速查表（PNG） | 297 KB（base64 后） | **1022** |

**对比一下：**

```
一张图 ≈ 1000 token ≈ 700-1000 个汉字
```

**一张 512×512 的 CT 切片，大约等同于让模型读 800 字。**

**如果你给 10 张图，就是 8000 token——已经接近一半的普通对话长度了。**

## 三、怎么调用

### 代码

```python
import os, base64, requests

def ask_with_image(image_path: str, question: str, max_tokens=1500) -> str:
    with open(image_path, "rb") as f:
        b64 = base64.b64encode(f.read()).decode()

    ext = image_path.lower().rsplit(".", 1)[-1]
    media_type = {"png": "image/png", "jpg": "image/jpeg",
                  "jpeg": "image/jpeg", "webp": "image/webp"}[ext]

    r = requests.post(
        "https://api.deepseek.com/anthropic/v1/messages",
        headers={
            "x-api-key": os.environ["DEEPSEEK_API_KEY"],
            "anthropic-version": "2023-06-01",
            "content-type": "application/json",
        },
        json={
            "model": "deepseek-flash",
            "max_tokens": max_tokens,          # ← 见下面的坑
            "temperature": 0,
            "messages": [{
                "role": "user",
                "content": [
                    {"type": "text", "text": question},
                    {"type": "image", "source": {
                        "type": "base64",
                        "media_type": media_type,
                        "data": b64,
                    }},
                ],
            }],
        },
        timeout=180,
    )
    d = r.json()
    if r.status_code != 200:
        return f"请求失败 {r.status_code}: {d}"

    return "".join(b["text"] for b in d["content"] if b["type"] == "text")
```

### 三个必须注意的点

**① `max_tokens` 要给足 —— 我在这里栽过**

**第一次我给了 `max_tokens=300`，结果：**

```
stop_reason: max_tokens
content 块类型: ['thinking']        ← 没有 text 块！
output_tokens: 300
```

**300 个 token 全被 `thinking` 吃光了，一个字的回答都没剩下。**

**这是推理模型看图时的常态**：它要花几百个 token 分析图像，然后才能开口。

**给 1500 起步。** 看到 `stop_reason == "max_tokens"`，就是不够。

**② 顺序：文字在前，图在后**

```python
"content": [
    {"type": "text", "text": question},    ← 先
    {"type": "image", ...},                ← 后
]
```

**反过来的话，模型有时会先描述图再回答，但更容易跑偏到「这张图是什么」而不是「回答我的问题」。**

**③ `media_type` 必须对**

```
png  → image/png
jpg  → image/jpeg
```

**写错会 400，而且报错信息不明显。**

## 四、医学影像的四道坎

**这一节是重点。VLM 在医学影像上有四个绕不过去的问题。**

### 坎一：它没怎么见过医学影像

**训练数据以互联网图文为主。医学影像占比很小。**

后果：

| 你问 | 它可能回答 |
|---|---|
| 这张 CT 上肝右叶有什么异常 | 编一个「低密度灶」 |
| 这个结节的密度是多少 HU | **它给不了 HU**（HU 是原始数据的事，不是像素） |

**关键区别：**

```
你给它的图，是「经过窗宽窗位映射后、8 位量化的显示图像」
       ↓
      HU 信息已经丢了
       ↓
模型看到的只是灰度，它没法反推回 HU
```

**这就是为什么 4-1 讲窗宽窗位那么重要。** **给模型看的图，取决于你用什么窗。**

### 坎二：它不能精确测量

**「这个结节直径多少毫米」——它答不了。**

**它只能看相对大小，不能量。** 而且它不知道你的像素间距是多少（那个信息在 DICOM 头里，不在图里）。

**任何需要测量的，必须用你的 CNN / 传统算法做。**

### 坎三：它会对没病的地方说有病

**医学的"正常"是长尾的。** 正常人的肺、肝、骨，形态差异极大。

**VLM 没见过足够多的正常样本，会把正常变异说成异常。**

**后果：假阳性率高。** 这在临床上意味着「医生要花时间看一堆没问题的片子」——直接导致系统被弃用。

### 坎四：它不能出诊断

**法律层面。**

现行规定下，**AI 不能出具诊断报告**。它只能做「辅助提示」。

**你的系统输出必须是「提示」「疑似」，不能是「诊断」。**

这一条在面试里可以加分——很多候选人不知道。

## 五、那它到底能干什么

**不是不能用，是要用对地方。**

| 能做 | 不能做 |
|---|---|
| 把影像描述文字转成结构化字段 | 从像素判断病灶性质 |
| 根据你的模型输出，写一段解释 | 替代你的分类模型 |
| 解释医学概念、术语 | 给出精确测量值 |
| 把你检索到的指南和病例关联起来 | 独立出具诊断 |
| 生成报告草稿，供医生修改 | 直接给患者看 |

**最好的用法：**

```
你的 CNN 出客观结论（概率、位置、大小）
        ↓
VLM 负责把它翻译成人话，并结合指南解释
        ↓
医生审核修改
```

**分工明确。CNN 管「是什么、多大、在哪」，VLM 管「怎么解释」。**

**这就是你毕业项目的架构。**

### 任务二：测出它的边界

**准备四个问题，看它哪些能答、哪些答不了：**

| 问题 | 期望 |
|---|---|
| 这张图上肝脏的位置在哪 | 能答（相对位置） |
| 这个病灶的 CT 值是多少 HU | **应该答不了** |

### 任务三：DICOM → 图 → 模型

**完整链路：**

```python
import pydicom
import numpy as np
from PIL import Image

def dicom_to_image(path, window_width, window_level):
    ds = pydicom.dcmread(path)
    hu = ds.pixel_array.astype(float) * float(ds.RescaleSlope) + float(ds.RescaleIntercept)

    lo = window_level - window_width / 2
    hi = window_level + window_width / 2
    img = np.clip((hu - lo) / (hi - lo) * 255, 0, 255).astype(np.uint8)
    return Image.fromarray(img).convert("RGB")

# 肺窗
img = dicom_to_image(r"CT_small.dcm", 1500, -600)
img.save("lung_window.png")
print(ask_with_image("lung_window.png", "这张影像上能看到什么？"))
```

**验收：**

- [ ] 能用你机器上的 DICOM 文件跑通整条链路
- [ ] 肺窗和骨窗给出的描述**不一样**（证明窗真的起作用了）
- [ ] 回答里没有出现 HU 数值（出现了就是编的）

### 练习 16-8-D（选做）：结构化输出 + 影像

**结合 16-2 的成果：让模型看影像，输出 JSON（而不是自然语言）。**

```json
{
  "可见结构": ["肺野", "纵隔", "膈肌"],
  "疑似异常": [{"位置": "右肺下叶", "描述": "斑片状高密度影", "置信度": "中"}],
  "无法判断": ["病灶CT值", "病灶直径"],

```

**「无法判断」这个字段很有用，强迫它承认边界。**

## 十、常见错误

| 错误 | 表现 | 改法 |
|---|---|---|
| `max_tokens` 太小 | 空回答，`stop_reason: max_tokens` | 1500 起步 |
| `media_type` 写错 | 400 错误 | png 对应 image/png |
| 指望它给 HU | 编一个数字 | HU 必须从 DICOM 原始数据算 |
| 用它替代分类模型 | 假阳性一片 | CNN 管判断，VLM 管解释 |
| 输出措辞写成「诊断为」 | 法律风险 | 改「提示」「疑似」 |
| 只给一张窗图 | 结论片面 | 多个窗一起看 |
