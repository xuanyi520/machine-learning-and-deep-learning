# 16-4 RAG 检索增强生成

**建议用时：12 小时**

**出口标准：能搭一个带引用溯源的本地知识库问答，回答里每条结论都能指到原文第几段。**

---

## 〇、这一节在解决什么

16-1 讲过：**模型没有「我不知道」这个选项，它编。**

16-3 讲了你给它写函数。但真实场景是这样的：

```
你有一份 200 页的《原发性肝癌诊疗指南》
用户问：III 期肝癌的推荐治疗方案是什么？
```

**你不可能把 200 页的每一条都写成函数。**

正确做法：**先把相关的那几段找出来，再连同问题一起发给模型。**

这个思路叫 **RAG（Retrieval-Augmented Generation，检索增强生成）**。

**一句话：先查资料，再回答。查的是你自己的资料。**

---

## 一、RAG 的四个环节

```
        ┌─────────────────── 离线做一次 ───────────────────┐
        │                                                   │
  文档 ──▶ ① 切分 ──▶ ② 建索引（把所有片段变成向量/词频） │
        │                                                   │
        └───────────────────────────────────────────────────┘
                                    │
                               索引存在硬盘
                                    │
        ┌─────────────────── 每次提问都做 ─────────────────┐
        │                                                   │
  问题 ──▶ ③ 检索（在索引里找最相关的几段）                 │
        │                                                   │
        └───────────────────────────────────────────────────┘
                                    │
                     找到的几段 + 原问题一起发给模型
                                    │
                                    ▼
                              ④ 生成答案 + 标出处
```

**四个环节，每一环都会失败。** 这一节的重点不是「怎么搭起来」，是「怎么知道哪一环坏了」。

### 每一环的典型失败

| 环节 | 典型失败 | 现象 |
|---|---|---|
| **切分** | 一个完整的句子被切成两半 | 检索到的片段读不懂 |
| **建索引** | 医学缩写没做归一 | 搜「HCC」找不到「肝细胞癌」 |
| **检索** | 只按字面匹配 | 搜「肝肿瘤」找不到「肝脏占位」 |
| **生成** | 模型自己加料 | 答案里有原文没有的内容 |

**记住这张表。后面每一节都会回来用它。**

---

## 二、切分：RAG 里最容易搞砸的一步

### 为什么必须切

**三个理由：**

1. **上下文窗口有限**：200 页塞不进去
2. **检索需要粒度**：整篇文档当一条，检索出来整篇，模型还得自己找
3. **准确性**：给模型 3 段相关的，比给它 200 页让它自己找，准得多

### 三种切法

| 切法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **固定长度** | 每 500 字切一段 | 简单 | 经常从句子中间切断 |
| **按段落** | 按空行/换行切 | 语义完整 | 段落长短差异极大 |
| **按结构** | 按标题层级切 | 保留上下文 | 需要文档有清晰结构 |

### 推荐：按结构切 + 重叠

```python
def split_by_heading(text, max_chars=800, overlap=100):
    """按 markdown 标题切，超长的再按长度切"""
    import re
    chunks, buf = [], ""
    for line in text.splitlines(keepends=True):
        if re.match(r"^#{1,4}\s", line) and buf.strip():
            chunks.append(buf)
            buf = ""
        buf += line
    if buf.strip():
        chunks.append(buf)

    # 超长的还是得硬切，但要带重叠
    final = []
    for c in chunks:
        if len(c) <= max_chars:
            final.append(c)
        else:
            for i in range(0, len(c), max_chars - overlap):
                final.append(c[i:i + max_chars])
    return final
```

### 重叠（overlap）为什么重要

```
不重叠：                      重叠 100 字：
|----段A----||----段B----|    |----段A----|
              ↑                              |----|
          这里切断                 ↑ 这段同时属于A和B
```

**一个结论可能横跨两段。重叠让它在两边都完整出现。**

**经验值**：`overlap` 取 `max_chars` 的 10%-20%。太小没用，太大重复检索浪费钱。

### 一条容易被忽略的规矩

**在每个片段的开头，拼上它的「路径」。**

```python
chunk = f"【来源：{doc_name} > {heading}】\n{content}"
```

**为什么**：切碎之后，「该指标应控制在 7 ng/mL 以下」这句话单独看，你不知道说的是 AFP 还是 CEA。

**带上标题路径，片段自己就说得清楚了。**

## 三、先做一个零依赖的版本

**不装任何向量库，用 TF-IDF + numpy 余弦相似度。**

**为什么先做这个**：你能看懂每一行。等你装了向量库，也知道它在底层干什么。

### 完整可跑代码

```python
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

# ---------- 假的知识库（换成你自己的 txt）----------
DOCS = [
    "【来源：肝癌诊疗指南 > 诊断】甲胎蛋白 AFP 是原发性肝癌最常用的血清标志物。"
    "参考上限为 7 ng/mL，超过 400 ng/mL 高度提示肝癌。",

    "【来源：肝癌诊疗指南 > 分期】BCLC 分期将肝癌分为 0、A、B、C、D 五期。"
    "C 期对应门静脉侵犯或肝外转移，推荐系统治疗。",

    "【来源：肝癌诊疗指南 > 治疗】早期肝癌首选手术切除或局部消融。"
    "中晚期可考虑经动脉化疗栓塞（TACE）、靶向药物和免疫治疗。",

    "【来源：影像手册 > CT】肝脏 CT 常用肝窗，窗宽 160 HU，窗位 60 HU。"
    "此设置下肝实质与病灶对比最清晰。",

    "【来源：影像手册 > 肺炎】肺部感染在 CT 上多表现为斑片状或大片状高密度影，"
    "边界模糊，常伴空气支气管征。",
]

# ---------- 建索引 ----------
class SimpleRAG:
    def __init__(self, docs):
        self.docs = docs
        # analyzer='char': 中文不分词，直接按字切
        # ngram_range=(2,3): 同时看两个字和三个字的组合
        self.vec = TfidfVectorizer(analyzer="char", ngram_range=(2, 3))
        self.matrix = self.vec.fit_transform(docs)

    def search(self, query, top_k=2):
        q = self.vec.transform([query])
        sims = cosine_similarity(q, self.matrix)[0]
        idx = np.argsort(sims)[::-1][:top_k]
        return [(int(i), float(sims[i]), self.docs[i]) for i in idx if sims[i] > 0]

rag = SimpleRAG(DOCS)

for q in ["肝癌怎么分期", "肺部的CT窗宽多少", "AFP 多高算高"]:
    print(f"\n【问题】{q}")
    for i, s, d in rag.search(q):
        print(f"  相似度 {s:.3f} | {d[:60]}...")
```

### 实际输出（我本机跑的）

```
【问题】肝癌怎么分期
  相似度 0.301 | 【来源：肝癌诊疗指南 > 分期】BCLC 分期将肝癌分为...

【问题】肺部的CT窗宽多少
  相似度 0.330 | 【来源：影像手册 > CT】肝脏 CT 常用肝窗，窗宽 160 HU...
```

**看到问题了吗？**

第二个问题问的是**肺部**，检索出来的却是**肝脏**的 CT。因为两句话里都有「CT」「窗宽」。

**这就是词面匹配的局限。**

## 四、词面匹配 vs 语义匹配

### 问题的本质

| 提问 | 文档里写的 | TF-IDF 能找到吗 |
|---|---|---|
| 肝肿瘤怎么治 | 原发性肝癌的治疗 | **找不到**（字不全一样） |
| 这个指标高了 | AFP 升高提示…… | 找不到 |
| 肺部 CT 窗宽 | 肝脏 CT 窗宽 | **找到了，但是错的** |

**原因：TF-IDF 比的是「字面重叠度」，不是「意思像不像」。**

### 语义检索：把句子变成向量

**核心思想：把每段文字映射成一个高维向量，意思相近的向量距离近。**

```
"肝肿瘤怎么治"     → [0.21, -0.55, 0.83, ...]  ┐
                                                 ├ 距离近
"原发性肝癌的治疗"  → [0.19, -0.51, 0.79, ...]  ┘

"肺部CT窗宽"       → [-0.44, 0.12, 0.31, ...]  ← 距离远
```

**做这件事的模型叫 embedding 模型。**

import numpy as np

model = SentenceTransformer(
    "BAAI/bge-small-zh-v1.5",
    cache_folder=r"F:\AI学习环境\models",
)

doc_vecs = model.encode(DOCS, normalize_embeddings=True)

def semantic_search(query, top_k=2):
    qv = model.encode([query], normalize_embeddings=True)
    sims = (qv @ doc_vecs.T)[0]              # 归一化后，点积就是余弦相似度
    idx = np.argsort(sims)[::-1][:top_k]
    return [(int(i), float(sims[i]), DOCS[i]) for i in idx]
```

**用本节前面那三条假数据，查「肝肿瘤怎么治」：**

```

  0.6020  AFP 升高提示肝癌
  0.4145  肺部感染表现为斑片状高密度影

**看第三行。** 用 TF-IDF 时，「肝囊肿」和「肺部感染」会打平——它们和「肝肿瘤怎么治」都没有字面重叠。

**这就是「换说法也能找到」。**

**这一行是性能优化，但不是必须的。忘了它结果也不会错，只是要自己算余弦。**

### 什么时候还需要 TF-IDF

**别急着把 TF-IDF 扔掉。** 真实系统里常常两个一起用：

| 方法 | 强项 | 弱项 |
|---|---|---|
| TF-IDF / BM25 | **精确词命中**（药名、编号、缩写） | 同义词、换说法 |
| 语义检索 | 换说法能找到 | **专有名词容易漂** |

**混合检索（Hybrid）**：两路各取前 10 条，合并去重，再一起排序。

**医学场景强烈建议混合**，因为药名和缩写必须精确匹配——「吉西他滨」和「健择」是同一种药，但语义模型不一定知道；而「AFP」和「甲胎蛋白」TF-IDF 也匹配不上。

## 五、重排序：让最相关的排到最前面

### 为什么需要

**检索（embedding）是「粗排」**：快，但不够准。

**重排序（rerank）是「精排」**：用一个更慢更准的模型，给前 20 条重新打分，取前 3 条。

```
检索出 50 条  →  重排  →  取前 3 条给模型
       ↑ 快但糙              ↑ 慢但准
```

**为什么值得多这一步**：给模型的上下文越干净，答案越准。塞 10 条噪音进去，模型会被带偏。

**零成本的做法**：用大模型自己打分。

```python
def rerank(query, candidates):
    scored = []
    for doc in candidates:
        prompt = f"""判断这段资料能否回答这个问题。只输出 0-10 的一个数字。

问题：{query}
资料：{doc}

分数："""
        # 调模型，temperature=0
        s = int(call_model(prompt).strip())
        scored.append((s, doc))
    return [d for s, d in sorted(scored, reverse=True)]
```

**代价**：每条一次调用。20 条就是 20 次。**钱要算清楚。**

## 六、引用溯源：医疗场景的硬要求

### 为什么必须做

```
不许溯源的回答：  "III 期肝癌推荐系统治疗。"
```

**医生说：依据呢？** 答不上来 = 不可用。

```
带溯源的回答：    "III 期肝癌推荐系统治疗。
                 【依据：肝癌诊疗指南 2022版 > 第 5.3 节 系统治疗】"
```

**医生能自己去核对。** 这才是能进临床讨论的东西。

### 实现

**检索到的每个片段都带来源，生成时要求模型在结论后面标注。**

```python
context = "\n\n".join(
    f"[{i+1}] {doc}" for i, (_, _, doc) in enumerate(hits)
)

prompt = f"""根据下面的资料回答问题。

要求：
1. 只根据资料回答，资料里没有的不要编
2. 每条结论后面用方括号标注资料编号，如 [1]
3. 如果资料不足以回答，直接说「资料中未找到相关内容」

资料：
{context}

问题：{query}

回答："""
```

### 一个必须检查的失败

**模型可能标了一个不存在的编号，或者把 [1] 标在错误的位置上。**

**要验证：**

```python
import re
cited = set(int(x) for x in re.findall(r"\[(\d+)\]", answer))
assert cited <= set(range(1, len(hits)+1)), f"引用了不存在的编号: {cited}"
```

## 七、评估：怎么知道你这套 RAG 是好是坏

**这是最容易跳过、也最重要的一节。**

### 分两段评估

| 段 | 指标 | 怎么算 |
|---|---|---|
| **检索** | 命中率 Recall@K | 标准答案所在的片段，有没有出现在前 K 条里 |
| **生成** | 答对率、幻觉率 | 人工看，或者用另一个模型判 |

**先测检索。** 检索错了，生成再准也没用——它拿的就是错资料。

### 做一个小测试集

**20 条够用了。** 格式：

```python
TESTS = [
    {"q": "AFP 超过多少提示肝癌",
     "answer_chunk_id": 0},          # 答案在第 0 个片段
    {"q": "BCLC 分几期",
     "answer_chunk_id": 1},
    {"q": "肝窗的窗宽窗位",
     "answer_chunk_id": 3},
]
```

### 算 Recall@K

```python
def evaluate(rag, tests, k=3):
    hit = 0
    for t in tests:
        ids = [i for i, s, d in rag.search(t["q"], top_k=k)]
        if t["answer_chunk_id"] in ids:
            hit += 1
    return hit / len(tests)

print(f"Recall@3 = {evaluate(rag, TESTS):.2%}")
```

**经验值：**

| Recall@3 | 说明 |
|---|---|
| < 60% | 切分或索引有问题，先别调生成 |
| 60-80% | 能用，但值得加混合检索或重排序 |
| > 85% | 可以调生成部分了 |

### 四个失败环节怎么定位

**回到第一节那张表：**

```
现象：回答得很像，但细节是错的
    ↓
先看检索到的片段
    ├─ 片段里没有正确答案 → 检索问题（回到切分/索引）
    └─ 片段里有正确答案，模型没用上 → 生成问题（改提示词/换模型）
```

**这个判断顺序要养成习惯。** 90% 的人第一反应是调提示词，其实一半的问题在检索。

同一份文档，用三种 `max_chars`（300 / 800 / 2000）各跑一次，算 Recall@3。

**填表：**

| max_chars | 片段数 | Recall@3 |
|---|---|---|
| 300 | | |
| 800 | | |
| 2000 | | |

**结论写一句话：太长和太短分别坏在哪？**

### 练习 16-4-B（必做）：词面 vs 语义

准备 10 个问题，其中 5 个是「换说法」的（比如问「肝肿瘤怎么治」，文档写的是「原发性肝癌的治疗」）。

**分别用 TF-IDF 和 embedding 各跑一次，对比 Recall@3。**

**如果没装 sentence-transformers，先只统计 TF-IDF 错在哪几条、错的原因是什么。**

### 练习 16-4-C（必做）：制造一次幻觉

**故意删掉知识库里包含答案的那一段**，然后问那个问题。

**观察：它是说「未找到」，还是编一个答案？**

**如果编了，就加一条更硬的约束再试：**

```
资料中没有明确说明的，一律回答「资料中未找到相关内容」。
不允许根据常识或推理补充。
```

### 练习 16-4-D（选做）：混合检索

TF-IDF 取前 10，embedding 取前 10，合并去重后按「两边排名的平均值」排序。

**对比混合检索和单路的 Recall@3。**

## 十二、常见错误

| 错误 | 表现 | 改法 |
|---|---|---|
| 整篇文档当一个片段 | 检索出来一大坨，模型抓不住重点 | 切到 500-800 字 |
| 不加重叠 | 关键句被切断 | overlap 取 10-20% |
| 片段不带来源 | 溯源无从谈起 | 开头拼标题路径 |
| 中文用默认分词 | TF-IDF 效果极差 | `analyzer="char", ngram_range=(2,3)` |
| 只测生成不测检索 | 一直调提示词，怎么都不对 | 先算 Recall@k |
| 提示词没写「不知道就说不知道」 | 编 | 明确禁止补充 |
| 把重排结果当检索结果 | 召回本来就低，重排救不回来 | 先修召回 |

## 十三、下一节要干什么

你现在有一个能查资料的系统了。但它是「一问一答」——**只走一次检索，然后回答。**

**真实的任务往往需要好几步：**

```
查指南 → 发现要查分期 → 根据分期再查治疗 → 发现要查药物相互作用
```

**每一步用什么工具、下一步该干什么，都不是你写死的，得它自己决定。**

**这就是 Agent。下一节 16-5，我们不用任何框架手写一个。**
