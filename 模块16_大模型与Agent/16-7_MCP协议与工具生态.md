## 一、MCP 解决什么问题

### 没有 MCP 的时候

**你想让 Claude Code 能跑你环境里的 Python，怎么做？**

```python
# 在 claude.md 里写：请用这个命令跑代码
# 在 Claude Code 里用 Bash 工具执行
```

**能用，但有三个问题：**

| 问题 | 表现 |
|---|---|
| **没有类型约束** | 模型传什么参数都行，出错才报 |
| **没有接口文档** | 模型得先读你的 README 才知道怎么调 |
| **换客户端就要重写** | 你在 Claude Code 里的一套，换成 Cursor 用不了 |

### MCP 的做法

**把「能力」封装成一个标准协议的服务，任何支持 MCP 的客户端都能发现和调用。**

```
你写一次 study_mcp.py
        │
        ├──▶ Claude Code 能用
        ├──▶ Cursor 能用
        ├──▶ VS Code 插件能用
        └──▶ 你自己写的 Agent 也能用
```

**一句话：MCP 是「AI 应用的工具接口标准」，类似 USB。**

## 二、和普通 HTTP API 的区别

**这是最容易被问住的地方。**

| | 普通 HTTP API | MCP |
|---|---|---|
| 谁去调 | 你的代码，**你写死了调哪个** | **模型自己发现、自己选** |
| 怎么知道有哪些接口 | 读文档 | **协议里有 `list_tools`，自动发现** |
| 参数描述给谁看 | 给人看 | **给模型看，模型据此填参数** |
| 谁维护连接 | 每次 HTTP 请求 | **长连接会话，有生命周期** |
| 能传状态吗 | 无状态 | **有 session，能记住上下文** |

**关键区别第二行：**

> **HTTP API 的接口列表是给开发者看的文档。MCP 的工具列表是给模型看的、运行时动态获取的。**

**这就是为什么 MCP Server 里每个工具都要写 `description`——那是模型唯一能看到的东西。**

**和 16-3 的 `TOOLS` 定义是同一个道理，只是从「硬编码在请求里」变成了「服务端提供」。**

## 三、三个角色

```
┌──────────────────────────────────────────┐
│  Host（宿主）                             │
│  Claude Code / Cursor / 你自己的程序       │
│                                          │
│   ┌────────────────────────────────┐     │
│   │  Client（客户端）                │     │
│   │  负责跟 Server 通信              │     │
│   └───────────┬────────────────────┘     │
└───────────────┼──────────────────────────┘
                │  MCP 协议（JSON-RPC）
                ▼
┌──────────────────────────────────────────┐
│  Server（服务端）                         │
│  study_mcp.py                            │
│    ├─ tools      模型可调用的函数         │
│    ├─ resources  可读取的数据（文件、DB） │
│    └─ prompts    预设的提示词模板         │
└──────────────────────────────────────────┘
```

**三种能力：**

| 能力 | 谁发起 | 例子 |
|---|---|---|
| **Tools** | **模型决定调用** | `run_python(code)` |
| **Resources** | 客户端/用户选 | 读取 `进度追踪.md` |
| **Prompts** | 用户选 | 「帮我写今日反馈」模板 |

**你现有的 7 个都是 Tools。** 这也是最常用的。

## 四、写一个 MCP Server

### 环境状态（2026-11-10 已装）

**两个环境都有 mcp 了：**

| 环境 | Python | mcp 版本 | 说明 |
|---|---|---|---|
| base | `E:\Dowmload\Anaconda3_Dowmload\python.exe` | **2.2.0** | 你现在跑的 `study_mcp.py` 用这个 |
| **ai** | `E:\Dowmload\Anaconda3_Dowmload\envs\ai\python.exe` | **2.3.0** | 新装的，以后写新 Server 用这个 |

**两个都是 2.x，所以 `MCPServer` 的写法通用。**

**注意：`mcp.exe` 装到了 `E:\Dowmload\Anaconda3_Dowmload\envs\ai\Scripts\`，这个目录不在 PATH 里。** 不影响用，因为你启动 Server 是直接用 Python 调脚本，不靠那个 exe。

### 最小可运行示例

```python
# -*- coding: utf-8 -*-
from mcp.server.mcpserver import MCPServer

mcp = MCPServer("demo-server", instructions="示例服务器，所有输出用中文。")

@mcp.tool()
def add(a: int, b: int) -> str:
    """把两个整数相加。

    参数 a、b 是整数，返回它们的和。
    """
    return str(a + b)

@mcp.tool()
def read_file(path: str) -> str:
    """读取一个文本文件的内容。只支持 .txt 和 .md。"""
    from pathlib import Path
    p = Path(path)
    if p.suffix not in (".txt", ".md"):
        return f"拒绝读取：不支持 {p.suffix}"
    if not p.exists():
        return f"文件不存在：{path}"
    return p.read_text(encoding="utf-8")[:3000]

if __name__ == "__main__":
    mcp.run("stdio")
```

**就这么多。** `@mcp.tool()` 装饰器 + 类型注解 + docstring，它会自动生成给模型看的 schema。

### 三个必须写对的地方

**① 版本对了，import 才对**

```
mcp 2.x  →  from mcp.server.mcpserver import MCPServer     ✓
旧写法   →  from mcp.server.fastmcp import FastMCP         ✗ 连不上
```

**这是你踩过的第一个坑。** 网上大量教程还是 FastMCP 的写法，照抄会失败。

**② docstring 就是工具描述**

```python
def add(a: int, b: int) -> str:
    """把两个整数相加。"""        ← 模型看到的就是这一句
```

**写清楚「干什么、什么时候用、什么时候别用」**，和 16-3 讲的一样。

**③ 返回值必须是字符串**

```python
return str(a + b)        # ✓
return a + b             # ✗ 可能报序列化错误
```

**返回复杂结构时先 `json.dumps(..., ensure_ascii=False)`。**

## 六、四个必踩的坑（你全踩过）

### 坑 1：FastMCP 写法失效

```
错误：from mcp.server.fastmcp import FastMCP
现象：ImportError 或连上后没有工具
原因：mcp 2.x 改了模块结构
改法：from mcp.server.mcpserver import MCPServer
```

**验证办法：**

```
python -c "import mcp; import importlib.metadata as md; print(md.version('mcp'))"
```

**是 2.x 就用 `MCPServer`。**

### 坑 2：`command` 写了裸 `python`

```json
"command": "python"                                    ← 错
"command": "E:\\Dowmload\\Anaconda3_Dowmload\\python.exe"  ← 对
```

**现象：** 状态一直 `CONNECTION_CLOSED`。

**原因：** Claude Code 启动子进程时的 PATH 和你的终端不一样，找不到 `python`。

**这是你排查了好一阵才发现的。** **所有 MCP 的 `command` 一律写绝对路径。**

### 坑 3：`-I` 隔离模式屏蔽了 site-packages

```python
# study_mcp.py 里原本想用 -I 隔离执行用户代码
subprocess.run([python, "-I", tmp_file])
```

**现象：** 工具跑起来报 `ModuleNotFoundError: No module named 'mcp'`。

**原因：** `-I` 会忽略用户 site-packages，而 `mcp` 恰好装在那里。

**改法：** 改用 `PYTHONSAFEPATH=1` 环境变量，同样能防止当前目录的杂散模块被导入。

**这个坑的教训：** `-I` 和 `PYTHONSAFEPATH=1` 效果接近但不等价，`-I` 更彻底，会连用户包一起屏蔽。

### 坑 4：中文乱码

**现象：** 工具返回的中文全是问号。

**改法：** `env` 里加三行：

```json
"env": {
  "PYTHONSAFEPATH": "1",
  "PYTHONUTF8": "1",
  "PYTHONIOENCODING": "utf-8"
}
```

**另外，脚本第一行加编码声明：**

```python
# -*- coding: utf-8 -*-
```

## 八、Resources 和 Prompts（了解即可）

**Tools 是模型调的。另外两种是人选的。**

### Resources

```python
@mcp.resource("study://progress")
def get_progress() -> str:
    """进度追踪文件的内容"""
    return Path(r"E:\AI学习\进度追踪.md").read_text(encoding="utf-8")
```

**客户端里会显示成一个可以「附加到对话」的条目。**

**和 Tools 的区别：**

| | Tools | Resources |
|---|---|---|
| 谁决定用 | 模型 | **用户** |
| 能带参数吗 | 能 | 能（URI 模板） |
| 适合 | 有副作用的操作 | **只读的数据** |

### Prompts

```python
@mcp.prompt()
def daily_feedback(date: str) -> str:
    """生成每日学习反馈的模板"""
    return f"请为 {date} 写学习反馈，包含……"
```

**在客户端里会显示成 `/daily_feedback` 这样的命令。**

**你现在用的 `/问`、`/跑` 这些斜杠命令，本质上是本地 command 文件，不是 MCP prompt。** 但作用类似。

### 练习 16-7-D（选做）：危险工具的安全边界

**仿照 `study_mcp.py` 里的 `FORBIDDEN` 正则**，给你自己的工具加一道拦截：

```python
FORBIDDEN = re.compile(r"(rm\s+-rf|del\s+/[fsq]|format\s+[a-z]:)", re.IGNORECASE)

@mcp.tool()
def run_python(code: str) -> str:

    ...
```

**为什么必须有这个**：MCP 工具执行的是模型生成的参数。模型被提示词注入，或者自己编了一段危险命令，**你的机器就完了。**

## 十三、常见错误

| 错误 | 现象 | 改法 |
|---|---|---|
| 用 `FastMCP` | ImportError / 工具不出现 | 改 `MCPServer` |
| `command` 写 `python` | `CONNECTION_CLOSED` | 绝对路径 |
| 没设 `PYTHONUTF8` | 中文乱码 | env 里加 |
| 工具返回非字符串 | 序列化错误 | `json.dumps` / `str` |
| 工具抛异常 | server 崩 | 捕获后返回错误字符串 |
| docstring 太简 | 模型不调用 | 写清何时用、何时别用 |
| 没有输入校验 | 被注入 | 正则校验参数 |
