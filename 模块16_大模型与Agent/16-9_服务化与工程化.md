## 一、模型服务化的本质

**一句话：把「Python 函数」变成「网络接口」。**

```
原来：predict(image)                    ← 同一个进程里调用
现在：POST /predict  {"image": "..."}   ← 通过网络调用
```

**为什么非要这样：**

| 原因 | 说明 |
|---|---|
| 前端要调 | 网页不能直接跑 PyTorch |
| 多人要用 | 不能每人装一套环境 |
| 要监控 | 调用量、耗时、错误要能看到 |
| 要部署 | 放到服务器上，换台机器不用改 |

## 二、最小可运行的服务

**代码我在你本机验证过了，下面这些输出是真的。**

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI(title="影像模型服务")

class ImageRequest(BaseModel):
    hu_mean: float
    hu_std: float

class Prediction(BaseModel):
    probability: float
    label: str

@app.get("/health")
def health():
    return {"status": "ok"}

@app.post("/predict", response_model=Prediction)
def predict(req: ImageRequest):
    if not (-2000 <= req.hu_mean <= 3000):
        raise HTTPException(status_code=400, detail="HU 值超出合理范围")
    p = min(max((req.hu_mean + 1000) / 2000, 0.0), 1.0)
    return Prediction(probability=round(p, 4),
                      label="肺炎" if p > 0.5 else "正常")
```

**启动：**

```
uvicorn app:app --host 0.0.0.0 --port 8000
```

### 实测结果

```
GET  /health   -> {'status': 'ok'}
POST /predict  -> {'probability': 0.56, 'label': '肺炎'}
异常输入       -> 400 {'detail': 'HU 值超出合理范围'}
文档地址       -> /docs 自动生成
```

### 三件白拿的好处

**① `/docs` 自动生成交互式文档**

**这不是小事。** 你不用写任何 API 文档，浏览器打开 `http://localhost:8000/docs` 就能看到所有接口、参数、返回值，**还能直接点「Try it out」调用。**

**面试演示时，这一步的观感极强。**

**② pydantic 自动校验**

```python
class ImageRequest(BaseModel):
    hu_mean: float
```

**传 `{"hu_mean": "abc"}` 会被自动拒绝，返回 422，根本不会进你的函数。**

**你的函数里只需要处理「业务上不合理」的情况（HU 超出范围），不用管类型。**

**③ `response_model` 自动过滤**

```python
@app.post("/predict", response_model=Prediction)
```

**返回的字段必须和 `Prediction` 一致。** 你多返回了字段（比如内部调试信息），会被自动砍掉——**防止意外泄露。**

## 三、把真模型装进去

### 关键：模型只加载一次

**错误写法：**

```python
@app.post("/predict")
def predict(req: ImageRequest):
    model = MyModel()
    model.load_state_dict(torch.load("model.pt"))    # ← 每次请求都加载！
    ...
```

**后果：** 每个请求多花 2-3 秒，显存反复分配释放。

**正确写法：**

```python
import torch
from contextlib import asynccontextmanager
from fastapi import FastAPI

MODEL = None

@asynccontextmanager
async def lifespan(app: FastAPI):
    global MODEL
    MODEL = MyModel()
    MODEL.load_state_dict(torch.load("model.pt", map_location="cuda"))
    MODEL.eval()
    print("模型已加载")
    yield
    MODEL = None

app = FastAPI(title="影像模型服务", lifespan=lifespan)
```

**`lifespan` 里的代码在服务启动时跑一次，关闭时跑一次。**

### 推理要用 `no_grad`

```python
@app.post("/predict")
def predict(req: ...):
    with torch.no_grad():          # ← 别忘了
        out = MODEL(x)
```

**不写 `no_grad` 的后果：** 每次推理都建计算图，显存越用越多，几十次之后爆掉。

**这是 3-3 讲过的东西，在服务里更容易忘。**

## 四、接口设计的三条规矩

### ① 一定要有 `/health`

```python
@app.get("/health")
def health():
    return {"status": "ok", "model_loaded": MODEL is not None}
```

**为什么：** 容器编排、负载均衡都靠它判断「这个服务活着吗」。

**没有它，Docker 不知道你的服务是不是卡死了。**

### ② 请求和响应分开定义

```python
class PredictRequest(BaseModel):
    image_base64: str

class PredictResponse(BaseModel):
    probability: float
    label: str
    model_version: str          # ← 加上版本
```

**`model_version` 很重要。** 出了问题要能回溯「当时用的是哪个模型」。

### ③ 错误用 HTTPException，不要返回 200

```python
# 错误
return {"error": "图片太大"}          # ← HTTP 200，但内容是错的

# 正确
raise HTTPException(status_code=413, detail="图片超过 10MB")
```

**为什么：** 调用方靠状态码判断成败。你返回 200 加一个 error 字段，**调用方的重试逻辑、监控告警全都失效。**

**常用的几个状态码：**

| 码 | 什么时候 |
|---|---|
| 400 | 参数不合法 |
| 413 | 请求体太大 |
| 422 | 类型不对（pydantic 自动返回） |
| 500 | 你的代码崩了 |
| 503 | 模型没加载好 |

## 五、Docker：让它能在任何机器上跑

### 为什么需要

**你现在能跑，是因为你的机器上装了：torch 2.9.1+cu128、monai、pydicom、sklearn……**

**换台机器，少一个包就跑不起来。**

**Docker 把「程序 + 环境」打成一个镜像，任何装了 Docker 的机器都能跑。**

### Dockerfile

```dockerfile
FROM python:3.11-slim

WORKDIR /app

# 先装依赖（这一层会被缓存，改代码不用重装）
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 再拷代码
COPY . .

EXPOSE 8000

CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]
```

### 两个关键的层顺序

```
先 COPY requirements.txt  →  RUN pip install
再 COPY .                 →  改代码时不用重装依赖
```

**反过来写（先 COPY . 再 pip install），每次改一行代码都要重装全部依赖，构建时间从 10 秒变成 10 分钟。**

### requirements.txt

```
fastapi==0.162.0
uvicorn==0.54.0
pydantic==2.14.2
numpy==2.4.6
pillow==12.3.0
torch==2.9.1
pydicom==3.0.2
scikit-learn==1.9.1
```

**版本要钉死。** 不钉死的话，半年后别人构建出来的环境和你的不一样，「在我这能跑」重演。

### GPU 版本

**要用 CUDA 的话，基础镜像换成：**

```dockerfile
FROM pytorch/pytorch:2.9.1-cuda12.8-cudnn9-runtime
```

**注意：** 镜像是 5-8 GB。**你现在这台机器是在 Windows 上跑 Docker Desktop，GPU 直通需要额外配置。**

**建议：先做 CPU 版本，能跑通再说 GPU。**

### 本机未验证的说明

**你的机器上装了 Docker 29.8.2 + Compose v5.5.1，但我没有实际构建过这个镜像**（要拉基础镜像，几个 GB，得你同意）。

**你自己构建时如果报错，把完整报错发我。**

## 六、docker-compose：一个文件起全套

**你的毕业项目不止一个服务：模型服务、向量库、可能还有个前端。**

```yaml
services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DEEPSEEK_API_KEY=${DEEPSEEK_API_KEY}
    volumes:
      - ./models:/app/models          # 模型文件挂进去，不打进镜像
      - ./knowledge_base:/app/knowledge_base
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 5s
      retries: 3
    restart: unless-stopped
```

**三条值得注意的：**

**① `volumes` 挂模型**

**不要把 `.pt` 文件 COPY 进镜像。** 模型 100 MB 起，改一次模型就要重建镜像。

**挂载进去，改模型只要重启容器。**

**② `environment` 传密钥**

**API Key 绝对不要写进 Dockerfile。** 写进去，镜像分享出去就泄露了。

```yaml
environment:
  - DEEPSEEK_API_KEY=${DEEPSEEK_API_KEY}
```

**这个 `${...}` 从你 shell 的环境变量读。**

**③ `healthcheck`**

**Docker 靠它判断容器健不健康。** 没有它，容器进程活着但服务卡死时，Docker 也认为没问题。

## 七、评估：服务上线前必须有的数字

**「我的模型准确率 0.95」不够。服务化之后还要问：**

| 指标 | 怎么测 | 目标 |
|---|---|---|
| **单次推理耗时** | 计时 100 次取 P50/P95 | P95 < 500ms |
| **吞吐量** | 每秒能处理几个请求 | 看需求 |
| **并发下的稳定性** | 10 个并发跑 1 分钟 | 不崩、不 OOM |
| **大图会不会挂** | 故意传 20 MB 的图 | 返回 413，不是 500 |

### 压测的最小写法

```python
import time, requests

times = []
for _ in range(100):
    t0 = time.time()
    r = requests.post("http://localhost:8000/predict", json={...})
    times.append(time.time() - t0)
    assert r.status_code == 200

times.sort()
print(f"P50 = {times[50]*1000:.0f} ms")
print(f"P95 = {times[95]*1000:.0f} ms")
```

**P95 比平均值重要得多。** 平均值 100ms 但 P95 是 3 秒，说明每 20 个用户里有一个卡了很久——这比整体慢更难受。

## 八、成本控制：LLM 服务的特殊问题

**传统模型服务成本是固定的（电费 + 机器）。LLM 服务**每次调用都花钱**。**

### 三个必须监控的数

```python
class CallStats:
    def __init__(self):
        self.calls = 0
        self.input_tokens = 0
        self.output_tokens = 0
        self.cache_hits = 0

    def record(self, usage):
        self.calls += 1
        self.input_tokens += usage.get("input_tokens", 0)
        self.output_tokens += usage.get("output_tokens", 0)
        self.cache_hits += usage.get("cache_read_input_tokens", 0)

    def cost(self, price_in, price_hit, price_out):
        """三分开算，别混在一起"""
        return (self.input_tokens * price_in
                + self.cache_hits * price_hit
                + self.output_tokens * price_out)
```

**为什么三分开算：** 缓存命中的价格是未命中的五十分之一。混在一起算，你会严重高估成本，然后做出错误的优化决策。

### 四道防线

```python
# 1. 单次请求 token 上限
MAX_TOKENS_PER_REQUEST = 2000

# 2. 单次请求的 max_tokens 要设置
"max_tokens": 1500

# 3. 每日预算告警
if daily_cost > BUDGET * 0.8:
    logger.warning(f"今日已用 {daily_cost:.2f} 元，接近预算 {BUDGET}")

# 4. 超预算直接拒绝
if daily_cost > BUDGET:
    raise HTTPException(429, "今日调用额度已用完")
```

**最后一条是真的需要。** 没有它，一个死循环或者被刷，一晚上能把余额烧光。

## 十三、常见错误

| 错误 | 表现 | 改法 |
|---|---|---|
| 每次请求加载模型 | 响应 3 秒起，日志刷屏 | `lifespan` 里加载 |
| 忘了 `no_grad` | 显存越用越多，最终 OOM | 加 `with torch.no_grad()` |
| 错误返回 200 | 调用方无法判断 | `HTTPException` |
| API Key 写进 Dockerfile | 镜像泄露 = Key 泄露 | 用环境变量 |
| 先 COPY . 再 pip install | 每次构建 10 分钟 | 先 COPY requirements |
| 模型文件 COPY 进镜像 | 镜像几百 MB，改模型要重建 | `volumes` 挂载 |
| 只报平均耗时 | 掩盖了长尾 | 报 P50/P95 |
| 不设预算上限 | 一晚上烧光余额 | 加每日额度 |
