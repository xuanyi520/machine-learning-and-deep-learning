### 练习 14-A（5 分钟筛选）

**参考代码**
文字题。评分不看"选得对不对"，看**判断有没有依据、速度有没有控制住**。产出格式固定为一行一篇：

```
标题 / 判断（精读/存档/放弃）/ 一句理由（必须含数字、数据集或代码证据）/ 有没有代码
```

5 分钟只看六处：标题、摘要最后两句、图 1、表 1、结论最后一段、代码链接。**不看**引言、相关工作、公式、方法细节。

**实测输出**

不适用（依赖你自己的 Zotero 库，我无法代替你选那 5 篇）。下面给判分表和三类典型行的写法。

| 维度 | 权重 | 达标 | 不合格 |
|---|---|---|---|
| 时间控制 | 20% | 5 篇总用时 ≤ 30 分钟，每篇单独计时 | 有一篇看了 20 分钟 |
| 判断分布 | 20% | 至少 2 篇"放弃" | 5 篇全"精读" |
| 理由具体性 | 40% | 每条含一个数字 / 数据集名 / 代码状态 | "感觉不错""挺有意义的" |
| 代码信息 | 20% | 明确写"有/无/仅推理代码" | 漏写或写"应该有" |

合格行的三种样子（论文名与判断需你替换成自己库里的）：

```
<标题 A> / 精读 / 在 <公开数据集> 上报告 Dice，样本量 <N> 例，有官方代码 / 有
<标题 B> / 存档 / 只有 <8> 例单中心数据，无外部验证，方法无新意 / 无
<标题 C> / 放弃 / 任务是 <分类> 不是分割，与本课题无关 / 有
```

**判分要点**
- 每行必须有"判断 + 依据 + 代码状态"三件套，缺一件扣分。
- "放弃"不是贬义，是筛选能力的体现；5 篇全精读说明标准太松。
- 理由里出现数字（样本量、Dice、数据集例数）比形容词可信。
- 总用时是硬指标，超时说明第一遍还在读方法。

**常见错误**
- 把摘要整段抄下来当理由——摘要是作者写的，不是你的判断。
- 用"方法新颖"当理由——没说出新在哪，也没说对你有什么用。
- 先看代码再看论文，5 分钟全花在读 README 上。
- 5 篇都是同一主题、同一方法，筛选没有区分度。
- 不记时间，实际每篇 15 分钟，一周也筛不完 50 篇。

### 练习 14-C（指标实现差异）

**参考代码**
```python
import numpy as np

gt   = np.array([1, 1, 1, 1, 0, 0, 0, 0])
pred = np.array([1, 1, 0, 0, 0, 0, 0, 0])

def dice(g, p, smooth=0.0):
    inter = (g * p).sum()
    return (2 * inter + smooth) / (g.sum() + p.sum() + smooth)

print('无 smooth :', dice(gt, pred))
print('smooth=1 :', dice(gt, pred, 1))

z = np.zeros(8, dtype=int)
with np.errstate(invalid='ignore', divide='ignore'):
    print('空掩膜 无 smooth:', dice(z, z))
print('空掩膜 smooth=1 :', dice(z, z, 1))

# 边界情况：GT 为空、Pred 非空
p = np.array([1, 1, 0, 0, 0, 0, 0, 0])
g = np.zeros(8, dtype=int)
print('GT空 Pred非空 无 smooth:', dice(g, p), ' smooth=1:', dice(g, p, 1))
```

**实测输出**

手算：

```
交集 = 2，GT 阳性 = 4，Pred 阳性 = 2
无 smooth： 2×2 / (4+2) = 4/6 = 0.6667
smooth=1：(2×2+1) / (4+2+1) = 5/7 = 0.7143

空掩膜（GT 全 0，Pred 全 0）：
无 smooth：0/0 → numpy 给 nan（有的实现直接返回 0）
smooth=1：1/1 = 1.0
```

代码输出：

```
无 smooth : 0.6666666666666666
smooth=1 : 0.7142857142857143
空掩膜 无 smooth: nan
空掩膜 smooth=1 : 1.0
GT空 Pred非空 无 smooth: 0.0  smooth=1: 0.3333333333333333
```

**为什么空掩膜时差异最大**：非空病例上，smooth 只改变分子分母各 1，Dice 变化约 0.001-0.005；空掩膜时分母本来就是 0，加不加 smooth 决定的是"0/0 未定义"还是"1/1=1"。这不是数值精度问题，是**语义分歧**：空病例到底算"完全正确"还是"无法计算"。

**差异什么时候超过 0.02**：设空病例占比为 f。若一种实现把空病例记 1、另一种记 0，整体均值差恰好是 f。所以 f > 2% 时差异就超过 0.02。实测：

```
空病例比例  0%: 均值差 0.000
空病例比例  5%: 均值差 0.050
空病例比例 10%: 均值差 0.100
空病例比例 20%: 均值差 0.200
```

另一个会超过 0.02 的分歧是**平均方式**：per-case 平均给每个病例相同权重，global 累计给大病灶更高权重。小病灶多、空病例多的数据集上，两者差 0.01-0.03。

**判分要点**
- 三个数必须算对：0.6667、0.7143、nan（或 0）与 1。
- 能说清 smooth 在非空样本上几乎无影响，在空样本上是语义问题。
- 能给出"空病例比例 × 记法差异 = 均值差"这个定量关系。
- 能补充 GT 空、Pred 非空这个边界：无 smooth 得 0，smooth=1 得 0.333，**smooth 会把"全错"抬成 0.33**。
- 知道正确做法：用作者仓库的 metric，先在小样本上对齐到完全一致。

**常见错误**
- 分子分母只加一处 smooth（如 `2*inter/(union+smooth)`），得到 0.5714。
- 认为 `np.nanmean` 能解决空掩膜问题——它只是跳过，不同实现跳过的样本集可能不同。
- 把 smooth 当成"提高 Dice 的技巧"，在报告里隐去。
- 用 `pred > 0` 二值化而没有先确认 pred 是概率还是 0/1。
- 多类任务用 argmax 和用 0.5 阈值混着比，类别不平衡时差很多。

### 练习 14-D（复现失败归因）

**参考代码**
文字题。要求是"5 个原因、按可能性排序、每个可检验"。下面给一份达标答案。前提是"官方数据 + 官方代码"，所以排查顺序要从**你替换过的环节**开始，而不是从模型结构开始。

| 排序 | 原因 | 为什么排这里 | 怎么检验（可执行） | 预期结果 |
|---|---|---|---|---|
| 1 | 预处理链被自己重写（归一化 / 窗宽 / resize） | 官方代码跑通不代表你的 dataloader 一致；差 8 个点最符合"输入分布变了" | 在 Dataset 的 `__getitem__` 打印 `img.shape, img.min(), img.max(), img.mean()`，取 3 例存 PNG，与论文图 1 并排看 | 若你的 CT 值域是 0-255 而论文是 HU -1000~3000，或均值差 >0.1，就是它 |
| 2 | 数据划分 / 病例纳入不同 | 官方划分文件可能有多个版本；差 3-10%，与 8 个点吻合 | `set(train_ids) & set(test_ids)` 必须为空；再核对划分文件的行数和病例数 | 交集非 0，或测试集例数与论文表格不一致 |
| 3 | 指标实现不同（空掩膜、per-case vs global、smooth） | 差 0.02-0.05，空病例多时可到 0.08 | 用作者仓库的 metric 重算你的预测；再手算 5 例空掩膜 | 换 metric 后差距缩小 >0.02 |
| 4 | 用了最后一个 epoch / 缺后处理 | 论文报 best，你报 last；或论文取最大连通域你没做 | 检查 ckpt 的 epoch 号；对预测做/不做最大连通域各算一次 Dice | best 比 last 高 1-3 点；后处理补上后回升 1-4 点 |
| 5 | 随机种子 / 非确定性算子 | 差 1-2%，解释不了 8 个点，但会影响结论 | 固定 seed 跑 3 次；`torch.use_deterministic_algorithms(True)` 再跑一次 | 三次结果落在 ±0.02 内，说明不是它 |

**明确不采用的原因**："环境不同""GPU 不一样""版本不兼容"——这些无法检验，也不能解释 8 个点的系统偏差。官方代码在 CPU 和 GPU 上的数值差通常在 1e-5 量级，不会到 Dice 0.08。

**实测输出**

不适用（情景分析题）。判分时看四件事：

- 5 个原因是否覆盖至少 4 类（划分、预处理、指标、种子、代码 bug）。
- 每条是否有"命令/代码级"的检验方法，而不是"再仔细看看"。
- 排序是否有理由（差距大小 × 出现频率），不是随手排。
- 是否排除了不可检验的原因。

**判分要点**
- 第 1 名给"预处理"或"划分"都算合理，但必须给出与 8 个点量级匹配的理由。
- "代码 bug"可以排最后，但要说明为什么仍要查（closed issues 里有没有人报同样的低值）。
- 检验方法必须能写出来：打印张量统计、集合交集、换 metric 重算、看 ckpt epoch。
- 每条要有"预期结果"，否则检验完也不知道是不是它。

**常见错误**
- 一上来调学习率、换优化器——8 个点大概率不是调参能解决的。
- 写"可能是环境不同"——无法检验，等于没归因。
- 5 条全是同一类（比如 5 条都在说预处理），覆盖面不够。
- 排序按"我觉得"而不是按差距量级和排查成本。
- 检验方法写成"检查一下数据"，没有具体命令。

**常见错误**

- 偏差日志写"调了 lr，好了"——没说是哪个假设、怎么排除其他原因。
