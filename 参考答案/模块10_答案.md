### 练习 10-A（三种策略 + 数据量扫描）

**参考代码**

```python
import math
import numpy as np
import torch
import torch.nn as nn

import sys
sys.path.insert(0, r"E:\AI学习\模块10_迁移学习与训练技巧\_exp")
import common as C
from common import (DEVICE, build_resnet18, count_trainable, evaluate,
                    freeze_to, load_arrays, make_loader, set_seed,
                    stratified_subset, train)

imgs, labels, lm = load_arrays("bloodmnist", "train")
timgs, tlabels, _ = load_arrays("bloodmnist", "test")
NC, SIZE, EPOCHS, BS = len(lm), 28, 15, 128
test_loader = make_loader(timgs, tlabels, size=SIZE, bs=256)

def cosine_warmup(opt, total, warm_frac=0.1):
    warm = max(1, int(total * warm_frac))
    def f(s):
        if s < warm:
            return (s + 1) / warm
        p = (s - warm) / max(1, total - warm)
        return 0.5 * (1 + math.cos(math.pi * p))
    return torch.optim.lr_scheduler.LambdaLR(opt, f)

def run(Xtr, Ytr, pretrained, keep, lr_groups):
    set_seed(42)
    m = build_resnet18(NC, pretrained=pretrained)
    if keep is not None:
        freeze_to(m, keep)                 # 先冻结
    groups = []
    for prefix, lr in lr_groups:
        ps = [p for n, p in m.named_parameters()
              if p.requires_grad and n.startswith(prefix)]
        if ps:
            groups.append({"params": ps, "lr": lr})
    opt = torch.optim.AdamW(groups, lr=1e-3, weight_decay=1e-4)
    tl = make_loader(Xtr, Ytr, size=SIZE, train=True, bs=BS)
    sched = cosine_warmup(opt, len(tl) * EPOCHS)
    train(m, tl, test_loader, epochs=EPOCHS, optimizer=opt, sched=sched)
    acc, _, _, _ = evaluate(m, test_loader)
    return float(acc)

STRATS = {
    "scratch":    (False, None, [("", 1e-3)]),
    "head_only":  (True, ["fc"], [("fc", 1e-3)]),
    "partial_l4": (True, ["layer4", "fc"], [("layer4", 2e-4), ("fc", 1e-3)]),
    "full_diff":  (True, None, [("layer1", 1e-5), ("layer2", 1e-5),
                                ("layer3", 3e-5), ("layer4", 1e-4), ("fc", 1e-3)]),
}

for n in [500, 1000, 2000, 5000]:
    idx = stratified_subset(labels, n, seed=0)
    row = {"n": len(idx)}
    for k, (pre, keep, lrs) in STRATS.items():
        row[k] = run(imgs[idx], labels[idx], pre, keep, lrs)
    print(row)
```

**三个结论**

**第一，策略排序是 B 和 C 接近、都远好于 A，而且四个数据量下都成立。** 冻结到 layer4 和全量微调互有胜负（496/1000 时 B 略高，2000/5000 时 C 略高），差距 0.5-1.9 个点；只训头比它们低 12-19 个点。数据从 496 涨到 5000，只训头从 0.504 涨到 0.712，涨幅 20.8 个点；全量微调从 0.677 涨到 0.852，涨幅 17.5 个点。两条线没有收敛，说明只训头差的不是数据量，是特征本身不可用。

**第二，只训头只有 4104 个可训练参数，是另外两个策略的 1/2700。** 它几乎没有过拟合空间，但也几乎没有适配能力。冻结的 512 维特征是什么样，分类头就只能在这个空间里画线性边界。

**第三，这张表里从头训在四个数据量上全部赢了预训练，5000 张时领先 5.1 个点。** 这不是"迁移学习没用"，是分辨率不匹配，见下。

**为什么只训头最差（三条原因）**

1. **28×28 输入时 layer4 的输出是 1×1。** ResNet18 的结构是 conv1(stride 2) → maxpool(stride 2) → layer1/2/3/4 各下采样一次。28 经过六次减半：28 → 14 → 7 → 4 → 2 → 1。layer4 输出 1×1，全局平均池化等于没做，512 维向量只剩"整张图的一个平均语义"。血细胞靠细胞核形状、胞浆纹理、颗粒分布区分，这些信息在 1×1 上全没了。冻结这个特征，分类头拿到的是一张被压扁的摘要。

2. **域差异。** ImageNet 是自然彩色照片，BloodMNIST 是显微镜下的染色细胞。浅层的边缘和颜色通道还能用，但 layer4 学的是"狗、车、椅子"这类语义，和血细胞类型无关。

3. **BatchNorm 统计量和目标域不匹配。** 冻结参数不等于冻结 BN 的 running_mean/running_var，但即使它们随训练更新，也只有 fc 的梯度在驱动，更新方向不是为特征适配服务的。前向时特征分布和 ImageNet 的统计量错位，深层激活饱和或死掉。

**为什么从头训能赢**

同一句话：**28×28 下预训练特征已经退化成全局语义，借不到"浅层通用特征"这个好处。** 讲义 2.6 节的 64×64 对照里，496 张时预训练冻结到 layer4 是 0.7428，从头训是 0.6995，迁移从亏 5.7 个点变成赚 4.3 个点。同一批图、同一个模型，只改输入尺寸，结论反转。所以这张 28×28 的表不能推广到 64×64 以上。

**判分要点**

- 4×4 表格完整，四列四行都要有数，不能只报最好的那一列。
- 可训练参数量要对：4104 / 8,397,832 / 11,180,616。
- 能说出只训头差的三条原因，至少两条：layer4 输出 1×1、域差异、BN 统计量。
- 能解释从头训反超的原因是分辨率，并且知道 64×64 下结论会变。
- 能指出 B 是性价比最高的默认选择（用 75% 的参数拿到 C 的 95-100%）。

**常见错误**

- 先换 `fc` 再冻结，新层也被冻上，loss 一动不动。
- 冻结后写 `model.eval()` 训练，BN 统计量不更新，指标异常。
- 全量微调用 1e-3 单一学习率，浅层被冲垮。
- 四个数据量用不同种子，把种子噪声当成数据量效应。
- 只跑 5000 张一个点就下结论。数据量扫描至少要 3 个点，本例用了 4 个。
- 把 28×28 的结论直接写成"预训练没用"。换 64×64 就反了。

### 练习 10-B（增强安全性审计）

**参考代码**


**8 条判断**

| # | 增强 | 判断 | 理由 |
|---|---|---|---|
| 1 | RandomRotation(10) | **可用（分类）** | 病人摆位本来就有角度差，±10° 在临床上真实存在。但 28×28 的小图上 10° 已经算重，会削掉边角信息，建议 5-8°。 |
| 2 | RandomHorizontalFlip | **看任务**：分类可用，定位/分割禁用 | 皮肤镜、病理、胸片"有无病灶"都可以；肝分割、左右肺定位、乳腺左右侧任务不行。翻转后解剖位置反了。 |
| 3 | RandomVerticalFlip | **默认禁用**，病理切片例外 | 轴位 CT、胸片有明确的上下关系（膈上/膈下），倒过来在临床上不存在。病理切片没有方向性，可以任意翻转。 |
| 4 | ColorJitter(0.3, 0.3) | **CT 禁用；皮肤镜/眼底可用；病理慎用** | CT 的像素是 HU，改亮度等于伪造组织密度。皮肤镜的光照和肤色差异真实存在，本实验涨 0.9 个点。H&E 染色的颜色对应染色剂浓度，应该做颜色归一化而不是随机抖动。 |
| 5 | RandomAffine(translate=0.1, scale=0.1) | **可用** | 拍摄中心和距离本来就会变。平移 ±10%、缩放 0.9-1.1 都在合理范围。注意平移比例是相对图像尺寸，28×28 上 0.1 只有 2.8 像素。 |
| 6 | MixUp(alpha=0.2) | **默认不用** | 两个病灶叠加会造出临床上不存在的图像，标签变成 50/50 也没有临床含义。只有多标签任务或病灶占比极小时才考虑，且必须在验证集上证明涨点。 |
| 7 | RandomErasing(p=0.5) | **慎用** | 擦除区域可能正好盖住整个病灶，标签还留着，等于给模型喂错标签。p=0.5 太高，建议 p≤0.25 且擦除面积 ≤10%。 |
| 8 | GaussianBlur(3) | **大图可用，28×28 禁用** | 轻度模糊模拟探测器 PSF 和失焦，对 256 以上的 CT/X 光安全。但 28×28 上 kernel=3 已经模糊掉 1/9 的边长，细节直接没了。 |

**实测输出**

对照实验：DermaMNIST 7007 张，SmallCNN 44,680 参数，12 epoch，测试集 2005 张。

| 增强 | accuracy | macro F1 | 相对无增强（acc） |
|---|---|---|---|
| 无增强 | 0.7352 | 0.5138 | — |
| 安全增强（旋转 10° + 平移 8% + 缩放 10%） | 0.7337 | 0.4646 | −0.15 |
| 安全 + 水平翻转 | 0.7147 | 0.4335 | **−2.05** |
| 安全 + 垂直翻转 | 0.7262 | 0.4648 | −0.90 |
| 颜色抖动（jitter 0.3） | **0.7441** | 0.4901 | **+0.89** |

**怎么读**

**第一，安全增强在 accuracy 上几乎没动（−0.15），但 macro F1 掉了 4.9 个点。** 这是一个容易被 accuracy 掩盖的损失：整体正确率不变，少数类（3 类 80 张、6 类 99 张）的召回被增强的随机性吃掉了。所以增强的评估也必须看 macro F1，不能只看 accuracy。

**第二，safe + hflip 比 safe 低 2.05 个点。** 原因不是"翻转有害"，而是**翻转对这个任务没有新增信息，却增加了 2 倍的样本多样性需求**。皮肤病灶本身没有左右之分，hflip 后的图和原图在语义上完全等价，模型要学的是同一个映射。在 12 epoch 的固定预算下，多出来的多样性没有对应的数据量支撑，等于稀释了训练信号。讲义 3.5 节 20 epoch、7007 张时 safe+hflip 是 0.7147，比 safe 低 2.5 个点，和这里一致。

**第三，颜色抖动是唯一正收益（+0.89）。** 皮肤镜的光照、白平衡、肤色差异是真实存在的域偏移，改亮度正好覆盖这个方向。这和"CT 不能改亮度"不矛盾：判断标准是"变换后在临床上是否存在"，不是"变换本身叫不叫颜色抖动"。

**第四，垂直翻转只掉 0.9 个点，比水平翻转的 2.05 还小。** 这看起来反直觉，但它恰好说明：**皮肤镜图像没有解剖方向，vflip 和 hflip 在语义上都是等价变换**。掉点是训练预算和随机性造成的，不是标签被破坏。如果换到轴位 CT，vflip 会直接破坏上下解剖关系，掉点会大得多。

**判分要点**

- 8 条都要有明确判断，不能写"看情况"。可以写"CT 禁用、皮肤镜可用"，但要给出条件。
- 每条理由要落到"变换后在临床上是否可能存在"或"标签是否还成立"，不能只写"可能有用"。
- 5 行对照表完整，至少报 accuracy，最好同时报 macro F1。
- 能解释 safe+hflip 为什么可能比 safe 低：任务不依赖方向，翻转没有新增标签信息，只增加了多样性需求。
- 能指出颜色抖动在皮肤镜上是正收益、在 CT 上是伪造密度，两者的判断标准是同一个。

**常见错误**

- 把"水平翻转安全"当全局规则。定位任务上它会直接改标签，合成实验里掉到 0.42。
- 在 CT 上用 ColorJitter，还觉得"只是调亮度"。
- 增强加在验证/测试集上，指标不可复现。
- 只看 accuracy 判断增强好坏。本例 safe 的 accuracy 只掉 0.15，macro F1 掉了 4.9。
- 用 RandomRotation(30)，插值破坏细节，而且摆位不会偏这么多。
- 把病理切片的 vflip 也禁掉。病理没有方向性，任意旋转都可以。

### 练习 10-C（AMP + 梯度累积）

**参考代码**

```python
import time
import torch
import torch.nn as nn
import torch.nn.functional as F
from torchvision import models

DEVICE = "cuda"

def make_model(nclass=8):
    m = models.resnet18(weights=None)
    m.fc = nn.Linear(512, nclass)
    return m.to(DEVICE)

def bench(dtype, batch=64):
    m = make_model()
    opt = torch.optim.AdamW(m.parameters(), lr=1e-3)
    scaler = torch.amp.GradScaler("cuda", enabled=(dtype == torch.float16))
    x = torch.randn(batch, 3, 128, 128, device=DEVICE)
    y = torch.randint(0, 8, (batch,), device=DEVICE)

    for _ in range(3):                          # 预热
        opt.zero_grad(set_to_none=True)
        with torch.autocast("cuda", dtype=dtype, enabled=(dtype is not None)):
            loss = F.cross_entropy(m(x), y)
        if scaler.is_enabled():
            scaler.scale(loss).backward(); scaler.step(opt); scaler.update()
        else:
            loss.backward(); opt.step()

    torch.cuda.synchronize()
    torch.cuda.empty_cache()
    torch.cuda.reset_peak_memory_stats()
    t0 = time.time()
    n = 30
    for _ in range(n):
        opt.zero_grad(set_to_none=True)
        with torch.autocast("cuda", dtype=dtype, enabled=(dtype is not None)):
            loss = F.cross_entropy(m(x), y)
        if scaler.is_enabled():
            scaler.scale(loss).backward(); scaler.step(opt); scaler.update()
        else:
            loss.backward(); opt.step()
    torch.cuda.synchronize()
    ms = (time.time() - t0) / n * 1000
    print(f"{str(dtype):15s} {ms:6.2f} ms  "
          f"{torch.cuda.max_memory_allocated()/1e6:7.1f} MB  "
          f"{batch/(ms/1000):7.0f} img/s")

bench(None)
bench(torch.float16)
bench(torch.bfloat16)
```

**注意：探测只到 512 就停了，所以这是"至少 512"，不是真实上限。** 8 GB 卡上 128×128 的 ResNet18 比想象中省显存，512 还没有触发 OOM。再往上探测时显存分配变得很慢（Windows 的显存换页），实验主动停在了 512，没有测出真实上限。

梯度累积等价性（真 batch 32 对 4 × batch 8，loss 除以 4）：

| 模式 | 梯度相对误差 |
|---|---|
| eval（BN 用固定 running 统计量） | **0.99%** |
| train（BN 用当前 batch 统计量） | **69.3%** |

3 epoch、5000 张、从头训，有效 batch 256 的两种实现：

| 实现 | 测试准确率 |
|---|---|
| 真实 batch 256（每 epoch 19 步） | 0.7425 |
| batch 128 × 累积 2 步（每 epoch 39 步） | **0.8182** |

**为什么累积反而高了 7.6 个点，以及为什么这不是"累积更好"**

真实 batch 256 时，5000 张一个 epoch 只有 19 步；batch 128 累积 2 步时，一个 epoch 有 39 步。3 个 epoch 下来，前者走了 57 次参数更新，后者走了 117 次。**学习率都设 1e-3，更新次数差 2 倍，这是训练不足，不是梯度质量差异。**

这纠正了一个常见误解：讲"梯度累积等价于大 batch"时，说的是**同一次更新的梯度**等价（上面 eval 模式误差 0.99% 已经证明），不是说**同等 epoch 下**结果等价。有效 batch 翻倍后，每个 epoch 的更新步数减半；如果学习率或 epoch 不随步数补偿，训练进度就会落后。AdamW 的更新量和梯度尺度无关，但它仍然需要足够的步数才能收敛。

正确的对照应该是：batch 256 跑 6 个 epoch（114 步）对 batch 128 累积 3 个 epoch（117 步），或者给 batch 256 用更大的学习率。本实验没有做这个对照，所以只能得出"3 epoch 预算下，步数少的那个欠训练"，不能得出"累积比真 batch 好"。

**三个必须解释清楚的点**

**第一，AMP 为什么省显存。** 省的不只是参数（参数只占几十 MB），主要是**前向激活值**。ResNet18 在 128×128 上，每个 batch 的中间特征图要一直留到反向传播，这部分占显存的 80% 以上。FP16 存储让这部分直接减半，所以总显存从 703 MB 降到 474 MB（0.67×），不是精确的 0.5×，因为还有 FP32 的 master weights、BN 的 running 统计量和优化器状态。

**第二，这张卡上 FP16 比 BF16 快。** FP16 有 Tensor Core 的加速路径，BF16 在这张卡上吞吐低一些（20.95 ms 对 22.48 ms）。但 BF16 不用 GradScaler，数值范围也和 FP32 一样，调试更省心。本机两者显存几乎一样（474 MB），所以选哪个看的是稳定性而不是显存。

**第三，梯度累积和真大 batch 不等价，差异全部来自 BatchNorm。** eval 模式（BN 用固定的 running 统计量）相对误差 0.99%，这 1% 是 cuDNN 对不同 batch size 选了不同卷积算法的数值差异。train 模式误差 69.3%，因为：

```
4 个 batch 8 的均值方差 ≠ 1 个 batch 32 的均值方差
```

BN 在每个 micro-batch 上用自己的统计量归一化，梯度自然不同。这就是"累积 ≠ 大 batch"的地方，也是为什么分割、检测这种 batch 恒小的任务更推荐 GroupNorm。

**判分要点**

- 三行表格要有耗时、峰值显存、吞吐，缺一不可。
- 梯度累积的代码里 `loss / accum_steps` 必须在，且要放在 backward 之前。
- 能解释 AMP 省的是激活值，不是参数量。
- 能报出 eval 和 train 两种模式下的梯度误差，并指出差异来自 BN。
- 能说明最大 batch 是探测值，不是理论值；本机探测到 512 就停了。
- 能指出 3 epoch 下两种实现的准确率差 7.6 个点，根源是更新步数差 2 倍（欠训练），不是累积本身更好；能提出正确的对照方式（补齐步数或调学习率）。

**常见错误**

- 梯度累积忘了除以 accum_steps，等效学习率变成 2 倍。讲义里踩过这个坑，相对误差精确等于 accum-1。
- 只改模型 `model.half()` 但不开 `autocast`，dtype 报错。
- AMP 下忘了 `scaler.step()`，参数根本不更新。
- 在 `autocast` 里调 `loss.item()`，触发同步，速度反而慢。
- 用 `Adam(weight_decay=...)` 而不是 AdamW。
- 把"AMP 快 1.44 倍"当成通用结论。换张卡、换个 batch，收益完全不同，必须在目标卡上测。

### 练习 10-D（小 batch 崩坏实验）

**参考代码**

```python
import sys
sys.path.insert(0, r"E:\AI学习\模块10_迁移学习与训练技巧\_exp")
import common as C
from common import DEVICE, evaluate, load_arrays, make_loader, set_seed, train
import torch

imgs, labels, lm = load_arrays("bloodmnist", "train")
timgs, tlabels, _ = load_arrays("bloodmnist", "test")
idx = C.stratified_subset(labels, 3000, seed=0)

for norm_kind in ["bn", "gn"]:
    for bs in [1, 2, 8, 32]:
        set_seed(42)
        m = C.SmallCNN(len(lm), in_ch=3, norm=norm_kind).to(DEVICE)
        opt = torch.optim.AdamW(m.parameters(), lr=1e-3, weight_decay=1e-4)
        tl = make_loader(imgs[idx], labels[idx], size=28, train=True, bs=bs)
        te = make_loader(timgs, tlabels, size=28, bs=256)
        train(m, tl, te, epochs=6, optimizer=opt)
        acc, _, _, _ = evaluate(m, te)
        print(f"{norm_kind} batch={bs}: {acc:.4f}")
```

**实测输出**

BloodMNIST 3000 张，SmallCNN 44,680 参数，6 epoch，单种子 42：

| batch | BatchNorm | GroupNorm | 差距（BN − GN） |
|---|---|---|---|
| 1 | **0.7448** | **0.8673** | **−12.3 个点** |
| 2 | 0.8688 | 0.8705 | −0.2 |
| 8 | 0.8685 | 0.8471 | +2.1 |
| 32 | 0.8647 | 0.8644 | +0.03 |

**三个结论**

**第一，batch = 1 时 BN 崩了，掉了 12.3 个点。** 原因很硬：一个样本的方差是 0（只有它自己），BN 的分母只剩 `sqrt(eps)`，归一化后输出退化成 `beta`，这一层的信息几乎全丢。训练时每层都这样，网络只能靠残差和后面的层硬撑，效果自然差。

**第二，batch = 2 到 32 时 BN 没有崩，甚至略好于 GN。** 这和"batch < 8 必须换 GN"的流行说法不符。原因有三：网络很浅（3 个卷积），统计量误差不会逐层放大；任务简单（8 类血细胞，3000 张）；只训 6 个 epoch，BN 的噪声还没累积到爆发。batch 2 时 BN 只比 GN 低 0.2 个点，在单种子噪声范围内。

**第三，GN 在 batch 增大时反而略降（0.8705 → 0.8644）。** GN 没有 BN 那种"用 batch 统计量做正则"的副作用，大 batch 下少了这层正则，泛化略差。这个差距很小，但方向稳定。

**为什么小 batch 下 BN 的统计量不可靠**

样本方差的相对标准误是 `sqrt(2/(B-1))`：

| batch | 相对标准误 |
|---|---|
| 2 | 141% |
| 8 | 53% |
| 32 | 25% |
| 256 | 8.8% |

batch 2 时，每层估计出的方差可能偏离真实值一倍以上。每个 batch 的统计量都在跳，running_mean/running_var 是动量 0.1 的滑动平均，估出来的值到推理时就是错的，指标直接崩。

**GroupNorm 为什么不受影响**

```
BatchNorm:  对 (N, H, W) 求均值方差  -> 依赖 N
GroupNorm:  对 (C/G, H, W) 求均值方差 -> 与 N 无关
```

GN 把通道分成 G 组（本例 G=8），每组在"组内通道 × 空间"上归一化。这个统计量只和当前样本自己的特征有关，batch 里有 1 个样本还是 32 个，算出来的均值方差完全一样。所以 batch = 1 时它仍然是稳定的。

**判分要点**

- 2×4 表格（或 2×3，至少覆盖 batch 2/8/32），能看出 BN 在 batch 1 明显掉点。
- 能报出 batch 2 时 BN 并没有明显崩，不要为了迎合结论改数字。
- 能解释 BN 失效的机制：单样本方差为 0，小 batch 方差估计噪声大。
- 能说出 GN 在通道维分组、与 N 无关。
- 能指出 GN 在大 batch 下略差的原因：少了 batch 统计量带来的正则。

**常见错误**

- 认为"batch < 8 就必须 GN"。本实验 batch 2/8 时 BN 都不差，真正的崩坏条件是"深网络 + 难任务 + 小数据 + batch ≤ 4"叠加。
- 只跑 batch 1 和 32，漏掉中间的 2 和 8，看不出拐点。
- BN 和 GN 用不同的学习率或 epoch，比较不公平。
- 忘了 `model.train()`，BN 用 running 统计量，batch 大小根本没影响。
- 在 batch = 1 时用 BN 还不开 `track_running_stats=False`，推理时统计量是错的。

### 练习 10-E（Focal Loss 的 gamma 扫描）

**参考代码**

```python
import sys
sys.path.insert(0, r"E:\AI学习\模块10_迁移学习与训练技巧\_exp")
import common as C
from common import DEVICE, FocalLoss, evaluate, load_arrays, make_loader, set_seed, train
import torch, torch.nn as nn
from sklearn.metrics import f1_score, balanced_accuracy_score, recall_score

imgs, labels, lm = load_arrays("dermamnist", "train")
timgs, tlabels, _ = load_arrays("dermamnist", "test")

def run(gamma):
    set_seed(42)
    m = C.SmallCNN(len(lm), in_ch=3).to(DEVICE)
    opt = torch.optim.AdamW(m.parameters(), lr=1e-3, weight_decay=1e-4)
    tl = make_loader(imgs, labels, size=28, train=True, bs=128)
    te = make_loader(timgs, tlabels, size=28, bs=256)
    crit = nn.CrossEntropyLoss() if gamma == 0 else FocalLoss(gamma=gamma)
    train(m, tl, te, epochs=12, optimizer=opt, criterion=crit)
    acc, _, probs, ys = evaluate(m, te)
    p, y = probs.argmax(1).numpy(), ys.numpy()
    return {
        "acc": float(acc),
        "macro_f1": float(f1_score(y, p, average="macro")),
        "bal_acc": float(balanced_accuracy_score(y, p)),
        "recall_3": float(recall_score(y, p, labels=[3], average="macro", zero_division=0)),
        "recall_6": float(recall_score(y, p, labels=[6], average="macro", zero_division=0)),
    }

for g in [0, 1, 2, 3]:
    print(g, run(g))
```

**实测输出**

DermaMNIST 7007 张，7 类，SmallCNN 44,680 参数，12 epoch，单种子 42：

| gamma | accuracy | macro F1 | balanced acc | 3 类 recall（80 张） | 6 类 recall（99 张） |
|---|---|---|---|---|---|
| 0（普通 CE） | 0.7352 | **0.5094** | **0.5245** | 0.217 | 0.655 |
| 1 | **0.7446** | 0.5087 | 0.5084 | 0.130 | 0.655 |
| 2 | 0.7352 | 0.4875 | 0.4962 | 0.130 | 0.621 |
| 3 | 0.7421 | 0.4929 | 0.5059 | 0.130 | 0.655 |

**gamma 与 macro F1 的关系**

```
gamma:    0       1       2       3
F1:     0.5094  0.5087  0.4875  0.4929
```

不是单调下降，但趋势清楚：gamma = 0 和 1 基本持平，gamma 从 1 涨到 2 掉了 2.1 个点，gamma = 3 又回升 0.5 个点。**峰值在 gamma 0-1，不是在论文常推荐的 2。**

**为什么 gamma 越大反而掉点**

Focal Loss 的权重是 `(1 - p_t)^gamma`。gamma 越大，模型越把注意力放在"当前分错"的样本上。这套逻辑在目标检测里成立，因为那里 99.9% 的候选框是容易分的负样本，压掉它们能让模型专心学少数正样本。

这里的情况不同：

1. **不平衡没有到那个量级。** 最大类 4693 张、最小类 80 张，比例 59:1；检测任务常是 1000:1。
2. **难样本里有标注噪声。** 皮肤镜的良恶性边界本来就模糊，不同医生的判断都不一致。模型分错的样本，有一部分是标签本身有问题。gamma 越大，越会去拟合这些噪声。
3. **3 类只有 80 张，recall 对 gamma 极敏感。** gamma 从 0 到 1，3 类 recall 从 0.217 掉到 0.130，等于 80 张里多错了 7 张。这种量级的波动在单种子下不可靠，但方向是负的。

所以这张表支持讲义 5.5 节的建议：**先上加权 CE，别一上来就用 Focal。** Focal 多两个超参（gamma、alpha），在中等不平衡上不一定比普通 CE 好。

**判分要点**

- 4 行结果表，accuracy、macro F1、balanced acc、两个少数类 recall 都要有。
- 能画出 gamma-F1 曲线（或至少用文字描述形状：先平、再降、再微升）。
- 能解释 gamma 太大掉点的机制：难样本里混着标注噪声，放大它会过拟合噪声。
- 能指出本数据的不平衡比例（59:1）远低于检测任务（1000:1），Focal 的前提不成立。
- 能说明单种子下 0.5 个点的差异不可靠，结论要谨慎。

**常见错误**

- 只报 accuracy。本例 gamma 3 的 accuracy 是 0.7421，比 gamma 0 还高，但 F1 更低，只看 accuracy 会选错。
- 用测试集调 gamma。应该用验证集选，测试集只看一次。
- gamma 设成 5 或 10，训练不收敛。
- 把 Focal 和 class weight 一起开很大，双重加权，少数类过拟合。
- 认为"gamma 越大越关注难样本，所以一定更好"。难样本不都是真难，有一部分是脏标签。

### 练习 10-F（完整消融表）

**参考代码**

```python
# 6 行累积消融 + 最后一行 3 个种子
# 数据：BloodMNIST 2000 张，ResNet18 @64x64，8 epoch，batch 128
# 注意：讲义原表用 20 epoch，这里为控制总时长用 8 epoch，结论方向一致但绝对值不可直接对比

import sys
sys.path.insert(0, r"E:\AI学习\模块10_迁移学习与训练技巧\_exp")
import common as C
from common import (DEVICE, build_resnet18, evaluate, load_arrays, make_loader,
                    norm, set_seed, stratified_subset, train)
import math, torch, torch.nn as nn
from sklearn.metrics import f1_score

imgs, labels, lm = load_arrays("bloodmnist", "train")
timgs, tlabels, _ = load_arrays("bloodmnist", "test")
NC, SIZE, EPOCHS, BS = len(lm), 64, 8, 128
idx = stratified_subset(labels, 2000, seed=0)
Xtr, Ytr = imgs[idx], labels[idx]
te = make_loader(timgs, tlabels, size=SIZE, bs=256)
SOFT = dict(rot=8, trans=0.05, scale=0.05)

def cosine_warmup(opt, total, warm_frac=0.1):
    warm = max(1, int(total * warm_frac))
    def f(s):
        if s < warm:
            return (s + 1) / warm
        p = (s - warm) / max(1, total - warm)
        return 0.5 * (1 + math.cos(math.pi * p))
    return torch.optim.lr_scheduler.LambdaLR(opt, f)

@torch.no_grad()
def tta(m):
    m.eval()
    P, Y = [], []
    for xb, yb in te:
        xb = xb.to(DEVICE)
        p = m(norm(xb)).softmax(1) + m(norm(torch.flip(xb, dims=[3]))).softmax(1)
        P.append((p / 2).float().cpu()); Y.append(yb)
    P, Y = torch.cat(P), torch.cat(Y)
    return (float((P.argmax(1) == Y).float().mean()),
            float(f1_score(Y.numpy(), P.argmax(1).numpy(), average="macro")))

def run(pretrained, aug, sched_on, ls=0.0, use_tta=False, seed=42):
    set_seed(seed)
    m = build_resnet18(NC, pretrained=pretrained)
    if pretrained:
        def g(prefix, lr):
            return {"params": [p for n, p in m.named_parameters()
                               if n.startswith(prefix)], "lr": lr}
        opt = torch.optim.AdamW([g("layer1", 1e-5), g("layer2", 1e-5),
                                 g("layer3", 3e-5), g("layer4", 1e-4),
                                 g("fc", 1e-3)], lr=1e-3, weight_decay=1e-4)
    else:
        opt = torch.optim.AdamW(m.parameters(), lr=1e-3, weight_decay=1e-4)
    tl = make_loader(Xtr, Ytr, size=SIZE, train=True, bs=BS)
    sched = cosine_warmup(opt, len(tl) * EPOCHS) if sched_on else None
    train(m, tl, te, epochs=EPOCHS, optimizer=opt, sched=sched,
          criterion=nn.CrossEntropyLoss(label_smoothing=ls), aug=aug)
    if use_tta:
        return tta(m)
    acc, _, probs, ys = evaluate(m, te)
    return float(acc), float(f1_score(ys.numpy(), probs.argmax(1).numpy(), average="macro"))

rows = [
    ("1 基线（从头训 + 常数 LR + 无增强）", run(False, {}, False)),
    ("2 + 安全增强", run(False, SOFT, False)),
    ("3 + Cosine + warmup", run(False, SOFT, True)),
    ("4 + 预训练（差分 LR）", run(True, SOFT, True)),
    ("5 + Label Smoothing 0.1", run(True, SOFT, True, ls=0.1)),
    ("6 + TTA", run(True, SOFT, True, ls=0.1, use_tta=True)),
]
for s in [0, 1, 2]:
    print("seed", s, run(True, SOFT, True, ls=0.1, use_tta=True, seed=s))
```

**实测输出**

BloodMNIST 2000 张，ResNet18 @64×64，8 epoch，batch 128，种子 42：

| # | 配置 | accuracy | macro F1 | 相对上一行 |
|---|---|---|---|---|
| 1 | 基线：从头训 + 常数 LR + 无增强 | 0.8272 | 0.8050 | — |
| 2 | + 安全增强 | 0.7603 | 0.7095 | **−6.69** |
| 3 | + Cosine + warmup | 0.8901 | 0.8732 | **+12.98** |
| 4 | + 预训练（差分 LR） | 0.8308 | 0.8045 | **−5.93** |
| 5 | + Label Smoothing 0.1 | 0.8167 | 0.7895 | **−1.41** |
| 6 | + TTA（原图 + 水平翻转） | 0.8416 | 0.8161 | **+2.49** |

最后一行 3 个种子：

| 种子 | accuracy |
|---|---|
| 0 | 0.8416 |
| 1 | 0.8261 |
| 2 | 0.8375 |
| 均值 ± 标准差 | **0.8350 ± 0.0080** |

**三个掉点行，逐个分析**

**第 2 行掉 6.69 个点，是本表最大的负作用。** 安全增强的参数是 rot=8、trans=0.05、scale=0.05，在 64×64 上不算重，但基线只有 8 个 epoch。增强每个 batch 都在改输入，模型要用更多的轮数才能拟合同样的训练集；8 epoch 不够，模型还停在"欠训练"阶段，增强的收益还没显现，成本先付了。第 3 行加上 Cosine 后涨 13 个点，说明训练预算和调度才是这一段的瓶颈，增强本身不是错的。

**第 4 行掉 5.93 个点，是分辨率问题。** 64×64 下 layer4 输出是 2×2，比 28×28 的 1×1 好，但仍然很粗。差分学习率把浅层锁在 1e-5，8 个 epoch 里浅层几乎没动，深层也只走了很少的步。预训练特征是 ImageNet 的自然图像语义，和血细胞的染色纹理不匹配，模型没有足够的预算把它调过来。讲义 6.3 节 20 epoch 时预训练是正收益（0.8392 对 0.7638），这里 8 epoch 就反了。**同一组配置，训练预算不同，结论相反，这正是"迁移学习值多少要看预算"的意思。**

**第 5 行掉 1.41 个点，是 label smoothing 和干净标签的冲突。** BloodMNIST 是 8 类均衡数据，标签由细胞形态决定，一致性高。LS 假设"标签有噪声"，在这里是错误假设，它把模型往"不确定"的方向推。讲义 4.2 节说 LS 对医学数据有用，前提是临床标签确实有噪声（kappa 0.6-0.8），不是所有医学数据集都满足。

**第 3 行为什么涨 13 个点**

Cosine + 10% warmup 在这个预算下是决定性的。基线用常数 1e-3，8 个 epoch 里学习率一直很大，最后几轮 loss 在震荡，模型没有收敛到一个尖锐的解。Cosine 让学习率在后半程降到接近 0，模型有时间把权重收进一个局部极小。这不是"调度一定涨点"，而是"短预算 + 常数大学习率"本身就是一个坏组合。

**3 个种子的解读**

均值 0.8350，标准差 0.0080（0.8 个点）。这意味着：

- 两个配置差 1 个点以内，单种子无法区分是方法有效还是种子碰巧。
- 第 5 行和第 4 行差 1.41 个点，略高于 1 个标准差，但仍然不够稳健，最好补 3 个种子。
- 第 2 行和第 3 行的 6-13 个点差距，远超种子噪声，可以下结论。

**判分要点**

- 6 行都是真实跑出来的，同一份数据、同一个种子、同一个测试集。
- 最后一行必须补 3 个种子，报 mean ± std（实测 0.8350 ± 0.0080）。
- 掉点的行必须有分析，而且分析要落到具体机制，不能写"可能是随机性"。
- 能指出第 2 行的掉点是训练预算不足，不是增强有害。
- 能指出第 4 行的掉点是分辨率 + 预算，并知道 20 epoch 时结论会变。
- 能说明本表用 8 epoch，绝对值不能和讲义的 20 epoch 表逐行对比。

**常见错误**

- 累积消融每行换一个种子，测的是噪声不是方法。
- 只跑最后一行，不跑中间行，不知道哪一步是白做的。
- 看到掉点就删掉那一行，只留涨点的。掉点比涨点更有信息量。
- 用测试集选"最好的一行"。所有选择应该在验证集上做。
- 单种子报 0.8416 就下结论，不说标准差 0.0080。

### 练习 10-G（早停 + 调度曲线）

**参考代码**

```python
import math
import numpy as np
import torch
import torch.nn as nn

import sys
sys.path.insert(0, r"E:\AI学习\模块10_迁移学习与训练技巧\_exp")
import common as C
from common import (DEVICE, build_resnet18, evaluate, load_arrays,
                    make_loader, norm, set_seed, stratified_subset, train)

imgs, labels, lm = load_arrays("bloodmnist", "train")
vimgs, vlabels, _ = load_arrays("bloodmnist", "val")
idx = stratified_subset(labels, 2000, seed=0)

set_seed(42)
m = build_resnet18(len(lm), pretrained=True).to(DEVICE)
for n_, p in m.named_parameters():                 # 只解冻 layer3 以后
    p.requires_grad = n_.startswith(("layer3", "layer4", "fc"))

def g(prefix, lr):
    return {"params": [p for n_, p in m.named_parameters()
                       if p.requires_grad and n_.startswith(prefix)], "lr": lr}

opt = torch.optim.AdamW([g("layer3", 3e-5), g("layer4", 1e-4), g("fc", 1e-3)],
                        lr=1e-3, weight_decay=1e-4)
tl = make_loader(imgs[idx], labels[idx], size=28, train=True, bs=128)
vl = make_loader(vimgs, vlabels, size=28, bs=256)
EPOCHS = 20

def cosine_warmup(opt, total, warm_frac=0.1):
    warm = max(1, int(total * warm_frac))
    def f(s):
        if s < warm:
            return (s + 1) / warm
        p = (s - warm) / max(1, total - warm)
        return 0.5 * (1 + math.cos(math.pi * p))
    return torch.optim.lr_scheduler.LambdaLR(opt, f)

sched = cosine_warmup(opt, len(tl) * EPOCHS)
crit = nn.CrossEntropyLoss()

hist, best_loss, best_state = [], float("inf"), None
bad, patience = 0, 5
for ep in range(EPOCHS):
    m.train()
    for xb, yb in tl:
        xb = norm(xb.to(DEVICE)); yb = yb.to(DEVICE)
        opt.zero_grad(set_to_none=True)
        loss = crit(m(xb), yb)
        loss.backward()
        opt.step()
        sched.step()
    va, vloss, _, _ = evaluate(m, vl, crit)
    hist.append({"epoch": ep + 1, "lr": opt.param_groups[-1]["lr"],
                 "val_loss": vloss, "val_acc": va})
    if vloss < best_loss - 1e-4:
        best_loss = vloss
        best_state = {k: v.clone() for k, v in m.state_dict().items()}
        bad = 0
    else:
        bad += 1
        if bad >= patience:
            print("early stop at", ep + 1)
            break

m.load_state_dict(best_state)                      # 关键：恢复最好权重
```

**实测输出**

BloodMNIST 2000 张，ResNet18 @28×28，预训练 + 差分 LR（layer3 3e-5、layer4 1e-4、fc 1e-3），batch 128，验证集 1712 张：

| epoch | 学习率 | 验证 loss | 验证准确率 |
|---|---|---|---|
| 1 | 5.33e-04（warmup 中） | 1.9469 | 0.2967 |
| 2 | **1.00e-03（峰值）** | 1.1452 | 0.6700 |
| 3 | 9.92e-04 | 0.7564 | 0.7348 |
| 4 | 9.70e-04 | 0.6485 | 0.7850 |
| 5 | 9.33e-04 | 0.6071 | 0.7938 |
| 6 | 8.83e-04 | 0.6095 | 0.7944 |
| 7 | 8.21e-04 | 0.6162 | 0.7961 |
| **8** | 7.50e-04 | **0.6051（最低）** | 0.8078 |
| 9 | 6.71e-04 | 0.6291 | 0.8049 |
| 10 | 5.87e-04 | 0.6298 | 0.8072 |
| 11 | 5.00e-04 | 0.6318 | 0.8084 |
| 12 | 4.13e-04 | 0.6308 | 0.8107 |
| 13 | 3.29e-04 | 0.6391 | 0.8090 |

`early stop at epoch 13`，`best_epoch = 8`，最优验证 loss 0.6051。

**学习率曲线的形状**

```
step 0        -> 0            （从 0 开始，不是从 1e-3 开始）
step warm(10%) -> 1.00e-03    （前 10% 步数线性上升到峰值）
step 之后      -> 余弦下降到 0（0.5 * (1 + cos(pi * p))）
```

epoch 1 打印的 lr 是 5.33e-04，因为打印发生在 epoch 末尾，warmup 还没走完；epoch 2 到达 1.00e-03 峰值，之后单调下降。这条曲线的形状是"先线性上升、再余弦下降"，和设计一致。

**早停为什么在第 13 轮触发**

验证 loss 在第 8 轮到达最低 0.6051，之后第 9 到 13 轮分别是 0.6291、0.6298、0.6318、0.6308、0.6391，连续 5 轮没有低于 0.6051 - 1e-4，patience=5 用完，停止。

**注意验证准确率还在涨（0.8078 → 0.8090），但 loss 在涨。** 这就是"早停监控 loss 而不是 accuracy"的理由：accuracy 是阶梯状的，1712 张的最小变化单位是 1/1712 = 0.00058，它会在同一个值附近徘徊，早停判断会失效；loss 是连续的，能更早发现过拟合。本例里准确率到第 13 轮还在缓慢上升，但 loss 已经连续 5 轮变差，说明模型在把正确样本的置信度推得更高，同时把错样本推得更错，泛化没有变好。

**一个诚实的观察：第 5 到第 8 轮的 loss 差异只有 0.002（0.6071 对 0.6051）。** 这个量级在单次训练里接近噪声，所谓"最优 epoch"有很大偶然性。更稳的做法是用 3 个种子各跑一次早停，看最优 epoch 的分布；本实验只跑了单种子，所以只能说"早停停在第 13 轮"，不能说"第 8 轮一定比第 5 轮好"。

**为什么必须保存 best_state**

早停停了以后，模型里装的是第 13 轮的权重，不是第 8 轮的。第 13 轮的验证 loss 是 0.6391，比第 8 轮的 0.6051 差 5.6%。如果只记录 `best_loss` 而不保存 `state_dict`，训练结束后你拿到的是"训得最久的那一版"，不是"最好的一版"。

```python
# 错误：只记 loss
if vloss < best_loss:
    best_loss = vloss
# 训练结束后 model 里是最后一轮的权重

# 正确：同时存权重
if vloss < best_loss:
    best_loss = vloss
    best_state = {k: v.clone() for k, v in model.state_dict().items()}
...
model.load_state_dict(best_state)
```

`clone()` 不能省。直接存 `model.state_dict()` 拿到的是引用，下一轮 `optimizer.step()` 会原地改掉这些张量，你存的"最好权重"会跟着变。

**判分要点**

- lr 曲线必须能看出"前 10% 线性上升、之后余弦下降"，最好打印每个 epoch 的 lr 核对。
- 能标出早停发生的 epoch（13）和最优 epoch（8），并说明两者不是同一个。
- 能解释为什么监控 val loss 而不是 val accuracy（阶梯指标、判断失效）。
- 能解释为什么必须保存 best_state（最后一轮不是最好的一轮）。
- 能指出 `state_dict()` 要 clone，否则存的是引用。
- 能说明本例准确率还在涨但 loss 在涨，二者背离时以 loss 为准。

**常见错误**

- 早停只记 `best_loss`，不存权重，最后用的是第 13 轮。
- 早停监控 accuracy，1712 张的阶梯太粗，判断失效。
- patience 设成 2-3，医学数据噪声大，会在正常波动处误停。
- `scheduler.step()` 放在 epoch 循环里但调度器是按 step 设计的，lr 曲线错乱。
- 存 `state_dict()` 不 clone，最好权重被后续 step 覆盖。
- warmup 从 0 开始时忘了 `(step + 1) / warm`，第一步 lr 恒为 0，白跑一个 iter。
