### 练习 1（手算 Dice 和 IoU）

**参考代码**

```python
def dice_iou(a, b, inter):
    dice = 2 * inter / (a + b)
    iou = inter / (a + b - inter)
    return dice, iou

for a, b, i in [(100, 120, 90), (500, 400, 350), (100, 100, 60)]:
    d, j = dice_iou(a, b, i)
    d_back = 2 * j / (1 + j)      # 从 IoU 反算 Dice
    j_back = d / (2 - d)          # 从 Dice 反算 IoU
    print(f"A={a} B={b} inter={i}")
    print(f"  Dice={d:.4f}  IoU={j:.4f}")
    print(f"  反算 Dice={d_back:.4f}  反算 IoU={j_back:.4f}")
    print(f"  误差 {abs(d - d_back):.2e} / {abs(j - j_back):.2e}")

d = 0.5
print("Dice=0.5 时 IoU =", d / (2 - d))
```

**手算过程**

第 (1) 组：|A| = 100，|B| = 120，|A∩B| = 90。

```
Dice = 2 × 90 / (100 + 120) = 180 / 220 = 0.81818...
IoU  = 90 / (100 + 120 - 90) = 90 / 130 = 0.69230...
```

第 (2) 组：|A| = 500，|B| = 400，|A∩B| = 350。

```
Dice = 2 × 350 / (500 + 400) = 700 / 900 = 0.77777...
IoU  = 350 / (500 + 400 - 350) = 350 / 550 = 0.63636...
```

第 (3) 组：|A| = 100，|B| = 100，|A∩B| = 60。

```
Dice = 2 × 60 / (100 + 100) = 120 / 200 = 0.60000
IoU  = 60 / (100 + 100 - 60) = 60 / 140 = 0.42857...
```

反算验证（以第 1 组为例）：

```
从 IoU 反算 Dice：2 × 0.692307 / (1 + 0.692307) = 1.384615 / 1.692307 = 0.818182
从 Dice 反算 IoU ：0.818182 / (2 - 0.818182) = 0.818182 / 1.181818 = 0.692308
```

三组结果汇总：

| 组 | |A| | |B| | |A∩B| | Dice | IoU |
|---|---|---|---|---|---|---|
| 1 | 100 | 120 | 90 | 0.8182 | 0.6923 |
| 2 | 500 | 400 | 350 | 0.7778 | 0.6364 |
| 3 | 100 | 100 | 60 | 0.6000 | 0.4286 |

**实测输出**

```
A=100 B=120 inter=90: Dice=0.818182 IoU=0.692308 反算 Dice=0.818182 反算 IoU=0.692308
A=500 B=400 inter=350: Dice=0.777778 IoU=0.636364 反算 Dice=0.777778 反算 IoU=0.636364
A=100 B=100 inter=60: Dice=0.600000 IoU=0.428571 反算 Dice=0.600000 反算 IoU=0.428571
Dice=0.5 时 IoU = 0.3333333333333333
```

反算误差三组都是 0 或 1.1e-16（浮点舍入），小于 1e-4 的验收线。

**Dice = 0.5 时 IoU 为什么是 1/3**

把 Dice = 1/2 代进 IoU = Dice / (2 - Dice)：

```
IoU = 0.5 / (2 - 0.5) = 0.5 / 1.5 = 1/3
```

直观解释：Dice 的分母是 |A| + |B|，IoU 的分母是 |A| + |B| - |A∩B|。完全重合时两者都是 1；一旦有差异，IoU 的分母比 Dice 小，所以 IoU 总是更低，而且 Dice 越低差距越大。Dice 0.5 意味着重叠量只有两边面积之和的四分之一，并集却是面积之和的四分之三，比值正好 1/3。

**判分要点**

- 三组 Dice / IoU 必须与 0.8182/0.6923、0.7778/0.6364、0.6000/0.4286 一致，四位小数。
- 必须写出两个换算式：Dice = 2×IoU/(1+IoU)，IoU = Dice/(2-Dice)，并且能反算回原值。
- 能指出 IoU 恒小于 Dice（除 0 和 1 两个端点），且 Dice 越低两者差距越大。
- 能解释 1/3 的来历，而不是背结论。

**常见错误**

- 把 IoU 的分母写成 |A| + |B|，算出来和 Dice 一样。IoU 的分母是并集，要减掉交集。
- 反算时把公式记反，用 Dice = IoU/(2-IoU)。记不住就现场推一遍：|A|+|B| = 并集 + 交集。
- 保留两位小数就交卷。Dice 0.82 和 0.8182 在论文里不是一个精度层级。
- 把 Dice 和 IoU 当成两个独立指标同时报，等于重复计分。

### 练习 2（复现"全猜背景"陷阱）

**参考代码**

```python
import numpy as np

def case_dice(pred, target, cls):
    p, t = (pred == cls), (target == cls)
    denom = p.sum() + t.sum()
    if denom == 0:
        return 1.0
    return float(2 * (p & t).sum() / denom)

d = np.load(r"E:\AI学习\模块11_医学图像分割\outputs\phantom.npz")
y = d["va_y"]                      # (100, 256, 256)
n = len(y)

for name, cls in [("全猜背景", None), ("全猜肝脏", 1), ("全猜肿瘤", 2)]:
    pred = np.zeros_like(y) if cls is None else np.full_like(y, cls)
    acc = float((pred == y).mean())
    ld = np.mean([case_dice(pred[i], y[i], 1) for i in range(n)])
    td = np.mean([case_dice(pred[i], y[i], 2)
                  for i in range(n) if (y[i] == 2).any()])
    print(f"{name}: 像素准确率 {acc:.4f}  肝脏 Dice {ld:.4f}  肿瘤 Dice {td:.4f}")

print("前景比例", (y > 0).mean())
print("肝脏比例", (y == 1).mean())
print("肿瘤比例", (y == 2).mean())
```

**实测输出**

```
全猜背景: 像素准确率 0.8284  肝脏 Dice 0.0000  肿瘤 Dice 0.0000
全猜肝脏: 像素准确率 0.1671  肝脏 Dice 0.2861  肿瘤 Dice 0.0000
全猜肿瘤: 像素准确率 0.0045  肝脏 Dice 0.0000  肿瘤 Dice 0.0103
前景 0.1716  肝脏 0.1671  肿瘤 0.0045
```

**为什么 0.83 的准确率等于什么都没学会**

验证集里 82.84% 的像素本来就是背景。一个把每个像素都判成背景的模型，只要"答对"这 82.84%，就能拿到 0.8284 的像素准确率。但它对肝脏和肿瘤的 Dice 都是 0，也就是说它一个前景像素都没找到。

像素准确率把"背景"和"病灶"当成同等重要的两类来计分，而这两类的像素数差了 184 倍（背景 82.84% 对肿瘤 0.45%）。模型只要押注多数类就能拿高分，这不需要学到任何解剖结构。所以分割任务的主指标必须是 Dice 或 IoU，准确率只能作为辅助参考。

**一个必须注意的口径差异**

全猜肝脏的肝脏 Dice，按"逐例平均"算是 0.2861；按"全图汇总"的公式 `2×0.167147/(0.167147+1)` 算是 0.2864。两者差 0.0003，来源是前者先算每例再平均、后者把所有像素混在一起算。这说明**报 Dice 时必须说明口径**，否则两个都"对"的数字会对不上。

**判分要点**

- 三个预测的准确率和 Dice 都要有，尤其是"准确率 0.8284 而 Dice 0"这个组合。
- 能说清准确率被背景主导的机制：背景占 82.84%，模型押多数类即可。
- 能指出全猜肝脏的准确率只有 0.1671，比全猜背景低得多，但它的肝脏 Dice 反而更高（0.2861 对 0）。准确率和 Dice 在这里是背离的。
- 能提到口径：逐例平均和全局汇总是两个数。

**常见错误**

- 只算准确率就下结论"模型 83% 很准"。
- 用 `(pred == y).mean()` 算 Dice，把背景也算进去。
- 空病灶病例直接跳过，导致假阳性不计入。本例 13 例无肿瘤，跳过它们会让指标虚高。
- 用 `smooth=1.0` 算 Dice，把"预测全空、真实有病灶"的 0 抬成 0.0099。

### 练习 3（从零写 U-Net 并验证尺寸）

**参考代码**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class DoubleConv(nn.Module):
    def __init__(self, cin, cout):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(cin, cout, 3, padding=1, bias=False),
            nn.BatchNorm2d(cout), nn.ReLU(inplace=True),
            nn.Conv2d(cout, cout, 3, padding=1, bias=False),
            nn.BatchNorm2d(cout), nn.ReLU(inplace=True))
    def forward(self, x):
        return self.net(x)

class UNet(nn.Module):
    def __init__(self, in_ch=1, num_classes=3, base=32):
        super().__init__()
        c = [base, base * 2, base * 4, base * 8]
        self.enc1, self.enc2 = DoubleConv(in_ch, c[0]), DoubleConv(c[0], c[1])
        self.enc3, self.enc4 = DoubleConv(c[1], c[2]), DoubleConv(c[2], c[3])
        self.pool = nn.MaxPool2d(2)
        self.bottleneck = DoubleConv(c[3], base * 16)
        self.up4 = nn.ConvTranspose2d(base * 16, c[3], 2, stride=2)
        self.up3 = nn.ConvTranspose2d(c[3], c[2], 2, stride=2)
        self.up2 = nn.ConvTranspose2d(c[2], c[1], 2, stride=2)
        self.up1 = nn.ConvTranspose2d(c[1], c[0], 2, stride=2)
        self.dec4 = DoubleConv(c[3] * 2, c[3])
        self.dec3 = DoubleConv(c[2] * 2, c[2])
        self.dec2 = DoubleConv(c[1] * 2, c[1])
        self.dec1 = DoubleConv(c[0] * 2, c[0])
        self.head = nn.Conv2d(c[0], num_classes, 1)

    def forward(self, x):
        e1 = self.enc1(x)
        e2 = self.enc2(self.pool(e1))
        e3 = self.enc3(self.pool(e2))
        e4 = self.enc4(self.pool(e3))
        b = self.bottleneck(self.pool(e4))
        d4 = self.dec4(torch.cat([self.up4(b), e4], 1))
        d3 = self.dec3(torch.cat([self.up3(d4), e3], 1))
        d2 = self.dec2(torch.cat([self.up2(d3), e2], 1))
        d1 = self.dec1(torch.cat([self.up1(d2), e1], 1))
        return self.head(d1)

m = UNet(1, 3)
y = m(torch.randn(1, 1, 256, 256))
print("256 输出", tuple(y.shape))
print("参数量", sum(p.numel() for p in m.parameters()))

# 250 输入：观察报错
try:
    m(torch.randn(1, 1, 250, 250))
except Exception as e:
    print("250 报错:", type(e).__name__, e)

# pad 到 256，推理后裁回 250
x = torch.randn(1, 1, 250, 250)
xp = F.pad(x, (3, 3, 3, 3))
yp = m(xp)
yc = yp[:, :, 3:253, 3:253]
print("pad 后", tuple(yp.shape), "裁回", tuple(yc.shape))
```

**实测输出**

```
256 输出 (1, 3, 256, 256)
参数量 7762531
250 报错: RuntimeError: Sizes of tensors must match except in dimension 1. Expected size 30 but got size 31 for tensor number 1 in the list.
pad 后 (1, 3, 256, 256) 裁回 (1, 3, 250, 250)
```

**250 输入错在哪一层**

逐层数一遍：

```
250 -> enc1 250 -> pool 125 -> enc2 125 -> pool 62 -> enc3 62
    -> pool 31  -> enc4 31  -> pool 15 -> bottleneck 15
```

上采样：

```
bottleneck 15 -> up4 30，但 enc4 是 31 -> torch.cat([30, 31], dim=1) 报错
```

报错信息里的 `Expected size 30 but got size 31` 就是这一层：`up4` 把 15 翻倍成 30，skip 过来的 `e4` 是 31。根因是 `250 -> 125` 这一步向下取整丢了 1 个像素，后面每一步都差一点。

**pad 的算式**：250 不是 16 的倍数，下一个 16 的倍数是 256，差 6，左右各补 3。推理完 `[3:253]` 裁回 250。训练时如果直接用 256 的 patch，就不需要 pad。

**换成 F.interpolate + Conv2d 的版本**

```python
class UpBlock(nn.Module):
    """双线性放大 2 倍，再接 3x3 卷积。"""
    def __init__(self, cin, cout):
        super().__init__()
        self.conv = nn.Conv2d(cin, cout, 3, padding=1)
    def forward(self, x):
        return self.conv(F.interpolate(x, scale_factor=2, mode="bilinear",
                                       align_corners=False))
```

把四个 `ConvTranspose2d` 换成 `UpBlock` 后：

```
输出形状 (1, 3, 256, 256)  与转置卷积版一致
参数量 8632931             比转置卷积版多 870,400
```

参数量多出来的原因：转置卷积 `ConvTranspose2d(cin, cout, 2, stride=2)` 的卷积核是 2×2，参数量是 `cin*cout*4`；换成 `3×3 Conv2d` 后是 `cin*cout*9`，多出 2.25 倍的那部分。

**判分要点**

- 256 输入输出必须是 `(1, 3, 256, 256)`，参数量 7.76M ± 0.05M（实测 7,762,531，即 7.763M）。
- 能准确说出 250 输入报错在 `dec4` 的 `torch.cat`，并且给出 30 与 31 的来历，不能只说"尺寸不匹配"。
- pad 要补到 256（左右各 3），推理后能裁回 250。
- 双线性 + 卷积版本输出形状不变，能解释参数量为什么变了。

**常见错误**

- 上采样次数和下采样次数不配对，输出比输入小一圈。
- `torch.cat` 写成 `dim=0`，在 batch 维拼接，通道数不对还报奇怪的错。
- `ConvTranspose2d(2, stride=2)` 写成 `kernel_size=3, stride=2`，输出会多 1 个像素（257），需要 `output_padding=1`。
- pad 之后忘了裁回去，输出和原图不对齐，Dice 直接算错。
- 在 250 输入上直接 `F.interpolate` 到 256 再推理，然后忘了把预测缩回 250，评估时形状对不上。

### 练习 4（patch 采样统计）

**参考代码**

```python
import numpy as np

d = np.load(r"E:\AI学习\模块11_医学图像分割\outputs\phantom.npz")
va_y = d["va_y"]
pos_idx = [i for i in range(len(va_y)) if (va_y[i] == 2).any()]
rng = np.random.default_rng(0)

for patch in [64, 96]:
    tum = bg = 0
    for _ in range(2000):
        i = pos_idx[rng.integers(0, len(pos_idx))]
        y0 = rng.integers(0, 256 - patch + 1)
        x0 = rng.integers(0, 256 - patch + 1)
        p = va_y[i, y0:y0 + patch, x0:x0 + patch]
        tum += int((p == 2).any())
        bg += int((p == 0).all())
    print(f"{patch}x{patch}: 含肿瘤 {tum/2000:.4f}  纯背景 {bg/2000:.4f}")

# pos:neg = 1:1，正样本中心落在肿瘤上，负样本随机
for patch in [64, 96]:
    hit = 0
    for k in range(2000):
        i = pos_idx[rng.integers(0, len(pos_idx))]
        if k % 2 == 0:
            ys, xs = np.where(va_y[i] == 2)
            j = rng.integers(0, len(ys))
            y0 = int(np.clip(ys[j] - rng.integers(0, patch), 0, 256 - patch))
            x0 = int(np.clip(xs[j] - rng.integers(0, patch), 0, 256 - patch))
        else:
            y0 = int(rng.integers(0, 256 - patch + 1))
            x0 = int(rng.integers(0, 256 - patch + 1))
        p = va_y[i, y0:y0 + patch, x0:x0 + patch]
        hit += int((p == 2).any())
    print(f"{patch} pos:neg=1:1 -> 含肿瘤 {hit/2000:.4f}")
```

**实测输出**

```
87 例有肿瘤的验证图
64x64 随机: 含肿瘤 0.1815  纯背景 0.3315
96x96 随机: 含肿瘤 0.4265  纯背景 0.0410
64x64 pos:neg=1:1: 含肿瘤 0.5870
96x96 pos:neg=1:1: 含肿瘤 0.7080
```

**怎么读这两组数**

| patch | 随机含肿瘤 | 随机纯背景 | pos:neg 1:1 后含肿瘤 |
|---|---|---|---|
| 64×64 | 0.1815 | 0.3315 | 0.5870 |
| 96×96 | 0.4265 | 0.0410 | 0.7080 |

随机采样下，64×64 有三分之一是纯背景，只有 18% 含肿瘤。一个 batch 8 个 patch，平均只有 1.4 个含肿瘤，其余都在告诉模型"这里没有病灶"。

**为什么 patch 越大越容易碰到肿瘤**：肿瘤在整张图里只占 0.45%，但它不是均匀撒开的，而是集中在肝脏内部的一小块。patch 越大，覆盖的视野越大，碰到这块区域的概率越高。面积比是 (96/64)² = 2.25 倍，实测命中率从 0.1815 涨到 0.4265，涨了 2.35 倍，和面积比基本对得上。

**pos:neg 1:1 后为什么不是精确的 0.50**

这是本练习最值得写进报告的一点。我最初的实现里，负样本是"随机位置"，不是"纯背景位置"。随机 patch 本身有 18%（或 41%）的概率含肿瘤，所以：

```
含肿瘤比例 = 0.5 × 1.0（正样本必有肿瘤）+ 0.5 × 0.18（负样本偶然含肿瘤）= 0.59
```

实测 0.587，对上。96×96 时是 0.5 + 0.5×0.4265 = 0.713，实测 0.708，也对上。

要让比例严格等于 0.50，负样本必须显式从 `label == 0` 的纯背景区域采样。这么做之后，含肿瘤比例就是构造出来的 0.50，但代价是训练分布和真实推理分布不一致：推理时 patch 里是可能同时有背景和肿瘤的。所以实践里更常见的是"正样本中心落在病灶、负样本中心落在背景，但 patch 内不限制"，接受 0.55-0.60 的实际比例。

**判分要点**

- 64×64 的两个比例要在 0.18 / 0.33 附近（±0.03），96×96 在 0.41 / 0.04 附近。
- 能解释"patch 越大命中率越高"来自面积覆盖，并给出 2.25 倍的量级。
- pos:neg 采样后能报出实际比例，并解释它为什么不是 0.50。**能主动发现"负样本不纯"这个细节的，是优秀答案。**
- 能说出采样比例不是最重要的，"有没有采样"才是。

**常见错误**

- 在全部 100 例上采样，包括 13 例无肿瘤的。这样含肿瘤比例会被稀释，而且无肿瘤图上的"正样本"根本不存在。
- 用 `np.random.randint` 时上界写成 `256 - patch`，漏掉最后一个合法位置。
- 认为 pos:neg 设成 1:1 就等于"50% 含肿瘤"，不检查负样本里混进了多少前景。
- 只统计"中心点是不是肿瘤"，不统计"patch 里有没有肿瘤"。分割任务关心的是后者。

- 肝脏 Dice ≥ 0.95、肿瘤 Dice ≥ 0.60（实测 0.9821 / 0.7110，达标）。
- 报告里必须同时有均值、中位数、失败率，缺一不可。

- 对第 10 轮的掉点，能区分"个别病例"和"全局现象"。三个指标同向下降指向 BN 统计量或优化状态，不是某几例。
- 必须说明数据是合成体模，数字不能写进论文当 LiTS 结果。

**常见错误**

- 只报均值 0.7110，不提 14 例 0 分。
- 把"有肿瘤的 83 例"和"全部 100 例"混着平均。无肿瘤病例的肿瘤 Dice 按定义是 1（都空），混进去会把均值抬高到 0.76 左右，虚报性能。

- 用测试集选最佳 epoch。本例的 best 是按验证集分数选的，测试集只评一次。
- 把第 10 轮的掉点解释成"学习率太大"，但学习率是 cosine 单调下降的，第 10 轮并没有突变。

### 练习 6（滑窗推理）

**参考代码**

```python
import time
import numpy as np
import torch
import torch.nn.functional as F

def gaussian_window(size, sigma=None):
    sigma = sigma or size / 8
    ax = np.arange(size) - (size - 1) / 2
    g = np.exp(-(ax ** 2) / (2 * sigma ** 2))
    w = np.outer(g, g)
    return (w / w.max()).astype(np.float32)

@torch.no_grad()
def infer_direct(model, x):
    return model(x).argmax(1)[0].cpu().numpy().astype(np.uint8)

@torch.no_grad()
def infer_resize(model, x, size=256):
    small = F.interpolate(x, size=(size, size), mode="bilinear", align_corners=False)
    logits = model(small)
    logits = F.interpolate(logits, size=x.shape[-2:], mode="bilinear",
                           align_corners=False)
    return logits.argmax(1)[0].cpu().numpy().astype(np.uint8)

@torch.no_grad()
def infer_sliding(model, x, window=128, stride=64, num_classes=3):
    _, _, H, W = x.shape
    prob = torch.zeros((num_classes, H, W), device=x.device)
    weight = torch.zeros((H, W), device=x.device)
    g = torch.from_numpy(gaussian_window(window)).to(x.device)
    ys = list(range(0, H - window + 1, stride))
    xs = list(range(0, W - window + 1, stride))
    if ys[-1] != H - window:
        ys.append(H - window)
    if xs[-1] != W - window:
        xs.append(W - window)
    for yy in ys:
        for xx in xs:
            patch = x[:, :, yy:yy+window, xx:xx+window]
            p = torch.softmax(model(patch), 1)[0]
            prob[:, yy:yy+window, xx:xx+window] += p * g
            weight[yy:yy+window, xx:xx+window] += g
    return (prob / weight).argmax(0).cpu().numpy().astype(np.uint8)

def peak(fn, *a):
    torch.cuda.empty_cache()
    torch.cuda.reset_peak_memory_stats()
    t = time.time()
    out = fn(*a)
    torch.cuda.synchronize()
    return out, torch.cuda.max_memory_allocated() / 1e6, time.time() - t
```

**缩到 256 为什么肿瘤 Dice 崩了**

512 缩到 256 是 2 倍降采样。一个半径 4-10 像素的病灶，缩完只剩 2-5 像素。经过 4 次下采样（每次减半），在瓶颈层只剩不到 1 个像素，网络根本没有足够的空间证据判断"这里有一个低密度灶"。同时双线性插值会把病灶和周围肝实质的 8-22 HU 差值平均掉，边界更糊。

看具体病例更清楚：病例 1、3、5 的肿瘤 Dice 在缩放后直接变成 0，而这三例在直接推理下分别是 0.428、0.841、0.927。这不是"精度略降"，是把病灶整块丢了。

**滑窗为什么反而比直接推理好**

直接推理把整张 512×512 塞进一个只在 256×256 上训练过的网络。网络没见过这么大的输入，深层特征图的尺度分布和训练时不一致（BN 的统计量是按 256 输入估的）。滑窗 128 的每个 patch 都是 128×128，比训练尺寸小，但至少每个 patch 内部的解剖尺度是一致的，而且每个窗口都能独立给出局部判断，再用高斯权重融合，边界处不会因为一次前向的误差就被放大。

**overlap 和计算量的关系**

窗口 128、步长 64 时，相邻窗口重叠 64 像素，重叠率 0.5。每个像素被覆盖的次数约 `(window/stride)² = 4` 次。窗口 256、步长 128 时也是 4 次，但窗口面积是 4 倍，单窗口计算量是 4 倍，窗口数量少 4 倍，总计算量相近。实测耗时 0.346 s 对 0.075 s，说明 128 的方案窗口数更多、调度开销更大。

overlap 从 0.5 降到 0.25（步长 96），覆盖次数降到约 1.8 次，速度接近翻倍，但窗口接缝处的融合权重不够平滑，边界更容易出现台阶。

**判分要点**

- 四种方式都要有 Dice、显存、耗时，缺一不可。
- 滑窗 128 的显存要 ≤ 直接推理的 1/3（实测 0.169，达标）。
- 滑窗 128 的肿瘤 Dice 不比直接推理低 5 个点；实测反而高 3.7 个点，明显达标。
- 能解释缩放丢病灶的机制：降采样 + 插值平滑 + 感受野失配。
- 能说出 overlap 与覆盖次数、计算量的平方关系。

**常见错误**

- 滑窗不补最后一行/一列，右下角永远是黑的。`if ys[-1] != H - window` 这几行不能省。
- 用均匀权重累加，窗口边界出现接缝；高斯权重过渡更平滑。
- 窗口大小和训练 patch 差太远（比如训练 256、推理用 64），每个窗口的上下文都不对。
- 只测 Dice 不测显存，"滑窗省显存"这句话就没有证据。
- 把缩放方案的 0.1629 当成"模型不行"，其实是输入分辨率不对。

### 练习 7（后处理阈值扫描）

**参考代码**

```python
import numpy as np
from scipy import ndimage

def postprocess_tumor(mask, min_tumor):
    out = np.zeros_like(mask)
    liver = mask == 1
    if liver.any():
        lab, n = ndimage.label(liver)
        sizes = ndimage.sum(liver, lab, range(1, n + 1))
        liver = lab == (int(np.argmax(sizes)) + 1)
        liver = ndimage.binary_fill_holes(
            ndimage.binary_closing(liver, np.ones((3, 3))))
        out[liver] = 1

    tumor = mask == 2
    if tumor.any():
        lab, n = ndimage.label(tumor)
        sizes = ndimage.sum(tumor, lab, range(1, n + 1))
        keep = np.zeros_like(tumor)
        for k, s in enumerate(sizes, 1):
            if s >= min_tumor:
                keep |= lab == k
        keep = ndimage.binary_closing(keep, np.ones((3, 3)))
        out[keep] = 2
    return out

def surface(pred, gt):
    if not pred.any() or not gt.any():
        return None
    st = ndimage.generate_binary_structure(2, 1)
    ps = pred ^ ndimage.binary_erosion(pred, st)
    gs = gt ^ ndimage.binary_erosion(gt, st)
    dg = ndimage.distance_transform_edt(~gs)
    dp = ndimage.distance_transform_edt(~ps)
    return np.concatenate([dg[ps], dp[gs]])

d = np.load(r"E:\AI学习\模块11_医学图像分割\outputs\phantom.npz")
gts = d["te_y"]
preds = np.load(r"E:\AI学习\模块11_医学图像分割\outputs\test_pred.npz")["pred"]

for mt in [0, 10, 20, 40, 80, 150, 300]:
    ds, hs = [], []
    for p, t in zip(preds, gts):
        q = postprocess_tumor(p, mt)
        if (t == 2).any():
            ds.append(2 * ((q == 2) & (t == 2)).sum() /
                      ((q == 2).sum() + (t == 2).sum()))
            s = surface(q == 2, t == 2)
            if s is not None:
                hs.append(np.percentile(s, 95))
    print(f"min_tumor={mt:3d}  Dice={np.mean(ds):.4f}  HD95={np.mean(hs):.2f}")

**拐点在哪，该选哪个**

拐点在 20-40 px 之间：

- 0 到 20 px：Dice 从 0.7111 微涨到 0.7114，HD95 从 12.57 降到 10.26，**白赚 2.3 mm 的边界改善，Dice 不降**。
- 40 px：Dice 只掉 0.0009（从 0.7114 到 0.7102），HD95 再降 1.54 mm 到 8.72。
- 80 px 开始崩：Dice 掉 4.7 个点，说明开始误删真病灶。
- 150 px 掉到 0.5197（比 40 px 低 19 个点），300 px 只剩 0.2094，几乎全删光。

**我的选择是 40 px。** 理由：Dice 的代价只有 0.09 个百分点，在 83 例上不到 0.1 个病例的差异，属于噪声量级；HD95 从 12.57 降到 8.72，改善 30.6%。在临床场景里，边界误差从 12.6 mm 降到 8.7 mm 对放疗靶区勾画是有意义的，而 Dice 几乎不动。

但有两个前提必须说清楚：

1. **这个扫描是在测试集上做的。** 严格按规矩，阈值应该在验证集上选，测试集只评一次。验证集和测试集的困难例比例不同（验证集 hard_ratio 0.35，测试集 0.6），所以 40 px 在验证集上的最优点可能更小。
2. **欠训练模型不能用同样的阈值。** 同一个 40 px，2 epoch 模型的 Dice 从 0.2918 掉到 0.2758。弱模型本来就靠小碎块"蒙"到一点重叠，删掉就没了。所以后处理参数必须跟着模型一起调。

**为什么后处理没提高 Dice**

Dice 只看重叠体积。删掉小碎块不会增加任何真阳性像素，它只能做两件事：删掉假阳性（Dice 的分母变小，略微有利），或者误删真病灶的边角（分子变小，不利）。这个模型本来就干净，平均每例只有 0.88 个连通域、少于 20 px 的碎块只有 0.07 个，可删的东西很少，所以 Dice 的收益空间几乎为零。

HD95 看的是表面距离的 95 分位数。一个离主病灶 50 像素的孤立小碎块，会把这一例的 HD95 直接拉到 50 mm；删掉它之后，这一例的 HD95 立刻降到 2-3 mm。少数几例的极端值对均值影响巨大，所以 HD95 的改善远大于 Dice。

**判分要点**

- 表格要有 7 个阈值，Dice 和 HD95 两列都要有。
- 能指出拐点在 20-40 px，并说明 80 px 之后是误删真病灶。
- 结论必须同时报 Dice 和 HD95，不能只挑好看的那个。
- 能解释"后处理提高 HD95 但不提高 Dice"的机制：Dice 看体积、HD95 看极端表面距离。
- **能指出扫描是在测试集上做的、应该改到验证集**，是加分项。

**常见错误**

- 只扫 HD95，把阈值调到 150，Dice 已经掉到 0.52 还觉得"边界变好了"。
- 对肿瘤取最大连通域。肝转移瘤是多发的，这么做会把其他病灶全删掉。本例肿瘤只做小连通域过滤。
- 先赋肿瘤再赋肝脏，肝脏把肿瘤盖掉。顺序必须是先肝后瘤。
- 后处理完不重算指标，报的还是旧数字。
- 形态学核在各向异性数据上用 3×3×3 立方体，物理上其实是椭球。要先重采样。

pos.sort(key=lambda r: r["dice"])

for r in pos[:8]:
    print(f"#{r['i']:3d} Dice={r['dice']:.3f} 面积={r['area']:4d} "
          f"对比度={r['contrast']:5.1f} 病灶数={r['lesions']} "
          f"贴边距离={r['margin']:5.1f} 预测面积={r['pred_area']:4d}")

d = [r["dice"] for r in pos]
for name, key in [("面积", "area"), ("对比度", "contrast"), ("贴边距离", "margin")]:
    rho, p = spearmanr(d, [r[key] for r in pos])
    print(f"Dice vs {name}: rho={rho:.4f}, p={p:.2e}")
```

**实测输出**

测试集 83 例有肿瘤病例，按肿瘤 Dice 升序，最差 8 例：

| 例号 | Dice | 病灶面积 (px) | 对比度 (HU) | 病灶数 | 贴边距离 (px) | 预测面积 (px) |
|---|---|---|---|---|---|---|
| 18 | 0.000 | 171 | 15.7 | 1 | 0.0 | 0 |
| 22 | 0.000 | 179 | 3.7 | 1 | 0.0 | 0 |
| 23 | 0.000 | 115 | 13.6 | 1 | 0.0 | 30 |
| 27 | 0.000 | 70 | 13.9 | 1 | 0.0 | 115 |
| 28 | 0.000 | 90 | 4.7 | 1 | 0.0 | 0 |
| 29 | 0.000 | 215 | 9.4 | 1 | 14.0 | 0 |
| 41 | 0.000 | 55 | 5.9 | 1 | 44.6 | 0 |
| 45 | 0.000 | 243 | 2.1 | 1 | 16.3 | 15 |

83 例中 14 例 Dice 为 0（16.9%），最差 8 例全部为 0。

**Spearman 相关**

| 变量 | rho | p 值 | 方向 |
|---|---|---|---|
| 病灶面积 | **0.5008** | 1.4e-06 | 面积越大，Dice 越高 |
| 对比度 | **0.3792** | 4.1e-04 | 对比度越高，Dice 越高 |
| 贴边距离 | **0.3132** | 3.9e-03 | 离肝边界越远，Dice 越高 |

三个方向都和预期一致，p 值都小于 0.005。面积的相关性最强（rho 0.50），说明**小病灶是首要失败原因**；对比度次之（0.38），贴边最弱但仍显著（0.31）。

**失败分三类**

**第一类：低对比小病灶，完全漏检**

| 例号 | 面积 | 对比度 | 预测面积 | 表现 |
|---|---|---|---|---|
| 28 | 90 px | 4.7 HU | 0 | 完全没看见 |
| 41 | 55 px | 5.9 HU | 0 | 完全没看见 |

两例的对比度都低于 6 HU，而肝实质本身的噪声标准差是 8-15 HU。也就是说，**病灶信号比噪声还弱**。面积都小于 100 px（在 256×256 图里约 10×10），经过 4 次下采样后瓶颈层只剩不到 1 个像素。这类失败不是模型容量不够，是信息在输入和网络结构里就已经丢了。

改进方向：提高输入分辨率（512 而不是 256）、减少一次下采样、或者用 2.5D 把相邻层的信息带进来。单纯加 Dice 权重没用，因为 Dice 也看不见不存在的信号。

**第二类：贴肝边界病灶，被当成肝外组织**

| 例号 | 面积 | 对比度 | 贴边距离 | 预测面积 | 表现 |
|---|---|---|---|---|---|
| 18 | 171 px | 15.7 HU | 0.0 | 0 | 完全漏检 |
| 23 | 115 px | 13.6 HU | 0.0 | 30 | 只预测出一小块 |

两例的对比度都正常（13-16 HU），面积也不算最小（115-171 px），但 `margin = 0` 表示病灶紧贴肝脏轮廓。模型在肝边界处的特征被"肝 vs 非肝"的强边界主导，病灶的那点低密度差异被掩盖了。例 23 只预测出 30 px，说明模型在边界附近只捕捉到了病灶的一角。

改进方向：边界加权损失（boundary loss）、在肝脏 mask 内部做 crop 训练、或者把肝脏分割和肿瘤分割解耦成两级网络。单纯加数据增强帮助有限，因为问题出在边界处的特征竞争。

**第三类：预测存在但位置/面积错，部分命中**

| 例号 | 面积 | 对比度 | 预测面积 | 表现 |
|---|---|---|---|---|
| 27 | 70 px | 13.9 HU | 115 px | 预测面积是真实的 1.6 倍 |
| 45 | 243 px | 2.1 HU | 15 px | 只命中 6% 的面积 |

例 27 的对比度正常，但预测面积偏大 64%，说明模型把病灶周围的肝实质也判成了肿瘤，边界向外扩。例 45 的对比度只有 2.1 HU，是所有病例里最低的，模型只勉强找到 15 px，Dice 为 0。

改进方向：例 27 需要更紧的边界约束（Dice + 边界损失，或者后处理开运算）；例 45 又回到低对比问题，需要多期增强扫描或更强的强度归一化。

**三类失败的共同点**

三类里有两类（第一类和第三类的例 45）都指向同一个根因：**对比度低于噪声**。这不是靠换网络能解决的，得从成像端（多期、薄层）或输入表示端（窗宽窗位、局部对比度增强）入手。第二类才是网络结构问题，可以通过边界损失和两级级联改善。

**判分要点**

- 至少 8 例，必须包含完全漏检（Dice = 0）和部分命中（预测面积非 0 但 Dice 仍低）。
- 每例要有面积、对比度、是否贴边、预测面积四个量化字段，不能只写"这例很难"。
- 分类至少 3 类，每类 2 个例子，分类依据必须是面积/对比度/边界，不是主观描述。
- Spearman 三个系数方向必须正确，最好给出 p 值。
- 每类要有一个具体改进方向，并且能说清为什么这个方向对这类有效。

**常见错误**

- 只挑 Dice 最低的 8 例，全是 0，看不出"部分命中"这一类。必须同时取 0 分和低分非 0。
- 用 Pearson 相关。Dice 在 0 处堆积，分布严重偏态，Pearson 会被异常值带偏，必须用 Spearman。
- 把"对比度低"和"面积小"混成一个原因。本例两者 rho 分别是 0.38 和 0.50，是独立的两个因素，应该分开分析。
- 失败分类写成"模型没学好""数据太难"这种无法验证的描述。
- 只分析失败例，不看整体分布，得出"模型完全不行"的错误结论。实际上 69/83 例的 Dice 中位数是 0.85。
