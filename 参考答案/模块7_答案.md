### 练习 7-A（GBDT 手推与验证）

**参考代码**

```python
import numpy as np
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import GradientBoostingRegressor

x = np.array([1, 2, 3, 4, 5, 6], dtype=float).reshape(-1, 1)
y = np.array([1, 2, 3, 4, 5, 10], dtype=float)

# ---------- 第 0 轮 ----------
F0 = y.mean()
r = y - F0
print("F0 =", round(F0, 4))
print("residual =", np.round(r, 4))

# ---------- 第 1 棵树：目标值是残差，不是 y ----------
tree = DecisionTreeRegressor(max_depth=1, random_state=0).fit(x, r)
print("tree pred =", np.round(tree.predict(x), 4))
print("split at x <=", tree.tree_.threshold[0],
      " left n =", tree.tree_.n_node_samples[1],
      " right n =", tree.tree_.n_node_samples[2])

# ---------- 学习率扫描 ----------
for lr in [0.01, 0.1, 0.5, 1.0]:
    F1 = F0 + lr * tree.predict(x)
    print(f"lr={lr}: F1={np.round(F1, 4)}  MSE={np.mean((y - F1) ** 2):.4f}")

# ---------- 和 sklearn 对账 ----------
gb = GradientBoostingRegressor(n_estimators=1, learning_rate=0.1,
                               max_depth=1, random_state=0).fit(x, y)
hand = F0 + 0.1 * tree.predict(x)
print("sklearn 一轮:", np.round(gb.predict(x), 4))
print("手算一轮:    ", np.round(hand, 4))
print("max abs diff:", np.abs(gb.predict(x) - hand).max())

# ---------- lr x depth 的 MSE 表 ----------
for depth in [1, 2]:
    for lr in [0.01, 0.1, 0.5, 1.0]:
        g = GradientBoostingRegressor(n_estimators=1, learning_rate=lr,
                                      max_depth=depth, random_state=0).fit(x, y)
        p = g.predict(x)
        print(f"depth={depth} lr={lr}: MSE={np.mean((y - p) ** 2):.4f} pred={np.round(p, 4)}")
```

**手算过程（必须写出来，判分看这个）**

```
F0 = 25 / 6 = 4.1667

x    y     F0        r = y - F0
1    1     4.1667    -3.1667

4    4     4.1667    -0.1667

6    10    4.1667    +5.8333

深度 1 的树只能切一刀。最优切分是 x <= 5.5：
左叶子（x=1..5）均值 = (-3.1667-2.1667-1.1667-0.1667+0.8333) / 5 = -1.1667
右叶子（x=6）   均值 = +5.8333

lr=0.1：
x=1..5：F1 = 4.1667 + 0.1 * (-1.1667) = 4.0500
x=6   ：F1 = 4.1667 + 0.1 * (+5.8333) = 4.7500
MSE = [(-3.05)^2 + (-2.05)^2 + (-1.05)^2 + (-0.05)^2 + 0.95^2 + 5.25^2] / 6 = 7.1792
```

**判分要点**

- F0、6 个残差、左叶 -1.1667 / 右叶 5.8333 全部算对，且残差符号是 `y - F0`（负多正少）。
- 明确说出"树拟合的是残差 r，不是 y"。写成用 y 建树直接零分。
- lr=0.1 的 F1 与 `GradientBoostingRegressor(n_estimators=1, learning_rate=0.1)` 完全一致（差值 0.0 < 1e-6）。
- 8 个 MSE 值齐全，且解释"lr=1.0 时 MSE 最小，但实践中不用"：
  - 这里的 MSE 是**训练集** MSE；lr=1.0 等于完全相信这一棵树。
  - 6 个点、一棵树，训练 MSE 最小只说明它把训练集背下来了。
  - 真实数据上单棵树会拟合噪声，lr=1.0 没有第二棵树来纠错，方差最大。lr 小是"每棵树只信一点，用多棵树平均掉单棵的错误"。
  - 一个直接证据：depth=2 + lr=1.0 的训练 MSE 是 0.4167，比 depth=1 的 1.6667 还好，但这是 4 个叶子对 6 个点的过度拟合。
- 加分项：指出 depth=2 时树在 x<=2.5 和 x<=3.5 处切，叶子值 -2.6667 / -0.1667 / +5.8333（对应预测 1.5 / 4.0 / 10.0）。

**常见错误**

- 残差写成 `F0 - y`，符号全反，后面预测越走越远。
- 忘记 `F1 = F0 + lr * 树输出`，直接拿树输出当预测。
- 把 `max_depth` 当成"树的棵数"，与 `n_estimators` 混用。
- 用 `DecisionTreeRegressor` 拟合 `y` 再解释成 GBDT，混淆了"单棵树"和"boosting 的一轮"。
- 只报 lr=0.1 一组，不交 4x2 的表；或只报 MSE 不报预测值，无法核对。

### 练习 7-B（随机森林的三种随机性）

**参考代码**

```python
import pandas as pd
import numpy as np
import warnings
warnings.filterwarnings("ignore")

from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.ensemble import RandomForestClassifier
from sklearn.tree import DecisionTreeClassifier

h = pd.read_csv(r"E:\AI学习\练习代码\data\uci\Hepatitis.csv", na_values=["?"])
h.columns = h.columns.str.strip().str.replace(" ", "_")
y = (h["Class"] == 1).astype(int).values

num = ["Age", "Bilirubin", "Alk_Phosphate", "Sgot", "Albumin", "Protime"]
binv = ["Sex", "Steroid", "Antivirals", "Fatigue", "Malaise", "Anorexia",
        "Liver_Big", "Liver_Firm", "Spleen_Palpable", "Spiders", "Ascites", "Varices"]
X = h[num + binv].copy()

cv = StratifiedKFold(5, shuffle=True, random_state=0)
imp = ("impute", SimpleImputer(strategy="median"))

def evaluate(model, name):
    auc = cross_val_score(model, X, y, cv=cv, scoring="roc_auc")
    print(f"{name:38s} AUC={auc.mean():.4f}±{auc.std():.4f}  folds={np.round(auc, 4)}")

evaluate(Pipeline([imp, ("clf", DecisionTreeClassifier(random_state=0))]),
         "单棵深树")
evaluate(Pipeline([imp, ("clf", RandomForestClassifier(
             n_estimators=300, max_features=None, bootstrap=False, random_state=0))]),
         "无随机（全量数据 + 全部特征）")
evaluate(Pipeline([imp, ("clf", RandomForestClassifier(
             n_estimators=300, max_features=None, bootstrap=True, random_state=0))]),
         "只有样本随机（bootstrap + 全部特征）")
evaluate(Pipeline([imp, ("clf", RandomForestClassifier(
             n_estimators=300, max_features="sqrt", bootstrap=False, random_state=0))]),
         "只有特征随机（全量数据 + 4 个特征）")
evaluate(Pipeline([imp, ("clf", RandomForestClassifier(
             n_estimators=300, max_features="sqrt", bootstrap=True,
             random_state=0, n_jobs=-1))]),
         "两重随机（标准随机森林）")
```

**实测输出**

```
单棵深树                                     AUC=0.7036±0.0960  folds=[0.8167 0.7533 0.5433 0.753  0.6518]
无随机（全量数据 + 全部特征）                 AUC=0.7468±0.0866  folds=[0.8267 0.8133 0.6    0.7976 0.6964]
只有样本随机（bootstrap + 全部特征）          AUC=0.8469±0.0469  folds=[0.7667 0.8467 0.88   0.8363 0.9048]
只有特征随机（全量数据 + 4 个特征）           AUC=0.8893±0.0422  folds=[0.85   0.8867 0.8733 0.8661 0.9702]
两重随机（标准随机森林）                      AUC=0.8798±0.0407  folds=[0.8467 0.9067 0.86   0.8393 0.9464]
```

**判分要点**

- 四个配置的数字都要有，且是 5 折 CV 的 mean ± std，不能报单次划分。
- 结论：**在这份数据上，特征随机的贡献略大**（0.8893 vs 0.8469，相差 4.2 个点）。原因要能说出"18 个特征里 12 个是二值体征，信息高度重叠（Ascites、Varices、Spiders 都在描述门脉高压），只靠样本随机，每棵树的分裂结构仍然很像"。
- 为什么两重随机没有更好：0.8798 vs 0.8893，差 0.0095，**远小于折间标准差 0.04**。两个技巧叠加不保证更好，要用 CV 测，不能假设。
- 必须指出"无随机"（0.7468）和"只有样本随机"（0.8469）的差距说明 Bagging 本身就有效；单棵树到任一集成提升 14-19 个点。
- 加分项：说明 `max_features='sqrt'` 在 18 个特征时 m=4；`max_features=None` 时每棵树看全部特征。

**常见错误**

- 只跑一次 `train_test_split`，155 例下测试集只有 39 人，AUC 波动 ±0.1，四个配置的排序会翻。
- 把 `bootstrap=False` 当成"没有随机"，其实还有特征随机；把 `max_features=None` 当成默认值，默认是 `'sqrt'`。
- 忘记 `Pipeline` 里的 imputer 在折内 fit，先用全量中位数插补再 CV，造成轻微泄露。
- 用准确率代替 AUC 下结论。这份数据 79% 是存活，全预测存活就有 0.79 准确率。
- 认为"两重随机一定优于单一随机"，实测反例就在这里。

**判分要点**

- 三划分比例 60/20/20，且 `stratify=y`；实际人数 93 / 31 / 31，验证集 6 个死亡。
- 报 `best_iteration=27` 时必须说明**实际用了 28 棵树**（索引从 0 开始）。只写 27 棵算错。
- 第 4 步重训结果 0.7933，与早停模型完全一致，证明"按最优轮数重训"是等价的。
- 第 5 步测试 AUC 0.84 > 诚实版 0.7933，虚高约 0.047。原因：早停的停止点由测试集决定，测试集信息通过"选了多少棵树"（这里选了 86 棵而不是 28 棵）泄露进模型。同时 logloss 反而从 0.4389 变成 0.4278，说明不只是阈值问题，是模型真的向测试集调过。
- 第 6 步：同一份数据换切分，`best_iteration` 从 1 跳到 20 再到 12。**31 人的验证集里只有 6 个死亡，AUC 的抽样误差约 ±0.15，早停点极不稳定。** 正确做法是用多次重复 CV 的早停轮数中位数，或用固定轮数 + 正则。
- 必须回答"如果只看 AUC 会不会发现错误"：不会。泄露版 AUC 更高，只有当你对照"早停用了什么数据"才会发现。

**常见错误**

- 把 `best_iteration` 直接当树数，少用一棵。
- 用 test 当 eval_set 还报告"早停提升了泛化"，这是本练习的核心陷阱。
- 只画一条曲线（train 或 valid），看不出"训练单调升、验证先升后降"。
- 重训时忘了把 `n_estimators` 改成 `best_iteration+1`，仍然用 1000 棵，测试崩掉。
- 换了 random_state 只换模型种子、不换切分种子，验证集还是同一批人，测不出不稳定性。
- 报"验证 AUC 0.79，所以模型一般"。31 人的验证集不能用来评价模型好坏，只能验证流程。

```python
import matplotlib
matplotlib.use("Agg")

from xgboost import XGBClassifier, DMatrix

h = pd.read_csv(r"E:\AI学习\练习代码\data\uci\Hepatitis.csv", na_values=["?"])
h.columns = h.columns.str.strip().str.replace(" ", "_")
y = (h["Class"] == 1).astype(int).values
num = ["Age", "Bilirubin", "Alk_Phosphate", "Sgot", "Albumin", "Protime"]
binv = ["Sex", "Steroid", "Antivirals", "Fatigue", "Malaise", "Anorexia",

# 2 5 折 OOF 排列重要性，每折重复 15 次
cv = StratifiedKFold(5, shuffle=True, random_state=0)
perm = np.zeros((5, len(F)))
for k, (tri, vai) in enumerate(cv.split(X, y)):
    mm = XGBClassifier(**par).fit(X.iloc[tri], y[tri])
    r = permutation_importance(mm, X.iloc[vai], y[vai], scoring="roc_auc",
                               n_repeats=15, random_state=0)
    perm[k] = r.importances_mean
pm = perm.mean(0)

# 3 SHAP（用 pred_contribs 代替，本机未装 shap）
contrib = m.get_booster().predict(DMatrix(X, label=y, missing=np.nan),
                                  pred_contribs=True)
sh = np.abs(contrib[:, :-1]).mean(0)     # 最后一列是 bias，丢掉

df = pd.DataFrame({"feat": F, "gain%": gain / total * 100,
                   "perm": pm, "shap": sh})
df["r_gain"] = df["gain%"].rank(ascending=False, method="min").astype(int)
df["r_perm"] = df["perm"].rank(ascending=False, method="min").astype(int)
df["r_shap"] = df["shap"].rank(ascending=False, method="min").astype(int)
print(df.sort_values("r_gain").round(4).to_string(index=False))
print("Spearman gain-perm:", round(spearmanr(df["gain%"], df["perm"]).statistic, 3))
print("Spearman gain-shap:", round(spearmanr(df["gain%"], df["shap"]).statistic, 3))
print("Spearman perm-shap:", round(spearmanr(df["perm"], df["shap"]).statistic, 3))

fig, ax = plt.subplots(figsize=(6.5, 5))
ax.scatter(df["gain%"], df["perm"], s=40)
for _, r in df.iterrows():
    ax.annotate(r.feat, (r["gain%"], r["perm"]), fontsize=7,
                xytext=(3, 3), textcoords="offset points")
ax.set_xlabel("分裂增益占比 %")
ax.set_ylabel("排列重要性（AUC 下降）")
ax.set_title(f"增益 vs 排列  Spearman={spearmanr(df['gain%'], df['perm']).statistic:.3f}")
fig.tight_layout()
fig.savefig(r"E:\AI学习\参考答案\figs\7d_importance_scatter.png", dpi=130)
```

- 排列必须做 5 折 OOF，不能在训练集上打乱。

- `get_score()` 的 key 用 `f0..f17` 去取，结果全是 0。用 DataFrame 训练时 key 是特征名，要先打印 `list(g.keys())`。
- `pred_contribs` 的最后一列是 bias（基准值），没丢掉，多算一个"特征"。
- 排列重要性在训练集上做，模型已经记住数据，打乱任何特征影响都小，结论失真。
- 把 SHAP 值当成"因果效应"或"对单个病人的解释"。SHAP 是模型内部的分账，不是生物学机制。
- 只报排序不报数值，无法判断差距是否在噪声内。
- 用 `feature_importances_`（默认 gain）下结论"Fatigue 最重要"，被 SHAP 复核立刻翻车。

### 练习 7-E（Stacking 的 OOF）

**参考代码**

```python
import pandas as pd
import numpy as np
import warnings
warnings.filterwarnings("ignore")

from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score, log_loss
from xgboost import XGBClassifier
import lightgbm as lgb

h = pd.read_csv(r"E:\AI学习\练习代码\data\uci\Hepatitis.csv", na_values=["?"])
h.columns = h.columns.str.strip().str.replace(" ", "_")
y = (h["Class"] == 1).astype(int).values
num = ["Age", "Bilirubin", "Alk_Phosphate", "Sgot", "Albumin", "Protime"]
binv = ["Sex", "Steroid", "Antivirals", "Fatigue", "Malaise", "Anorexia",
        "Liver_Big", "Liver_Firm", "Spleen_Palpable", "Spiders", "Ascites", "Varices"]
X = h[num + binv]

Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25,
                                      stratify=y, random_state=42)
print("train/test:", len(ytr), len(yte), "death:", ytr.sum(), yte.sum())

def base_models():
    return {
        "rf": RandomForestClassifier(n_estimators=300, min_samples_leaf=2,
                                     max_features="sqrt", random_state=0, n_jobs=-1),
        "xgb": XGBClassifier(n_estimators=200, max_depth=2, learning_rate=0.05,
                             subsample=0.8, colsample_bytree=0.8, reg_lambda=10,
                             random_state=0, n_jobs=4, eval_metric="logloss"),
        "lgbm": lgb.LGBMClassifier(n_estimators=200, learning_rate=0.05,
                                   num_leaves=7, min_child_samples=10,
                                   verbose=-1, random_state=0),
    }

names = list(base_models().keys())

# ---------- 正确版：内层 5 折 OOF ----------
oof = np.zeros((len(ytr), len(names)))
kf = StratifiedKFold(5, shuffle=True, random_state=0)
for j, nm in enumerate(names):
    for tri, vai in kf.split(Xtr, ytr):
        mod = base_models()[nm].fit(Xtr.iloc[tri], ytr[tri])
        oof[vai, j] = mod.predict_proba(Xtr.iloc[vai])[:, 1]

meta = LogisticRegression(max_iter=2000).fit(oof, ytr)
meta_cv = cross_val_score(LogisticRegression(max_iter=2000), oof, ytr,
                          cv=StratifiedKFold(3, shuffle=True, random_state=0))

te = np.zeros((len(yte), len(names)))
for j, nm in enumerate(names):
    mod = base_models()[nm].fit(Xtr, ytr)
    te[:, j] = mod.predict_proba(Xte)[:, 1]
p_correct = meta.predict_proba(te)[:, 1]
print("[正确版] meta train AUC:", round(roc_auc_score(ytr, meta.predict_proba(oof)[:, 1]), 4))
print("[正确版] meta 3折CV:", round(meta_cv.mean(), 4), "±", round(meta_cv.std(), 4))
print("[正确版] outer test AUC:", round(roc_auc_score(yte, p_correct), 4),
      "logloss:", round(log_loss(yte, p_correct), 4))
print("[正确版] weights:", dict(zip(names, np.round(meta.coef_[0], 3))),
      "b=", round(meta.intercept_[0], 3))

# ---------- 错误版：用训练集 in-sample 预测训练第二层 ----------
tr_w = np.zeros((len(ytr), len(names)))
te_w = np.zeros((len(yte), len(names)))
for j, nm in enumerate(names):
    mod = base_models()[nm].fit(Xtr, ytr)
    tr_w[:, j] = mod.predict_proba(Xtr)[:, 1]
    te_w[:, j] = mod.predict_proba(Xte)[:, 1]

meta_w = LogisticRegression(max_iter=2000).fit(tr_w, ytr)
meta_w_cv = cross_val_score(LogisticRegression(max_iter=2000), tr_w, ytr,
                            cv=StratifiedKFold(3, shuffle=True, random_state=0))
p_wrong = meta_w.predict_proba(te_w)[:, 1]
print("[错误版] meta train AUC:", round(roc_auc_score(ytr, meta_w.predict_proba(tr_w)[:, 1]), 4))
print("[错误版] meta 3折CV:", round(meta_w_cv.mean(), 4), "±", round(meta_w_cv.std(), 4))
print("[错误版] outer test AUC:", round(roc_auc_score(yte, p_wrong), 4),
      "logloss:", round(log_loss(yte, p_wrong), 4))
print("[错误版] weights:", dict(zip(names, np.round(meta_w.coef_[0], 3))),
      "b=", round(meta_w.intercept_[0], 3))
```

**判分要点**

- 正确版的三个 AUC 要能区分：meta 训练 0.8528、meta 3 折 CV 0.8277、外层 test 0.879。**meta 训练 AUC 不是模型性能**，它只是第二层在 OOF 特征上的拟合程度。
- 错误版的 meta 训练 AUC = 1.0000，3 折 CV 也是 1.0000。这是判定错误的**唯一可靠信号**：真实任务上不可能完美。
- 机制必须说清楚：基模型在训练集上的预测是 in-sample 的，RF 训练 AUC 0.9991、LGBM 1.0，预测值已经接近 0/1 的标签本身；第二层拿到的是"已经看过答案的特征"，只需记住每个样本的取值就能完美分开。这就是**目标泄露**。
- 权重的变化：错误版 LGBM 权重从 0.922 被放大到 3.448（3.7 倍），因为 LGBM 的 in-sample 预测最"自信"（训练 AUC 1.0，预测接近 0 和 1），第二层最信任它。正确版因为 OOF 预测都变"软"了，权重回到 0.92-2.05 的合理区间。
- 关键问题："如果只看 AUC，会不会发现错误？"——**不会**。错误版外层 test AUC 0.8871，比正确版 0.879 还高；只有 logloss 变差（0.4001 vs 0.3814）和 meta 训练 AUC=1.0 能暴露问题。**AUC 只关心排序，对过度自信不敏感。**
- 补充：错误版外层 AUC 不掉，是因为两层都只用训练集拟合，测试集始终没参与；问题在于第二层的权重被 in-sample 噪声带偏，属于"运气好"，换一个切分就会露馅。要证明这点应换 5 个切分重复。

**常见错误**

- 内层用 `cross_val_predict` 却忘了 `method='predict_proba'`，拿到硬标签。
- OOF 只对部分基模型做，另一些用 in-sample，混着拼进 meta 特征。
- 用训练集全量 fit 基模型后直接 `predict` 训练集来生成 meta 特征（就是错误版）。
- 第二层再用复杂模型（如另一个 GBDT），在 116 个样本上必然过拟合；meta 层应该用强正则的线性模型。
- 只报外层 test AUC，不报 meta 训练 AUC 和 logloss，无法发现泄露。
- 把 Stacking 的收益说成"一定比单模型好"：本例正确版 0.879，单 RF 0.8589、单 XGB 0.8911，Stacking 并没有超过最好的单模型。

### 练习 7-F（四模型对比与结论写作）

**参考代码**

```python
import pandas as pd
import numpy as np
import warnings, time
warnings.filterwarnings("ignore")

from sklearn.model_selection import StratifiedKFold
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import (roc_auc_score, f1_score, accuracy_score,
                             confusion_matrix)
from xgboost import XGBClassifier
import lightgbm as lgb

h = pd.read_csv(r"E:\AI学习\练习代码\data\uci\Hepatitis.csv", na_values=["?"])
h.columns = h.columns.str.strip().str.replace(" ", "_")
y = (h["Class"] == 1).astype(int).values
num = ["Age", "Bilirubin", "Alk_Phosphate", "Sgot", "Albumin", "Protime"]
binv = ["Sex", "Steroid", "Antivirals", "Fatigue", "Malaise", "Anorexia",
        "Liver_Big", "Liver_Firm", "Spleen_Palpable", "Spiders", "Ascites", "Varices"]
X = h[num + binv].copy()

cv = StratifiedKFold(5, shuffle=True, random_state=0)
spw = float((y == 0).sum() / (y == 1).sum())   # 3.84
print("scale_pos_weight:", round(spw, 2))

models = {
    "逻辑回归": lambda: Pipeline([("sc", StandardScaler()),
        ("c", LogisticRegression(max_iter=2000, class_weight="balanced"))]),
    "随机森林": lambda: RandomForestClassifier(n_estimators=300, max_features="sqrt",
        min_samples_leaf=2, class_weight="balanced", random_state=0, n_jobs=-1),
    "XGBoost": lambda: XGBClassifier(n_estimators=300, max_depth=3, learning_rate=0.05,
        subsample=0.8, colsample_bytree=0.8, reg_lambda=1.0,
        scale_pos_weight=spw, random_state=0, n_jobs=4, eval_metric="logloss"),
    "LightGBM": lambda: lgb.LGBMClassifier(n_estimators=300, learning_rate=0.05,
        num_leaves=31, class_weight="balanced", verbose=-1, random_state=0),
}

for name, fac in models.items():
    met = {k: [] for k in ["auc", "rec", "spec", "f1", "acc"]}
    t0 = time.time()
    for tri, vai in cv.split(X, y):
        imp = SimpleImputer(strategy="median").fit(X.iloc[tri])
        A, B = imp.transform(X.iloc[tri]), imp.transform(X.iloc[vai])
        m = fac().fit(A, y[tri])
        p = m.predict_proba(B)[:, 1]
        pred = (p >= 0.5).astype(int)
        tn, fp, fn, tp = confusion_matrix(y[vai], pred, labels=[0, 1]).ravel()
        met["auc"].append(roc_auc_score(y[vai], p))
        met["rec"].append(tp / (tp + fn))
        met["spec"].append(tn / (tn + fp))
        met["f1"].append(f1_score(y[vai], pred, zero_division=0))
        met["acc"].append(accuracy_score(y[vai], pred))
    print(f"{name:6s} " + " | ".join(
        f"{k} {np.mean(v):.3f}±{np.std(v):.3f}" for k, v in met.items())
        + f" | {(time.time() - t0) / 5:.2f}s")
```

**结论（150 字，可直接当模板）**

> 在 155 例、32 例死亡的 Hepatitis 数据上，5 折交叉验证显示随机森林的 AUC 最高（0.879±0.052）与 F1 最高（0.672±0.124），逻辑回归次之（0.835±0.083），XGBoost 为 0.837±0.052，LightGBM 最低（0.807±0.061）。但随机森林与 XGBoost 的 AUC 差 0.042，小于两者任一的标准差 0.052，属于噪声范围，不能宣称随机森林显著更优。临床场景若是"宁可多复查、不可漏诊"，应选召回最高的随机森林（0.776），并配合阈值下调；若需要可解释的线性评分卡，逻辑回归的 0.835 已经够用，且系数可直接读。样本量决定了这份数据只能支持"三者在同一档"的结论。

**判分要点**

- 表格必须 four models × 5 metrics，全部 mean±std，不能只报 AUC。
- `class_weight='balanced'` / `scale_pos_weight=3.84` 必须用上，否则召回只有 0.47-0.59（本机未加权的随机森林召回 0.467、特异度 0.944），医学场景先看召回。
- 明确判断"差异是否超过一个标准差"：RF 0.879 vs XGB 0.837，差 0.042 < std 0.052，**没超过**。
- 结论不能出现"XGBoost 最强"。正确说法是"在同一档，按场景选"。
- 加分项：指出 LightGBM 在 155 例上用默认 `num_leaves=31` 是危险默认值（见 7-G），它的低分不代表 LightGBM 本身差。
- 应该提到阈值 0.5 是固定的；医学上常用约登指数或固定召回率反推阈值，本表仅用于横向比较。

**常见错误**

- 用不带 `class_weight` 的默认配置，得到召回 0.47 还写"模型召回不错"。
- 报准确率 0.845 就说"模型很好"，忽略 79% 的多数类基线。
- 把 0.005 的差异写成"提升"，不报标准差。
- 只跑一次划分，四个人数不同的测试集不可比。
- 忘了 XGBoost 的 `scale_pos_weight` 与 sklearn 的 `class_weight` 不是同一机制，直接照搬参数名。
- 结论只描述数字，不给临床选择建议，验收不通过。

```python
                           random_state=0).fit(Xtr, ytr)
    a_tr = roc_auc_score(ytr, m.predict_proba(Xtr)[:, 1])
    a_te = roc_auc_score(yte, m.predict_proba(Xte)[:, 1])
    print(f"num_leaves={nl:2d} train={a_tr:.4f} test={a_te:.4f} diff={a_tr-a_te:+.4f}")
```

**实测输出**

```
num_leaves= 2 train=0.9592 test=0.8992 diff=+0.0600
num_leaves= 4 train=1.0000 test=0.8145 diff=+0.1855
num_leaves= 7 train=1.0000 test=0.8629 diff=+0.1371
num_leaves=15 train=1.0000 test=0.8629 diff=+0.1371
num_leaves=31 train=1.0000 test=0.8629 diff=+0.1371
num_leaves=63 train=1.0000 test=0.8629 diff=+0.1371
```

**判分要点**

- 6 行表齐全；训练/测试用同一个 `random_state=42` 的 75/25 分层划分，否则不可比。
- 回答"num_leaves 从 7 加到 63，测试 AUC 变了吗"：**没变，四档都是 0.8629**。瓶颈是 116 个训练样本，不是模型容量。
- 回答"为什么训练 AUC 在 num_leaves=4 就到 1.0"：155 例里训练集 116 例，其中只有 24 例死亡；4 个叶子已经足够把 24 个正例和 92 个负例分开记忆，训练 AUC 必然到 1。**训练 AUC=1 不是好消息，是样本量不足的信号。**
- 注意 num_leaves=2（train 0.9592 / test 0.8992）的测试 AUC 反而**最高**，但这个差异（0.036）在 39 人测试集上不显著，不要据此宣称"2 叶最好"。
- 推荐值：`num_leaves=4-8`，并同时设 `max_depth=3` 兜底（Leaf-wise 不保证平衡，只限 `num_leaves` 时树可能长成一条 12 层的链）；`min_child_samples` 设 10-20。
- 结论要写成"在这份 155 例数据上"，不能写成"LightGBM 不行"。

**常见错误**

- 用 5 折 CV 分别调 num_leaves 再和单次划分的数字混在一张表里，口径不一致。
- 只觉得"训练 AUC 1.0 说明模型很强"，不解释这是记忆而非泛化。
- 用 `num_leaves=31` 的默认值，看到测试 0.86 就说"LightGBM 比 XGBoost 差"。
- 忘记 LightGBM 是 Leaf-wise，以为 `num_leaves=31` 等价于 `max_depth=5` 的平衡树；实际深度不可控。
- 不设 `min_child_samples`，叶子只有 1-2 个样本，小数据上噪声被完整背下来。

### 练习 7-H（缺失值策略）

**参考代码**

```python
import pandas as pd
import numpy as np
import warnings
warnings.filterwarnings("ignore")
from sklearn.model_selection import StratifiedKFold
from sklearn.impute import SimpleImputer
from sklearn.metrics import roc_auc_score
from xgboost import XGBClassifier

h = pd.read_csv(r"E:\AI学习\练习代码\data\uci\Hepatitis.csv", na_values=["?"])
h.columns = h.columns.str.strip().str.replace(" ", "_")
y = (h["Class"] == 1).astype(int).values
num = ["Age", "Bilirubin", "Alk_Phosphate", "Sgot", "Albumin", "Protime"]
binv = ["Sex", "Steroid", "Antivirals", "Fatigue", "Malaise", "Anorexia",
        "Liver_Big", "Liver_Firm", "Spleen_Palpable", "Spiders", "Ascites", "Varices"]
X = h[num + binv].copy()
cv = StratifiedKFold(5, shuffle=True, random_state=0)

PAR = dict(n_estimators=300, max_depth=3, learning_rate=0.05, subsample=0.8,
           colsample_bytree=0.8, reg_lambda=1.0, random_state=0,
           n_jobs=4, eval_metric="logloss")

def cv_auc(Xd, yd, name, native=False):
    scores = []
    for tri, vai in cv.split(Xd, yd):
        Xt, Xv = Xd.iloc[tri], Xd.iloc[vai]
        if not native:
            imp = SimpleImputer(strategy="median").fit(Xt)
            Xt, Xv = imp.transform(Xt), imp.transform(Xv)
        m = XGBClassifier(**PAR).fit(Xt, yd[tri])
        scores.append(roc_auc_score(yd[vai], m.predict_proba(Xv)[:, 1]))
    print(f"{name:26s} AUC={np.mean(scores):.4f}±{np.std(scores):.4f}  n={len(Xd)}")

cv_auc(X, y, "1 原生 NaN", native=True)
cv_auc(X, y, "2 中位数插补")

Xi = X.copy()
for c in X.columns:
    if X[c].isna().any():
        Xi[c + "_miss"] = X[c].isna().astype(int)
print("indicators:", [c for c in Xi.columns if c.endswith("_miss")])
cv_auc(Xi, y, "3 插补 + 指示列")

sub = h.dropna(subset=num + binv)
ys = (sub["Class"] == 1).astype(int).values
print("删除后:", sub.shape, "death:", ys.sum())
cv_auc(sub[num + binv].copy(), ys, "4 删除含缺失行")
```

**实测输出**

```
1 原生 NaN                   AUC=0.8356±0.0581  n=155
2 中位数插补                  AUC=0.8512±0.0562  n=155
indicators: ['Bilirubin_miss', 'Alk_Phosphate_miss', 'Sgot_miss',
             'Albumin_miss', 'Protime_miss', 'Steroid_miss', 'Fatigue_miss',
             'Malaise_miss', 'Anorexia_miss', 'Liver_Big_miss',
             'Liver_Firm_miss', 'Spleen_Palpable_miss', 'Spiders_miss',
             'Ascites_miss', 'Varices_miss']
3 插补 + 指示列               AUC=0.8430±0.0551  n=155
删除后: (80, 20) death: 13
4 删除含缺失行                AUC=0.8606±0.1128  n=80
```

**判分要点**

- 四种策略各报 5 折 CV AUC mean±std，`n` 必须写出来，否则 0.8606 会被误读成"最好"。
- 第 4 种样本量从 155 腰斩到 80 的原因：**Protime 缺 67 个（43.2%）**。只删 Protime 一个特征就剩 88 人；再把 18 个特征里任何有缺失的行删掉，只剩 80 人（13 例死亡）。注意不是 83——83 是"六个连续特征都不缺"的人数，若把 12 个二值体征也算进 dropna，会再少 3 人。这个区别要在答案里指出。
- 加指示列没有用：0.8430 vs 0.8512，差 -0.008，在 std 0.056 以内，属于噪声。原因：缺失在这份数据里主要是"没做这项检查"，与病情严重度的关联很弱；且 15 个指示列在 155 例上是 15 个额外维度，稀释了信号。
- 删除法的 0.8606 最高，但 std 0.1128 是四种里最大的（约为插补法的两倍），且样本只剩 80 人、13 个事件，**不能据此说删除更好**。
- 结论必须限定为"在这份数据上，中位数插补与原生 NaN 差别在噪声内，删除法样本代价过大不可取"，不能推广成"医学数据都应该中位数插补"。
- 加分项：指出原生 NaN 的默认方向在临床上不透明（医生问"这个缺失值为什么这样判"答不出），生产环境倾向显式插补 + 指示列。

**常见错误**

- 先对全量数据 `fillna` 再 CV，中位数用到了验证折的信息（轻微泄露）。
- 第 4 种直接 `dropna()` 不写 `subset`，把所有列都算进去，样本量对不上还不知道为什么。
- 只报 AUC 不报 n，把"样本少所以方差大"误读成"策略好"。
- 把"原生 NaN 一定更好"当结论。本机实测是插补略好（0.8512 vs 0.8356），差值在噪声内。
- 指示列只对连续特征建，漏掉二值特征里的缺失（Steroid、Fatigue 等也有缺失）。
- 用测试集的中位数插补训练集，或先插补再划分。
