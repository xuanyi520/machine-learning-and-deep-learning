### 练习 1（手写 NMS）

**参考代码**
```python
import numpy as np

def iou(a, b):
    x1, y1 = max(a[0], b[0]), max(a[1], b[1])
    x2, y2 = min(a[2], b[2]), min(a[3], b[3])
    inter = max(0.0, x2 - x1) * max(0.0, y2 - y1)
    area_a = (a[2] - a[0]) * (a[3] - a[1])
    area_b = (b[2] - b[0]) * (b[3] - b[1])
    return inter / (area_a + area_b - inter)

def nms(boxes, scores, thr=0.5):
    order = np.argsort(-scores)          # 分数从高到低
    keep = []
    while order.size > 0:
        i = order[0]
        keep.append(int(i))
        if order.size == 1:
            break
        rest = order[1:]
        ious = np.array([iou(boxes[i], boxes[j]) for j in rest])
        order = rest[ious <= thr]        # 只保留没被抑制的
    return keep

def nms_per_class(boxes, scores, labels, thr=0.5):
    """按类别分别做 NMS，最后按原下标排序返回。"""
    keep_all = []
    for c in np.unique(labels):
        idx = np.where(labels == c)[0]
        keep_all += [idx[k] for k in nms(boxes[idx], scores[idx], thr)]
    return sorted(keep_all)

boxes = np.array([
    [10, 10, 60, 60], [12, 14, 58, 62], [100, 100, 150, 150],
    [104, 98, 152, 148], [200, 50, 240, 90], [14, 12, 56, 58],
], dtype=float)
scores = np.array([0.92, 0.85, 0.78, 0.65, 0.60, 0.55])
names = ['A', 'B', 'C', 'D', 'E', 'F']

for t in [0.30, 0.50, 0.70, 0.80, 0.85]:
    print(t, [names[i] for i in nms(boxes, scores, t)])

# 跨类别的反例：F 是另一个类别，阈值 0.5
labels = np.array([0, 0, 0, 0, 0, 1])
print('全部一起:', [names[i] for i in nms(boxes, scores, 0.5)])
print('按类别  :', [names[i] for i in nms_per_class(boxes, scores, labels, 0.5)])
```

**实测输出**

手算过程（与代码输出逐位一致）：

```

A 与 F = [14,12,56,58]：F 完全落在 A 内部

```

NMS 逐轮执行（阈值 0.5，按分数降序 A 0.92、B 0.85、C 0.78、D 0.65、E 0.60、F 0.55）：

```
第 1 轮：取 A，抑制 B(0.816)、F(0.773)
第 2 轮：剩下的最高分是 C(0.78)，抑制 D(0.820)
第 3 轮：剩下的最高分是 E(0.60)，没有可抑制的
结束：保留 A、C、E
```

```

 [0.816 1.    0.    0.    0.    0.806]
 [0.    0.    1.    0.82  0.    0.   ]

```

**为什么 0.3 到 0.7 结果不变**：这 6 个框的"同簇 IoU"只有三个值——0.773、0.806、0.816、0.820。阈值只要落在这组值的空隙里，判定完全相同。阈值升到 0.80 时，F 与 B 的 0.806 仍大于 0.80，但 F 与 A 的 0.773 小于 0.80；A 先被选中，F 不再是"被 A 抑制"，于是 F 被保留。阈值到 0.85 时，所有 IoU 都低于阈值，一个都不抑制。**这不是"阈值越大越好"，而是阈值跨过了数据里的一个 IoU 台阶。**

**判分要点**
- `iou` 的分母必须是"并集"：`area_a + area_b - inter`，不是简单相加；交集宽高要 `max(0, ...)` 防止负值。
- `argsort(-scores)` 的负号不能少；返回的是下标，不是框本身。
- 每轮只和"当前剩余"的框比，不能和已经被删的框比。
- 阈值 0.5 必须输出 `['A','C','E']`；0.80 必须输出 4 个（多 F）。
- 按类别 NMS 的正确性看这个反例：同阈值 0.5 下，一起做得到 3 个框，分类别得到 4 个。说明 F 作为另一类，不应被 A 抑制。

**常见错误**
- 用 `min(x2)-max(x1)` 后忘记 `max(0, ...)`，两个不相交的框会算出负面积，IoU 变成负数。
- 把 `IoU > thr` 写成 `IoU >= thr`：本题 0.80 恰好没有相等值，碰不到；但在 0.816 这种阈值上会差一个框。
- 抑制时把"当前最高分框自己"也算进去，IoU=1 直接把自己删掉。
- 对全类别一起做 NMS，肝脏和肿瘤互相抑制；医学检测必须按类别分组。
- 只实现 2D IoU 就用到 3D 检测上，Z 方向相邻层会重复保留。

### 练习 2（手算 attention）

**参考代码**
```python
import numpy as np

Q = np.array([[1., 0.], [0., 1.], [1., 1.]])
K = Q.copy(); V = Q.copy()
S = Q @ K.T / np.sqrt(2)          # 缩放点积

def softmax(x):
    e = np.exp(x - x.max(axis=1, keepdims=True))   # 减最大值防溢出
    return e / e.sum(axis=1, keepdims=True)

A = softmax(S)
O = A @ V
print('QK^T\n', Q @ K.T)
print('scaled\n', np.round(S, 4))
print('attention\n', np.round(A, 4))
print('row sums', A.sum(1))
print('output\n', np.round(O, 4))
```

**实测输出**

完整手算：

```

[1 1]               [1 1 2]

[0.7071  0       0.7071]
[0       0.7071  0.7071]
[0.7071  0.7071  1.4142]

第三步 逐行 softmax：
第 1 行：exp(0.7071)=2.0281, exp(0)=1, exp(0.7071)=2.0281
         和 = 5.0562 → [0.4011, 0.1978, 0.4011]
第 2 行：结构对称 → [0.1978, 0.4011, 0.4011]

         和 = 8.1695 → [0.2483, 0.2483, 0.5035]
```


PyTorch 版本与手算的最大绝对差为 `2.78e-17`，即完全相同。

**为什么除以 sqrt(d)**：点积的每个分量是 d 个乘积之和。若 q、k 各分量独立、均值 0、方差 1，则点积方差约为 d。d=64 时分数尺度是 d=1 时的 8 倍，softmax 的输入差距被放大，输出接近 one-hot，梯度趋近 0（饱和）。除以 sqrt(d) 把方差拉回 1 附近，softmax 工作在梯度不为零的区间。**注意是 sqrt(d)，不是 d**。

**判分要点**
- 三行 attention 必须分别对上 0.401/0.198/0.401、0.198/0.401/0.401、0.248/0.248/0.503，误差 < 0.001。
- 输出三行对上 [0.802,0.599]、[0.599,0.802]、[0.752,0.752]。
- 每行之和为 1，且输出是 V 的凸组合（每个输出分量都落在 V 各行的取值范围内）。
- 能说清 sqrt(d) 控的是"点积方差 → softmax 饱和度 → 梯度"这条链。
- 手算与代码一致；代码里 softmax 要减行最大值，否则大分数会溢出。

**常见错误**
- 除以 d 而不是 sqrt(d)，得到 [0.475,0.183,0.342] 这类错误分布。
- softmax 按列做（axis=0），行和不再是 1。
- 忘记缩放，直接把 QK^T 送 softmax：本例数值小，结果看起来"差不多"，换成 d=64 的真实特征就会饱和。
- 把 attention 权重当成最终输出，忘记再乘 V。
- 认为 attention 矩阵对称——只有 Q=K 时才对称，一般不对称。

### 练习 3（训练一个检测器）

**参考代码**
```python
import numpy as np, torch, torch.nn.functional as F, time
from torchvision.models.detection import (
    fasterrcnn_mobilenet_v3_large_320_fpn,
    FasterRCNN_MobileNet_V3_Large_320_FPN_Weights)
from torchvision.models.detection.faster_rcnn import FastRCNNPredictor

device = 'cuda' if torch.cuda.is_available() else 'cpu'
torch.manual_seed(0)

def make_sample(seed):
    rng = np.random.default_rng(seed)
    img = rng.normal(0.12, 0.03, (1, 128, 128)).astype(np.float32)
    cy, cx = rng.integers(25, 103, 2)
    r = rng.integers(7, 14)
    yy, xx = np.mgrid[0:128, 0:128]
    mask = (yy - cy) ** 2 + (xx - cx) ** 2 <= r * r
    img[0][mask] = rng.uniform(0.65, 0.95)
    t = torch.tensor(img)[None]
    t = F.avg_pool2d(F.pad(t, (2, 2, 2, 2), mode='replicate'), 5, 1)
    return t[0].numpy(), np.array([cx-r, cy-r, cx+r, cy+r], dtype=np.float32)

train = [make_sample(s) for s in range(60)]
test  = [make_sample(s) for s in range(1000, 1012)]

model = fasterrcnn_mobilenet_v3_large_320_fpn(
    weights=FasterRCNN_MobileNet_V3_Large_320_FPN_Weights.DEFAULT)
in_feat = model.roi_heads.box_predictor.cls_score.in_features
model.roi_heads.box_predictor = FastRCNNPredictor(in_feat, 2)   # 背景 + 结节
model.to(device)
for p in model.backbone.parameters():
    p.requires_grad = False

imgs = [torch.tensor(x[0]) for x in train]
tgts = [{'boxes': torch.tensor(x[1])[None], 'labels': torch.tensor([1])} for x in train]
opt = torch.optim.SGD([p for p in model.parameters() if p.requires_grad],
                      lr=0.005, momentum=0.9)

model.train()
for it in range(40):
    idx = np.random.default_rng(it).choice(len(imgs), 2, replace=False)
    xb = [imgs[i].to(device) for i in idx]
    yb = [{k: v.to(device) for k, v in tgts[i].items()} for i in idx]
    loss_dict = model(xb, yb)
    loss = sum(v for v in loss_dict.values())
    opt.zero_grad(); loss.backward(); opt.step()

model.eval()
with torch.no_grad():
    out = model([torch.tensor(test[0][0]).to(device)])[0]

# anchor 实验：把默认 ((32,64,128,256,512),...) 整体放大 4 倍后重训
model.rpn.anchor_generator.sizes = tuple(
    tuple(s * 4 for s in level) for level in model.rpn.anchor_generator.sizes)
```

**实测输出**
```
参数量            18.93 M
训练 40 iter       5.1 s（RTX 5060，冻结 backbone）
loss 前 5 轮均值    2.127
loss 后 10 轮均值   1.196
loss 最低          0.275
测试 recall@IoU0.5 12/12 = 1.000（score > 0.3）
每图平均保留框数     1.00
单图推理           23.8 ms，42.0 FPS（320 短边）
```

anchor 尺度实验。先改 `model.rpn.anchor_generator.sizes` 重训（min=128 那组）：

```
min=32（默认）  重训后 recall 12/12 = 1.000，每图 1.00 框
min=128        重训后 recall 12/12 = 1.000，每图 1.25 框
```

**训练召回没有下降，但这不能说明 anchor 无所谓。** 这个合成任务只有 12 个测试样本且对比度极高，指标已经饱和。直接计算"GT 与 anchor 的匹配"才能看到机制（输入 320×320，FPN 三层，每位置 3 种长宽比）：

```
min_anchor   anchor数   GT最大IoU均值   有>=0.5正样本的GT数   每GT正anchor数
        8         675        0.241              0/20              0.0
       16         675        0.439              6/20              0.6
       32         675        0.519             11/20              1.2
       64         675        0.478              9/20              0.9
      128         675        0.156              0/20              0.0
      256         675        0.039              0/20              0.0
```

**解释**：这张图被缩放到 320，结节边长约 35-70 px，所以最佳 anchor 尺度在 32-64 之间；min=128 时 20 个 GT 没有一个能匹配到 IoU≥0.5 的 anchor，RPN 拿不到正样本。训练召回仍是 12/12，是因为 ROI 头还能从少量低 IoU 的 proposal 里把框回归回来，而且合成目标太容易。**如果换成真实 3 mm 结节（4.3 px），同样的尺度错配会直接让召回从第 0 轮就是 0，没有 ROI 头能救。**

**判分要点**
- 检测头必须换成 2 类（背景 + 1 类病灶），输出 91 类说明没换。
- target 格式正确：`boxes` 是 (N,4) float32 的 xyxy 绝对坐标，`labels` 是 (N,) int64。
- loss 用滑动平均判断趋势，不能只看最后一个 iter。
- recall 的计算必须真的按 IoU≥0.5 匹配，不能"有框就算对"。
- anchor 实验要能说清"匹配不到正样本"这个机制；只报"召回没变"不算完成。

**常见错误**
- 忘记 `model.train()` / `model.eval()`，BatchNorm 用错统计量。
- 把 `xywh` 当 `xyxy` 送进去，框整体偏移。
- 全量微调 backbone，60 张图直接过拟合或崩。
- 拿 12/12 说"模型可用于临床"——合成圆斑比真实结节干净得多。
- 只看最终 loss，不看波动来源（每轮只抽 2 张图，正负样本比例抖）。

### 练习 4（多模态融合对比）

**参考代码**
```python
# 完整脚本：E:\AI学习\模块12_检测三维与前沿\_验证代码\exp4_multimodal.py
# 数据：OrganAMNIST 8000 训练 / 3000 测试，28x28，11 类
# 临床指标：按类别均值生成 4 个连续变量 + 1 个二值变量（构造数据，不是真实临床表格）
# 模型：ImgOnly / ClinOnly / EarlyFusion / LateFusion / InterFusion
# 每个模型 3 个种子（1、2、3），12 epoch，AdamW lr=1e-3
# "临床缺失"：把临床输入整体替换为训练集均值向量

for name, mk, use_clin in models:
    res = []
    for seed in [1, 2, 3]:
        torch.manual_seed(seed)
        m = mk().to(dev)
        res.append(run(m, use_clin=use_clin))
    res = np.array(res)
    print(name, res[:, 0].mean(), res[:, 0].std(), res[:, 1].mean(), res[:, 1].std())
```

**实测输出**
```
train (8000, 1, 28, 28) test (3000, 1, 28, 28)

模型          准确率              宏平均AUC           临床缺失准确率   临床缺失AUC
图像单模态    0.8056 ± 0.0227     0.9843 ± 0.0023     0.8056          0.9843
临床单模态    0.3516 ± 0.0035     0.7884 ± 0.0004     0.1863          0.5000
早融合        0.8082 ± 0.0171     0.9823 ± 0.0018     0.7724          0.9757
晚融合        0.8129 ± 0.0184     0.9762 ± 0.0031     0.7970          0.9838
中间融合      0.7891 ± 0.0083     0.9825 ± 0.0025     0.7512          0.9736
```

**怎么读这张表**
- 图像单模态已经 0.8056，AUC 0.9843。构造的临床变量只带 5 维弱信号，单模态只有 0.3516，远弱于图像。
- 早融合 0.8082 比图像单模态高 0.0026，但**小于标准差 0.0227**，统计上不能算提升。
- 晚融合准确率最高（0.8129），但 AUC 反而比图像单模态低（0.9762 vs 0.9843）。原因是晚融合把弱临床分支的概率等权平均，压低了排序质量。**准确率和 AUC 在这里给出了不同结论，必须同时报。**
- 临床缺失时：晚融合 0.7970 最稳（只掉 0.0159），早融合 0.7724（掉 0.0358），中间融合 0.7512（掉 0.0379）。**晚融合最稳，因为缺一路就退化成图像单模态；早融合的输入维度被均值填满后分布变了。**
- 中间融合在这组数据上最差：只有 2 个 token 做 cross-attention，8000 张图不足以训练好融合层，方差也最大。

**为什么早融合可能比单模态差**：早融合把图像 embedding（64 维）和临床向量（5 维）直接拼接后送一个 MLP。如果临床特征弱且噪声大，分类器会把一部分权重分给噪声维度；在训练集上能拟合，在测试集上就是方差。更极端的情况是弱模态把强模态的特征尺度冲掉。**判据不是"早融合一定差"，而是"弱模态 + 小数据时，早融合没有机制保护强模态"。**

**判分要点**
- 四个模型必须用同一划分、同一测试集、同一批种子；只跑一个种子不给分。
- 同时报准确率和宏平均 AUC，并说明两者是否一致。
- 缺失模态实验要真的替换输入，不能只是口头分析。
- 能指出晚融合在缺失场景最稳，并给出机制（可退化为单模态）。
- 能说清构造的临床变量不是真实数据，结论只用于比较融合方式。

**常见错误**
- 各模型用不同的随机划分，指标不可比。
- 只报均值不报 std，0.002 的差距被当成提升。
- 缺失模态时用 0 填充而不是训练集均值/可学习 token，分布偏移被误读成"融合不稳"。
- 把构造的临床数据和真实临床结论混为一谈。
- 多类 AUC 用 `average='macro'` 还是 `'weighted'` 不写清楚，数字对不上。

### 练习 5（SimCLR 线性探针）

**参考代码**
```python

def nt_xent(z1, z2, tau=0.2):
    z1 = F.normalize(z1, dim=1); z2 = F.normalize(z2, dim=1)
    N = z1.size(0)
    z = torch.cat([z1, z2], 0)
    sim = z @ z.t() / tau
    sim.fill_diagonal_(-1e9)
    target = torch.cat([torch.arange(N, 2*N), torch.arange(0, N)]).to(z.device)
    return F.cross_entropy(sim, target)
```

**为什么随机特征时 loss ≈ log(2N-1)**：随机初始化下，任意两个视图的余弦相似度接近 0，`sim(i,k)` 近似全相等；分母有 2N-1 个候选（去掉自己），交叉熵退化为 `log(2N-1)`。N=8 时 log(15)=2.7081，实测 2.7063，差 0.07%。**这是对比损失实现的第一个自检：初始化时损失偏离 log(2N-1) 太多，说明正样本索引或 mask 写错了。**

**判分要点**
- 随机初始化探针约 0.25（11 类，随机猜是 0.09；0.25 说明特征有一点结构但仍很弱）。
- SimCLR 后 ≥ 0.70；本机 0.8047。
- loss 曲线从约 4.8 降到约 2.6，且要给出首末轮数值，不能只画图不看数。
- 能解释 log(2N-1) 的推导，而不是背结论。
- 线性探针必须冻结编码器；如果微调了编码器，就不是在测"特征质量"。

**常见错误**
- 探针在测试集上训练（泄露），准确率虚高。
- 正样本索引写错（`i` 配 `i+1` 而不是 `i+N`），loss 也能降，但学的是错的东西。
- 温度 tau 设成 1.0 或更大，对比信号太弱。
- 增强过强（大角度旋转、颜色抖动），正样本对的语义都变了。
- batch 太小（<64），负样本不够，loss 降不下去。

```markdown
**会议/期刊**：CVPR      **年份**：2016

### 1. 解决什么问题

### 2. 之前的方法有什么不足
1. VGG 式 plain 网络：34 层比 18 层训练误差更高，这不是过拟合（训练集也变差），

3. 此前的 highway network 用带门控的 shortcut，参数多、门控可能关闭，
   没有证明"恒等映射"这条最简单的路可行。

### 3. 核心方法
把每个堆叠层要学的目标从 H(x) 改成 F(x)=H(x)-x，前向变成 y=F(x)+x。
shortcut 是恒等映射，不加参数、不加计算量；维度不一致时用 1x1 卷积
投影（stride 2 时同时降分辨率）。主干用 bottleneck：1x1 降维、3x3 卷积、
1x1 升维，控制 152 层的参数量。反向传播时梯度可以沿 shortcut 直接回传，
不需要穿过所有卷积层。

### 4. 关键创新点
1. 残差学习：让优化目标变成"学增量"，恒等映射在 F=0 时天然可达。
2. 恒等 shortcut 不引入额外参数，可以无缝插进任意深网络。
3. 用 18/34 层 plain vs residual 的对照实验直接证明退化来自优化，不是容量。

ILSVRC 2015 第一（论文报告）。检测任务 COCO 上也优于 VGG 基线
（论文报告）。本机未复现。

### 6. 消融实验证明了什么
最关键的是 plain-18/34 与 residual-18/34 的对照：plain 从 18 层加到 34 层，
训练误差上升；residual 从 18 层加到 34 层，训练误差下降。这一组对照
把"退化"和"残差能解决退化"同时钉死。其次是 shortcut 类型消融：
恒等 vs 1x1 投影 vs 门控，差距很小，说明收益主要来自"有 shortcut"，
不是来自投影参数。

### 7. 局限
1. shortcut 要求通道数和空间分辨率一致，跨 stage 必须用 1x1 投影 +
   stride 2；这使"纯恒等"只在 stage 内部成立，跨 stage 的残差路径仍带参数。
2. 论文只给了优化层面的解释（恒等映射易学），没有给出为什么残差目标
   的条件数更好；后续的 "Visualizing the Loss Landscape" 才补上这部分。
3. 所有实验都在自然图像上，目标尺度大；没有验证在 3-5 px 的小结节
   检测上，stride 32 的深层特征是否还有足够空间分辨率。
4. 计算量集中在 3x3 卷积，但论文没有报告推理延迟随深度的实际变化，
   只有 FLOPs；FLOPs 和 GPU 延迟在 152 层上并不线性。

### 8. 我的想法
把 ResNet 的 stage 结构直接搬到 3D 肺结节检测时，最直接的可验证改动是
"跨 stage 的 shortcut 改成可变形卷积对齐"：因为结节在呼吸前后有位移，
固定 1x1 投影会把错位的特征相加。验证方法：在同一个 3D 检测 backbone 上，
只替换跨 stage shortcut（恒等投影 vs 可变形对齐），固定其他超参和种子，
跑 3 个种子，比较 FROC 在 FP/scan=0.25 处的敏感度；如果提升小于种子间
std，就说明这个改动没有价值。
```
