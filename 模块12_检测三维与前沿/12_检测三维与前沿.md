## 一、目标检测：从"有病灶"到"病灶在哪"

**核心问题：一张 512×512 的 CT 里可能有一个 4 毫米的结节。怎么让模型输出它的框、类别和置信度？**

### 1.1 检测的输出是什么

分类输出一个向量，分割输出一张掩码，检测输出**一组变长的框**：

```
[
  {"box": [x1, y1, x2, y2], "label": "nodule", "score": 0.91},
  {"box": [x1, y1, x2, y2], "label": "nodule", "score": 0.43},
  ...
]
```

三个任务的区别：

| | 分类 | 检测 | 分割 |
|---|---|---|---|
| 输出 | 1 个标签 | N 个框 + 标签 + 分数 | 每像素 1 个标签 |
| 输出维度 | 固定 | **变长** | 固定（与原图同尺寸） |
| 定位粒度 | 无 | 粗（框） | 细（像素） |
| 典型损失 | CE | 分类损失 + 框回归损失 | Dice + CE |
| 医学例子 | 有无结节 | 结节在哪、几个 | 结节边界 |

**检测比分类难的核心原因：输出是变长的。** 一张图可能有 0 个、1 个、7 个结节，网络不能直接输出固定长度的向量。三种范式本质上是在用三种不同办法解决"变长"这件事。

### 1.2 三种范式对照

| | 两阶段 | 单阶段 | 无锚框 |
|---|---|---|---|
| 代表 | Faster R-CNN | YOLO、SSD、RetinaNet | DETR、Deformable DETR |
| 候选框怎么来 | RPN 生成 proposal | 每个位置直接回归 | 一组可学习的 query |
| 要不要 NMS | 要 | 要 | **不要** |
| 速度 | 慢 | 快 | 中等 |
| 小目标 | 较好（FPN + 高分辨率） | 一般 | 较弱 |
| 训练数据需求 | 中 | 中 | **大** |
| 医学落地 | nnDetection、MONAI RetinaNet | 内镜、超声实时筛查 | 研究为主 |

**两阶段（Faster R-CNN）**

```
图像 → backbone → 特征图
                    ├→ RPN：每个位置铺 anchor，判断"有没有目标" + 粗修框
                    └→ ROIAlign：把每个 proposal 对齐成固定大小
                              → 分类头 + 回归头（精修）
```

两个阶段的分工：第一阶段只回答"这里可能有个东西"，第二阶段回答"它是什么、框准不准"。**准，但慢。**

**单阶段（YOLO / SSD）**

去掉"先生成候选"这一步，直接在特征图的每个位置回归框和类别。SSD 在多个尺度上各预测一次，小目标用浅层大特征图。**快，但小目标和密集目标容易漏。**

**无锚框（DETR）**

用 Transformer 解码器输出固定数量的 query（论文是 100 个），每个 query 预测一个框。训练时用匈牙利匹配（Hungarian matching）把预测和真实框一一配对。**没有 anchor，也没有 NMS**，但收敛慢，通常要训 500 epoch，小目标弱。

**一句话选择：**

```
要精度、数据中等 → Faster R-CNN（或它的 3D 版 nnDetection）
要速度、要部署   → YOLO / SSD
要做研究、追新意  → DETR 系列
```

### 1.3 anchor：检测里最容易被忽略的设计

anchor 是预先铺在特征图每个位置上的"参考框"。网络不直接预测框的绝对坐标，而是预测**相对 anchor 的偏移**。

一个位置铺 9 个 anchor：3 种尺度 × 3 种长宽比。

```
尺度 8px      尺度 16px     尺度 32px
┌──┐          ┌────┐        ┌──────┐
└──┘          └────┘        └──────┘
每种尺度再配 1:2、1:1、2:1 三种长宽比
```

**anchor 数量怎么算：**

```
特征图大小 = 输入尺寸 / stride
anchor 总数 = 特征图宽 × 特征图高 × 每个位置的 anchor 数
```

实测：

| 输入 | stride | 位置数 | anchor 数（9/位置） |
|---|---|---|---|
| 512 | 16 | 1024 | 9216 |
| 512 | 8 | 4096 | 36864 |
| 224 | 16 | 196 | 1764 |

**关键问题：anchor 的尺度必须覆盖目标的大小。** 3 mm 结节在 0.7 mm 像素间距下只有 4.29 像素。下面这组实测说明了后果：

| anchor 尺度 | 与 3 mm 结节的最高 IoU | IoU ≥ 0.5 的 anchor 数 |
|---|---|---|
| 8, 16, 32 | **0.287** | **0** |
| 4, 8, 16 | **0.871** | **3** |
| 2, 4, 8 | **0.871** | **3** |

**第一行是最常见的错误：用自然图像的标准 anchor（8/16/32），3 mm 结节一个正样本都匹配不上，训练开始前召回率就是 0。** 网络再深也救不回来。

**这就是为什么医学检测不能直接套 COCO 的超参。** 你要先算：目标在重采样后的体素里有多大，再定 anchor 的最小尺度。

### 1.4 手写 NMS

**核心问题：一个结节，网络会输出几十个重叠的框。怎么只留一个？**

NMS（Non-Maximum Suppression，非极大值抑制）的规则只有四步：

```
1. 所有框按分数从高到低排序
2. 取分数最高的框，保留
3. 计算它和剩余所有框的 IoU，删除 IoU 超过阈值的
4. 重复 2-3，直到没有框剩下
```

**IoU 的定义：**

```
IoU = 交集面积 / 并集面积
    = 交集 / (A 面积 + B 面积 - 交集)
```

**具体例子。** 输入 6 个框，同一个类别：

| 名字 | 框 [x1,y1,x2,y2] | 分数 |
|---|---|---|
| A | [10, 10, 60, 60] | 0.92 |
| B | [12, 14, 58, 62] | 0.85 |
| C | [100, 100, 150, 150] | 0.78 |
| D | [104, 98, 152, 148] | 0.65 |
| E | [200, 50, 240, 90] | 0.60 |
| F | [14, 12, 56, 58] | 0.55 |

**先算 IoU 矩阵（实测）：**

|  | A | B | C | D | E | F |
|---|---|---|---|---|---|---|
| **A** | 1.000 | 0.816 | 0 | 0 | 0 | 0.773 |
| **B** | 0.816 | 1.000 | 0 | 0 | 0 | 0.806 |
| **C** | 0 | 0 | 1.000 | 0.820 | 0 | 0 |
| **D** | 0 | 0 | 0.820 | 1.000 | 0 | 0 |
| **E** | 0 | 0 | 0 | 0 | 1.000 | 0 |
| **F** | 0.773 | 0.806 | 0 | 0 | 0 | 1.000 |

**手算一遍 A 和 B：**

```
A 面积 = 50 × 50 = 2500
B 面积 = 46 × 48 = 2208
交集：x 从 12 到 58 = 46，y 从 14 到 60 = 46 → 2116
IoU = 2116 / (2500 + 2208 - 2116) = 2116 / 2592 = 0.816
```

**逐步执行（阈值 0.5）：**

| 步骤 | 当前最高分 | 动作 | 被抑制 |
|---|---|---|---|
| 1 | A (0.92) | 保留 A | B (0.816)、F (0.773) |
| 2 | C (0.78) | 保留 C | D (0.820) |
| 3 | E (0.60) | 保留 E | 无 |
| 结束 | - | 剩 3 个 | B、D、F |

**输出：A、C、E。**

**代码实现（可直接运行）：**

```python
import numpy as np

def iou(a, b):
    x1, y1 = max(a[0], b[0]), max(a[1], b[1])
    x2, y2 = min(a[2], b[2]), min(a[3], b[3])
    inter = max(0.0, x2 - x1) * max(0.0, y2 - y1)
    area_a = (a[2] - a[0]) * (a[3] - a[1])
    area_b = (b[2] - b[0]) * (b[3] - b[1])
    return inter / (area_a + area_b - inter)

def nms(boxes, scores, thr=0.5):
    order = np.argsort(-scores)
    keep = []
    while order.size > 0:
        i = order[0]
        keep.append(i)
        if order.size == 1:
            break
        rest = order[1:]
        ious = np.array([iou(boxes[i], boxes[j]) for j in rest])
        order = rest[ious <= thr]
    return keep

boxes = np.array([
    [10, 10, 60, 60],
    [12, 14, 58, 62],
    [100, 100, 150, 150],
    [104, 98, 152, 148],
    [200, 50, 240, 90],
    [14, 12, 56, 58],
], dtype=float)
scores = np.array([0.92, 0.85, 0.78, 0.65, 0.60, 0.55])
names = ['A', 'B', 'C', 'D', 'E', 'F']

keep = nms(boxes, scores, 0.5)
print('保留:', [names[i] for i in keep])

for t in [0.3, 0.5, 0.7, 0.8, 0.85]:
    k = nms(boxes, scores, t)
    print(f'thr={t:.2f} 保留 {len(k)} 个: {[names[i] for i in k]}')
```

**实测输出：**

```
保留: ['A', 'C', 'E']
thr=0.30 保留 3 个: ['A', 'C', 'E']
thr=0.50 保留 3 个: ['A', 'C', 'E']
thr=0.70 保留 3 个: ['A', 'C', 'E']
thr=0.80 保留 4 个: ['A', 'C', 'E', 'F']
thr=0.85 保留 6 个: ['A', 'B', 'C', 'D', 'E', 'F']
```

**这张表说明什么：** 因为 IoU 值集中在 0.77 到 0.82 之间，阈值从 0.3 调到 0.7 结果完全不变；一旦越过 0.8，抑制突然失效。**NMS 阈值是一个"悬崖式"超参，不是平滑的。** 调它的时候必须看 IoU 分布，不能凭感觉。

**三个必须知道的坑：**

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 跨类别做 NMS | 肝脏和肿瘤框互相抑制 | **按类别分别做** |
| 3D 检测用 2D NMS | 相邻层各留一个，切片方向重复 | 用 3D IoU（体积交集） |
| 密集小目标 | 真实相邻结节被误删 | 降低阈值，或换 Soft-NMS |

**Soft-NMS 的思路**：不直接删除高分框附近的框，而是按 IoU 给它降分。IoU 越高，分数降得越多。适合"两个结节挨得很近"的场景。

### 1.5 mAP@0.5 是怎么算的

**核心问题：NMS 之后还剩一堆框，怎么用一个数字衡量检测好坏？**

先定义两个量：

```
TP：预测框和某个真实框 IoU ≥ 阈值，且该真实框还没被匹配过
FP：没有匹配上任何真实框的预测框
FN：没被任何预测框匹配上的真实框
```

```
Precision = TP / (TP + FP)     预测出来的框里，有多少是真的
Recall    = TP / (TP + FN)     真实目标里，有多少被找到了
```

**AP 是 Precision-Recall 曲线下的面积。** mAP 是各类别 AP 的平均。mAP@0.5 就是 IoU 阈值取 0.5。

**手算例子。** 两张图，共 2 个真实目标，4 个预测：

| 预测 | 图像 | 分数 | 匹配结果 |
|---|---|---|---|
| P1 | img1 | 0.95 | FP（IoU < 0.5） |
| P2 | img1 | 0.90 | TP |
| P3 | img2 | 0.85 | TP |
| P4 | img2 | 0.70 | FP |

**按分数从高到低累积：**

| 处理到 | 判定 | 累计 TP | 累计 FP | Precision | Recall |
|---|---|---|---|---|---|
| P1 | FP | 0 | 1 | 0.000 | 0.0 |
| P2 | TP | 1 | 1 | 0.500 | 0.5 |
| P3 | TP | 2 | 1 | 0.667 | 1.0 |
| P4 | FP | 2 | 2 | 0.500 | 1.0 |

**AP（全点插值，VOC2010 之后的算法）：**

```
在 Recall = 0 到 0.5 区间，最大 Precision = 0.667
在 Recall = 0.5 到 1.0 区间，最大 Precision = 0.667
AP = 0.5 × 0.667 + 0.5 × 0.667 = 0.667
```

**实测 AP@0.5 = 0.6667。** 注意不是简单的 (0.5+0.667)/2，而是先做 Precision 包络（从右往左取最大），再算面积。

```python
import numpy as np

def average_precision(tp_flags, n_gt):
    """tp_flags: 按分数降序排列的 0/1 列表"""
    tp = fp = 0
    prec, rec = [], []
    for hit in tp_flags:
        tp += hit
        fp += 1 - hit
        prec.append(tp / (tp + fp))
        rec.append(tp / n_gt)
    mrec = np.concatenate(([0.], rec, [1.]))
    mpre = np.concatenate(([0.], prec, [0.]))
    for i in range(len(mpre) - 2, -1, -1):
        mpre[i] = max(mpre[i], mpre[i + 1])
    idx = np.where(mrec[1:] != mrec[:-1])[0]
    return np.sum((mrec[idx + 1] - mrec[idx]) * mpre[idx + 1])

print(average_precision([0, 1, 1, 0], 2))   # 0.6666...
```

**mAP@0.5 对小结节有多苛刻？** 这是医学检测最该算的一笔账。

设结节直径 4.29 像素（3 mm，0.7 mm 间距），预测框只平移：

| 平移量 | IoU | 是否算 TP（阈值 0.5） |
|---|---|---|
| 0.5 px | 0.640 | 是 |
| **1.0 px** | **0.416** | **否** |
| 2.0 px | 0.166 | 否 |

**结论：对 3 mm 结节，框只要偏 1 个像素，mAP@0.5 就判你错。** 而两个放射科医生画同一个 3 mm 结节的框，边界差 1 到 2 像素是常态。

**所以 mAP@0.5 在小目标上测量的是"标注和预测的像素级一致性"，不是"临床上有没有发现病灶"。** 这是后面 FROC 更合适的原因之一。

### 1.6 FROC：医学检测真正该看的曲线

**核心问题：临床上医生关心的不是"框画得准不准"，而是"每个扫描我要多看几个假阳性"。**

FROC（Free-response Receiver Operating Characteristic）的两个轴：

```
横轴：平均每个扫描的假阳性数（FP/scan）
纵轴：敏感度（病灶级召回）
```

**和 ROC 的区别：**

| | ROC | FROC |
|---|---|---|
| 横轴 | 1 - 特异度（按图像算） | **FP/scan（按扫描算）** |
| 正样本单位 | 图像 | **病灶** |
| 一个扫描多个病灶 | 只能算"有/无" | 每个病灶单独算 |
| 临床含义 | 误诊率 | **医生每例要多看几个框** |

**为什么医学必须用 FROC：** 一张 CT 有 300 层，只要模型在任意一层冒出一个假阳性，这张扫描就算"有报警"。ROC 的"图像级特异度"会把这个信息压扁；FROC 直接告诉你"平均每扫 1 个假阳性时，能查出多少结节"。

**实测 FROC（合成数据，20 个阳性扫描、20 个阴性扫描、56 个假阳性候选）：**

| 工作点 FP/scan | 敏感度 | 对应阈值 |
|---|---|---|
| 0.125 | 0.600 | 0.54 |
| 0.25 | 0.850 | 0.47 |
| 0.50 | 0.950 | 0.39 |
| 1.00 | 0.950 | 0.22 |
| 2.00 | 1.000 | 0.01 |

**读法：** 如果科室能接受"每例平均 0.5 个假阳性"，敏感度是 0.95；如果要压到 0.125 个，敏感度掉到 0.60。**这条曲线直接对应一个管理决策，而 mAP 给不出这个信息。**

**算一笔临床账：**

```
一个医院每天 200 例胸部 CT
每例 1 个假阳性 → 每天多 200 个框要医生点开看
每个框平均 30 秒 → 每天多 100 分钟，约 1.7 小时
```

**这就是为什么医学检测论文必须报"敏感度 @ 固定 FP/scan"，而不是只报 mAP。**

**代码（可直接运行）：**

```python
import numpy as np

rng = np.random.default_rng(0)
n_scan = 40
scores_pos = np.clip(rng.normal(0.62, 0.18, 20), 0.02, 0.99)

fp_scores = []
for _ in range(n_scan):
    n_fp = rng.poisson(1.2)
    fp_scores.extend(np.clip(rng.normal(0.30, 0.15, n_fp), 0.01, 0.95).tolist())
fp_scores = np.array(fp_scores)

ths = np.linspace(0.01, 0.99, 99)
sens = [(scores_pos >= t).mean() for t in ths]
fps = [((fp_scores >= t).sum() / n_scan) for t in ths]

for target in [0.125, 0.25, 0.5, 1.0, 2.0]:
    cand = [(f, s, t) for f, s, t in zip(fps, sens, ths) if f <= target]
    if cand:
        f, s, t = max(cand, key=lambda x: x[1])
        print(f'FP/scan<={target:<5} sensitivity={s:.3f} @thr={t:.2f} (actual FP/scan={f:.2f})')
```

**LUNA16 官方指标就是 FROC 的七个点：** 在 FP/scan = 0.125、0.25、0.5、1、2、4、8 处的敏感度取平均。**注意它没有"8 个假阳性以上"的要求，因为那已经不可用了。**

### 1.7 跑通一个 torchvision 检测模型

**核心问题：不碰 LUNA16，怎么在本地把检测的训练和推理流程走一遍？**

用**合成结节**：128×128 灰度图，背景噪声 + 一个亮圆，圆的位置和半径随机。这不是医学数据，但包含了检测的全部工程环节：数据格式、模型改造、训练循环、NMS 后处理、评估。

```python
import numpy as np
import torch
import torch.nn.functional as F
import time
from torchvision.models.detection import (
    fasterrcnn_mobilenet_v3_large_320_fpn,
    FasterRCNN_MobileNet_V3_Large_320_FPN_Weights,
)
from torchvision.models.detection.faster_rcnn import FastRCNNPredictor

device = 'cuda' if torch.cuda.is_available() else 'cpu'
torch.manual_seed(0)

def make_sample(seed):
    rng = np.random.default_rng(seed)
    img = rng.normal(0.12, 0.03, (1, 128, 128)).astype(np.float32)
    cy, cx = rng.integers(25, 103, 2)
    r = rng.integers(7, 14)
    yy, xx = np.mgrid[0:128, 0:128]
    mask = (yy - cy) ** 2 + (xx - cx) ** 2 <= r * r
    img[0][mask] = rng.uniform(0.65, 0.95)
    t = torch.tensor(img)[None]
    t = F.avg_pool2d(F.pad(t, (2, 2, 2, 2), mode='replicate'), 5, 1)
    return t[0].numpy(), np.array([cx - r, cy - r, cx + r, cy + r], dtype=np.float32)

train = [make_sample(s) for s in range(60)]
test = [make_sample(s) for s in range(1000, 1012)]

model = fasterrcnn_mobilenet_v3_large_320_fpn(
    weights=FasterRCNN_MobileNet_V3_Large_320_FPN_Weights.DEFAULT)
in_feat = model.roi_heads.box_predictor.cls_score.in_features
model.roi_heads.box_predictor = FastRCNNPredictor(in_feat, 2)  # 背景 + 结节
model.to(device)

for p in model.backbone.parameters():
    p.requires_grad = False

imgs = [torch.tensor(x[0]) for x in train]
tgts = [{'boxes': torch.tensor(x[1])[None], 'labels': torch.tensor([1])} for x in train]

opt = torch.optim.SGD([p for p in model.parameters() if p.requires_grad],
                      lr=0.005, momentum=0.9)
model.train()
for it in range(40):
    idx = np.random.default_rng(it).choice(len(imgs), 2, replace=False)
    xb = [imgs[i].to(device) for i in idx]
    yb = [{k: v.to(device) for k, v in tgts[i].items()} for i in idx]
    loss_dict = model(xb, yb)
    loss = sum(v for v in loss_dict.values())
    opt.zero_grad(); loss.backward(); opt.step()
    if it % 10 == 0:
        print(it, round(loss.item(), 3), {k: round(v.item(), 3) for k, v in loss_dict.items()})

model.eval()
with torch.no_grad():
    out = model([torch.tensor(test[0][0]).to(device)])[0]
print(out['boxes'].shape, out['scores'][:3], out['labels'][:3])
```

**实测结果：**

| 指标 | 值 |
|---|---|
| 替换检测头后参数量 | 18.93 M |
| 训练 40 iter 用时 | 8-22 s（受 GPU 状态影响） |
| loss（前 5 轮均值） | 2.127 |
| loss（后 10 轮均值） | 1.196 |
| loss 最低 | 0.275 |
| 测试 recall@IoU0.5（score>0.3） | **12/12 = 1.000** |
| 每图平均保留框数 | 1.00 |
| 单图推理（320 短边） | **40.4 ms，24.8 FPS** |

**注意 loss 的波动：** 后 10 轮均值 1.196 高于中途最低的 0.275。原因是每轮随机抽 2 张图，ROI 采样到的正负样本比例差别很大。**报告 loss 时不要只报最后一个 iter，要报滑动平均。**

**这段代码的三个关键点，换成真实 CT 也一样：**

1. **换检测头**：`FastRCNNPredictor(in_features, 2)`，2 = 背景 + 1 类病灶。COCO 的 91 类必须换掉。
2. **冻结 backbone**：小数据下全量微调会崩。先只训 RPN 和 ROI 头，再考虑解冻。
3. **格式**：target 必须是 `{'boxes': (N,4) float, 'labels': (N,) int64}`，box 是 `x1,y1,x2,y2` 绝对坐标。

**局限必须说清楚：** 合成圆斑的对比度、边界、背景都比真实结节干净得多，12/12 不代表真实场景。真实结节的挑战是毛玻璃、血管贴边、胸膜相连、3 mm 以下。**这个实验证明的是流程通了，不是模型能用了。**

### 1.8 真实医学检测：换成 LUNA16

**数据集事实：**

| 项 | 值 |
|---|---|
| 扫描数 | 888 例胸部 CT |
| 结节数 | 1186 个，直径 ≥ 3 mm |
| 来源 | LIDC-IDRI，四位放射科医生标注后合并 |
| 划分 | 10 个 subset，4 折交叉验证 |
| 大小 | 约 120 GB |
| 标注文件 | `annotations.csv`、`candidates.csv`、`dataset.csv` |

**下载方法（本机未执行）：**

1. 官方入口：LUNA16 官网（Grand Challenge）或 Zenodo 记录 3723295
2. 下载 `subset0.zip` 到 `subset9.zip`，共 10 个包
3. 解压后每个病例是一个 `.mhd` + `.raw`（MetaImage 格式）
4. 用 `SimpleITK` 读取：

```python
import numpy as np
import SimpleITK as sitk

def read_luna_case(path):
    """读取一个 LUNA16 的 .mhd 病例。需要真实文件才能运行。"""
    itk = sitk.ReadImage(path)
    image = sitk.GetArrayFromImage(itk)      # (z, y, x)，HU 值
    origin = np.array(itk.GetOrigin())       # 世界坐标原点
    spacing = np.array(itk.GetSpacing())     # (x, y, z) mm
    return image, origin, spacing

# 用法（需要真实文件）：
# image, origin, spacing = read_luna_case(r"C:/data/subset0/1.3.6...mhd")
```

**这段代码需要真实文件，本机没有 LUNA16，所以没有执行读取。函数本身可以导入和调用，缺的只是文件。**

**从 CSV 到训练样本的标准流程：**

```
1. 读 annotations.csv，拿到每个结节的 world 坐标 (x, y, z) 和直径
2. 用 origin + spacing 把 world 坐标转成 voxel 坐标
3. 重采样到 1 mm × 1 mm × 1 mm（原层厚常为 2.5 mm）
4. 以结节为中心裁 64×64×64 的 patch
5. 负样本：从肺实质内随机裁，且与所有结节中心距离 > 20 mm
6. 正负比 1:1 到 1:3
```

**评估必须用官方脚本。** LUNA16 的 FROC 计算有一堆细节：一个预测命中多个结节怎么算、多个预测命中一个结节怎么算、按结节直径分层。自己手写的 FROC 和官方脚本对不上是常态。

**3D 检测的两种做法：**

| 做法 | 输入 | 优点 | 缺点 |
|---|---|---|---|
| 2D 逐层 + 3D 聚合 | 单层切片 | 显存小、可用 2D 预训练 | 丢失层间信息，相邻层重复 |
| 3D patch | 64³ 体素 | 利用三维形状 | 显存大、数据需求高 |

**推荐起点：** 先用 2.5D（相邻 3 层当 3 通道）跑通，再上 3D。nnDetection 是开源的 3D 医学检测框架，基于 Faster R-CNN，支持 LUNA16，可以作为强基线。

### 1.9 检测部分的常见错误

| 错误 | 表现 | 原因 | 更正 |
|---|---|---|---|
| anchor 尺度不对 | 召回率从第 0 轮就是 0 | 最小 anchor 8px，目标 4px | 按目标尺寸重设 anchor |
| 忘记换检测头 | 输出 91 类，loss 不降 | COCO 预训练头没换 | `FastRCNNPredictor(in_feat, 2)` |
| box 格式搞混 | 框飞到图像外 | xywh 和 xyxy 混用 | 统一 xyxy，写注释 |
| 跨类别 NMS | 肿瘤把肝脏抑制掉 | 所有类别一起做 | 按类别分开 |
| 用 mAP 调医学模型 | 指标好看但假阳性爆炸 | mAP 不反映 FP/scan | 同时报 FROC |
| 只报最后一个 iter 的 loss | loss 看起来在涨 | 单批波动大 | 报滑动平均 |
| 按切片划分数据 | 指标虚高 | 同一病人不同层进了测试集 | 按病人划分 |
| 3 mm 结节缩到 224 | 只剩 1.9 像素 | 预处理直接 resize | 保持高分辨率或切 patch |

## 二、医学检测的特殊性

**核心问题：自然图像检测的模型直接搬到 CT 上，为什么经常不可用？**

### 2.1 小目标：3 mm 到底有多小

先把账算清楚。假设层内像素间距 0.7 mm：

```
3 mm / 0.7 mm = 4.29 像素
面积 = π × (4.29/2)² = 14.4 平方像素（圆）或 18.4（外接方框）
占 512×512 图像的面积比例 = 18.37 / 262144 = 0.0070%
```

| 处理方式 | 结节直径 | 后果 |
|---|---|---|
| 原始 512×512，0.7 mm | 4.3 px | 可检测，但需要小 anchor |
| resize 到 224×224 | **1.9 px** | 基本消失 |
| 层厚 2.5 mm 未重采样 | 层间只有 1.2 层 | 三维形状丢失 |
| 重采样到 1 mm 各向同性 | 3.0 px | 三维形状完整 |

**代码验证（可直接运行）：**

```python
import numpy as np

for spacing in [0.5, 0.7, 0.8, 1.0, 2.5]:
    px = 3 / spacing
    area = np.pi * (px / 2) ** 2
    print(f'spacing={spacing}mm: 3mm = {px:.1f} px, 面积 {area:.1f} px^2')

print('512x512 中占比 %.4f%%' % (np.pi * (3/0.7/2)**2 / 512**2 * 100))
print('缩到 224 后 %.1f px' % (3/0.7*224/512))
```

**实测输出：**

```
spacing=0.5mm: 3mm = 6.0 px, 面积 28.3 px^2
spacing=0.7mm: 3mm = 4.3 px, 面积 14.4 px^2
spacing=0.8mm: 3mm = 3.8 px, 面积 11.0 px^2
spacing=1.0mm: 3mm = 3.0 px, 面积 7.1 px^2
spacing=2.5mm: 3mm = 1.2 px, 面积 1.1 px^2
512x512 中占比 0.0055%
缩到 224 后 1.9 px
```

**三个对策，按性价比排序：**

| 对策 | 做法 | 代价 | 效果 |
|---|---|---|---|
| **切 patch，不整图 resize** | 以候选点为中心裁 64³ 或 96³ | 推理要滑窗 | 最有效 |
| **高分辨率特征图** | FPN 用 stride 4 的层做小目标预测 | 显存和计算翻倍 | 明显 |
| **小 anchor** | 最小尺度设为 4 或 2 | 正样本变多，需调采样 | 必要前提 |
| 深监督 | 中间层也加检测损失 | 训练稍复杂 | 辅助 |

**判断标准：** 目标在送入网络的那一层特征图上还剩几个像素？如果小于 3×3，检测头基本看不见它。

### 2.2 假阳性代价高

分类模型错一个，用户刷新一下；检测模型错一个，医生要点开一个不存在的病灶。

**假阳性的三种代价：**

| 代价 | 表现 | 量化 |
|---|---|---|
| 时间 | 每个框都要看 | 约 30 秒/框 |
| 信任 | 假阳性多了，医生直接忽略所有报警 | 告警疲劳 |
| 后续检查 | 可疑结节 → 3 个月复查 CT → 焦虑、费用、辐射 | 过度诊断 |

**这就是 FROC 的意义：** 它把"敏感度"和"医生工作量"放在同一张图上，让科室能选工作点。

**降低假阳性的四种工程手段：**

1. **级联（cascade）**：第一级高召回低阈值，第二级分类器（可用 3D CNN）过滤候选。LUNA16 前排方案几乎都这么做。
2. **硬负样本挖掘**：把上一轮误报的 patch 加入训练集，反复迭代。
3. **解剖先验**：结节在肺实质内，不在体外、不在纵隔。用肺掩码把候选限制在肺内，能去掉大量假阳性。
4. **多视图一致性**：2.5D 的三个视图（轴位、冠状位、矢状位）都认为是结节才保留。

### 2.3 标注贵

| 标注类型 | 成本 | 得到什么 | 适合 |
|---|---|---|---|
| 图像级标签 | 低（看一张图 5 秒） | 有/无病灶 | 筛查分诊、弱监督 |
| 框 | 中（1-2 分钟） | 位置 + 大小 | 检测 |
| 像素掩码 | 高（10-30 分钟） | 精确边界 | 分割 |
| 三位专家 + 仲裁 | 极高 | 金标准 | 数据集建设 |

**标注一致性问题：** 3 到 5 mm 的结节，不同医生的检出率差异很大。LIDC-IDRI 让四位医生独立标注，最后只有**所有人都标了的**才算"金标准结节"，这本身就说明小 nodules 的标注不稳定。

**这带来一个反直觉的结论：**

> 在小结节上，你的模型和"金标准"的差距里，有一部分是标注噪声，不是模型错误。
> 所以报告结果时要说明：金标准怎么来的、几位医生、分歧怎么处理。

### 2.4 极端类别不平衡

一张 512×512×300 的 CT：

```
总体素数 = 78,643,200
一个 4 mm 结节的体素数 ≈ 4/0.7 × 4/0.7 × 4/1 ≈ 130
正样本比例 ≈ 130 / 78,643,200 = 0.000165%
```

**正负比约 1:600,000。** 如果随机采样 patch，训练 1000 个 patch 可能一个正样本都没有。

**处理顺序：**

```
1. 按病灶中心采样正样本（保证每个 batch 有正样本）
2. 负样本从肺实质内采，且离病灶足够远
3. 正负比 1:1 到 1:3（检测头层面）
4. Focal Loss 处理剩余的不平衡（单阶段检测器）
5. 最后才考虑全局重采样
```

**注意：** 检测里的不平衡和分类里的不平衡不是一回事。检测的 RPN 阶段本身会采样（Faster R-CNN 默认每图 256 个 anchor，正负 1:1），所以真正的极端不平衡发生在**候选生成之前**和**滑窗推理时**。

### 2.5 医学检测数据集一览

| 数据集 | 任务 | 规模（公开信息） | 备注 |
|---|---|---|---|
| LUNA16 | 肺结节检测 | 888 扫描，1186 结节 | 最常用基准，120 GB |
| LIDC-IDRI | 肺结节 | 1018 例 | LUNA16 的母数据集，含 4 位医生标注 |
| ANODE09 | 肺结节 | 55 扫描 | 老，规模小 |
| DeepLesion | 全身病灶 | 10,594 研究，32,735 病灶 | 书签式标注，框较粗 |
| LiTS | 肝脏/肿瘤分割 | 131 训练 + 70 测试 | 分割，不是检测 |
| KiTS | 肾脏/肿瘤 | 300+ 例 | 分割 + 检测 |

**本机现状：一个都没有。** 这不是问题，检测的工程流程可以用合成数据走通；等有真实数据时，换数据加载器即可。

### 2.6 本节的常见错误

| 错误 | 表现 | 更正 |
|---|---|---|
| 把检测当分类做 | 只输出"有/无"，不给位置 | 临床要位置，用检测 |
| 用图像级 AUC 报检测结果 | 看不出假阳性负担 | 加 FROC |
| 忽略结节大小分层 | 小结节全漏，大结节全中，总体召回好看 | 按 <6mm、6-10mm、>10mm 分层报 |
| 负样本从全图随机采 | 大量在体外/骨骼 | 限制在肺实质内 |
| 认为标注是绝对正确的 | 模型"错"的其实是标注分歧 | 报告标注协议 |

## 三、3D 与多期相

**核心问题：CT 是三维的，直接上 3D 卷积行不行？多期相 CT 的几组图像怎么用？**

### 3.1 3D 卷积的代价

3D 卷积就是把 2D 的 k×k 核换成 k×k×k。

**参数量对比（实测）：**

| 层 | 参数量 |
|---|---|
| Conv2d(32, 64, 3) | 18,496 |
| Conv3d(32, 64, 3) | 55,360 |
| 比值 | **2.99 倍** |

参数量只涨 3 倍，但**计算量涨得更多**，因为体素数量也涨了。

**实测前向耗时（RTX 5060）：**

| 输入 | 层 | 10 次平均 | 峰值显存 |
|---|---|---|---|
| 1×32×64×128×128 | Conv3d(32,64,3) | **11.7-14.7 ms**（受 GPU 频率影响） | **0.95-1.00 GB** |
| 1×32×128×128 | Conv2d(32,64,3) | **0.20 ms** | 很小 |

**3D 比 2D 慢约 60-75 倍。** 算法：体素多 64 倍（64 层），每体素计算多 3 倍，理论 192 倍；GPU 对 3D 的优化不如 2D，实测 60-75 倍。

```python
import torch, torch.nn as nn, time

c2 = nn.Conv2d(32, 64, 3, padding=1)
c3 = nn.Conv3d(32, 64, 3, padding=1)
print(sum(p.numel() for p in c2.parameters()))
print(sum(p.numel() for p in c3.parameters()))

if torch.cuda.is_available():
    c2, c3 = c2.cuda(), c3.cuda()
    x3 = torch.randn(1, 32, 64, 128, 128, device='cuda')
    for _ in range(3): c3(x3)
    torch.cuda.synchronize(); torch.cuda.reset_peak_memory_stats()
    t0 = time.time()
    for _ in range(10): c3(x3)
    torch.cuda.synchronize()
    print('3D %.1f ms, %.2f GB' % ((time.time()-t0)*100,
          torch.cuda.max_memory_allocated()/1024**3))
```

**2D、2.5D、3D 怎么选：**

| 方案 | 输入 | 显存 | 数据量 | 层间信息 | 推荐场景 |
|---|---|---|---|---|---|
| 2D | 单层 | 小 | 少 | 无 | 基线、切片级筛查 |
| 2.5D | 相邻 3 层当 3 通道 | 中 | 中 | 局部 | **最实用的起点** |
| 3D | 64³ patch | 大 | 多 | 完整 | 有足够数据和显存 |
| 3D + 各向同性 | 重采样后 | 更大 | 多 | 完整且不歪 | nnU-Net 类方案 |

**为什么 2.5D 常常够用：** 结节的三维形状在 3 层里已经能看出"圆不圆、有没有分叶"，而 2.5D 可以直接用 ImageNet 预训练的 2D backbone。**先用 2.5D 拿到基线，再决定要不要付 3D 的代价。**

### 3.2 各向异性：3D 卷积最容易踩的坑

CT 的体素不是立方体。典型腹部 CT：

```
层内 spacing：0.7 mm × 0.7 mm
层厚：5 mm
```

**Z 方向比 XY 粗 7 倍。** 直接做 3×3×3 卷积，等于在 Z 方向用 7 倍的范围做平滑，形状会被学歪。

**处理：重采样到各向同性。**

```python
import numpy as np
import SimpleITK as sitk

# 造一个 64x64x10、层厚 5mm 的体数据（真实数据换成 sitk.ReadImage）
arr = np.random.default_rng(0).normal(0, 1, (10, 64, 64)).astype(np.float32)
img = sitk.GetImageFromArray(arr)
img.SetSpacing((0.7, 0.7, 5.0))
print('before', img.GetSize(), img.GetSpacing())

resampler = sitk.ResampleImageFilter()
resampler.SetOutputSpacing((1.0, 1.0, 1.0))
resampler.SetSize([
    int(round(img.GetSize()[0] * img.GetSpacing()[0] / 1.0)),
    int(round(img.GetSize()[1] * img.GetSpacing()[1] / 1.0)),
    int(round(img.GetSize()[2] * img.GetSpacing()[2] / 1.0)),
])
resampler.SetInterpolator(sitk.sitkLinear)
out = resampler.Execute(img)
print('after ', out.GetSize(), out.GetSpacing())
```

**实测输出：**

```
before (64, 64, 10) (0.7, 0.7, 5.0)
after  (45, 45, 50) (1.0, 1.0, 1.0)
```

层厚从 5 mm 变成 1 mm，Z 方向从 10 层变成 50 层；XY 从 0.7 mm 变成 1 mm，尺寸从 64 缩到 45。**这就是各向同性重采样的实际效果。**

**注意插值方式：**

| 对象 | 插值 | 原因 |
|---|---|---|
| CT 图像 | 线性 / B 样条 | 保持灰度连续 |
| 分割掩码 | **最近邻** | 不能产生 0.5 这种标签 |

**用线性插值处理掩码，会造出不存在的类别，这是分割里最常见的静默错误。**

### 3.3 多期相 CT：肝癌的关键信息在"时间"里

**核心问题：同一个病人，动脉期、门脉期、延迟期各扫一遍，这三组图怎么一起用？**

**为什么肝癌要看多期：** HCC 的典型强化模式是"快进快出"。

| 期相 | 扫描时间 | HCC 表现 | 肝实质 |
|---|---|---|---|
| 平扫 | 注射前 | 低密度 | 正常 |
| 动脉期 | 25-35 s | **明显强化（快进）** | 强化不明显 |
| 门脉期 | 60-70 s | 等/低密度 | 明显强化 |
| 延迟期 | 3-5 min | **低密度（快出）** | 强化减退 |

**"动脉期高强化 + 门脉期/延迟期廓清"是 LI-RADS 诊断 HCC 的主要标准之一。** 单看一个期相，很多病灶和血管瘤、转移瘤分不开。

**三种用法：**

| 用法 | 输入形状 | 优点 | 缺点 |
|---|---|---|---|
| **通道堆叠** | (3, D, H, W) | 简单，一次前向 | 要求三期已配准 |
| **多分支编码** | 每期一个 encoder | 允许未配准 | 参数量 ×3 |
| **期相注意力** | 每期一个 token，做 attention | 可学习期相权重 | 数据需求大 |

**通道堆叠最小示例：**

```python
import torch, torch.nn as nn

# 3 期，每期 32 层 128×128，重采样到 1mm
x = torch.randn(1, 3, 32, 128, 128)
net = nn.Sequential(
    nn.Conv3d(3, 32, 3, padding=1), nn.BatchNorm3d(32), nn.ReLU(),
    nn.Conv3d(32, 64, 3, padding=1), nn.BatchNorm3d(64), nn.ReLU(),
    nn.AdaptiveAvgPool3d(1), nn.Flatten(), nn.Linear(64, 2),
)
print(net(x).shape)

# 对比：单期输入
x1 = torch.randn(1, 1, 32, 128, 128)
print(sum(p.numel() for p in net.parameters()))
```

**关键工程问题：配准。** 三期是三次屏气扫描，病人位置、呼吸相位都不同。**没配准就堆通道，等于把肝脏的位置错开 1-2 cm 叠加**，模型学到的是伪影。

| 情况 | 做法 |
|---|---|
| 已配准（同一次检查、有 registration） | 通道堆叠 |
| 未配准 | 先做刚性/形变配准，或多分支分别编码 |
| 只有单期 | 老实做单期模型，不要假装多期 |

**医学上还要注意：** 不是每个病人都有三期。有的只做了平扫 + 动脉期。**多期模型必须能处理"缺期相"**，训练时随机丢掉 1-2 期（modality dropout），推理时才稳。

### 3.4 超声视频与内镜

超声和內镜不是"一张图"，是**一段视频**。

| 数据形态 | 维度 | 典型任务 | 模型 |
|---|---|---|---|
| 单帧 | H×W | 分类 | CNN / ViT |
| 片段 | T×H×W | 分类（视频级） | 3D CNN / CNN + LSTM |
| 完整视频 | 数百帧 | 病灶检出、跟踪 | 时序检测 |

**超声的额外难点：**

| 难点 | 表现 | 对策 |
|---|---|---|
| 斑点噪声 | 颗粒状纹理，和结节纹理混在一起 | 不做锐化，用更强的增强 |
| 探头依赖 | 不同机器、不同增益，灰度分布完全不同 | 每台机器单独标准化，或域适应 |
| 扫查手法 | 医生扫得快慢、角度不同 | 视频级标签，不要逐帧标 |
| 帧间冗余 | 相邻帧几乎一样 | 按时间抽样，不要均匀抽全部帧 |

**视频级标签的用法：** 一段 10 秒视频标"有病灶"，但不知道具体哪一帧。这属于弱监督，用 MIL（多示例学习）或注意力池化：每帧出一个分数，取最大或加权平均作为视频分数。

### 3.5 本节的常见错误

| 错误 | 表现 | 更正 |
|---|---|---|
| 3D 卷积不重采样 | 形状学歪，Z 方向模糊 | 先重采样到 1 mm 各向同性 |
| 掩码用线性插值 | 出现 0.5 类标签 | 最近邻 |
| 多期相未配准就堆通道 | 模型学到错位伪影 | 先配准，或多分支 |
| 假设每个病人都有三期 | 推理时缺期相直接崩 | 训练时 modality dropout |
| 视频逐帧当独立样本 | 同一段视频跨训练/测试，指标虚高 | 按视频/病人划分 |
| 2D 模型处理 300 层整卷 | 显存爆 | 切片或 patch |

## 四、Vision Transformer：把图切成词

**核心问题：卷积的归纳偏置是"局部、平移不变"。如果不要这些假设，让每个位置直接看全图，会怎样？**

### 4.1 patch embedding：一张图怎么变成序列

ViT 的第一步不是 Transformer，是一个**卷积**：

```
224×224×3 的图像
  → 用 16×16、stride 16 的卷积切块
  → 14×14 = 196 个 patch
  → 每个 patch 展平成 16×16×3 = 768 维
  → 196×768 的矩阵
  → 加一个 [CLS] token → 197×768
  → 加位置编码
  → 送入 Transformer
```

**关键算术（必须会心算）：**

```
patch 网格 = 224 / 16 = 14
patch 数 = 14 × 14 = 196
序列长度（含 CLS）= 197
每个 patch 的维度 = 16 × 16 × 3 = 768
```

**实测验证：**

```python
import torch
from torchvision.models import vit_b_16

m = vit_b_16(weights=None)
print('参数量 %.1fM' % (sum(p.numel() for p in m.parameters()) / 1e6))
print(m.conv_proj)

x = torch.randn(1, 3, 224, 224)
with torch.no_grad():
    p = m.conv_proj(x)
print(p.shape, p.flatten(2).shape)

for img, patch in [(224, 16), (224, 8), (512, 16), (512, 32), (96, 16)]:
    n = (img // patch) ** 2
    print(f'{img}px patch{patch}: {img//patch}x{img//patch} = {n} tokens')
```

**实测输出：**

```
参数量 86.6M
Conv2d(3, 768, kernel_size=(16, 16), stride=(16, 16))
torch.Size([1, 768, 14, 14]) torch.Size([1, 768, 196])
224px patch16: 14x14 = 196 tokens
224px patch8: 28x28 = 784 tokens
512px patch16: 32x32 = 1024 tokens
512px patch32: 16x16 = 256 tokens
96px patch16: 6x6 = 36 tokens
```

**三个直接后果：**

1. **patch 越小，序列越长，计算越贵。** attention 是 O(N²)，patch 从 16 降到 8，token 从 196 涨到 784，attention 矩阵从 196² 涨到 784²，约 16 倍。
2. **医学图像的 512×512 直接切 patch 16，序列 1024，显存吃不消。** 常见做法是 patch 32（256 token）或先裁 patch 再送网络。
3. **patch 边界会切断小病灶。** 一个 4 px 的结节如果正好落在两个 patch 的交界，两个 patch 各看到一半。**这是 ViT 在小目标上弱的结构性原因。**

### 4.2 self-attention 手算（3×3 例子）

**公式：**

```
Attention(Q, K, V) = softmax(QK^T / sqrt(d)) * V
```

三个矩阵的直觉：

| 矩阵 | 含义 | 类比 |
|---|---|---|
| Q（Query） | 我想找什么 | 检索时输入的关键词 |
| K（Key） | 我有什么 | 每篇文档的标题 |
| V（Value） | 我的内容 | 每篇文档的正文 |

**手算设定：** 3 个 token，每个 2 维。为了好算，令 Q = K = V：

```
Q = K = V = [[1, 0],
             [0, 1],
             [1, 1]]
d = 2，sqrt(d) = 1.414
```

**第一步：QK^T**

```
[[1,0]   [[1,0,1]      [[1, 0, 1],
 [0,1] ×  [0,1,1]  =    [0, 1, 1],
 [1,1]]                 [1, 1, 2]]
```

**第二步：除以 sqrt(2)**

```
[[0.707, 0.000, 0.707],
 [0.000, 0.707, 0.707],
 [0.707, 0.707, 1.414]]
```

**第三步：每行做 softmax**

第 1 行：exp(0.707)=2.028，exp(0)=1，exp(0.707)=2.028，和 = 5.056

```
[0.401, 0.198, 0.401]
```

第 3 行：exp(0.707)=2.028，exp(0.707)=2.028，exp(1.414)=4.113，和 = 8.169

```
[0.248, 0.248, 0.503]
```

**完整 attention 矩阵：**

|  | token 1 | token 2 | token 3 | 行和 |
|---|---|---|---|---|
| **token 1** | 0.401 | 0.198 | 0.401 | 1.000 |
| **token 2** | 0.198 | 0.401 | 0.401 | 1.000 |
| **token 3** | 0.248 | 0.248 | 0.503 | 1.000 |

**第四步：乘以 V**

```
输出第 1 行 = 0.401×[1,0] + 0.198×[0,1] + 0.401×[1,1]
           = [0.802, 0.599]

输出第 2 行 = [0.599, 0.802]
输出第 3 行 = [0.752, 0.752]
```

**怎么读这个结果：**

- token 3 的 Q 和所有 K 都相似，所以注意力被"摊平"（0.248/0.248/0.503），输出接近三个 V 的平均。
- token 1 和 token 2 的结构相同，输出也对称。
- **softmax 让每行和为 1，所以输出是 V 的凸组合。** 这就是"加权平均"这个词的来源。

```python
import numpy as np
import torch

Q = np.array([[1., 0.], [0., 1.], [1., 1.]])
K = Q.copy(); V = Q.copy()
S = Q @ K.T / np.sqrt(2)

def softmax(x):
    e = np.exp(x - x.max(axis=1, keepdims=True))
    return e / e.sum(axis=1, keepdims=True)

A = softmax(S)
print('scores\n', np.round(S, 3))
print('attention\n', np.round(A, 3))
print('row sums', A.sum(1))
print('output\n', np.round(A @ V, 3))

# PyTorch 版，带 batch 和 head 维度
q = torch.tensor(Q).view(1, 1, 3, 2)
k = torch.tensor(K).view(1, 1, 3, 2)
v = torch.tensor(V).view(1, 1, 3, 2)
attn = torch.softmax(q @ k.transpose(-2, -1) / 2 ** 0.5, dim=-1)
print(torch.round(attn[0, 0], decimals=3))
```

**实测输出与手算完全一致：**

```
A = [[0.401 0.198 0.401]
     [0.198 0.401 0.401]
     [0.248 0.248 0.503]]
O = [[0.802 0.599]
     [0.599 0.802]
     [0.752 0.752]]
```

**为什么要除以 sqrt(d)：** d 越大，点积的方差越大，softmax 越容易饱和成 one-hot，梯度趋近 0。除以 sqrt(d) 把方差拉回 1 附近。

### 4.3 多头、位置编码、CLS

**多头（multi-head）：** 把 768 维切成 12 个头，每个头 64 维，各自做一次 attention，再拼回来。

```
每个头看不同的关系：
  头 1 可能学"相邻 patch"
  头 2 可能学"左右对称"
  头 3 可能学"同一器官的远距离部分"
```

**参数量不变，表达能力变强。** 因为每个头的维度是 d/h，h 个头拼起来还是 d。

**位置编码：** attention 本身对顺序无感（把 token 打乱，输出只是跟着打乱）。所以必须显式加位置信息。

| 方式 | 做法 | 医学适用性 |
|---|---|---|
| 可学习 1D | 每个位置一个向量 | ViT 默认，换分辨率要插值 |
| 2D 位置编码 | 行、列各一个 | 更符合图像结构 |
| 相对位置 | 编码 token 间的相对距离 | Swin 用，泛化好 |
| 无位置编码 | 靠 patch 内容 | 不推荐 |

**换分辨率时位置编码会失效。** 224 训练的 ViT，推理 512 时 196 个位置编码对不上 1024 个 token，必须双线性插值。**这是医学 ViT 部署时最常见的报错来源。**

**CLS token：** 一个可学习的向量，拼在序列最前面。经过 Transformer 后，取它的输出做分类。它相当于"汇总全局信息的那个位置"。

### 4.4 CNN 和 Transformer 的三个区别

| | CNN | Transformer |
|---|---|---|
| **感受野** | 局部，逐层扩大。3×3 卷积堆 5 层才看到 11×11 | **全局，第一层就能看到所有 patch** |
| **归纳偏置** | 强：平移不变、局部性、层级结构 | 弱：几乎不假设数据长什么样 |
| **数据需求** | 少也能训（偏置帮忙） | **大**（要自己从数据里学出"局部性"） |
| 计算复杂度 | O(N)（N 为像素数） | **O(N²)**（N 为 token 数） |
| 长程依赖 | 要堆很多层 | 一层到位 |
| 小目标 | 高分辨率特征图友好 | patch 会切碎小目标 |

**一句话：**

> CNN 把"图像应该是局部的"写进了结构里，所以小数据也能学。
> Transformer 不写这个假设，所以需要大量数据把假设学出来；一旦数据够，它更灵活。

**"数据需求大"到底大多少：** ViT 论文的结论是，在 ImageNet（120 万张）上从头训，ViT 不如同规模 CNN；要到 ImageNet-21k（1400 万）或 JFT-300M（3 亿）预训练，才反超。**这个数量级医学影像基本达不到，所以医学 ViT 几乎都靠预训练或大量无标注数据。**

### 4.5 小数据实测：CNN vs TinyViT

**设定：** OrganAMNIST（腹部 CT，28×28，11 类），同一个训练集规模，同一个测试集（3000 张），3 个随机种子。

| 训练样本 | CNN 准确率 | TinyViT 准确率 | 谁赢 |
|---|---|---|---|
| 500 | **0.6881 ± 0.0585** | 0.5699 ± 0.0078 | CNN，且 ViT 方差极小（欠拟合） |
| 2000 | 0.6321 ± 0.0419 | **0.6577 ± 0.0014** | ViT 略高；CNN 在 2000 时方差大，500 的高分有运气成分 |
| 8000 | **0.8554 ± 0.0034** | 0.7652 ± 0.0104 | **CNN 明显赢** |

**参数量：** CNN 102.1K，TinyViT 105.1K，基本对等。

**这个结果和"ViT 数据越多越强"的流行说法不一致，必须解释清楚：**

1. **这个 ViT 不是标准 ViT。** patch 4、2 层、64 维，容量很小；patch embedding 本身是卷积，已经带入了局部性。
2. **28×28 的医学图像没有足够的长程结构。** 器官位置固定，局部纹理就够分类，全局注意力的优势用不上。
3. **8000 张仍然太少。** ViT 的反转点在百万级。

**真正的结论不是"ViT 差"，而是：**

> 不要因为 ViT 新就用它。在小数据、低分辨率、强解剖先验的任务上，CNN 仍是默认选择。
> 用 ViT 的前提是：有预训练权重，或有大量无标注数据做自监督。

**可运行代码（8000 样本，8 epoch，单种子）：**

```python
import numpy as np, torch, torch.nn as nn
import medmnist

dev = 'cuda' if torch.cuda.is_available() else 'cpu'
root = r'E:\AI学习\练习代码\data\medmnist'
tr = medmnist.OrganAMNIST(split='train', root=root, download=False, size=28)
te = medmnist.OrganAMNIST(split='test', root=root, download=False, size=28)
Xtr = (tr.imgs.astype(np.float32)/255.)[:, None]
ytr = tr.labels.ravel().astype(np.int64)
Xte = (te.imgs.astype(np.float32)/255.)[:, None]
yte = te.labels.ravel().astype(np.int64)

rng = np.random.default_rng(0)
i = rng.choice(len(Xtr), 8000, replace=False); Xtr, ytr = Xtr[i], ytr[i]
j = rng.choice(len(Xte), 3000, replace=False); Xte, yte = Xte[j], yte[j]

class TinyViT(nn.Module):
    def __init__(self, n_cls=11, dim=64, depth=2, heads=4, patch=4, img=28):
        super().__init__()
        self.patch = nn.Conv2d(1, dim, patch, patch)
        n = (img // patch) ** 2
        self.pos = nn.Parameter(torch.randn(1, n, dim) * 0.02)
        self.cls = nn.Parameter(torch.randn(1, 1, dim) * 0.02)
        layer = nn.TransformerEncoderLayer(dim, heads, dim*4, batch_first=True)
        self.enc = nn.TransformerEncoder(layer, depth)
        self.norm = nn.LayerNorm(dim)
        self.head = nn.Linear(dim, n_cls)
    def forward(self, x):
        z = self.patch(x).flatten(2).transpose(1, 2)
        z = torch.cat([self.cls.expand(z.size(0), -1, -1), z + self.pos], 1)
        return self.head(self.norm(self.enc(z)[:, 0]))

torch.manual_seed(0)
model = TinyViT().to(dev)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-4)
lossf = nn.CrossEntropyLoss()
Xt = torch.tensor(Xtr).to(dev); yt = torch.tensor(ytr).to(dev)
Xt_te = torch.tensor(Xte).to(dev); yt_te = torch.tensor(yte).to(dev)

for ep in range(8):
    model.train()
    perm = torch.randperm(len(Xt), device=dev)
    for k in range(0, len(Xt), 128):
        idx = perm[k:k+128]
        opt.zero_grad()
        loss = lossf(model(Xt[idx]), yt[idx])
        loss.backward(); opt.step()

model.eval()
with torch.no_grad():
    acc = (model(Xt_te).argmax(1) == yt_te).float().mean().item()
print('test acc', round(acc, 4))
print('params', sum(p.numel() for p in model.parameters()))
```

**实测参数量 105.1K，token 数 49（28/4=7，7×7）。这段代码是 8 epoch 单种子，实测准确率 0.744-0.745；表中 0.7652 是 12 epoch、3 个种子的均值。**

### 4.6 Swin-UNETR：医学分割里的 Transformer

**Swin 的两个改动：**

| 改动 | 解决什么 | 怎么做 |
|---|---|---|
| **窗口注意力** | 全局 attention 在 3D 上算不动 | 只在局部窗口内做 attention |
| **移位窗口** | 窗口之间不交流 | 下一层把窗口平移半个窗口 |
| **层级结构** | 分割需要多尺度 | 逐层下采样，像 CNN |

**Swin-UNETR** 把 Swin 当编码器，接一个 CNN 解码器，输入通常是 96³ 或 128³ 的 patch。

```python
import torch, time
from monai.networks.nets import SwinUNETR

# MONAI 1.6.1：没有 img_size 参数，输入尺寸由张量决定
model = SwinUNETR(
    in_channels=1,
    out_channels=2,
    feature_size=24,
    use_checkpoint=True,
).cuda().eval()

print('params %.2fM' % (sum(p.numel() for p in model.parameters()) / 1e6))

for size in [64, 96]:
    x = torch.randn(1, 1, size, size, size, device='cuda')
    for _ in range(2):                      # 预热
        with torch.no_grad(): model(x)
    torch.cuda.synchronize()
    torch.cuda.reset_peak_memory_stats()
    t0 = time.time()
    with torch.no_grad():
        for _ in range(5): y = model(x)
    torch.cuda.synchronize()
    print(size, tuple(y.shape), '%.1f ms' % ((time.time()-t0)*200),
          'peak %.2f GB' % (torch.cuda.max_memory_allocated()/1024**3))
```

**实测（RTX 5060，推理，无梯度）：**

| 输入 | 输出 | 参数量 | 单次前向 | 峰值显存 |
|---|---|---|---|---|
| 64³ | (1, 2, 64, 64, 64) | 15.70 M | 38-74 ms | 0.51-0.52 GB |
| 96³ | (1, 2, 96, 96, 96) | 15.70 M | **102-184 ms** | **1.25-1.27 GB** |

**注意：** 这是 `feature_size=24`、推理模式、`use_checkpoint=True` 的数字。两次运行差一倍，是 GPU 频率/功耗墙导致的，报告时给区间比给单点诚实。训练时反向传播的显存约为推理的 2-3 倍，96³ 要预留 3-4 GB。

**医学上什么时候值得用 Swin-UNETR：**

| 条件 | 理由 |
|---|---|
| 数据量 > 数百例 | Transformer 需要数据 |
| 有 MONAI 预训练权重 | 从头训很难 |
| 病灶需要全局上下文（如肝脏分段） | 全局注意力有帮助 |
| 训练显存 ≥ 12 GB | 96³ 推理 1.27 GB，训练约 3-4 倍 |

**不满足这些条件时，nnU-Net 仍然是更稳的基线。** 这不是保守，是大量论文的共同结论：在中等规模医学分割数据上，调好的 CNN 很难被 Transformer 明显超过。

### 4.7 本节的常见错误

| 错误 | 表现 | 原因 | 更正 |
|---|---|---|---|
| 忘记位置编码 | 模型学不到空间结构，Dice 很低 | attention 对顺序无感 | 加 pos embedding |
| 换分辨率不插值 pos | 形状不匹配报错 | 196 vs 1024 | 双线性插值 |
| patch 切太小 | 显存爆，O(N²) | 224/8=784 token | patch 16 或 32 |
| 小数据从头训 ViT | 准确率不如 CNN | 缺归纳偏置 | 用预训练或 CNN |
| 把 CLS 当唯一特征 | 分割时定位差 | CLS 是全局汇总 | 分割用 patch token |
| 忽略 attention 可视化 | 不知道模型看哪 | 没检查 | 画 attention map |

## 五、自监督、半监督与弱监督

**核心问题：医院有几十万份 CT，但只有几千份有标注。怎么把没标注的用起来？**

### 5.1 为什么医学特别需要自监督

| 资源 | 自然图像 | 医学影像 |
|---|---|---|
| 无标注数据 | 互联网上无限 | 医院 PACS 里海量 |
| 标注成本 | 众包几毛钱一张 | 专家 10-30 分钟一张 |
| 标注一致性 | 高 | 低（小结节分歧大） |
| 类别定义 | 清晰 | 需要临床共识 |

**三种监督范式的区别：**

| 范式 | 标签 | 典型方法 | 医学例子 |
|---|---|---|---|
| 全监督 | 每张都有 | 分类/检测/分割 | 用 2000 例标注训练 |
| **半监督** | 少量有 + 大量无 | 伪标签、一致性正则 | 2000 标注 + 50000 无标注 |
| **自监督** | 完全不用人工标签 | SimCLR、MAE、对比学习 | 先用 50000 无标注预训练 |
| **弱监督** | 粗标签（图像级） | CAM、MIL | 只标"有病灶"，不标位置 |

### 5.2 SimCLR：同一张图的两个视角应该像

**核心思想三句话：**

1. 同一张图做两次随机增强，得到两个视图，它们应该**相似**
2. 不同图的视图应该**远离**
3. 用对比损失（NT-Xent）同时优化这两件事

**增强的组合（SimCLR 论文的消融结论）：**

| 增强 | 作用 | 医学注意 |
|---|---|---|
| 随机裁剪 + 缩放 | 学尺度不变 | 裁剪不能把病灶裁掉 |
| 水平翻转 | 学镜像不变 | 胸片会左右反转，慎用 |
| 颜色抖动 | 学光照不变 | **CT 的 HU 有物理意义，禁用** |
| 高斯模糊 | 学清晰度不变 | 可用 |
| 噪声 | 学鲁棒性 | 可用，模拟低剂量 |

**NT-Xent 损失：**

```
对一个 batch 的 2N 个视图：
  sim(i, j) = z_i · z_j / (||z_i|| ||z_j|| * tau)

  L_i = -log( exp(sim(i, i+)) / sum_{k != i} exp(sim(i, k)) )

  i+ 是同一张图的另一个视图，分母是其余 2N-2 个视图
```

**温度 tau 的作用：** 越小，模型越关注"最难的负样本"，表示越锐利；太小学崩。SimCLR 论文用 0.5，小数据常用 0.1-0.2。

**手算校验：** 随机初始化时，所有相似度接近 0，分母有 2N-1 项，损失应该接近 log(2N-1)。

N=8 时：

```
log(2×8 - 1) = log(15) = 2.708
```

**实测：**

| 输入 | NT-Xent |
|---|---|
| 随机特征，N=8，d=2048 | **2.7343** |
| 理论值 log(15) | 2.7081 |
| 正样本完全相同 | 0.0914 |

**随机特征时损失应该接近 log(2N-1)，差 1% 左右。** 维度越高越接近（d=128 时约 2.86，d=2048 时 2.73）。这是你写完任何对比损失后应该做的第一个检查：**初始化时损失不对，实现一定有问题。**

```python
import torch
import torch.nn.functional as F

def nt_xent(z1, z2, tau=0.2):
    z1 = F.normalize(z1, dim=1)
    z2 = F.normalize(z2, dim=1)
    N = z1.size(0)
    z = torch.cat([z1, z2], 0)
    sim = z @ z.t() / tau
    sim.fill_diagonal_(-1e9)
    target = torch.cat([torch.arange(N, 2 * N), torch.arange(0, N)]).to(z.device)
    return F.cross_entropy(sim, target)

torch.manual_seed(0)
z1 = F.normalize(torch.randn(8, 2048), dim=1)
z2 = F.normalize(torch.randn(8, 2048), dim=1)
print(nt_xent(z1, z2))          # 2.7343
print(torch.log(torch.tensor(15.)))   # 2.7081
print(nt_xent(z1, z1.clone()))  # 0.0914，正样本相同
```

**本机完整实验（5000 张无标注预训练 + 2000 张有标注线性探针）：**

| 编码器初始化 | 线性探针准确率（3000 张测试） |
|---|---|
| 随机初始化（不训练） | **0.2550** |
| SimCLR 自监督 30 epoch | **0.7967** |

**提升 54 个百分点，而且预训练一个标签都没用。** 这就是自监督在医学上的价值。

**注意：** 线性探针是冻结编码器，只训练最后一层 logistic regression。它衡量的是"特征本身有多好"，不是"微调后有多好"。

**SimCLR 的工程要点：**

| 要点 | 建议 | 原因 |
|---|---|---|
| batch size | 越大越好（256-4096） | 负样本越多，对比越有效 |
| 投影头 | 编码器后加 2 层 MLP | 对比损失在投影空间算，编码器特征更好 |
| 温度 | 0.1-0.5 | 小数据用 0.2 |
| 增强强度 | 医学上要保守 | 不能破坏病灶 |
| 训练轮数 | 长（100+ epoch） | 对比学习收敛慢 |

### 5.3 MAE：遮住大部分，让模型重建

**核心思想：** 把图像切成 patch，随机遮掉 75%，只把可见的 25% 送入编码器，要求解码器重建被遮的部分。

**和 SimCLR 的区别：**

| | SimCLR | MAE |
|---|---|---|
| 学什么 | 判别性特征（区分不同图） | 生成性特征（理解结构） |
| 输入 | 两个完整视图 | 一个残缺视图 |
| 解码器 | 无 | 有，重建像素 |
| 适合下游 | 分类、检索 | **分割、检测**（保留空间信息） |
| 训练成本 | 高（要两个视图） | 中（编码器只看 25%） |

**掩码比例（实测 token 数）：**

| 输入 | patch | 总 token | 遮 50% | 遮 75% | 遮 90% |
|---|---|---|---|---|---|
| 224×224 | 16 | 196 | 98 可见 | **49 可见** | 20 可见 |
| 28×28 | 4 | 49 | 24 可见 | 12 可见 | 5 可见 |

**为什么是 75%：** 比例太低，模型靠邻近视差就能补全，学不到语义；太高，信息不够。MAE 论文的消融显示 75% 左右最好。

**医学上的特殊考虑：** 遮住的区域如果正好是病灶，模型会学会"从周围猜病灶"，这可能是好事（学解剖上下文），也可能让模型过度依赖上下文。**如果病灶很小，建议用病灶感知的掩码策略：保证每次至少遮住一部分病灶区域。**

### 5.4 半监督：少量标注 + 大量无标注

| 方法 | 做法 | 一句话 |
|---|---|---|
| 伪标签（self-training） | 用模型给无标注数据打标签，再训练 | 简单，但会放大自己的错误 |
| 一致性正则 | 同一张图两种扰动，预测应该一致 | 抗扰动 |
| FixMatch | 弱增强的伪标签 + 强增强的预测对齐 | 目前最常用基线 |
|  Mean Teacher | 学生和教师的指数滑动平均 | 稳定 |

**医学上最实用的组合：**

```
1. 用少量标注训练一个教师模型
2. 在大量无标注数据上预测，取高置信度样本
3. 把高置信度样本加入训练集
4. 重复 2-3 轮
```

**风险：** 如果教师模型在某个亚组（比如小结节）上很差，伪标签会把这个偏差固化。**必须按病灶大小、设备、医院分层检查伪标签的分布。**

### 5.5 弱监督：只有图像级标签，怎么定位

**场景：** 病理科只标了"这张 CT 有结节"，没画框。能不能让模型告诉我们结节在哪？

**CAM（Class Activation Mapping）的做法：**

```
1. 分类网络：卷积特征图 → 全局平均池化（GAP）→ 全连接 → 类别
2. 取全连接层对类别 c 的权重 w_c
3. CAM_c = sum_k w_c[k] * 特征图[k]
4. 上采样到原图，归一化
```

**为什么有效：** GAP 之后，类别分数是特征图每个通道的加权和。权重大的通道，就是对这个类别贡献大的通道；这些通道的空间位置，就是模型"看"的地方。

**代码（形状演示，可运行）：**

```python
import torch
import torch.nn.functional as F

# 特征图 (1, 128, 7, 7)，分类权重 (11, 128)
feat = torch.randn(1, 128, 7, 7)
weight = torch.randn(11, 128)

cam = (feat[:, None] * weight[None, :, :, None, None]).sum(2)  # (1, 11, 7, 7)
cam = F.relu(cam)
cam = F.interpolate(cam, size=28, mode='bilinear', align_corners=False)
cam = cam / (cam.sum((2, 3), keepdim=True) + 1e-8)
print(cam.shape)          # (1, 11, 28, 28)
print(cam[0, 3].sum())    # 1.0
```

**本机实测（OrganAMNIST，分类器测试准确率 0.5823）：**

| 指标 | 值 | 参考 |
|---|---|---|
| CAM 落在中心 14×14 区域的质量比例（中位数） | **0.311** | 均匀分布 = 0.250 |
| 均值 | 0.310 | - |
| 预测正确样本的中心质量 | 0.320 | - |
| CAM 峰值到图像中心距离（中位数） | **8.75 像素** | 图像半宽 14 |

**怎么读：** CAM 确实比随机更集中在中心（0.311 vs 0.250），但集中度不高，峰值离中心还有 8.75 像素。**因为分类器只学了 0.58 的准确率，CAM 的质量上限就是分类器的质量。**

**CAM 的三个局限（必须知道）：**

1. **只定位"判别性区域"，不是完整病灶。** 一个结节只要有局部纹理像，CAM 就只高亮那一小块。
2. **类别之间会互相抑制。** 多类任务里，CAM 可能高亮"不是其他类"的区域。
3. **分辨率受特征图限制。** stride 32 的网络，CAM 最细只有 1/32 原图分辨率。

**改进：** Grad-CAM（用梯度加权）、Grad-CAM++、Score-CAM。医学上还常加一个后处理：取 CAM 的最大连通域作为候选框，再用分类器复核。

### 5.6 本节的常见错误

| 错误 | 表现 | 原因 | 更正 |
|---|---|---|---|
| 对比学习增强过强 | 正样本对语义都变了 | CT 加了颜色抖动/大旋转 | 医学增强要保守 |
| 用测试集做线性探针 | 指标虚高 | 特征见过测试集 | 探针只用训练集 |
| 伪标签全量使用 | 越训越差 | 低置信度样本污染 | 只取高置信度 + 分层检查 |
| CAM 当分割用 | 边界很差 | CAM 是粗定位 | 用弱监督分割方法 |
| 忘记投影头 | 对比效果差 | 损失直接作用在编码器 | 加 2 层 MLP 投影头 |
| batch 太小做 SimCLR | 损失降不下去 | 负样本不够 | batch ≥ 256 |

## 六、多模态融合：影像 + 临床

**核心问题：肝癌早筛只看 CT 不够，AFP、肝功能、病史都有信息。怎么把它们放进一个模型？**

### 6.1 三种融合方式

| | 早融合（early） | 晚融合（late） | 中间融合（intermediate） |
|---|---|---|---|
| 什么时候合并 | 输入层 | 预测层 | 特征层 |
| 做法 | 特征拼接后一起送网络 | 各模态各出概率，加权平均 | 各模态编码后做 attention/门控 |
| 参数量 | 少 | 多（每个模态一个模型） | 中 |
| 缺失模态 | **崩**（输入维度不对） | **稳**（缺谁就少一路） | 较稳（可 mask） |
| 可解释性 | 差 | 好（每路有独立预测） | 中 |
| 效果 | 中 | 中 | **通常最好** |
| 训练难度 | 低 | 低 | 高（容易过拟合） |

**结构示意：**

```
早融合：
  影像 → CNN ─┐
               ├→ 拼接 → MLP → 输出
  临床 → MLP ─┘

晚融合：
  影像 → CNN → 分类器 → p1 ─┐
                              ├→ 加权平均 → 输出
  临床 → MLP → 分类器 → p2 ─┘

中间融合：
  影像 → CNN → token1 ─┐
                        ├→ cross-attention → 融合特征 → 输出
  临床 → MLP → token2 ─┘
```

### 6.2 本机实测对比

**数据：** OrganAMNIST 8000 训练 / 3000 测试，11 类。图像 28×28。

**临床指标是构造的，必须说明：** OrganAMNIST 没有真实临床表格。我按类别均值生成 4 个连续变量 + 1 个二值变量，加噪声，模拟"临床指标和类别相关"的情况。**这不是真实临床数据，数字只用于比较融合方式，不能当成医学结论。**

| 模型 | 准确率 | 宏平均 AUC | 临床缺失时准确率 | 临床缺失时 AUC |
|---|---|---|---|---|
| 图像单模态 | 0.8226 ± 0.0233 | 0.9857 ± 0.0023 | 0.8226 | 0.9857 |
| 临床单模态 | 0.3516 ± 0.0035 | 0.7884 ± 0.0004 | 0.1863 | 0.5000 |
| 早融合 | 0.8004 ± 0.0355 | 0.9803 ± 0.0048 | 0.7642 | 0.9730 |
| 晚融合 | 0.8378 ± 0.0174 | 0.9788 ± 0.0031 | **0.8197** | **0.9857** |
| **中间融合** | **0.8599 ± 0.0202** | **0.9893 ± 0.0016** | 0.8179 | 0.9843 |

**四个结论：**

1. **中间融合准确率最高（0.8599），但只比图像单模态高 3.7 个百分点。** 因为构造的临床指标信息量有限（单模态只有 0.35）。
2. **早融合反而比图像单模态低（0.8004 vs 0.8226）。** 5 维弱特征拼进 64 维强特征，稀释了图像信息，还增加了过拟合。**这是早融合最常见的失败模式。**
3. **晚融合最稳。** 临床缺失时只掉 1.8 个百分点，因为图像分支完全不受影响。
4. **中间融合在缺模态时也稳（0.8179）**，因为 attention 可以学会忽略缺失的 token。但训练时**必须随机丢模态**，否则推理时缺失会崩。

**这张表最重要的不是"谁第一"，是"早融合会拖累强模态"。** 医学里影像通常是最强的模态，把弱表格特征直接拼进去，很容易掉点。

**最小可运行版（3000 训练 / 1000 测试 / 4 epoch）：**

```python
import numpy as np, torch, torch.nn as nn
import medmnist
from sklearn.metrics import roc_auc_score

dev = 'cuda' if torch.cuda.is_available() else 'cpu'
root = r'E:\AI学习\练习代码\data\medmnist'
tr = medmnist.OrganAMNIST(split='train', root=root, download=False, size=28)
te = medmnist.OrganAMNIST(split='test', root=root, download=False, size=28)
Xtr = (tr.imgs.astype(np.float32)/255.)[:, None]
ytr = tr.labels.ravel().astype(np.int64)
Xte = (te.imgs.astype(np.float32)/255.)[:, None]
yte = te.labels.ravel().astype(np.int64)
rng = np.random.default_rng(0)
i = rng.choice(len(Xtr), 3000, replace=False); Xtr, ytr = Xtr[i], ytr[i]
j = rng.choice(len(Xte), 1000, replace=False); Xte, yte = Xte[j], yte[j]

# 构造 5 维“临床指标”：按类别均值生成，仅用于演示融合方式
rng2 = np.random.default_rng(42)
MU = rng2.normal(0, 1.0, (11, 4))
def clin(y, rng):
    c = MU[y] + rng.normal(0, 1.2, (len(y), 4))
    p = 1/(1+np.exp(-MU[y, 0]*0.8))
    b = rng.binomial(1, p).astype(np.float32)
    return np.concatenate([c.astype(np.float32), b[:, None]], 1)
Ctr = clin(ytr, np.random.default_rng(1)); Cte = clin(yte, np.random.default_rng(2))
mu, sd = Ctr[:, :4].mean(0), Ctr[:, :4].std(0)
Ctr[:, :4] = (Ctr[:, :4]-mu)/sd; Cte[:, :4] = (Cte[:, :4]-mu)/sd

Xt = torch.tensor(Xtr).to(dev); yt = torch.tensor(ytr).to(dev)
Xe = torch.tensor(Xte).to(dev); ye = torch.tensor(yte).to(dev)
Ct = torch.tensor(Ctr).to(dev); Ce = torch.tensor(Cte).to(dev)

class Enc(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(1, 32, 3, padding=1), nn.BatchNorm2d(32), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(32, 64, 3, padding=1), nn.BatchNorm2d(64), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(64, 128, 3, padding=1), nn.BatchNorm2d(128), nn.ReLU(),
            nn.AdaptiveAvgPool2d(1), nn.Flatten(), nn.Linear(128, 64), nn.ReLU())
    def forward(self, x): return self.net(x)

class Img(nn.Module):
    def __init__(self): super().__init__(); self.e = Enc(); self.h = nn.Linear(64, 11)
    def forward(self, x, c=None): return self.h(self.e(x))

class Early(nn.Module):
    def __init__(self):
        super().__init__(); self.e = Enc()
        self.h = nn.Sequential(nn.Linear(69, 64), nn.ReLU(), nn.Linear(64, 11))
    def forward(self, x, c): return self.h(torch.cat([self.e(x), c], 1))

class Late(nn.Module):
    def __init__(self):
        super().__init__()
        self.img = Img()
        self.clin = nn.Sequential(nn.Linear(5, 32), nn.ReLU(), nn.Linear(32, 11))
    def forward(self, x, c): return self.img(x), self.clin(c)

def run(m, epochs=4):
    opt = torch.optim.AdamW(m.parameters(), lr=1e-3, weight_decay=1e-4)
    lf = nn.CrossEntropyLoss()
    for ep in range(epochs):
        m.train()
        perm = torch.randperm(len(Xt), device=dev)
        for k in range(0, len(Xt), 128):
            idx = perm[k:k+128]
            opt.zero_grad()
            out = m(Xt[idx], Ct[idx])
            loss = lf(out[0], yt[idx]) + lf(out[1], yt[idx]) if isinstance(out, tuple) else lf(out, yt[idx])
            loss.backward(); opt.step()
    m.eval()
    with torch.no_grad():
        out = m(Xe, Ce)
        p = 0.5*torch.softmax(out[0], 1)+0.5*torch.softmax(out[1], 1) if isinstance(out, tuple) else torch.softmax(out, 1)
        p = p.cpu().numpy()
    return (p.argmax(1) == yte).mean(), roc_auc_score(yte, p, multi_class='ovr', average='macro')

for name, mk in [('image', Img), ('early', Early), ('late', Late)]:
    torch.manual_seed(0)
    acc, auc = run(mk().to(dev))
    print(f'{name:6s} acc {acc:.4f}  AUC {auc:.4f}')
```

**实测输出（一次运行）：**

```
image  acc 0.6080  AUC 0.9509
early  acc 0.5390  AUC 0.9324
late   acc 0.6280  AUC 0.9571
```

**和上表的结论一致：早融合掉点（0.5390 < 0.6080），晚融合略升（0.6280）。** GPU 非确定性会让数字有 ±0.01 的波动，报告时写"约"或给区间。绝对数字比上表低，因为这里只用了 3000 张、4 epoch。


### 6.3 缺失模态：医学多模态的真正难点

| 缺失类型 | 例子 | 频率 |
|---|---|---|
| 完全随机缺失 | 机器故障，某项没做 | 低 |
| 随机缺失 | 年轻病人没查 AFP | 中 |
| **非随机缺失** | **病情重的反而没做增强 CT** | **高，且危险** |

**处理策略：**

| 策略 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 插补 | 用均值/模型补 | 简单 | 引入偏差 |
| 指示变量 | 加"是否缺失"列 | 保留缺失信息 | 维度增加 |
| **模态 dropout** | 训练时随机丢模态 | 推理稳 | 训练变慢 |
| 多模型兜底 | 缺模态时换模型 | 稳 | 工程复杂 |

**模态 dropout 的实现：**

```python
def drop_modality(x, p=0.3):
    """训练时以概率 p 把整个模态置零"""
    if torch.rand(1).item() < p:
        return torch.zeros_like(x)
    return x
```

**注意：** 置零前要确认特征已经过标准化（零 = 均值）。如果没标准化，置零等于给了一个极端的假值。

### 6.4 肝癌早筛的正确形态

**核心问题：一个 45 岁、HBV 阳性、AFP 15 ng/mL、ALT 正常的人，要不要做增强 CT？**

**单靠任何一个指标都不够：**

| 指标 | 单独用的问题 |
|---|---|
| AFP | 约 30-40% 的 HCC 不升高；肝炎活动也会升高 |
| 超声 | 受操作者影响，肥胖/脂肪肝下看不清 |
| CT/MRI | 贵、有辐射/造影剂风险，不适合所有人筛 |
| 病史 | 只能分层，不能定位 |

**正确的输入组合：**

| 模态 | 变量 | 类型 | 临床意义 |
|---|---|---|---|
| 影像 | 超声/增强 CT/MRI | 图像 | 病灶形态、强化模式 |
| 血清 | AFP、AFP-L3、PIVKA-II | 连续 | 肿瘤标志物 |
| 肝功能 | ALT、AST、胆红素、白蛋白、PLT | 连续 | 肝损伤、储备功能 |
| 病毒 | HBV/HCV、HBV-DNA | 二值/连续 | 病因 |
| 临床 | 年龄、性别、BMI、糖尿病、饮酒 | 混合 | 危险因素 |
| 病史 | 肝硬化、家族史、既往 HCC | 二值 | 高危分层 |
| 复合 | FIB-4、ALBI、Child-Pugh | 计算 | 肝纤维化/储备 |

**推荐架构（中间融合 + 缺失鲁棒）：**

```
影像分支：2.5D CNN 或 3D CNN → 64/128 维 token
表格分支：MLP（缺失指示 + 标准化）→ 64 维 token
          ↓
     cross-attention（2 层，4 头）
          ↓
     拼接 [影像 token, 表格 token, 交互 token]
          ↓
     分类头 → 风险概率
          ↓
     校准（Platt / isotonic）→ 临床可解释的概率
```

**训练策略：**

| 策略 | 设置 | 理由 |
|---|---|---|
| 病人级划分 | GroupKFold by patient | 同一病人多次检查不能跨折 |
| 模态 dropout | p=0.2-0.3 | 推理时缺模态 |
| 缺失指示 | 每个变量一列 | 缺失本身有信息 |
| 类别不平衡 | 加权 CE / Focal | 早筛阳性率低 |
| 校准 | 验证集上做 | 概率要能给医生用 |
| 外部验证 | 另一家医院 | 多模态模型最容易过拟合设备 |

**评估不能只看 AUC：**

| 指标 | 为什么 |
|---|---|
| 敏感度 @ 固定特异度（如 90%） | 筛查要低假阳性 |
| PPV / NPV | 随患病率变，必须报人群 |
| 决策曲线（DCA） | 净收益，贴近临床 |
| 按病因分层（HBV/HCV/酒精） | 模型可能只在某一亚组有效 |
| 按分期分层（早期 vs 晚期） | **早筛的目标是早期，晚期容易** |

**最后一条最重要：** 如果你的 AUC 0.90 主要来自晚期 HCC，这个模型对早筛没有价值。**必须单独报告早期（BCLC 0/A）的敏感度。**

### 6.5 本节的常见错误

| 错误 | 表现 | 原因 | 更正 |
|---|---|---|---|
| 早融合拼弱特征 | 比单模态还差 | 强特征被稀释 | 用中间融合或门控 |
| 未配准的多期相堆通道 | 学到错位伪影 | 呼吸/摆位不同 | 先配准 |
| 随机划分 | AUC 虚高 | 同一病人跨折 | 按病人 GroupKFold |
| 不做缺失处理 | 推理时崩 | 训练全是有模态样本 | 模态 dropout |
| 只报 AUC | 临床不可用 | 不看工作点 | 报敏感度@特异度 + DCA |
| 不校准 | 概率没意义 | 融合模型过度自信 | Platt/isotonic |
| 用未来信息 | 泄露 | 用了确诊后的检查 | 只用在诊断前可获得的变量 |

### 7.2 例一：U-Net

| 项 | 内容 |
|---|---|
| 论文 | U-Net: Convolutional Networks for Biomedical Image Segmentation |
| 会议/年份 | MICCAI 2015 |
| 1. 问题 | 少量标注的医学图像，怎么做像素级分割 |
| 2. 之前不足 | 滑窗 CNN 逐像素预测，重复计算、慢；FCN 上采样粗糙，边界不准 |
| 3. 核心方法 | 编码器（收缩路径）4 次下采样提语义；解码器（扩张路径）4 次上采样恢复分辨率；**同层 skip connection 把编码器特征拼到解码器**；重叠切块（overlap-tile）处理大图；弹性形变增强 |
| 4. 创新点 | 对称 U 形结构；skip 拼接而不是相加；为小数据设计的强增强 |
| 5. 结果 | ISBI 2012 电子显微镜细胞分割挑战赛，明显优于同期方法（论文报告） |
| 6. 消融 | skip connection 是性能关键；去掉后边界明显变差；弹性形变对小数据提升大 |
| 7. 局限 | 2D，逐层处理丢失层间信息；各向异性数据（层厚 5 mm）直接当 2D 会失真；没有多尺度融合；对类别不平衡没有专门处理 |
| 8. 我的想法 | 3D 版 + 各向异性卷积（Z 方向用更大的核），或者在 skip 上做注意力门控（Attention U-Net 后来做了） |

**一句话记住：U-Net 的贡献不是"深"，是"把浅层的高分辨率特征直接送到解码器"。**

### 7.3 例二：ResNet

| 项 | 内容 |
|---|---|
| 论文 | Deep Residual Learning for Image Recognition |
| 会议/年份 | CVPR 2016 |
| 1. 问题 | 网络越深，性能反而下降 |
| 2. 之前不足 | 深层网络出现退化（degradation）：训练误差也变高，不是过拟合；BN 只能缓解一部分 |
| 3. 核心方法 | 残差块：`y = F(x) + x`，让网络学残差 F 而不是完整映射；恒等 shortcut 不引入参数；bottleneck（1×1 降维、3×3、1×1 升维）控制参数量 |
| 4. 创新点 | 残差学习；极深网络（152 层）可训练；shortcut 让梯度直接回传 |
| 5. 结果 | ILSVRC 2015 检测/分类第一；152 层集成 top-5 错误率 3.57%（论文报告） |
| 6. 消融 | 18 层 vs 34 层：plain 网络加深后误差升高，ResNet 加深后误差下降。**这个对比直接证明了退化问题存在** |
| 7. 局限 | shortcut 要求通道数和分辨率一致，不一致时要用 1×1 卷积投影；残差为什么好训练，理论解释仍不完整；对医学的小目标没有特别设计 |
| 8. 我的想法 | 医学 3D 里把残差和密集连接结合；或者在 skip 上加入解剖先验（比如只允许同侧连接） |

**一句话记住：ResNet 解决的是"深网络训不动"，不是"深网络过拟合"。**

### 7.4 例三：ViT

| 项 | 内容 |
|---|---|
| 论文 | An Image is Worth 16x16 Words: Transformers for Image Recognition at Scale |
| 会议/年份 | ICLR 2021 |
| 1. 问题 | 能不能不用卷积，纯 Transformer 做图像分类 |
| 2. 之前不足 | CNN 有强归纳偏置（局部性、平移不变），在大数据上可能成为限制；此前 Transformer 用于视觉都要搭配 CNN backbone |
| 3. 核心方法 | 图像切 16×16 patch → 线性投影成 token → 加位置编码 + CLS token → 标准 Transformer encoder → CLS 输出分类；先在大数据集预训练，再下游微调 |
| 4. 创新点 | 证明纯 Transformer 可行；patch embedding 把图像变成序列；规模（数据 + 模型）带来持续收益 |
| 5. 结果 | ViT-H/14 在 ImageNet 上 88.55% top-1，需 JFT-300M 预训练（论文报告） |
| 6. 消融 | 数据量消融最关键：小数据上 ViT 不如 ResNet，大数据上反超；patch size 越小越好但越贵；混合架构（CNN 特征 + Transformer）中等数据更好 |
| 7. 局限 | 数据需求极大；O(N²) 复杂度；固定 patch 尺度，小目标弱；缺少多尺度层级，不适合分割/检测（后续 Swin、PVT 解决） |
| 8. 我的想法 | 医学上用 MAE 在无标注 CT 上预训练，再拿 patch token 做分割；或者用 Swin 的窗口注意力控制 3D 的计算量 |

**一句话记住：ViT 的胜利是"规模 + 数据"的胜利，不是"注意力一定比卷积好"。**

## 九、自测题

<details><summary>1. 两阶段和单阶段检测的本质区别是什么？</summary>

两阶段先生成候选区域（RPN），再对每个候选做分类和精修；单阶段直接在特征图每个位置回归类别和框。

本质区别是"有没有显式的候选生成步骤"。两阶段把"找目标"和"认目标"分开，所以精度高但慢；单阶段一步到位，快但小目标/密集目标容易漏。

DETR 是第三种：用固定数量的 query 和匈牙利匹配，既没有 anchor 也没有 NMS。

</details>

<details><summary>2. 为什么 3 mm 结节用标准 anchor 会完全检不到？</summary>

3 mm 在 0.7 mm 像素间距下只有 4.29 像素。标准 anchor 最小尺度是 8 像素，与 4.29 像素目标的最高 IoU 只有 0.287，低于 0.5 的匹配阈值，**没有任何 anchor 被标为正样本**。

没有正样本，RPN 的分类损失全是负样本，模型学到"哪里都没有目标"。这不是训练不充分，是训练开始前就注定了。

解决：最小 anchor 尺度设为 4 或 2，或提高输入分辨率。

</details>

<details><summary>3. NMS 的阈值为什么不是越大约好或越小越好？</summary>

阈值小：抑制太狠，两个相邻的真实结节会被合并成一个，召回下降。

阈值大：抑制不足，同一个结节保留多个框，假阳性增加。

本讲的实测显示了"悬崖效应"：IoU 集中在 0.77-0.82，阈值 0.3-0.7 结果完全一样，一旦到 0.80 就多保留一个，0.85 全部保留。所以阈值必须根据 IoU 分布来定，不能凭经验。

医学上两个结节紧挨着很常见，通常用较低阈值 + Soft-NMS，或者按病灶大小分层设阈值。

</details>

<details><summary>4. mAP@0.5 为什么不适合评价小结节检测？</summary>

两个原因。

第一，定位容差是按 IoU 算的。对 4.29 像素的结节，框平移 1 像素 IoU 就掉到 0.416，低于 0.5。而医生之间画框差 1-2 像素是常态，所以 mAP 在测量标注噪声。

第二，mAP 对所有召回水平积分，不告诉你"在临床可接受的假阳性数下，敏感度是多少"。筛查关心的是每扫描 1 个假阳性时能查出多少，这是 FROC 的横轴。

所以医学检测论文报 FROC 的固定工作点，mAP 只作为辅助。

</details>

<details><summary>5. FROC 的横轴为什么是 FP/scan 而不是 1-特异度？</summary>

因为一个扫描有多个病灶，而且假阳性的临床成本是按"每例多看几个框"算的。

图像级特异度会把"一张图里 5 个假阳性"和"1 个假阳性"都压成"这张图报警了"，丢失工作量信息。FP/scan 直接对应医生的阅片负担：每例 1 个 FP，一天 200 例就多 200 个框。

LUNA16 官方指标就是在 0.125 到 8 FP/scan 七个点上取平均敏感度。

</details>

<details><summary>6. Transformer 为什么比 CNN 需要更多数据？</summary>

CNN 把先验写进了结构：局部连接、权重共享、平移不变。这些假设对自然图像和医学图像大多成立，所以小数据也能学到有用特征。

Transformer 的 self-attention 对位置和局部性没有假设，所有 token 两两交互。它必须从数据里学出"相邻的东西更相关"这件事，这需要大量样本。

ViT 论文的消融显示：ImageNet 规模从头训不如 CNN，到 ImageNet-21k/JFT-300M 才反超。本讲的小数据实测也显示，8000 张时 CNN 0.855 vs TinyViT 0.765。

医学上的对策：预训练（ImageNet/RadImageNet）、自监督（MAE/SimCLR）、或者用带卷积分量的混合架构（Swin）。

</details>

<details><summary>7. 自监督在医学影像上的价值为什么比自然图像更大？</summary>

因为医学的"无标注多、标注贵"的矛盾更极端。

自然图像可以用众包便宜地标几百万张；医学影像必须专家花 10-30 分钟，而且一致性差。医院 PACS 里有几十万份 CT，但带像素级标注的可能只有几百份。

SimCLR/MAE 能把这几十万份无标注数据变成预训练信号。本讲实测：5000 张无标注预训练后，线性探针从 0.255 提到 0.797，一个标签都没用。

第二个价值是**领域适配**：ImageNet 预训练的特征和 CT 分布差很远，医学自监督能学到灰度、纹理、解剖结构。

</details>

<details><summary>8. 多模态融合的三种方式，什么时候选哪个？</summary>

早融合：模态之间强相关、维度相近、数据量大时可用。优点是简单。缺点是弱模态会稀释强模态，缺失模态直接崩。

晚融合：模态各自独立、需要可解释、经常缺模态时选。优点是稳、每路可单独解释。缺点是不能学跨模态交互。

中间融合：数据量足够、模态间有互补信息时选，通常效果最好。缺点是实现复杂、容易过拟合、需要模态 dropout。

医学肝癌早筛推荐中间融合 + 模态 dropout；如果影像质量差或经常缺失，晚融合更稳。

</details>

## 十一、常见错误总表

| 错误 | 表现 | 根因 | 更正 |
|---|---|---|---|
| 用 COCO 超参做医学检测 | 召回率 0 | anchor 太大 | 按目标尺寸重设 |
| 整图 resize 到 224 | 小结节消失 | 3 mm 只剩 1.9 px | 切 patch 或保持分辨率 |
| 检测只报 mAP | 临床不可用 | 没有 FP/scan | 加 FROC |
| NMS 跨类别 | 器官抑制病灶 | 没按类别分组 | 分类别做 |
| 3D 不重采样 | 形状学歪 | Z 向 5 mm | 重采样到 1 mm |
| 掩码线性插值 | 出现 0.5 标签 | 插值方式错 | 最近邻 |
| 多期相未配准 | 学到错位伪影 | 呼吸/摆位 | 先配准或多分支 |
| ViT 小数据从头训 | 不如 CNN | 缺归纳偏置 | 预训练或 CNN |
| 忘位置编码 | 学不到空间结构 | attention 无序 | 加 pos embedding |
| 早融合拼弱特征 | 比单模态差 | 强特征被稀释 | 中间融合/门控 |
| 随机划分病人数据 | 指标虚高 | 同一病人跨折 | GroupKFold |
| 自监督增强过强 | 正样本对失效 | CT 加颜色抖动 | 医学增强保守 |
| 伪标签全量用 | 越训越差 | 低置信样本污染 | 高置信 + 分层检查 |
| 只报 AUC | 概率不可用 | 没校准、没工作点 | 校准 + 敏感度@特异度 |
