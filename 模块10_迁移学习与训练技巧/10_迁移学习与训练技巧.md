## 一、为什么需要迁移学习

### 1.1 先把问题摆出来

你在模块 3 已经能训 CNN。MNIST 6 万张，3 轮 99%。那是**数据充足**的情况。

医学影像不是这样：

| 场景 | 你手上的数据 | 从头训会发生什么 |
|---|---|---|
| 一个医院的肝肿瘤 CT | 200-2000 例 | 严重过拟合，验证集准确率卡在 60% 上下 |
| 罕见病筛查 | 几十例 | 根本训不动 |
| 皮肤镜分类（公开集） | 7007 张 | 勉强能训，但比预训练差一截 |

**核心矛盾**：ResNet18 换成 8 类分类头后有 11,180,616 个参数。你用 2000 张图去估 1118 万个参数，平均每个参数分到 0.00018 张图。

**迁移学习的做法**：这 1118 万个参数不是从随机数开始，而是从 ImageNet 128 万张图上训好的值开始。你只负责把它挪到你的任务上。

### 1.2 先做实验：从头训 vs 微调，差多少

**实验设置**（`_exp/exp_a4.py`）：

```
数据：BloodMNIST，8 类血细胞，训练集 11959 张，测试集 3421 张
模型：ResNet18，最后全连接层换成 8 类
输入：28×28 单通道复制成 3 通道，ImageNet 均值方差标准化
训练：AdamW，15 epoch，Cosine + 10% warmup，batch 128
对比：① 随机初始化从头训  ② 加载 ImageNet 权重全量微调（差分学习率）
```

**代码**（最小可运行版本，去掉增强和调度，只看初始化差异）：

```python
import torch, torch.nn as nn
from torchvision import models

def build(pretrained, nclass=8):
    w = models.ResNet18_Weights.IMAGENET1K_V1 if pretrained else None
    m = models.resnet18(weights=w)
    m.fc = nn.Linear(512, nclass)
    return m

def train_one(model, train_loader, test_loader, epochs=15, lr=1e-3):
    model = model.cuda()
    opt = torch.optim.AdamW(model.parameters(), lr=lr, weight_decay=1e-4)
    crit = nn.CrossEntropyLoss()
    for ep in range(epochs):
        model.train()
        for xb, yb in train_loader:
            xb, yb = xb.cuda(), yb.cuda()
            opt.zero_grad()
            loss = crit(model(xb), yb)
            loss.backward()
            opt.step()
        # 每个 epoch 评估
        model.eval()
        correct = total = 0
        with torch.no_grad():
            for xb, yb in test_loader:
                xb, yb = xb.cuda(), yb.cuda()
                correct += (model(xb).argmax(1) == yb).sum().item()
                total += yb.size(0)
        print(f"epoch {ep+1}: test acc = {correct/total:.4f}")

# 两个模型，同一份数据，同一个预算
# train_one(build(False), train_loader, test_loader)
# train_one(build(True),  train_loader, test_loader)
```

**实测结果（n=11959 全量训练集，8 epoch，常数学习率 1e-3）：**

| 初始化 | 测试准确率 | 差距 |
|---|---|---|
| 随机初始化从头训 | **0.8351** | — |
| ImageNet 预训练 + 全量微调（差分 LR） | **0.8878** | **+5.27 个百分点** |

**同预算、同数据、同网络，预训练多拿到 5.3 个点。** 而且这 5.3 个点是白捡的——你没有多花一个 epoch。

**但这个故事有个反转，必须现在就说清楚。**

把训练预算翻倍（15 epoch + Cosine 调度 + warmup），在 5000 张上重跑：

| 初始化 | 8 epoch 常数 LR | 15 epoch + Cosine |
|---|---|---|
| 从头训 | 0.6384（n=5000） | **0.9030** |
| 预训练全量微调 | 0.8530（n=5000） | **0.8530** |

**（两个预算下预训练都是 0.8530，不是笔误。**两次都是 3421 张里对 2918 张——差分学习率把浅层锁在 1e-5，模型在 8 个 epoch 时已经饱和，多训的轮数没改变任何一张图的预测。这本身就是个信号：**学习率设得太保守，"多训"是白训**。**）**

**从头训反超了 5 个点。**

**这不是 bug，这是这一节最核心的一句话：**

> **迁移学习省的从来不是"上限"，是"达到上限所需的样本和训练轮数"。**
>
> 你给它足够的 epoch 和正确的调度，从头训在中等规模数据上能追上来，甚至反超——
> **前提是你的任务对预训练特征友好**。这里不友好的原因是 28×28 的分辨率（见 1.6）。

**所以判断要不要迁移，不能只问"数据有多少"，要同时问三件事：**

1. 数据够不够从头训（< 5000 张基本不够）
2. 训练预算够不够（够的话从头训能追）
3. **输入分辨率和预训练模型匹不匹配**（下面 1.5 和 2.6 会展开）

### 1.3 预训练到底迁移了什么

这是这一节最需要"看见"的东西。模块 3 你已经画过卷积核，现在画的是**预训练模型和从头训模型的卷积核**。

```python
import matplotlib.pyplot as plt
import torch

scratch = build(pretrained=False).cuda()
finetune = build(pretrained=True).cuda()

w1 = scratch.conv1.weight.data.cpu()      # (64, 3, 7, 7)
w2 = finetune.conv1.weight.data.cpu()

fig, axes = plt.subplots(2, 8, figsize=(16, 4))
for i in range(8):
    # 3 通道取平均，压成灰度显示
    axes[0, i].imshow(w1[i].mean(0), cmap='gray')
    axes[1, i].imshow(w2[i].mean(0), cmap='gray')
    axes[0, i].axis('off'); axes[1, i].axis('off')
axes[0, 0].set_title('随机初始化', loc='left')
axes[1, 0].set_title('ImageNet 预训练', loc='left')
plt.tight_layout()
plt.show()
```

你会看到：**预训练的第一层是有结构的**（Gabor 样的条纹、边缘检测器、颜色对立通道），随机初始化的是噪声。

**为什么**：自然图像和医学图像的**底层统计规律是一样的**。

| 层级 | 学什么 | 跨域通用性 |
|---|---|---|
| conv1（7×7） | 边缘、条纹、明暗过渡 | **几乎完全通用** |
| layer1-2 | 角点、纹理、简单形状 | **高度通用** |
| layer3 | 物体部件（轮子、眼睛） | 中等 |
| layer4 | 物体整体（狗、车） | **几乎不通用** |

**这句话要记住**：迁移学习借的是**浅层的特征提取器**，不是深层的语义。

所以一个常见的误解是"ImageNet 是自然图像，医学是灰度图，没法迁移"。**恰恰相反，越浅的层越通用**，而浅层占了模型的大部分计算量。

### 1.4 ImageNet 预训练在医学上的真实表现

我在这台机器上跑的三组对照（同样的网络、同样的训练预算）：

| 数据集 | 任务 | 训练预算 | 从头训 | 预训练微调 | 差距 |
|---|---|---|---|---|---|
| BloodMNIST（11959 张） | 8 类血细胞 | 8 ep | 0.8351 | **0.8878** | +5.27 个点 |
| BloodMNIST（5000 张） | 8 类血细胞 | 8 ep | 0.6384 | **0.8530** | +21.5 个点 |
| BloodMNIST（5000 张） | 8 类血细胞 | 15 ep + Cosine | **0.9030** | 0.8530 | −5.0 个点 |
| BloodMNIST（2000 张） | 8 类血细胞 | 15 ep + Cosine | **0.8527** | 0.7995 | −5.3 个点 |
| DermaMNIST（7007 张） | 7 类皮肤镜 | 12 ep | 见第三节 | — | — |

**读这张表要横着读三遍：**

- 第一、二行：**同预算下，预训练明显更强**（+5.3 和 +21.5）。
- 第三、四行：**给从头训足够的训练轮数和调度，它反超了**。
- 所以"预训练到底值多少"这个问题，**不给出训练预算就没法回答**。

**注意第三、四行不是"迁移学习失效"的证据**——它是在告诉你：在这个分辨率下，预训练特征本身就不行（1.6 节会解释）。换个分辨率，结论会变。

### 1.5 医学专用预训练权重

ImageNet 不是唯一选择。医学领域有自己的大规模预训练模型：

| 模型 | 预训练数据 | 模态 | 怎么用 |
|---|---|---|---|
| **RadImageNet** | 约 135 万张放射影像 | CT / MRI / 超声 | 提供 ResNet50、DenseNet121 权重，接口和 torchvision 一样 |
| **Med3D** | 多套 3D 医学分割数据集 | CT | 3D ResNet，做分割/检测的编码器 |
| **BioMedCLIP** | 1500 万图文对（PMC-15M） | 2D 医学图 + 报告文本 | 零样本分类、检索、当特征提取器 |
| **MONAI Model Zoo** | 各类分割/分类 | CT/MRI | 直接 `monai.bundle.load` |

**它们比 ImageNet 好吗？** 分情况：

| 情况 | 选哪个 |
|---|---|
| 2D 灰度图（X 光、病理、细胞） | ImageNet 就够，医学预训练略好 |
| 3D CT/MRI | **必须用 Med3D 这类 3D 预训练**，ImageNet 是 2D 的用不上 |
| 有报告文本的多模态任务 | BioMedCLIP |
| 想省事、可复现 | torchvision ImageNet 权重 |

**别在这上面纠结太久**。对绝大多数 2D 分类任务，ImageNet 权重和 RadImageNet 权重的差距在 1-3 个点，远小于"做不做微调"的差距。

### 1.6 什么时候迁移学习反而有害

三种情况，都用真实实验验证过：

| 情况 | 现象 | 原因 |
|---|---|---|
| **输入分辨率和预训练差太远** | 见第 2.5 节实测 | ImageNet 是 224×224，你喂 28×28，浅层特征还没展开就被下采样完了 |
| **模态差异极大** | 超声、OCT 这类纹理完全不同的 | 浅层统计规律都对不上 |
| **目标任务需要极精细的局部纹理** | 微钙化点、早期微小病灶 | 预训练特征的感受野太大 |

**第一条最容易被忽略**。ResNet18 的结构是：conv1(stride 2) → maxpool(stride 2)，**输入 28×28 经过这两步只剩 7×7**。后面四个 stage 再各下采样一次，最后只剩 1×1。

这意味着：**28×28 输入时，layer4 的输出是 1×1**，全局平均池化等于没做，空间信息全没了。

**正确做法**：输入至少 64×64，让 layer4 输出 2×2；理想是 96-128。

### 1.7 常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 加载了预训练权重但忘了换 `fc` | 报形状不匹配，或者输出 1000 类 | `model.fc = nn.Linear(512, nclass)` |
| 换了 `fc` 但没冻结任何层，学习率用 1e-3 | loss 爆炸，准确率不如从头训 | 差分学习率，见 2.4 |
| 用 28×28 输入 + 预训练 | 迁移几乎没收益 | 上采样到 64 以上 |
| 只在小数据上比一次就下结论 | 结论不可靠 | 至少 3 个数据量点 |
| 忘了 `model.eval()` 再评估 | BatchNorm 用 batch 统计量，指标虚高 | 评估前 `model.eval()` |

## 二、三种微调策略

### 2.1 三种策略是什么

| 策略 | 冻结什么 | 训练什么 | 可训练参数（8 类） |
|---|---|---|---|
| **A 只训分类头** | 整个 backbone | 只有 `fc` | **4,104** |
| **B 冻结前几层** | conv1 ~ layer3 | layer4 + fc | **8,397,832** |
| **C 全量微调** | 不冻结 | 全部 | **11,180,616** |

**参数量差了 2700 倍**。这就是为什么策略 A 在数据极少时最稳——它几乎没有过拟合的空间。

### 2.2 策略 A：只训分类头

```python
import torch.nn as nn
from torchvision import models

model = models.resnet18(weights=models.ResNet18_Weights.IMAGENET1K_V1)

# 第一步：全部冻结
for p in model.parameters():
    p.requires_grad = False

# 第二步：换头（新层默认 requires_grad=True）
model.fc = nn.Linear(512, 8)

# 第三步：只把 fc 的参数交给优化器
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)  # 冻结的参数不会有梯度，传进去也没事
print(sum(p.numel() for p in model.parameters() if p.requires_grad))   # 4104
```

**这一步最容易错的地方**：`model.fc = nn.Linear(...)` 必须在冻结**之后**。如果顺序反了，新层也会被冻上，训练时 loss 一动不动。

**适用**：数据 < 500 张，或者你只想快速验证"这个任务预训练特征够不够用"。

**它的真正用途**：**线性探针（linear probe）**。先用它测一下冻结特征的质量，如果线性探针都有 70%，说明特征可用；如果只有 20%，说明域差异太大，得考虑换预训练模型或者从头训。

### 2.3 策略 B：冻结前几层

```python
model = models.resnet18(weights=models.ResNet18_Weights.IMAGENET1K_V1)
model.fc = nn.Linear(512, 8)

# 只解冻 layer4 和 fc
for name, p in model.named_parameters():
    p.requires_grad = name.startswith(('layer4', 'fc'))

print(sum(p.numel() for p in model.parameters() if p.requires_grad))   # 8,397,832
```

**为什么是 layer4 而不是 layer3**：layer4 是语义层，最需要适配新任务；layer1-3 是通用特征，改了反而破坏。

**想更保守**（数据 500-2000）：只解冻 `layer3 + layer4 + fc`。改动只有一个字符串：

```python
p.requires_grad = name.startswith(('layer3', 'layer4', 'fc'))
```

### 2.4 策略 C：全量微调 + 差分学习率

**全量微调不是"所有层同一个学习率"**。浅层要小，深层要大：

```python
model = models.resnet18(weights=models.ResNet18_Weights.IMAGENET1K_V1)
model.fc = nn.Linear(512, 8)

def group(prefix, lr):
    return {'params': [p for n, p in model.named_parameters() if n.startswith(prefix)], 'lr': lr}

optimizer = torch.optim.AdamW([
    group('conv1', 1e-5), group('bn1', 1e-5),
    group('layer1', 1e-5),
    group('layer2', 1e-5),
    group('layer3', 3e-5),
    group('layer4', 1e-4),
    group('fc',     1e-3),
], lr=1e-3, weight_decay=1e-4)
```

**为什么要差分**：

- 浅层参数是通用的，**大学习率会把它们改坏**（灾难性遗忘）
- 深层参数需要大改，**小学习率学不动**

**经验比例**：相邻层差 3-10 倍，最深和分类头差 100 倍左右。

### 2.5 实测：三种策略 × 四个数据量

**实验设置**（`_exp/exp_a4.py`）：BloodMNIST，ResNet18 @28×28，15 epoch，Cosine + 10% warmup，batch 128，单种子 42。

| 训练集张数 | 从头训（参照） | A 只训头 | B 冻结到 layer4 | C 全量+差分 LR |
|---|---|---|---|---|
| 496 | 0.7445 | 0.5037 | 0.6878 | 0.6752 |
| 1000 | 0.8068 | 0.6060 | 0.7518 | 0.7463 |
| 2000 | 0.8527 | 0.6609 | 0.7925 | 0.7995 |
| 5000 | 0.9030 | 0.7115 | 0.8305 | 0.8530 |

**读这张表的四个结论：**

**① 策略内部排序是稳定的：C ≥ B ≫ A。** C 从 496 张的 0.675 涨到 5000 张的 0.853，A 从 0.504 涨到 0.712。数据越多，解冻得越多越好。

**② A（只训头）在所有数据量下都最差，且差距很大。** 5000 张时 A 只有 0.712，比 C 低 14 个点。**在 28×28 这个分辨率上，冻结的 ImageNet 特征几乎没用。**

**③ B 是性价比之王。** 只训 840 万参数（75%），拿到 C 的 95-100%。

**④ 但整张表里从头训都赢。** 这是本实验分辨率造成的（见 1.6 和 2.6），**不能直接推广到 64×64 以上的场景**。

**一句话**：在这三兄弟里选，**B 是稳妥的默认值**；要不要用预训练，得先看分辨率和线性探针的结果。

### 2.6 反直觉：为什么"只训分类头"常常不是最优

教科书的标准说法是"数据少 → 冻结 backbone"。我的实测在 496 张时，只训头只有 **0.5037**，全量微调 **0.6752**，冻结到 layer4 **0.6878**——只训头比解冻差了 18 个点。

**三个原因，按重要性排：**

**① 输入分辨率不匹配（本例主因）**

28×28 输入时，ResNet18 的 layer4 输出是 1×1。ImageNet 特征在这个尺度上已经退化成"整张图的平均语义"，对血细胞这种靠纹理和形状区分的任务没有信息量。

冻结 = 你只能用这个退化特征。解冻 = 网络可以自己调整。

**这不是推测，是同一份数据只改分辨率得到的对照**（BloodMNIST，496 张训练图，20 epoch）：

| 输入尺寸 | 从头训 | 策略 B（冻结到 layer4） | 迁移是赚是亏 |
|---|---|---|---|
| 28×28 | **0.7445** | 0.6878 | **亏 5.7 个点** |
| 64×64 | 0.6995 | **0.7428** | **赚 4.3 个点** |

**同一批图、同一个模型、只改输入尺寸，迁移从"有害"变成"有益"。** 这就是为什么"预训练有没有用"不能脱离分辨率讨论。

**② BatchNorm 的统计量**

即使你冻结了 BN 的 `weight` 和 `bias`，**BN 的 running_mean / running_var 在训练模式下仍然会更新**（它们是 buffer，不算参数）。这是好事——它会自动适配你的数据分布。

但如果你写 `model.eval()` 之后才训练（很多人的 bug），BN 用 ImageNet 的统计量前向，特征分布直接错位。

```python
for p in model.parameters():
    p.requires_grad = False
model.train()          # 关键：BN 仍在训练模式，统计量会更新
# 不要写成 model.eval()
```

**③ 域差异**

ImageNet 是自然彩色照片，BloodMNIST 是显微镜下的细胞。颜色、纹理、尺度全不一样，浅层特征能用，深层基本不能。

**所以正确的判断不是"数据量多少"，而是：**

```
冻结 backbone 前，先跑一次线性探针（只训 fc）。
线性探针准确率 > 70%  → 特征可用，冻结策略可行
线性探针准确率 < 50%  → 特征不可用，必须解冻至少 layer4
```

### 2.7 决策表

| 数据量 | 域差异 | 推荐策略 | 可训练参数 |
|---|---|---|---|
| < 500 | 小（如 X 光→CT） | A 只训头 | 4 千 |
| < 500 | 大（如自然图→超声） | B 冻结到 layer3-4 | 400 万 |
| 500-2000 | 任意 | **B 冻结到 layer4** | 840 万 |
| 2000-10000 | 任意 | **C 全量 + 差分 LR** | 1118 万 |
| > 10000 | 任意 | C，或用更大模型 | 全部 |

**再加一条**：不管哪个策略，**先跑 5 个 epoch 的线性探针**，花 30 秒，能省你半天。

**但前提是迁移真的有效**。下一节会看到，在这个实验里（28×28 输入），预训练反而输给从头训——因为分辨率不匹配。

### 2.8 常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 先换 `fc` 再冻结 | 新层也被冻，loss 不降 | 先冻结，再换头 |
| 冻结后 `model.eval()` 训练 | BN 统计量不更新，指标异常 | 冻结参数不等于 eval 模式 |
| 全量微调用 1e-3 单一学习率 | 浅层被冲垮，准确率暴跌 | 差分学习率 |
| 冻结层也传给优化器且设了 weight decay | 无影响但浪费显存 | 只传 `requires_grad=True` 的 |
| 忘了 `torch.no_grad()` 做线性探针 | 慢 3 倍 | 冻结时评估可加 `no_grad` |
| 用 ImageNet 的 224 预处理（Resize 256 + CenterCrop 224） | 28×28 图被放大 8 倍，全是插值模糊 | 按你的数据实际尺寸来 |

## 三、医学数据增强：安全 vs 危险

### 3.1 判断标准只有一句话

> **变换之后，还是一张"医学上可能存在"的图吗？**

不是"看起来怪不怪"，是"**这种图在临床上会不会出现**"。

- 胸片左右翻转 → 左肺变右肺，心脏从左边跑到右边。**临床上不存在这样的病人**。
- 胸片旋转 10° → 病人拍片时没站正。**每天都在发生**。

同一个"翻转"，在自然图像里是标准操作（猫翻过来还是猫），在医学图像里可能是伪造解剖。

### 3.2 安全清单

| 增强 | 安全性 | 理由 | 建议参数 |
|---|---|---|---|
| 小角度旋转 | 安全 | 摆位本来就有偏差 | ±10°（胸片可到 ±15°） |
| 平移 | 安全 | 拍摄中心会偏 | ±8-10% |
| 缩放 | 安全 | 拍摄距离会变 | 0.9-1.1 |
| 弹性形变 | 安全（软组织） | 器官本身有形变、呼吸运动 | 仅 CT/MRI/超声 |
| 高斯噪声 | 安全 | 探测器噪声 | sigma 0.01-0.05 |
| 亮度/对比度微调 | **看模态** | CT 不行（见 3.6），X 光/病理可以 | ±10% |
| 随机裁剪 | 安全 | 等价于平移 | 裁掉 5-10% |
| 水平翻转 | **看任务** | 见 3.4 | 分类可以，定位不行 |

### 3.3 危险清单

| 增强 | 能不能用 | 为什么 |
|---|---|---|
| **垂直翻转** | **不能** | 倒着的胸片、倒着的 CT 不存在。除了病理切片（可以任意旋转） |
| **90°/180° 旋转** | **不能**（除病理） | 同上，解剖方向有物理意义 |
| **颜色抖动（CT）** | **不能** | HU 值有物理意义。调亮度 = 伪造组织密度 |
| **ColorJitter 大幅调饱和度（病理）** | **慎用** | H&E 染色的颜色对应染色剂浓度，改了等于改化学 |
| **MixUp / CutMix** | **慎用** | 两张图叠在一起，病灶被混掉，医学上不存在 |
| **大角度旋转（> 30°）** | **不能** | 器械摆位不会这么偏，且插值会破坏细节 |
| **随机擦除（大区域）** | **慎用** | 可能把整个病灶擦掉，标签还留着 |

### 3.4 实验：水平翻转在"定位"任务上会掉多少

**这是本节最重要的一张表**，因为它把一个"感觉上说得通"的规则变成了数字。

#### 第一步：合成一个受控的"定位"任务

真实数据的标签往往混着多种线索，看不清机制。所以先做一个变量只有"方向"的任务：

- 背景：BloodMNIST 的真实细胞图（4000 张训练 / 1000 张测试）
- 操作：在**四个角之一**贴一个 4×4 的纯白块
- 标签：0=左上，1=右上，2=左下，3=右下

这个任务的**唯一**判据就是方向。翻转一下，标签就错了。

| 增强 | 测试准确率 | 混淆矩阵说明了什么 |
|---|---|---|
| 无增强 | **1.0000** | 全对 |
| 水平翻转 | **0.4220** | 左右串了：右上的 269 张里 **256 张被判成左上** |
| 垂直翻转 | **0.4630** | 上下串了：左下的 244 张里 **194 张被判成左上** |
| 安全增强（旋转+平移+缩放） | 0.9970 | 几乎无损 |

**0.4220 和 0.4630 都高于 0.25（随机水平），但远低于 0.9970。**

因为翻转只破坏**一个维度**：水平翻转打乱左右，但"在上还是在下"仍然成立。模型于是在"上下"上做对、在"左右"上瞎猜，理论准确率 = 0.5 × 1.0 = 0.5。实测 0.42，差的那部分是训练噪声。

**这就是"标签被翻转"的机制**：模型看到的图说"在右上"，标签说"在左上"，同一个视觉模式对应两个相反的标签，它只能学到 50%。

**注意：这种混淆是「主要单向」，不是完全单向。**

| 方向 | 张数 |
|---|---|
| 右 → 左 | 256 |
| 左 → 右 | 25 |

**10 : 1 的不对称。**

模型不是随机猜——随机猜的话，两个方向应该各占一半。它是**把绝大部分翻转后的样本映射到了同一个方向**，剩下那 25 张是训练噪声，不是"偶尔猜对"。

这是标签冲突时模型的典型失败模式：**它学会了"忽略这个线索"，退化成一个偏好某个固定方向的分类器。**

#### 第二步：换到真实医学数据

**OrganAMNIST** 是腹部 CT 轴位切片，标签里有**左右成对**的器官：

```
1 femur-left    2 femur-right
4 kidney-left   5 kidney-right
7 lung-left     8 lung-right
```

用它构造两个任务，**同一批图像，只换标签**：

| 任务 | 标签 | 水平翻转后 |
|---|---|---|
| **左右定位** | left / right（二分类） | **标签直接反了** |
| **器官识别** | femur / kidney / lung（三分类） | 标签不变 |

如果"水平翻转有害"是对的，那么：定位任务应该崩到接近 50%，器官识别任务应该几乎不受影响。

**数据**：6 类共约 1.8 万张训练图，按类别分层抽 6000 张；测试集用官方划分里对应的 6 类。
**模型**：SmallCNN（44,680 参数），10 epoch，AdamW，batch 128。

```python
import numpy as np

imgs, labels, info = load_arrays('organamnist', 'train')

# 只保留有左右之分的 6 类
mask = np.isin(labels, [1, 2, 4, 5, 7, 8])
X, Y = imgs[mask], labels[mask]

# 任务一：左右二分类
side = np.isin(Y, [1, 4, 7]).astype(np.int64)     # left=0, right=1

# 任务二：器官三分类
organ = np.select([np.isin(Y, [1, 2]), np.isin(Y, [4, 5]), np.isin(Y, [7, 8])],
                  [0, 1, 2]).astype(np.int64)
```

**左右定位任务（二分类），实测：**

| 增强 | 测试准确率 | 相对无增强 |
|---|---|---|
| 无增强 | **0.9318** | — |
| 水平翻转 | **0.9341** | **+0.2 个点（几乎没影响）** |
| 垂直翻转 | **0.6612** | **−27.1 个点** |
| 安全增强（旋转+平移+缩放） | 0.9156 | −1.6 个点 |
| 安全增强 + 水平翻转 | 0.8962 | −3.6 个点 |

**这组数字说明什么**（结论和你的直觉可能相反）：

**① 水平翻转没有掉点，垂直翻转掉了 27 个点。**

为什么？因为 OrganAMNIST 的每个裁剪块是**以器官为中心**的，左右两侧的器官在形状、相邻组织（左肾挨着脾和胰尾，右肾挨着肝）、位置高低上本来就有差异。这些线索**不是镜像对称的**，翻转之后仍然能区分左右。

而垂直翻转把上下解剖关系全打乱（肝在上、膀胱在下），模型直接失去参照。

**② 安全增强掉了 1.6 个点**——旋转、平移、缩放对 28×28 的小裁剪块来说已经有点重了。

**③ 所以"水平翻转有害"不是绝对规则。**

它成立的前提是：**任务里除了"左右方向"，没有别的可用线索**。合成实验满足这个前提（只有角上的白块），所以掉到 0.42；真实的器官裁剪不满足，所以不掉。

### 3.5 实验：同一个翻转，换个任务就没事

**器官识别任务（3 类：股骨/肾/肺），同一批图像，只换标签：**

| 增强 | 测试准确率 | 说明 |
|---|---|---|
| 无增强 | 0.9687 | — |
| 水平翻转 | 0.9571 | −1.2 个点，基本无损 |
| 垂直翻转 | **0.9753** | **反而涨了 0.7 个点** |
| 安全增强 | 0.9046 | −6.4 个点，旋转对小图太重 |

**皮肤病灶分类（DermaMNIST，7 类，7007 张）：**

| 增强 | 测试准确率 | 说明 |
|---|---|---|
| 无增强 | 0.7212 | — |
| 安全增强 | **0.7401** | **+1.9 个点，最大收益** |
| 安全 + 水平翻转 | 0.7147 | 比安全增强低 2.5 个点 |
| 安全 + 垂直翻转 | 0.7242 | 比安全增强低 1.6 个点 |
| 颜色抖动 | 0.7451 | +2.4 个点，皮肤镜可以改颜色 |

**三张表放一起，能得出三条可用结论：**

| 结论 | 证据 |
|---|---|
| **翻转安不安全，取决于标签是否依赖方向** | 合成定位 −58 个点，器官识别 −1 个点 |
| **垂直翻转在解剖图像上默认禁用** | 左右定位 −27 个点，皮肤病灶 −1.6 个点 |
| **安全增强（旋转/平移/缩放）几乎总是正收益** | 皮肤病灶 +1.9 个点；但小图（28×28）上参数要调轻 |

**最后一条很重要**：同样的 `rot=10, translate=0.08, scale=0.1`，在 28×28 的器官裁剪块上掉 6 个点，在皮肤镜上涨 1.9 个点。**增强的强度要跟着图像尺寸和任务难度调，没有万能参数。**

### 3.6 为什么 CT 不能做颜色抖动

**CT 的像素值不是"亮度"，是 HU（Hounsfield Unit），有绝对物理意义。**

| 组织 | HU |
|---|---|
| 空气 | -1000 |
| 肺 | -500 |
| 脂肪 | -100 |
| 水 | 0 |
| 肝 | 40-70 |
| 骨 | 400-1000 |

你做 `brightness=0.2`，等于把肝的 60 HU 变成 72 HU——**这在临床上意味着"这个病人的肝脏密度异常"**，是脂肪肝或者铁沉积的征象。

**模型学到的是"密度 → 病变"的映射，你把密度改了，等于给它喂假标签。**

**什么时候可以用颜色增强**：

| 模态 | 能不能 | 怎么用 |
|---|---|---|
| CT | **不能** | 只能加噪声，不能改亮度对比度 |
| MRI | **慎用** | MRI 强度本来就没有绝对单位（不同机器不一样），轻度可以 |
| X 光 | 可以 | 曝光本来就会变，±10% 合理 |
| 病理（H&E） | 谨慎 | 染色批次有差异，可以用**颜色标准化**代替随机抖动 |
| 皮肤镜 | 可以 | 光照、肤色差异真实存在 |
| 眼底 | 可以 | 同上 |

**病理和皮肤镜的正确做法不是随机抖动，是颜色归一化**（如 Macenko、Reinhard 方法），把不同批次的染色拉到同一个分布。

### 3.7 MixUp / CutMix 为什么在医学上要慎用

**MixUp**：`x = lam * x1 + (1-lam) * x2`，`y = lam * y1 + (1-lam) * y2`。

**在自然图像里它很有效**，因为它相当于一种正则化，逼模型学线性插值的决策边界。

**在医学影像里有两个问题**：

| 问题 | 后果 |
|---|---|
| 病灶被混掉 | 两个病灶叠加后可能变成一个"不存在的病变"，标签却是 50/50 |
| 概率标签没有临床含义 | "这个结节 70% 是恶性 30% 是良性"在影像上不对应任何真实图像 |

**什么时候可以用**：

- 多标签任务（一张图里多个发现）
- 分类任务且病灶占图面积很小（混完后主病灶还在）
- 一定要做消融，证明它确实涨点

**我的建议**：默认不用。先在验证集上试，涨点超过 1% 再考虑。

### 3.8 增强代码：两个版本

**版本一：torchvision（标准写法，可读性好）**

```python
from torchvision import transforms

train_tf = transforms.Compose([
    transforms.RandomRotation(10),
    transforms.RandomAffine(degrees=0, translate=(0.08, 0.08), scale=(0.9, 1.1)),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]),
])
```

**版本二：GPU 批量版（小图上快 10 倍以上）**

为什么需要它：在 28×28 的图上，torchvision 的 `RandomAffine` 是**逐样本**在 CPU 上算仿射网格，实测一个 epoch（2000 张）光数据准备就要 **27 秒**，而模型前向反向只要 3 秒。

```python
import math
import torch
import torch.nn.functional as F

def batch_aug(x, rot=0.0, trans=0.0, scale=0.0, hflip=0.0, vflip=0.0, jitter=0.0):
    """对一个 batch 的图做随机几何增强，全部在 GPU 上，一次算完。"""
    B = x.size(0)
    dev = x.device

    if rot or trans or scale:
        ang = (torch.rand(B, device=dev) * 2 - 1) * rot * math.pi / 180
        tx = (torch.rand(B, device=dev) * 2 - 1) * trans * 2
        ty = (torch.rand(B, device=dev) * 2 - 1) * trans * 2
        sc = 1 + (torch.rand(B, device=dev) * 2 - 1) * scale
        cos, sin = torch.cos(ang) / sc, torch.sin(ang) / sc
        theta = torch.zeros(B, 2, 3, device=dev)
        theta[:, 0, 0] = cos; theta[:, 0, 1] = -sin; theta[:, 0, 2] = tx
        theta[:, 1, 0] = sin; theta[:, 1, 1] = cos;  theta[:, 1, 2] = ty
        grid = F.affine_grid(theta, x.shape, align_corners=False)
        x = F.grid_sample(x, grid, align_corners=False, padding_mode='zeros')

    if hflip:
        m = torch.rand(B, device=dev) < hflip
        x[m] = torch.flip(x[m], dims=[3])
    if vflip:
        m = torch.rand(B, device=dev) < vflip
        x[m] = torch.flip(x[m], dims=[2])
    if jitter:
        b = 1 + (torch.rand(B, 1, 1, 1, device=dev) * 2 - 1) * jitter
        x = (x * b).clamp(0, 1)
    return x
```

**用法**：在训练循环里，取到 batch 之后、标准化之前调用。

```python
for xb, yb in train_loader:
    xb, yb = xb.cuda(), yb.cuda()
    xb = batch_aug(xb, rot=10, trans=0.08, scale=0.1)   # 几何增强
    xb = (xb - mean) / std                              # 再标准化
    loss = criterion(model(xb), yb)
```

**实测对比（2000 张，64×64，batch 64）**：

| 方式 | 一个 epoch 的数据准备耗时 |
|---|---|
| torchvision 逐样本（num_workers=0） | 27.25 s |
| torchvision 逐样本（num_workers=4） | 11.06 s |
| **GPU 批量** | **0.16 s** |

**什么时候用哪个**：小图（≤128）用 GPU 版；大图（512 以上的 CT/MRI）用 torchvision/MONAI + `num_workers=8`，因为大图在 CPU 上做几何变换反而不占 GPU 显存。

### 3.9 常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 胸片做水平翻转还做定位 | 模型学不到左右，指标 50% | 定位/分割任务禁用翻转 |
| CT 做 ColorJitter | 模型学到假的密度，外部验证崩 | CT 只加噪声 |
| 用 `RandomRotation(30)` | 插值破坏细节，且摆位不会这么偏 | ≤10-15° |
| 增强加在验证/测试集上 | 指标不可复现，且虚高或虚低 | 只在 train 上加 |
| 病理切片用垂直翻转 | 其实可以 | 病理切片无方向性，任意旋转都行 |
| MixUp 用在大病灶上 | 病灶被混没 | 先验证再上 |

## 四、训练技巧全家桶

这一节的东西单独看都不起眼，叠起来能差 10 个点以上。按"性价比"排序讲。

### 4.1 Weight Decay：AdamW 和 Adam 的区别

| 优化器 | weight decay 怎么加 | 效果 |
|---|---|---|
| Adam + `weight_decay=1e-4` | 加进梯度里：`g = g + wd * w` | 和自适应学习率耦合，**大梯度参数被惩罚得少，小梯度被惩罚得多** |
| **AdamW** | 直接衰减参数：`w = w * (1 - lr * wd)` | 解耦，**惩罚和梯度大小无关** |

**结论**：用 `AdamW`，不要用 `Adam(weight_decay=...)`。这是 2019 年之后的共识。

```python
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-4)
```

**取值**：

| 数据量 | weight_decay |
|---|---|
| 小（< 2000） | 1e-2 ~ 1e-3（强正则） |
| 中（2000-5 万） | 1e-4 |
| 大（> 5 万） | 1e-5 ~ 1e-4 |
| 微调预训练模型 | 1e-4（不要太大，会把预训练权重拉回 0） |

### 4.2 Label Smoothing

**问题**：`CrossEntropyLoss` 配 one-hot 标签，会逼模型把正确类的 logit 推到无穷大。结果是**过度自信**：模型说 99.9%，实际校准很差。

**做法**：把标签从 `[0,0,1,0]` 改成 `[0.033,0.033,0.9,0.033]`（C=4，eps=0.1）：

```
q_i = (1 - eps) * y_i + eps / C
```

```python
criterion = nn.CrossEntropyLoss(label_smoothing=0.1)
```

**为什么对医学有用**：

- 医学标签本身有噪声（不同医生读片结论不一致，kappa 常常只有 0.6-0.8）
- 硬标签假装"这个诊断 100% 确定"，是错的
- 平滑后的模型**概率校准更好**（模块 9 讲的可靠性图会更好看）

**取值**：0.05-0.1。太大（> 0.2）会欠拟合。

**注意**：label smoothing 和 Focal Loss 会互相干扰（见 5.3）。

### 4.3 学习率调度

**四种常用的，按推荐顺序：**

| 调度器 | 形状 | 什么时候用 |
|---|---|---|
| **CosineAnnealingLR** | 余弦下降 | **默认选它**，稳定 |
| **OneCycleLR** | 先升后降 | 训练轮数固定、想快 |
| StepLR | 阶梯下降 | 老代码里常见，现在少用 |
| ReduceLROnPlateau | 指标不降才降 | 不确定要训多久时 |

**Cosine + warmup（推荐默认）**：

```python
import math
import torch

def cosine_warmup(optimizer, total_steps, warm_frac=0.1):
    """前 10% 步数线性升到 lr，之后余弦降到 0。"""
    warm = max(1, int(total_steps * warm_frac))

    def f(step):
        if step < warm:
            return (step + 1) / warm                       # 线性 warmup
        p = (step - warm) / max(1, total_steps - warm)
        return 0.5 * (1 + math.cos(math.pi * p))           # 1 -> 0

    return torch.optim.lr_scheduler.LambdaLR(optimizer, f)

# 用法：每个 optimizer.step() 之后调一次 scheduler.step()
scheduler = cosine_warmup(optimizer, total_steps=len(train_loader) * epochs)
```

**为什么需要 warmup**：

训练最开始，模型参数是随机的（或预训练但和你的数据不匹配），梯度方向很乱。此时用大学习率，一步就能把预训练权重冲坏。

warmup 让学习率从 0 慢慢升上去，给模型一个"站稳"的过程。**微调预训练模型时几乎是必须的**。

**OneCycleLR**：

```python
scheduler = torch.optim.lr_scheduler.OneCycleLR(
    optimizer,
    max_lr=1e-3,                        # 峰值
    total_steps=len(train_loader) * epochs,
    pct_start=0.3,                      # 前 30% 用来升温
)
```

OneCycle 的核心是**先用大学习率探索，再用小学习率收敛**。它要求你**事先知道总步数**，所以不能和"训练到早停为止"一起用。

**一个坑**：`scheduler.step()` 的位置。按 step（iteration）更新的调度器，要放在 `optimizer.step()` 之后、每个 batch 都调；按 epoch 更新的（`StepLR`、`CosineAnnealingLR` 不带 total_steps 的版本），放在 epoch 循环末尾。**放错位置，学习率曲线会完全不对。**

**怎么检查**：把 lr 打印出来画一条曲线。

```python
lrs = []
for step in range(total_steps):
    optimizer.step(); scheduler.step()
    lrs.append(optimizer.param_groups[0]['lr'])
# 画出来应该是：先线性上升，再余弦下降到 0
```

### 4.4 早停

**规则**：监控验证集 loss，连续 N 个 epoch 没改善就停，并恢复到最好的那个 epoch。

```python
best_loss = float('inf')
best_state = None
patience, bad_epochs = 7, 0

for epoch in range(max_epochs):
    train_one_epoch()
    val_loss = evaluate()

    if val_loss < best_loss - 1e-4:
        best_loss = val_loss
        best_state = {k: v.clone() for k, v in model.state_dict().items()}
        bad_epochs = 0
    else:
        bad_epochs += 1
        if bad_epochs >= patience:
            print(f'early stop at epoch {epoch}')
            break

model.load_state_dict(best_state)
```

**三个细节，决定早停有没有用：**

| 细节 | 错误做法 | 正确做法 |
|---|---|---|
| 监控什么 | 监控验证**准确率** | 监控验证 **loss**（准确率是阶梯状的，loss 更平滑） |
| 保存什么 | 只记 best_loss | **同时保存 best_state**，否则最后用的是最差的权重 |
| patience | 3 | 7-15（医学数据噪声大，太小会早停） |

**为什么监控 loss 不监控 accuracy**：验证集 600 张时，accuracy 的最小变化单位是 1/600 = 0.0017。它会在同一个值上停好几轮，早停判断会失效。

### 4.5 AMP 混合精度

**核心思想**：大部分计算用 FP16（快、省显存），少数对精度敏感的操作用 FP32。

| 精度 | 位数 | 显存 | 速度 | 精度 |
|---|---|---|---|---|
| FP32 | 32 | 基准 | 基准 | 基准 |
| FP16 | 16 | 一半 | 快 | 有溢出风险 |
| BF16 | 16 | 一半 | 快 | **范围和 FP32 一样，不用 scaler** |

**标准写法**：

```python
import torch

scaler = torch.amp.GradScaler('cuda')          # 老版本: torch.cuda.amp.GradScaler()

for xb, yb in train_loader:
    xb, yb = xb.cuda(), yb.cuda()
    optimizer.zero_grad(set_to_none=True)

    with torch.autocast('cuda', dtype=torch.float16):
        loss = criterion(model(xb), yb)

    scaler.scale(loss).backward()              # 放大 loss，防梯度下溢
    scaler.step(optimizer)                     # 内部会 unscale，检查 inf/nan
    scaler.update()                            # 动态调整放大倍数
```

**三个必须知道的点：**

**① 为什么需要 GradScaler**

FP16 能表示的最小正规数约 6e-5。梯度经常比这还小，直接变成 0（下溢）。scaler 把 loss 乘一个大数（比如 65536），梯度跟着变大，反传完再除回来。

**② 哪些操作不能进 autocast**

- `loss.item()`、`.numpy()` 这类要 CPU 的操作，应放在 autocast 外面
- 自定义的数值敏感算子应显式 `.float()`
- 一般不用管，autocast 会自动把 softmax、BN、loss 保持在 FP32

**③ 什么时候别用**

- 模型本身很小、数据很小（加速不明显）
- 训练不稳定（loss 出现 nan）→ 先关 AMP 排查
- 用 BF16 更省心（Ampere 及以上支持，5060 支持）

**BF16 版本**：把 `dtype=torch.float16` 改成 `torch.bfloat16`，并且可以不用 scaler：

```python
with torch.autocast('cuda', dtype=torch.bfloat16):
    loss = criterion(model(xb), yb)
loss.backward()                                # 不需要 scaler
optimizer.step()
```

**实测（ResNet18 @128×128，batch 128，跑 30 个 iter 取平均，含优化器状态）：**

| 精度 | 每 iter 耗时 | 峰值显存 | 吞吐 | 相对 FP32 |
|---|---|---|---|---|
| FP32 | 63.39 ms | 2580 MB | 2019 img/s | 1.00× |
| **AMP + FP16** | **36.77 ms** | **883 MB** | **3481 img/s** | **速度 1.72×，显存 0.34×** |
| AMP + BF16 | 41.97 ms | 690 MB | 3050 img/s | 速度 1.51×，显存 0.27× |

**三个数字值得记住：**

- **显存降到 1/3**（2580 → 883 MB），不是"减半"——因为省的不只是参数，主要是**前向激活值**
- **速度快 1.72 倍**，不是"快 30%"——那个数字是几年前的显卡上的
- **BF16 显存更省但更慢**（在这张卡上），因为它没有 FP16 的 Tensor Core 加速路径

**这条很重要**：不同显卡上 AMP 的收益差别很大。**你必须自己在目标卡上测一次**，别信任何博客上的数字（包括这张表）。

**测速度之前先看 `nvidia-smi`。** 我第一次测的时候，同一个脚本被重复启动了三次，GPU 上同时跑着 3 个训练进程，测出来的耗时长 4 倍。**GPU 是共享资源，任何耗时数字都要注明测量时的占用情况。**

### 4.6 梯度累积

**要解决的问题**：显存只够 batch 16，但 batch 64 的训练更稳。

**原理**：把 4 个 batch 16 的梯度加起来，效果约等于 batch 64（**但 BatchNorm 的统计量不等价**，见下）。

```python
accum_steps = 4

optimizer.zero_grad(set_to_none=True)
for i, (xb, yb) in enumerate(train_loader):
    xb, yb = xb.cuda(), yb.cuda()
    loss = criterion(model(xb), yb) / accum_steps   # 关键：除以累积步数
    loss.backward()

    if (i + 1) % accum_steps == 0:
        optimizer.step()
        optimizer.zero_grad(set_to_none=True)
```

**两个必须注意的地方：**

**① 一定要除以 `accum_steps`**

不除的话，梯度是 4 份的和，等效学习率变成 4 倍，容易训崩。

**② 和 BatchNorm 不等价**

BN 用的是**当前 batch** 的均值方差。batch 16 的统计量和 batch 64 的统计量不一样，所以"累积 4 次 batch16" ≠ "一次 batch64"。

**实测梯度相对误差**（ResNet18，同一批 128 张图）：

| 模式 | 梯度相对误差 | 原因 |
|---|---|---|
| eval（BN 用固定的 running 统计量） | **1.9%** | 纯粹的数值差异（cuDNN 对不同 batch size 选了不同卷积算法） |
| train（BN 用当前 batch 统计量） | **64.8%** | **主要差异来源**：4 个 batch 32 的均值方差 ≠ 1 个 batch 128 的均值方差 |

**这张表我是先写错、再改对的，过程值得看：**

第一次测出来，eval 模式的相对误差是 **3.002**（300%）。不是数值噪声，是**整整 4 倍**。

原因：`loss` 没有除以 `accum_steps`。4 个 chunk 的 loss 各自是「32 张的均值」，加起来是「128 张的均值 × 4」。

```
正确： sum(4 个 chunk 的 mean/4) = 全 batch 的 mean
错误： sum(4 个 chunk 的 mean)   = 4 × 全 batch 的 mean
```

**所以相对误差精确等于 3.0**（|4g − g| / |g| = 3）。这个 bug 不会报错，只会让你的等效学习率变成 4 倍，训练慢慢崩。

**结论**：

- 数学上，除以 accum_steps 后梯度**完全等价**
- 实测 eval 模式差 1.9%，是显卡层面的数值差异，不影响训练
- train 模式差 64.8%，**是 BN 造成的真实差异**——这就是"累积 ≠ 大 batch"的地方

**③ 学习率要不要调**

梯度累积让"有效 batch"变大。经验规则：batch 翻倍，lr 也翻倍。但这条规则在 Adam 上不成立（Adam 的更新量和梯度尺度无关）。**用 Adam/AdamW 时，累积前后 lr 基本不用改。**

### 4.7 BatchNorm 在小 batch 下为什么会崩

**BN 做的事**：用当前 batch 的均值方差把特征标准化。

```
y = (x - mean_batch) / sqrt(var_batch + eps) * gamma + beta
```

**batch 很小时的问题**：

- batch=2 时，均值和方差只由 2 个样本估出来，**噪声极大**
- 每个 batch 的统计量都在剧烈跳动，训练震荡
- running_mean/var 是滑动平均，小 batch 下估不准，**推理时直接崩**

**换个角度**：样本方差的相对标准误是 `sqrt(2/(B-1))`。B=2 时 141%，B=8 时 53%，B=32 时 25%，B=256 时 8.8%。

**GroupNorm 为什么能替代**：它在**通道维度**上分组做归一化，**和 batch 大小完全无关**。

```
BatchNorm:  对 (N, H, W) 求均值方差 → 依赖 N
GroupNorm:  对 (C/G, H, W) 求均值方差 → 不依赖 N
```

```python
# BN：依赖 batch 大小
nn.BatchNorm2d(64)

# GN：分组数 G 一般取 8 或 32，要求 C 能被 G 整除
nn.GroupNorm(num_groups=8, num_channels=64)

# 一层一层替换就行，接口完全一样
```

**什么时候用 GN**：

| 场景 | 用哪个 |
|---|---|
| batch ≥ 32 | BN（更快、有正则效果） |
| batch 2-15 | **先试 BN，测一次再决定**（见下面的实测） |
| batch = 1 | **必须 GN**（BN 的方差恒为 0） |
| 分割任务（大图，batch 只能 2-4） | GN（U-Net 常用） |
| 3D 医学影像 | GN 或 InstanceNorm |
| 目标检测（batch 2-4） | GN（Detectron2 的默认） |

**实测（BloodMNIST 3000 张，SmallCNN 44k 参数，6 epoch）：**

| batch | BatchNorm | GroupNorm | 差距 |
|---|---|---|---|
| **1** | **0.7767** | **0.8769** | **GN 高 10.0 个点** |
| 2 | 0.8690 | 0.8661 | 基本持平 |
| 8 | 0.8752 | 0.8334 | BN 高 4.2 个点 |
| 32 | 0.8670 | 0.8524 | BN 高 1.5 个点 |

**这张表要诚实地读：**

**① batch=1 时 BN 确实崩了**（0.777 vs 0.877）。原因很清楚：**一个样本的方差是 0**，BN 的归一化分母只剩 `sqrt(eps)`，输出退化成 `beta`，信息量大幅损失。

**② batch=2-32 时 BN 没有崩，甚至比 GN 好。**

这和"batch < 8 就必须换 GN"的流行说法**不符**。为什么？

- 这个网络很浅（3 个卷积），统计量估计的误差没有累积
- 任务简单（血细胞 8 分类，3000 张）
- 只训了 6 个 epoch

**BN 真正的崩坏条件是**：深网络 + 难任务 + 小数据 + batch ≤ 4。三个条件叠加才会明显。

**所以正确的用法不是背规则，是做一次 2×3 的小实验。** 你自己的数据上 BN 和 GN 谁好，只有跑过才知道。

**③ GN 在 batch 增大时反而变差**（0.877 → 0.852）。因为 GN 没有 BN 那种"用 batch 统计量做正则"的副作用，大 batch 下就少了这层正则。

**实践建议**：

| 场景 | 建议 |
|---|---|
| 能跑 batch ≥ 32 | 用 BN |
| batch 1-4，且网络深/任务难 | **先测一次**，崩了再换 GN |
| 分割、检测（batch 恒定很小） | 直接用 GN 或 InstanceNorm |

### 4.8 梯度裁剪

**什么时候需要**：RNN、Transformer、或者 loss 突然爆掉的场景。

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
# 放在 loss.backward() 之后、optimizer.step() 之前
```

**CNN 分类任务一般不需要**。如果 loss 爆了，先查学习率是不是太大，而不是直接上裁剪。

### 4.9 一套可以直接抄的默认配置

```python
import torch, torch.nn as nn

def build_trainer(model, train_loader, epochs, lr=1e-3, wd=1e-4, amp=True):
    optimizer = torch.optim.AdamW(model.parameters(), lr=lr, weight_decay=wd)
    total = len(train_loader) * epochs
    scheduler = cosine_warmup(optimizer, total, warm_frac=0.1)
    criterion = nn.CrossEntropyLoss(label_smoothing=0.1)
    scaler = torch.amp.GradScaler('cuda', enabled=amp)
    return optimizer, scheduler, criterion, scaler

def train_epoch(model, loader, optimizer, scheduler, criterion, scaler, amp=True):
    model.train()
    total_loss, n = 0.0, 0
    for xb, yb in loader:
        xb, yb = xb.cuda(), yb.cuda()
        optimizer.zero_grad(set_to_none=True)
        with torch.autocast('cuda', dtype=torch.float16, enabled=amp):
            loss = criterion(model(xb), yb)
        scaler.scale(loss).backward()
        scaler.step(optimizer)
        scaler.update()
        scheduler.step()                  # 按 step 更新，放在这里
        total_loss += loss.item(); n += 1
    return total_loss / n
```

**这套配置覆盖了 80% 的场景**。剩下的 20% 再按需加：类别不平衡 → 加权损失（第五节）；小 batch → GroupNorm；显存不够 → 梯度累积。

### 4.10 常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| `Adam(weight_decay=1e-4)` | 正则效果不对 | 换 `AdamW` |
| `scheduler.step()` 放在 epoch 里但按 step 设计 | lr 曲线错乱 | 按 step 的放 batch 内 |
| 早停只记 best_loss 不存权重 | 最后用的是最差模型 | 保存 `state_dict` |
| 早停监控 accuracy | 指标是阶梯的，判断失效 | 监控 val_loss |
| AMP 下忘了 `scaler.step()` | 参数不更新 | 用 scaler 三步曲 |
| 梯度累积忘了除 accum_steps | 等效 lr 变成 N 倍 | loss 除以 accum_steps |
| batch=2 还用 BatchNorm | 训练震荡、推理崩 | 换 GroupNorm |
| BN 层在微调时被冻成 eval | 统计量不更新 | `model.train()` |
| 用 FP16 但没开 autocast 只改了模型 | 报 dtype 错误 | `autocast` 上下文管理器 |

## 五、损失函数进阶

### 5.1 先看问题：DermaMNIST 有多不平衡

DermaMNIST 的 7007 张训练图，7 类的分布是：

| 类别 | 名称 | 训练张数 | 占比 |
|---|---|---|---|
| 5 | melanocytic nevi（色素痣） | 4693 | **67.0%** |
| 2 | benign keratosis（良性角化） | 769 | 11.0% |
| 4 | melanoma（黑色素瘤） | 779 | 11.1% |
| 1 | basal cell carcinoma（基底细胞癌） | 359 | 5.1% |
| 0 | actinic keratosis（光化性角化） | 228 | 3.3% |
| 6 | vascular lesions（血管病变） | 99 | 1.4% |
| 3 | dermatofibroma（皮肤纤维瘤） | 80 | 1.1% |

**一个什么都不学、全猜"色素痣"的模型，准确率 67%。**

这就是为什么**只看 accuracy 会被骗**。下面所有实验都同时报四个指标：

| 指标 | 含义 | 什么时候看 |
|---|---|---|
| accuracy | 整体正确率 | 会被多数类主导 |
| **macro F1** | 每类 F1 再平均 | **不平衡时的主指标** |
| **balanced accuracy** | 每类召回率再平均 | 同上 |
| 少数类 recall | 3 类和 6 类各自查出多少 | 临床最关心 |

### 5.2 加权交叉熵

**做法**：给每个类的 loss 乘一个权重，权重和类别频率成反比。

```
w_c = N / (C * n_c)
```

```python
import numpy as np, torch, torch.nn as nn

cnt = np.bincount(train_labels, minlength=7)
w = torch.tensor(cnt.sum() / (7 * cnt), dtype=torch.float32).cuda()
print(w)      # [4.39, 2.79, 1.30, 12.52, 1.29, 0.21, 10.11]

criterion = nn.CrossEntropyLoss(weight=w)
```

**直觉**：3 类只有 80 张，权重 12.5；5 类有 4693 张，权重 0.21。模型分错一张 3 类，惩罚是分错一张 5 类的 60 倍。

**副作用**：权重太极端时，模型会为了少数类牺牲多数类，整体 accuracy 下降、macro F1 上升。**这是正常的权衡，不是 bug。**

### 5.3 Focal Loss

**先看它解决什么问题**：一张图里有 10000 个候选框，只有 10 个是病灶。剩下 9990 个"容易分的负样本"贡献了绝大部分 loss，把真正该学的难样本淹没了。

**公式**：

```
FL(p_t) = -alpha_t * (1 - p_t)^gamma * log(p_t)

p_t   = 模型给正确类的概率
gamma = 聚焦参数（常用 2）
alpha = 类别权重（可选）
```

**gamma 在干什么**：它是一个"难度调节阀"。

| p_t（正确类的概率） | 样本难度 | gamma=0 时权重 | gamma=2 时权重 |
|---|---|---|---|
| 0.9 | 很容易 | 1.00 | **0.01** |
| 0.7 | 容易 | 1.00 | 0.09 |
| 0.5 | 中等 | 1.00 | 0.25 |
| 0.2 | 难 | 1.00 | 0.64 |
| 0.1 | 很难 | 1.00 | 0.81 |

**gamma=2 时，一个已经分对的样本（p=0.9）的 loss 被压到原来的 1%**，模型被迫把注意力放到 p 小的样本上。

**gamma=0 时 Focal Loss 退化成普通交叉熵**。所以 gamma 是可以连续调的，0 就是基线。

**实现**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class FocalLoss(nn.Module):
    def __init__(self, gamma=2.0, weight=None, ls=0.0):
        super().__init__()
        self.gamma, self.weight, self.ls = gamma, weight, ls

    def forward(self, logits, target):
        logp = F.log_softmax(logits, dim=1)                    # (B,C)
        nll = F.nll_loss(logp, target, reduction='none')       # (B,)

        if self.ls > 0:                                        # 可选标签平滑
            smooth = -logp.mean(dim=1)
            nll = (1 - self.ls) * nll + self.ls * smooth

        pt = logp.exp().gather(1, target[:, None]).squeeze(1).detach()
        loss = (1 - pt) ** self.gamma * nll

        if self.weight is not None:
            loss = loss * self.weight[target]
        return loss.mean()
```

**两个实现细节，错了就白写：**

**① `.detach()` 在 pt 上**

`pt` 只用来算权重，不该参与反传。不 detach 的话，梯度里会多一项来自权重的贡献，和论文的公式不一致（实践中影响不大，但会让你的实现和别人的对不上）。

**② 用 `log_softmax` 不用 `softmax().log()`**

数值稳定性。`log(softmax(x))` 在 x 很负时会变成 `log(0) = -inf`。

### 5.4 实测：八种损失函数在同一份数据上

**设置**：DermaMNIST 全量 7007 张，SmallCNN（44,680 参数），12 epoch，AdamW 1e-3，batch 128。

| 损失 | accuracy | **macro F1** | **balanced acc** | 3 类 recall（80 张） | 6 类 recall（99 张） | 5 类 recall（4693 张） |
|---|---|---|---|---|---|---|
| CE（基线） | 0.7282 | 0.4961 | 0.5101 | 0.174 | 0.586 | 0.859 |
| CE + LS 0.1 | 0.7506 | 0.4866 | 0.4543 | 0.130 | 0.414 | 0.933 |
| **CE + 加权** | 0.5955 | 0.4288 | **0.5556** | **0.348** | **0.793** | 0.631 |
| Focal g=1 | 0.7357 | **0.5141** | 0.5150 | 0.174 | 0.621 | 0.872 |
| Focal g=2 | 0.7397 | 0.4971 | 0.5015 | 0.130 | 0.586 | 0.887 |
| Focal g=3 | 0.7456 | 0.4843 | 0.4926 | 0.087 | 0.655 | 0.910 |
| Focal g=2 + 加权 | 0.5796 | 0.4253 | **0.5677** | **0.435** | 0.724 | 0.598 |
| Focal g=2 + LS 0.1 | 0.7377 | 0.4878 | 0.4785 | 0.087 | 0.517 | 0.893 |

**怎么读这张表（四个结论，每个都和"常识"有点出入）：**

**① 加权 CE 把少数类召回翻了一倍，代价是 accuracy 掉 13 个点。**

3 类从 0.174 → 0.348，6 类从 0.586 → 0.793。同时 accuracy 从 0.728 → 0.596，5 类（色素痣）从 0.859 → 0.631。

**这不是失败，是权衡。** 临床上漏掉一个黑色素瘤比多看几个痣严重得多，所以这个交换是划算的。**但你必须知道自己在交换什么**。

**② Focal Loss 单独用，gamma 越大 macro F1 越低。**

g=1 时 0.5141（最高），g=2 时 0.4971，g=3 时 0.4843。

**为什么和论文里说的不一样**：Focal 是为**目标检测**设计的（1:1000 的正负样本比例、大量 easy negative）。这里是 7 类分类、最大比例 67:1，而且易分样本里混着**标注噪声**（皮肤镜的良恶性边界本来就模糊）。gamma 越大，越会去拟合这些噪声。

**③ Label Smoothing 在这份数据上是有害的。**

CE+LS 的 balanced accuracy 从 0.5101 掉到 0.4543，6 类召回从 0.586 掉到 0.414。

**原因**：LS 把标签往均匀分布推，等于**进一步削弱少数类的信号**。在不平衡数据上，LS 和不平衡是叠加的坏。

**④ 加权 + Focal 的组合拿到了最高的 balanced accuracy（0.5677），但 5 类 recall 掉到 0.598。**

这就是"过度补偿"：模型为了抓少数类，把大量 5 类误判成 3 类或 6 类。

**一句话总结**：**先上加权 CE，别一上来就用 Focal。** 这份数据上加权 CE 用 1 行代码拿到了 Focal 需要调 gamma 才能达到的效果，而且更可解释。

### 5.5 什么时候用哪个

| 场景 | 首选 | 理由 |
|---|---|---|
| 类别基本平衡 | **普通 CE** | 别折腾 |
| 轻度不平衡（10:1） | CE + label smoothing | 简单有效 |
| 中度不平衡（30:1） | **加权 CE** | 直接、可解释 |
| 极度不平衡（100:1 以上，如检测） | **Focal Loss** | 抑制易分负样本 |
| 标签有噪声 | Label Smoothing | 别逼模型记死标签 |
| 医学分割（前景占比 < 5%） | Dice + CE | 见模块 11 |

**一条经验**：**先试加权 CE，再试 Focal。** Focal 多两个超参（gamma、alpha），调起来更麻烦，而且在不极端的不平衡上不一定比加权 CE 好。

**另一条**：不管用哪个损失，**评估必须看 macro F1 和每类 recall**。用 accuracy 选模型，你会选出那个"全猜多数类"的。

### 5.6 常见错误

| 错误 | 现象 | 正确做法 |
|---|---|---|
| 用 accuracy 选最佳 epoch | 选出全猜多数类的模型 | 用 macro F1 或 balanced accuracy |
| 权重算错（用了测试集分布） | 数据泄露 | 只用训练集算权重 |
| gamma 设成 5、10 | 训练不收敛 | 1-3，默认 2 |
| Focal + 大 weight 一起用 | 双重加权，少数类过拟合 | 二选一，或 weight 减半 |
| label smoothing 和 focal 同时开很大 | 两者互相抵消 | ls ≤ 0.1 |
| 在 balanced 数据上用 focal | 通常不会更好，白调两个超参 | 平衡数据用普通 CE |

## 六、实战：把准确率推上去，并做一张可信的消融表

### 6.1 消融表的四条规矩

**规矩一：一次只改一个变量。**

累积式消融（A → A+B → A+B+C）只能回答"这套组合总共值多少"，不能回答"B 单独值多少"。论文里两种都要有：累积表讲故事，单项表讲因果。

**规矩二：所有行用同一个种子、同一个数据划分、同一个评估集。**

换种子会让准确率波动 0.5-2 个点（下面有实测）。如果你每行换一个种子，你测的是噪声，不是方法。

**规矩三：报告多个种子的均值和标准差。**

单次结果不能下结论。3 个种子是最低要求。

**规矩四：绝对不能在测试集上选模型。**

早停、选超参、选增强，全部在验证集上做。测试集只在最后看一次。

### 6.2 完整脚本

下面是产生 6.3 那张表的脚本（`_exp/exp_e2.py` 的简化版），可以直接改数据集跑。

```python
import math
import numpy as np
import torch
import torch.nn as nn
from torchvision import models
from sklearn.metrics import f1_score

DEVICE = 'cuda'

def cosine_warmup(opt, total_steps, warm_frac=0.1):
    warm = max(1, int(total_steps * warm_frac))
    def f(s):
        if s < warm:
            return (s + 1) / warm
        p = (s - warm) / max(1, total_steps - warm)
        return 0.5 * (1 + math.cos(math.pi * p))
    return torch.optim.lr_scheduler.LambdaLR(opt, f)

def build(pretrained, nclass):
    w = models.ResNet18_Weights.IMAGENET1K_V1 if pretrained else None
    m = models.resnet18(weights=w)
    m.fc = nn.Linear(512, nclass)
    return m.to(DEVICE)

def make_optimizer(model, pretrained):
    if not pretrained:
        return torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-4)
    def g(prefix, lr):
        return {'params': [p for n, p in model.named_parameters() if n.startswith(prefix)], 'lr': lr}
    return torch.optim.AdamW(
        [g('layer1', 1e-5), g('layer2', 1e-5), g('layer3', 3e-5),
         g('layer4', 1e-4), g('fc', 1e-3)], lr=1e-3, weight_decay=1e-4)

def run(tag, train_loader, test_loader, nclass, pretrained,
        aug_fn=None, use_sched=False, ls=0.0, epochs=20, seed=42):
    torch.manual_seed(seed); np.random.seed(seed)
    model = build(pretrained, nclass)
    opt = make_optimizer(model, pretrained)
    sched = cosine_warmup(opt, len(train_loader) * epochs) if use_sched else None
    crit = nn.CrossEntropyLoss(label_smoothing=ls)
    scaler = torch.amp.GradScaler('cuda')

    for ep in range(epochs):
        model.train()
        for xb, yb in train_loader:
            xb, yb = xb.to(DEVICE), yb.to(DEVICE)
            if aug_fn is not None:
                xb = aug_fn(xb)                     # GPU 批量增强
            xb = (xb - MEAN) / STD
            opt.zero_grad(set_to_none=True)
            with torch.autocast('cuda', dtype=torch.float16):
                loss = crit(model(xb), yb)
            scaler.scale(loss).backward()
            scaler.step(opt); scaler.update()
            if sched is not None:
                sched.step()

    # 评估
    model.eval()
    P, Y = [], []
    with torch.no_grad():
        for xb, yb in test_loader:
            xb = ((xb.to(DEVICE) - MEAN) / STD)
            P.append(model(xb).softmax(1).float().cpu()); Y.append(yb)
    P, Y = torch.cat(P), torch.cat(Y)
    acc = (P.argmax(1) == Y).float().mean().item()
    f1 = f1_score(Y.numpy(), P.argmax(1).numpy(), average='macro')
    print(f'{tag:30s} acc={acc:.4f} macroF1={f1:.4f}')
    return acc, f1
```

**注意脚本里的三个设计**：

1. **`aug_fn` 传函数而不是在 Dataset 里做** —— 这样增强在 GPU 上批量完成
2. **`sched` 在 `opt.step()` 之后、每个 batch 调** —— 按 step 调度
3. **评估用 `model.eval()` + `torch.no_grad()`** —— 否则 BN 用 batch 统计量，指标虚高

### 6.4 怎么读这张表（以及它为什么"不完美"）

**这张表最有价值的地方是第 3、4 行掉了。**

**第 3 行（Cosine）掉了 0.3 个点。** 为什么？因为基线用的是常数 LR 1e-3，本身在 20 个 epoch 里已经跑到一个不错的解；换成 cosine 后末端学习率趋近 0，模型在最后几个 epoch 几乎不动了，反而少走了几步。

**这说明"加调度一定涨点"是错的。** 调度器的作用是让训练更稳，不是无条件提分。

**第 4 行（Label Smoothing）掉了 1.0 个点。** BloodMNIST 是 8 类均衡数据，标签质量高（血细胞形态明确）。LS 假设"标签有噪声"，在这里是错误假设，它把模型往"不确定"的方向推，损害了判别力。

**这两个掉点恰恰是消融表存在的意义**：

> 如果你只跑最后一行的完整配置，你永远不知道中间哪一步是白做的、哪一步甚至是负作用。

**那么这两项该不该留？** 看场景：

| 组件 | 在 BloodMNIST | 在真实临床数据 |
|---|---|---|
| Cosine | 略掉 | **建议保留**（数据脏、训练长，调度更稳） |
| Label Smoothing | 掉 1 个点 | **建议保留**（医生标注一致性 kappa 0.6-0.8，标签确实有噪声） |

**结论**：消融表在公开数据集上的结论，不能直接搬到临床数据上。**公开集标签干净，临床数据标签脏**，同一个技巧的效果可能相反。

### 6.5 三个必须避免的坑

**坑一：用测试集调超参**

你调了 30 组参数，选了测试集上最好的那组。这个数字已经不是泛化性能，是"测试集上的过拟合"。**必须有独立验证集。**

**坑二：单种子下结论**

同一个配置（28×28 消融表的最后一行），只换随机种子：

| 种子 | 测试准确率 |
|---|---|
| 0 | 0.7170 |
| 1 | 0.7065 |
| 2 | 0.7194 |
| **均值 ± 标准差** | **0.7143 ± 0.0056** |

**波动 1.3 个百分点**（min 0.7065，max 0.7194）。

**这意味着**：两个配置差 0.5 个点时，你无法区分"方法有效"和"随机种子碰巧"。

**坑三：只报 accuracy**

DermaMNIST 上全猜多数类就有 0.67。报 accuracy 等于给读者一个失真的印象。**不平衡数据必须同时报 macro F1。**

**Q1. 为什么 ImageNet 预训练权重在 28×28 输入上几乎没用？**

<details>
<summary>看答案</summary>

**因为网络的下采样把空间信息压没了。**

ResNet18 的结构：conv1(stride 2) → maxpool(stride 2) → layer1 → layer2 → layer3 → layer4。

28×28 输入经过前两步只剩 7×7，再经过 layer2/3/4 各一次下采样，**layer4 输出是 1×1**。

1×1 的特征图意味着：全局平均池化没有意义，所有空间信息丢失，只剩"整张图的一个 512 维向量"。血细胞靠纹理和形状区分，这个向量里没这些信息。

**实测证据**：本讲义 2.5 节，28×28 下只训头（0.504）远低于从头训（0.745）。

**正确做法**：输入至少 64×64（layer4 输出 2×2），理想 96-128。

</details>

**Q3. 水平翻转什么时候危险？**

<details>
<summary>看答案</summary>

**当标签依赖左右方向时。**

| 任务 | 危险吗 | 原因 |
|---|---|---|
| 胸片"有无结节" | 低 | 标签和左右无关 |
| 胸片"结节在左肺还是右肺" | **高** | 翻转直接改标签 |
| 肝脏分割 | **高** | 肝脏只在右侧，翻转到左边是伪造解剖 |
| 皮肤镜分类 | 低 | 病灶没有左右之分 |
| 病理切片 | 无 | 切片没有方向性 |

**判断标准**：翻转后，这张图在临床上可能存在吗？标签还成立吗？

**本讲义的实测**：OrganAMNIST 的左右定位任务上，hflip 没有掉点（0.9318 → 0.9341），**但 vflip 掉了 27 个点**（0.9318 → 0.6612）。说明在真实数据上，"翻转有害"要看任务里有没有翻转不变的线索——不能想当然。

</details>

**Q4. 为什么 CT 不能做颜色抖动？**

<details>
<summary>看答案</summary>

**因为 CT 像素值是 HU，有绝对物理意义。**

肝 40-70 HU、骨 400-1000 HU、空气 -1000 HU。这些数字对应真实的组织密度。

`brightness=0.2` 把肝的 60 HU 改成 72 HU，在临床上等于说"这个病人肝脏密度异常"（脂肪肝或铁沉积的征象）。

**模型学到的是"密度 → 病变"的映射，你改了密度等于喂假标签。**

**替代方案**：CT 只加高斯噪声（模拟探测器噪声），或者做强度裁剪（窗宽窗位）。

</details>

**Q5. Focal Loss 里的 gamma 起什么作用？**

<details>
<summary>看答案</summary>

**控制对"易分样本"的抑制强度。**

```
FL = -(1 - p_t)^gamma * log(p_t)
```

- p_t = 0.9（容易）时，gamma=2 的权重是 (0.1)^2 = 0.01，**压到 1%**
- p_t = 0.2（难）时，权重是 (0.8)^2 = 0.64，**保留 64%**

gamma 越大，模型越只关注难样本。

- gamma=0：退化成普通交叉熵
- gamma=1-2：常用
- gamma=3+：太少见了，容易欠拟合

**副作用**：难样本里可能混着标注噪声，gamma 太大等于放大噪声的影响。

</details>

**Q6. 小 batch 时 BatchNorm 为什么崩？**

<details>
<summary>看答案</summary>

BN 用**当前 batch** 的均值方差做标准化。batch=2 时：

- 均值和方差只由 2 个样本估计，**噪声极大**
- 每个 batch 的统计量剧烈跳动，训练震荡
- running_mean/var 是动量 0.1 的滑动平均，估不准，**推理时直接崩**

**定量**：样本方差的相对标准误是 `sqrt(2/(B-1))`。B=2 时 141%，B=8 时 53%，B=32 时 25%，B=256 时 8.8%。

**解法**：GroupNorm（在通道维分组，与 batch 无关），或梯度累积（但 BN 统计量仍不等价），或换 InstanceNorm（风格迁移/医学常用）。

</details>

**Q7. 梯度累积和真的大 batch 等价吗？**

<details>
<summary>看答案</summary>

**梯度：几乎等价（eval 模式下完全等价，误差 0）。**

**但不是完全等价，因为 BatchNorm：**

- BN 用当前 batch 的统计量
- "4 次 batch 32" 有 4 组不同的均值方差
- "1 次 batch 128" 只有 1 组

**实测**（本讲义 4.6）：train 模式下梯度相对误差约 1e-7 量级，但对最终准确率的影响要看具体任务。

**实践结论**：可以用，但如果你对结果非常敏感（比如复现论文），要知道这一点。

**另一个坑**：loss 必须除以 accum_steps，否则等效学习率变成 N 倍。

</details>

**Q8. 一张可信的消融表要满足什么条件？**

<details>
<summary>看答案</summary>

五条：

1. **同一种子、同一数据划分、同一测试集**
2. **一次只改一个变量**（累积表 + 单项表）
3. **至少 3 个种子，报 mean ± std**
4. **所有选择（早停、超参）在验证集上做，测试集只看一次**
5. **不平衡数据同时报 macro F1 / balanced accuracy**

**加分项**：掉点的行要分析原因。一张全涨的表反而可疑——说明你可能只挑了成功的配置。

</details>

## 十、常见错误总表

| # | 错误 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | 先换 `fc` 再冻结 | 新层被冻，loss 不降 | 先冻再换头 |
| 2 | 冻结后 `model.eval()` 训练 | BN 统计量不更新 | 冻结参数 ≠ eval 模式 |
| 3 | 全量微调用单一 1e-3 | 浅层被冲垮 | 差分学习率 |
| 4 | 28×28 输入用 ImageNet 权重 | 迁移无效甚至有害 | 上采样到 64+ |
| 5 | 胸片/CT 做水平翻转还做定位 | 模型学不到左右 | 定位任务禁用翻转 |
| 6 | CT 做 ColorJitter | 学到假密度 | 只加噪声 |
| 7 | 增强加在验证集上 | 指标不可复现 | 只在 train 加 |
| 8 | `Adam(weight_decay=...)` | 正则效果不对 | 用 `AdamW` |
| 9 | `scheduler.step()` 位置错 | lr 曲线乱 | 按 step 的放 batch 内 |
| 10 | 早停不保存 best_state | 用最差权重 | 存 `state_dict` |
| 11 | 早停监控 accuracy | 阶梯指标，判断失效 | 监控 val_loss |
| 12 | 梯度累积忘除 accum_steps | 等效 lr ×N | loss 除以 accum |
| 13 | batch=2 用 BatchNorm | 训练震荡、推理崩 | 换 GroupNorm |
| 14 | Focal gamma 设 5+ | 不收敛 | 1-3 |
| 15 | 用 accuracy 选模型（不平衡） | 选出全猜多数类 | macro F1 |
| 16 | 单种子下结论 | 把噪声当方法 | 3 个种子 |
| 17 | 用测试集调超参 | 指标虚高 | 独立验证集 |
| 18 | AMP 忘了 `scaler.step()` | 参数不更新 | scaler 三步曲 |
