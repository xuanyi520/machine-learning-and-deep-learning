# 毕业项目 · 临床数据集整理与质检系统

**建议用时：40 小时（约 2-3 周）**

---

## 〇、项目定位

**一句话：把一堆来源不明、格式混乱的医学数据，变成一份带说明书、可追溯、能直接用于训练的规范化数据集。**

**这个项目不炫技，但它是所有算法工作的地基。**

**面试官会问：「你做过最枯燥但最有价值的工作是什么？」**

**这个项目就是标准答案。**

---

## 一、为什么值得做

| 理由 | 说明 |
|---|---|
| **每家公司都需要** | 但没人愿意写进简历 |
| **证明你懂真实数据的脏** | 这比会调模型难找 |
| **它是所有下游项目的前提** | 数据没理清，模型训得再好也是垃圾 |
| **可以直接演示** | 一份数据说明书 + 一个能跑的流水线 |

## 二、输入

**选一个你手上有的数据源：**

| 选项 | 说明 |
|---|---|
| **方案 A** | MedMNIST 的多个数据集（有现成的，容易起步） |
| **方案 B** | 公开的 DICOM 数据集（TCIA 上下几例） |
| **方案 C** | 自己造的干扰数据（故意塞入各种问题） |

**建议从 A 起步，再过渡到 B。**

**如果只有 A，可以在里面人为制造问题（改日期、删标签、破坏文件），验证质检能力。**

## 三、四个阶段

### 阶段一：扫描与摸底（8 小时）

- [ ] 遍历所有文件，判断格式（**不靠后缀，靠文件头**）
- [ ] 提取元数据，生成索引表 CSV
- [ ] 统计：总文件数、病人数、模态分布、尺寸分布
- [ ] **输出一份「数据摸底报告」**

**验收：**

```
病人数: 25
文件数: 1250
模态: CT 1000, MR 250
尺寸异常: 3 例（列出）
重复病人 ID: 1 组（列出）
```

---

### 阶段二：脱敏与规范化（12 小时）

- [ ] 按 17-3 的规则脱敏
- [ ] UID 重映射
- [ ] 删除私有标签
- [ ] 文件名和目录按 17-5 的规范重建
- [ ] 生成映射表，单独存放
- [ ] 自动验证：扫描脱敏后的数据，确认无残留

**验收：**

- [ ] 脱敏前后像素完全一致
- [ ] 残留检查返回空
- [ ] 映射表在另一个位置，且加了 `.gitignore`

---

### 阶段三：质检流水线（12 小时）

- [ ] 实现四类检查（完整性、可读性、一致性、合理性）
- [ ] 输出 `qc_report.json`
- [ ] 做成可直接运行的脚本：`python qc.py --input data/`
- [ ] **故意造 5 个错误，验证每个都能被抓住**

**验收：**

- [ ] 5 个错误全部被检出
- [ ] 报告能指明具体是哪个文件、什么问题
- [ ] 跑一遍的时间可接受（1000 个文件 < 30 秒）

---

### 阶段四：文档与交付（8 小时）

- [ ] `README.md`：别人能照着跑
- [ ] `dataset_description.json`：元信息
- [ ] `versions.md`：每个版本改了什么、为什么改
- [ ] `数据说明书.md`：给非技术人员看的
- [ ] 一份「数据质量问题清单」：发现了哪些问题、怎么处理

**验收：**

- [ ] 换一台机器，照 README 能跑通
- [ ] 数据说明书能让临床医生看懂

## 五、数据说明书要写什么

**这份文档是给「不写代码的人」看的。**

```markdown
# 数据集说明书

## 1. 概述
- 名称、版本、日期
- 数据量：N 个病人，M 个文件
- 模态：CT / MR / X 光
- 用途：研究（不可商用）

## 2. 来源与伦理
- 数据来源
- 伦理批件编号
- 使用范围限制

## 3. 数据结构
- 目录树
- 命名规则
- 每个字段的含义

## 4. 处理流程
- 做了什么处理，用的哪个脚本
- 版本之间的差异

## 5. 质量报告
- 各类检查的通过率
- 已知问题清单

## 6. 已知局限
- 样本偏倚
- 缺失情况
- 标注质量

## 7. 联系方式
```

**第 6 节最重要。** 主动说局限，比藏着掖着强。

## 六、简历怎么写

**不要写成：**

```
医疗数据整理
- 使用 Python 处理 DICOM 数据
- 完成数据清洗
```

**应该写成：**

```
临床影像数据集规范化流水线（个人项目）
- 设计并实现 DICOM 批量处理工具，支持无后缀文件的格式识别，
  完成 XXX 例 / XXX 个文件的元数据提取与索引
- 实现符合健康医疗数据安全指南的脱敏流程：字段替换、UID 重映射、
  私有标签清除，并通过自动残留检测验证
- 构建四类质检流水线（完整性/可读性/一致性/合理性），
  在测试集上 100% 检出人为注入的 5 类异常
- 产出数据说明书与版本记录，使数据集可被第三方直接复用
```

**注意每一条都有具体数字和「能被验证」的描述。**

## 七、面试怎么讲

### 3 分钟版

```
问题：拿到一批医院给的影像数据，4000 多个文件，没说明书，
     文件名是 1.dcm、2.dcm 这种，不知道谁是谁。
方法：先写扫描脚本，用文件头判断格式（不是靠后缀，
     因为一半文件没有 .dcm），提取所有元数据做成索引表。
     这一步就发现了 3 个问题：同一病人两个 ID、12 例层数不足、2 个日期是 2099 年。
     然后按规范脱敏，重点处理了私有标签和 UID 重映射——
     这两处是最容易漏的。
     最后做了质检流水线，固化成 pytest，数据一改就自动跑。
结果：数据集标准化完成，配套文档让同事能直接上手，不用问我。
```

### 可能被追问

| 问题 | 你要能答 |
|---|---|
| 脱敏怎么保证不漏？ | 讲残留检测 + 故意造错验证 |
| 私有标签是什么？ | 讲厂商写在 DICOM 里的非标准字段 |
| 为什么不直接用 DVC？ | 讲数据量小、团队规模，说清取舍 |
| 怎么判断文件是不是 DICOM？ | 讲文件头 128+4 字节的 `DICM` |

## 九、常见失败模式

| 失败 | 表现 | 预防 |
|---|---|---|
| 靠后缀找文件 | 漏掉一半数据 | 用文件头判断 |
| 脱敏不验证 | 以为干净了 | 必须跑残留检测 |
| 文档最后才写 | 写不出来 | 每做完一步就记 |
| 没有版本记录 | 不知道改了啥 | 边做边写 versions.md |
| 映射表和数据放一起 | 等于没脱敏 | 分开存，加 gitignore |
| 只做技术不写说明 | 别人用不了 | 说明书是交付物 |
