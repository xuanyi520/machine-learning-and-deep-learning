## 一、什么时候需要浏览器自动化

**requests 拿不到的东西，才轮到它。**

| 场景 | requests 够吗 | 需要浏览器吗 |
|---|---|---|
| 静态 HTML 页面 | ✅ | 不用 |
| 有内嵌 JSON（`__NEXT_DATA__`） | ✅ | 不用 |
| 有官方 API | ✅ | 不用 |
| **数据靠 JavaScript 渲染** | ❌ | **需要** |
| **需要登录态** | ⚠️ 可以带 cookie | 看情况 |
| **需要点击、翻页、填表** | ❌ | **需要** |
| 有强反爬（滑块、指纹） | ❌ | **别做，见第五节** |

**一句话：先试 requests，不行再上浏览器。浏览器自动化慢 10-50 倍，资源占用大 100 倍。**

## 二、Playwright 还是 Selenium

| | Playwright | Selenium |
|---|---|---|
| 出品方 | 微软 | 社区（老牌） |
| 速度 | **快** | 慢 |
| 自动等待 | **内置** | 要自己写 |
| 多浏览器 | Chromium/Firefox/WebKit | 全支持 |
| 录制工具 | **有（codegen）** | 有（IDE） |
| 社区教程 | 较少 | **极多** |
| 推荐 | **新项目用它** | 维护老项目 |

**结论：新项目用 Playwright。** 它的「自动等待」能省掉你一半的调试时间。

## 三、最小可运行示例

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=False)    # False 能看到浏览器
    page = browser.new_page()
    page.goto("https://pubmed.ncbi.nlm.nih.gov/", timeout=30000)

    # 等某个元素出现
    page.wait_for_selector("#search-term", timeout=10000)

    # 填表 + 点击
    page.fill("#search-term", "liver cancer segmentation")
    page.click("button[type='submit']")

    # 等结果加载
    page.wait_for_selector(".docsum-title", timeout=15000)

    # 取数据
    titles = [el.inner_text() for el in page.query_selector_all(".docsum-title")]
    print(f"拿到 {len(titles)} 条")
    for t in titles[:5]:
        print(" ", t[:60])

    browser.close()
```

### 四个核心操作

| 操作 | 方法 |
|---|---|
| 打开网页 | `page.goto(url, timeout=...)` |
| 找元素 | `page.query_selector(css)` / `query_selector_all` |
| 操作元素 | `click()` / `fill()` / `select_option()` |
| 取内容 | `inner_text()` / `get_attribute()` |

### `headless` 开不开

| 值 | 什么时候用 |
|---|---|
| `headless=False` | **调试时必开**，能看到它在干什么 |
| `headless=True` | 跑通之后，部署和批量执行 |

**新手最常见的错误：一上来就无头模式，出错了完全不知道发生了什么。**

## 四、等待策略：稳定性的核心

**90% 的「明明手动能跑，脚本就是不行」，都是等待问题。**

### 三种等待，只有一种该用

**① `time.sleep()` —— 最差**

```python
page.click("button")
time.sleep(3)              # 猜的
```

**网慢的时候 3 秒不够，网快的时候白等。**

**② 隐式等待 —— 也差**

```python
page.set_default_timeout(10000)    # 全局设一个超时
```

**它只影响「找元素」，不影响「元素能不能点」。**

**③ 显式等待 —— 正确**

```python
# 等到某个条件成立
page.wait_for_selector(".result", state="visible", timeout=15000)

# 等到网络空闲
page.wait_for_load_state("networkidle")

# 等到某个函数返回真
page.wait_for_function("document.querySelectorAll('.item').length > 10")
```

**三条原则：**

```
① 等「具体的东西出现」，不要等固定时间
② 每个等待都要设 timeout，不要无限等
③ 报错信息要能定位（见下一节）
```

### `state` 参数

| state | 含义 |
|---|---|
| `attached` | 元素在 DOM 里（可能不可见） |
| `visible` | **可见（默认）** |
| `hidden` | 消失了 |

**要点击的话，必须 `visible`。** 只 `attached` 的话元素存在但可能被遮挡，点了没反应。

## 五、稳定性：五个必须做的防护

### ① 超时不能省

```python
page.goto(url, timeout=30000)          # 30 秒
page.wait_for_selector(sel, timeout=15000)
```

**不设 timeout 的话，默认可能是 30 秒，也可能是无限——取决于版本。**

**显式写出来，出了问题才知道卡在哪一步。**

### ② 失败要能截图

```python
try:
    page.wait_for_selector(".result", timeout=15000)
except Exception as e:
    page.screenshot(path=f"error_{int(time.time())}.png", full_page=True)
    with open(f"error_{int(time.time())}.html", "w", encoding="utf-8") as f:
        f.write(page.content())
    raise
```

**截一张图 + 存一份 HTML，比看一行报错有用一百倍。**

### ③ 重试整个流程，而不是重试单个操作

```python
def run_with_retry(fn, max_retry=3):
    for i in range(max_retry):
        try:
            return fn()
        except Exception as e:
            print(f"第 {i+1} 次失败: {type(e).__name__}: {e}")
            if i == max_retry - 1:
                raise
            time.sleep(2 ** i)
```

**页面加载失败，重试整个 `goto + 操作` 通常能成功；只重试 `click` 往往还是失败。**

### ④ 会话复用，别每次都重新登录

```python
# 第一次登录后保存状态
context = browser.new_context()
page = context.new_page()
# ... 登录 ...
context.storage_state(path="auth.json")

# 下次直接用
context = browser.new_context(storage_state="auth.json")
```

**⚠️ 注意：`auth.json` 里有 cookie 和 token，等同于密码。不要提交到 git，不要传给别人。**

### ⑤ 处理好弹窗和 iframe

```python
# 新窗口
with page.expect_popup() as popup_info:
    page.click("a[target=_blank]")
new_page = popup_info.value

# iframe
frame = page.frame_locator("iframe#main")
frame.fill("#input", "内容")
```

## 六、边界：什么不该做

**这一节比技术部分重要。**

### 不该做的四件事

**① 绕过登录**

```
❌ 自动化输入账号密码登录别人（或公司）的系统
✅ 在自己的账号上，自动化重复操作
```

**「登录」这件事本身要有人授权。你没有权限的系统，自动化拿密码登录就是未授权访问。**

**② 破解验证码 / 滑块**

**这类设计的本意就是「阻止自动化」。绕过它，等于明确违反对方的意愿。**

**技术上有些方法能做，但这一节不会教，也不建议做。**

**③ 高频请求**

**浏览器自动化一次操作要 1-3 秒，比 requests 慢得多。用这种方式狂刷，对服务器的压力更大，也更容易被封。**

**④ 采集需要授权的内容**

**和 17-1 一样的红线，不重复。**

### 该做的三件事

**① 在授权范围内的重复劳动**

```
✅ 你自己有账号的系统，每天要导出十份报表
✅ 医院内部系统，管理员明确同意你做工具
✅ 公开的、robots.txt 允许的网站
```

**② 作为「人机协作」的辅助**

```
✅ 自动填表，人最后检查一眼再提交
✅ 自动翻页抓取，遇到异常页面停下等人处理
```

**③ 做数据分析前的准备**

```
✅ 把 100 份 PDF 报告批量下载下来（有授权）
```

## 七、调试技巧

### 用 codegen 录制

```
playwright codegen https://example.com
```

**会开一个浏览器，你在里面操作，它实时生成代码。**

**这是上手最快的方式，也是学习选择器写法的最好途径。**

### 定位元素失败时

```python
# 打印页面上所有可能的候选
for el in page.query_selector_all("div"):
    txt = el.inner_text()[:50]
    if "目标文字" in txt:
        print(el.evaluate("e => e.outerHTML")[:200])
```

### 慢动作模式

```python
page = browser.new_page()
page.set_default_timeout(30000)
# 用 trace 记录整个执行过程
context.tracing.start(screenshots=True, snapshots=True)
# ... 操作 ...
context.tracing.stop(path="trace.zip")
```

**用 `playwright show-trace trace.zip` 打开，能看到每一步的截图、DOM 快照、网络请求。**

**这是排错最强的工具，值得专门学一下。**

## 十二、常见错误

| 错误 | 现象 | 改法 |
|---|---|---|
| 一上来 `headless=True` | 出错完全不知道怎么回事 | 调试时开 False |
| 用 `time.sleep` | 网慢就失败、网快就浪费 | 显式等待 |
| 不设 timeout | 卡死不知道卡在哪 | 每个等待都设 |
| 只等 `attached` 就点击 | 点了没反应 | 等 `visible` |
| 每次都重新登录 | 慢且容易触发风控 | `storage_state` 复用 |
| `auth.json` 进了 git | 凭证泄露 | 加 `.gitignore` |
| 高频刷页面 | 被封 | 操作之间留间隔 |
