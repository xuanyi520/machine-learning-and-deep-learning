## 一、SFT 之后还缺什么

**SFT 教模型「怎么回答」。但它学的是「模仿数据里的答案」，不理解「什么样的答案更好」。**

**三个具体问题：**

| 问题 | 例子 |
|---|---|
| **不会拒绝** | 问「怎么造假病历」，它会认真编一个 |
| **啰嗦** | 简单问题给一大段 |
| **不安全** | 学到训练数据里的偏见和错误 |

**这些问题的共同点：不是「不知道答案」，是「不知道该怎么答」。**

**这就叫「对齐（alignment）」。**

## 二、RLHF：三阶段流程

**RLHF = Reinforcement Learning from Human Feedback，基于人类反馈的强化学习。**

**InstructGPT 论文（2022）确立的标准流程：**

```
阶段一：SFT
  用人工写的「好答案」监督微调
  ↓
阶段二：训练奖励模型（Reward Model, RM）
  同一个问题，让模型生成多个答案
  人工给这些答案排序（A > B > C）
  训练一个模型学会「打分」
  ↓
阶段三：用 PPO 做强化学习
  模型生成答案 → 奖励模型打分 → 用这个分数更新策略
```

### 阶段二的细节：为什么是「排序」而不是「打分」

**让人直接打「这个答案 7 分」，不同人的标准不一样，噪声很大。**

**让人比较「A 和 B 哪个好」，一致性高得多。**

**所以训练数据是「成对比较」：**

```
问题：肝窗的窗宽窗位是多少？
答案 A：160 / 60。                    ← 简洁准确
答案 B：肝窗是一个很重要的窗……（500 字）  ← 啰嗦
人类标注：A > B
```

**奖励模型的损失函数（Bradley-Terry 模型）：**

```
L = -log( sigmoid( r(A) - r(B) ) )
```

**含义：让「更好的答案」得分更高。**

### 阶段三：PPO 在做什么

**PPO（Proximal Policy Optimization）是一个强化学习算法。**

**它要解决一个核心矛盾：**

```
既要「追求高奖励」→ 模型会走极端，生成奇怪的输出骗高分
又要「别偏离太远」→ 保持语言能力
```

**解决办法：加一个 KL 惩罚。**

```
总分 = 奖励模型分数 - β × KL(当前模型 || SFT模型)
```

**`β` 控制「保守程度」。**

**`KL` 惩罚的意思是：你改得越多，扣分越多。**

**这就是为什么 RLHF 训练要同时加载两个模型（当前模型 + SFT 参考模型）——显存翻倍。**

### 显存账

**PPO 训练 7B 模型，需要同时装：**

```
① 当前策略模型（Actor）        14 GB
② 参考模型（Reference）        14 GB
③ 奖励模型（Reward）           14 GB
④ 价值模型（Critic）           14 GB
────────────────────────────────
合计                           56 GB（fp16，不含激活）
```

**你的 8 GB 显存：连第 ① 个都装不下。**

## 三、DPO：绕过奖励模型

**2023 年的 DPO（Direct Preference Optimization）论文做了一件很聪明的事：**

> **数学上证明，RLHF 的最优解可以直接用一个简单的分类损失逼近，不需要显式的奖励模型。**

### 它怎么做到的

**关键观察：**

**PPO 的目标函数可以化简，最终等价于：**

```
L = -log sigmoid( β × [ log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x) ] )
```

**其中：**

- `y_w` = 人类偏好的答案（winner）
- `y_l` = 被拒绝的答案（loser）
- `π` = 当前模型，`π_ref` = SFT 参考模型

**读法：让模型「比参考模型更倾向好答案，更不倾向坏答案」。**

### DPO 省掉了什么

| | RLHF (PPO) | DPO |
|---|---|---|
| 奖励模型 | **需要**（单独训一个） | **不需要** |
| 同时加载的模型 | 4 个 | **2 个**（当前 + 参考） |
| 稳定性 | 难调，容易崩 | **很稳** |
| 实现复杂度 | 高 | **一个损失函数** |
| 数据 | 排序偏好 | **成对偏好**（同样的数据） |

**实测经验：在很多任务上，DPO 的效果接近甚至超过 PPO。**

**所以现在大部分开源模型（Zephyr、LLaMA 3 的部分版本、Qwen）用 DPO 做对齐。**

### 数据格式

```json
{
  "prompt": "肝窗的窗宽窗位是多少？",
  "chosen": "160 / 60。",
  "rejected": "肝窗是观察肝脏用的窗宽窗位，窗宽设置需要考虑很多因素……（啰嗦的答案）"
}
```

**只要 `chosen` 和 `rejected` 两列。**

### 用 trl 做 DPO

```python
from trl import DPOTrainer, DPOConfig

trainer = DPOTrainer(
    model=model,
    ref_model=ref_model,        # 或者传 None，trl 会自动复制一份冻结的
    args=DPOConfig(
        output_dir="output/dpo",
        per_device_train_batch_size=1,
        gradient_accumulation_steps=8,
        learning_rate=5e-5,      # ← 比 SFT 小一个数量级
        num_train_epochs=1,
        beta=0.1,                # KL 惩罚系数
        fp16=True,
    ),
    train_dataset=dpo_dataset,
    tokenizer=tokenizer,
)
trainer.train()
```

**`beta` 是关键超参：**

| beta | 效果 |
|---|---|
| 0.01 | 激进，容易偏离太远 |
| **0.1** | **常用默认值** |
| 0.5 | 保守，改动小 |

## 四、GRPO：省掉价值模型

**GRPO = Group Relative Policy Optimization，DeepSeek 提出来的。**

### 它解决了什么

**PPO 要训练四个模型，其中「价值模型（Critic）」和主模型一样大。**

**GRPO 的想法：**

> **不要价值模型了。同一个问题生成 N 个答案，用这 N 个答案的平均分作为基线。**

**这就是「组内相对（Group Relative）」的意思。**

```
PPO：  优势 = 奖励 - 价值模型预测的基线      ← 要 Critic
GRPO： 优势 = 奖励 - 这一组 N 个答案的平均奖励   ← 不要 Critic
```

**省掉一整个模型的显存和训练成本。**

### 为什么有效

**价值模型的作用是「估计这个问题的平均表现，作为基线」。**

**但如果同一个 prompt 生成 8 个答案，这 8 个答案的平均分本身就是个好基线。**

**统计上更简单，工程上更省。**

### DeepSeek-R1 的做法

**DeepSeek-R1 用 GRPO 做推理能力的强化学习。**

**它的奖励信号很有意思：**

| 奖励类型 | 内容 |
|---|---|
| **准确性奖励** | 答案对不对（数学题有标准答案、代码能跑过） |
| **格式奖励** | 有没有用 `<think>...</think>` 包裹思考过程 |

**注意：没有用奖励模型。**

**纯规则化的奖励（对/错、格式符不符合），避免了「奖励黑客」问题。**

**这是 R1 能开源并且效果好的重要原因。**

## 五、四种方法对比

| | SFT | RLHF (PPO) | DPO | GRPO |
|---|---|---|---|---|
| 需要什么数据 | 问答对 | 排序 + 奖励模型 | **成对偏好** | 可验证的结果 |
| 加载几个模型 | 1 | **4** | 2 | 2-3 |
| 稳定性 | 高 | **低** | 高 | 中 |
| 实现难度 | 低 | **高** | 低 | 中 |
| 你的 8 GB 能做 | ✅ | ❌ | ⚠️ 1.7B 勉强 | ❌ |

**一句话总结：**

```
SFT      —— 教它「怎么答」
RLHF/PPO —— 教它「什么答案更好」（要奖励模型）
DPO      —— 同样目的，但数学化简了（不要奖励模型）
GRPO     —— 再省掉价值模型（组内比较代替基线）
```

**趋势很明显：越来越简单、越来越省。**

## 六、你的硬件能做什么

**8 GB 显存，1.7B 模型。**

| 方法 | 可行性 |
|---|---|
| SFT + LoRA | ✅ 已经在 19-3 做过 |
| DPO | ⚠️ **可以试**：当前模型 + 参考模型，每个 3.4 GB，加上激活值勉强 |
| PPO | ❌ 四个模型，装不下 |
| GRPO | ❌ 同上 |

**DPO 的做法：**

**参考模型不用单独加载——用 LoRA 的适配器，把「冻结的基座 + 无适配器」当作参考模型，「基座 + 适配器」当作当前模型。**

**这样只装一份基座权重。**

```python
from peft import PeftModel

# 只有一份基座
base = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16)
model = get_peft_model(base, lora_config)

# DPOTrainer 传 ref_model=None，它会用「关掉适配器」的状态当参考
trainer = DPOTrainer(model=model, ref_model=None)   # 其余参数略
```

**trl 对这种情况有支持。具体做法查当前版本文档。**

## 十一、常见错误

| 错误 | 现象 | 改法 |
|---|---|---|
| 以为 DPO 不需要参考模型 | 显存估错 | 需要，但可用 LoRA 技巧 |
| `beta` 设太小 | 模型偏离，胡言乱语 | 0.1 起步 |
| DPO 学习率用 SFT 的 | 训练崩 | 小一个数量级（5e-5） |
| 偏好数据太单一 | 模型只学会一种风格 | 覆盖多类「差」 |
| 以为 GRPO 是 DeepSeek 首创 | 说不清来源 | 论文里有引用前作 |

## 十二、下一节要干什么

**你现在知道怎么训模型了。**

**但「训练完，怎么证明它变好了」？**
