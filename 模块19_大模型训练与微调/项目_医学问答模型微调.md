# 毕业项目 · 医学问答模型微调

**建议用时：40 小时（约 2-3 周）**

**这是模块 19 的终点，也是唯一必须「亲手做出来」的东西。**

---

## 〇、项目定位

**一句话：用 8 GB 显存，把 Qwen3-1.7B 微调成一个医学影像助手，并证明它比基座好。**

**规模不大，但流程完整。面试时讲「我用消费级显卡完成了 LoRA 微调全流程」，比「我调了个 API」有说服力得多。**

---

## 一、为什么选 1.7B

| 参数量 | 8 GB 能 LoRA 吗 | 说明 |
|---|---|---|
| 0.6B | ✅ 轻松 | 但能力太弱，效果不明显 |
| **1.7B** | ✅ **推荐** | 能力够用，显存有余量 |
| 3B | ✅ 可以（batch 1） | 更慢 |
| 7B | ❌ | fp16 装不下，QLoRA 在 Windows 上装不上 |

**1.7B 是「能做出来」和「有效果」的交叉点。**

---

## 二、数据从哪来

**这是最大的工作量。**

### 三个来源，按优先级

| 来源 | 量 | 质量 | 工作量 |
|---|---|---|---|
| **① 从你的讲义里提取** | 你自己有 3000+ 行讲义 | 高 | **中** |
| ② 从公开指南整理 | 指南原文 | 高 | 高（要人工写问答） |
| ③ 用大模型生成 + 人工校对 | 多 | 中 | **低，但要校对** |

**建议：以 ① 为主，③ 补充。**

**你的模块 4-1（DICOM）、模块 11（分割）、模块 16（大模型）讲义里，全是现成的知识点。**

### 目标规模

```
最少：300 条
推荐：1000 条
不要超过：3000 条（1.7B 学不了太多，多了反而过拟合）
```

### 数据格式

```json
{"instruction": "肝窗的窗宽窗位是多少？", "input": "", "output": "窗宽 160 HU，窗位 60 HU。"}
```

### 三条质量红线

**① 答案必须是你验证过的**

**不要直接复制模型生成的内容。** 一个错误的知识点，会被训练进模型，而且很难发现。

**② 一个问题只对应一个标准答案**

**同一个问题有多个正确答案时，模型会学得含糊。**

**③ 答案要简洁**

**SFT 学的是「风格」。你给长篇大论，它就学会长篇大论。**

### 阶段二：基线 + 微调（12 小时）

**先跑基线，再跑微调。**

```python
# 基线：基座模型 + 同样的提示词
```

**验收：**

**还要测三项：**

- [ ] 事实一致性（答案里的数字对不对）

```

```

**应该写成：**

```

- 构建 900 条医学影像问答数据集（从自建讲义提取 + 人工校对），
  覆盖 DICOM、窗宽窗位、分割指标等 4 个主题
- 在 RTX 5060（8 GB）上用 LoRA 微调 Qwen3-1.7B，
  可训练参数占比 0.25%，完成 3 epoch 训练
- 设计四层评估（BLEU/ROUGE + 嵌入相似度 + LLM 裁判 + 人工），
```

## 七、面试怎么讲

### 3 分钟版

```
问题：通用大模型不知道我们医院的具体规范，每次调用都要塞 2000 字提示词，
     成本高而且慢。
方法：我做了一个小规模的验证——用 900 条问答对，在 8 GB 显卡上
     用 LoRA 微调 Qwen3-1.7B，可训练参数只占 0.25%。
     关键是设计评估：不能只看 loss，我用 BLEU、嵌入相似度、
     LLM 裁判和人工评分四层，人工那层最可信。
发现：微调后 ROUGE-L 从 0.31 提到 0.42，但 BLEU 提升很小——
     因为 BLEU 对措辞太敏感，换个说法就掉到 0。
     这说明单一指标不可靠，必须多层交叉验证。
落地：量化成 GGUF Q4_K_M，1 GB，能在 CPU 上跑，方便部署。
```

### 必被追问的问题

| 问题 | 你要能答 |
|---|---|
| **为什么不直接用 RAG？** | 讲两者适用场景，LoRA 省 token、改风格；RAG 更新知识。**最好说「两者结合」** |
| **只训 900 条够吗？** | 小规模验证的目的是跑通流程，不是追 SOTA |
| **怎么保证数据没错？** | 每一条人工核对，数字全部回到讲义原文 |
| **量化会不会影响医疗准确性？** | 会，所以要测；我测了 20 条无事实错误，但承认样本少 |
| **8 GB 能做什么，不能做什么** | 能 LoRA 1.7B，不能全量微调 7B，不能 RLHF |

## 九、常见失败模式

| 失败 | 表现 | 预防 |
|---|---|---|
| **数据没校对** | 模型学会错误知识 | 每条回到原文核对 |
| 不跑基线 | 不知道有没有变好 | 先跑基座 |
| 只看 loss | 说不出效果 | 四层评估 |
| 只看 BLEU | 被措辞骗 | 加语义和人工 |
| 过拟合 | 训练 loss 很低，测试很差 | 用 val 早停 |
| 数据太多 | 1.7B 学不过来 | 300-1000 条足够 |
| 量化后不验证 | 上线才发现答错 | 必须对比 |
