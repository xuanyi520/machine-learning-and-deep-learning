## 一、一个 Transformer block 长什么样

**原版（2017，GPT-2 风格）：**

```
x ──┬── LayerNorm ── 多头注意力 ──┬── + ──┬── LayerNorm ── FFN ──┬── + ── 输出
    │                              │      │                      │
    └──────── 残差 ────────────────┘      └────── 残差 ──────────┘
```

**LLaMA 风格：**

```
x ──┬── RMSNorm ── 多头注意力 ──┬── + ──┬── RMSNorm ── SwiGLU ──┬── + ── 输出
    │                            │      │                      │
    └──────── 残差 ──────────────┘      └────── 残差 ───────────┘
```

**看起来差不多，但四个地方变了。**

## 二、四个改动

### 改动一：Pre-Norm（层归一化放在前面）

**GPT-2 是 Post-Norm：`x + Sublayer(Norm(x))` 变成 `Norm(x + Sublayer(x))`**

**等一下，说反了。准确说：**

| 类型 | 位置 | 表达式 |
|---|---|---|
| **Post-Norm**（原版） | 归一化在残差**之后** | `x = Norm(x + Sublayer(x))` |
| **Pre-Norm**（LLaMA） | 归一化在残差**之前** | `x = x + Sublayer(Norm(x))` |

**为什么改：**

**Post-Norm 在深层网络里梯度不稳定，需要很小心地调 warmup。**

**Pre-Norm 的残差路径是「干净」的——梯度可以直通到底，训练更稳。**

**代价：** 表达能力略弱一点，但因为能训得更深，总账划算。

**现在几乎所有大模型都用 Pre-Norm。**

### 改动二：RMSNorm

**LayerNorm 做什么：**

```
x_norm = (x - mean) / sqrt(var + eps) * gamma + beta
```

**RMSNorm 做什么：**

```
x_norm = x / sqrt(mean(x²) + eps) * gamma
```

**两个区别：**

| | LayerNorm | RMSNorm |
|---|---|---|
| 减均值 | ✅ 减 | ❌ **不减** |
| 缩放 | 用标准差 | **用均方根（RMS）** |
| 可学习参数 | gamma + beta | **只有 gamma** |

**实测参数量对比（维度 64）：**

```
RMSNorm 参数量:     64
LayerNorm 参数量:  128      ← 多一个 bias
```

**为什么能省掉减均值和 bias：**

**作者发现，减均值对最终效果贡献很小，但计算上要额外一轮 reduce。**

**去掉之后，速度提升约 10-15%，效果几乎不掉。**

**这是典型的「用理论上的微小损失，换工程上的明显收益」。**

### 改动三：SwiGLU

**FFN 原来长这样：**

```python
x = W2 @ relu(W1 @ x)           # 两层，中间 ReLU
```

**SwiGLU 长这样：**

```python
x = W2 @ (silu(W1 @ x) * (W3 @ x))    # 三个矩阵，多一个门控
```

**`silu(x) = x * sigmoid(x)`，也叫 Swish。**

**关键：多了一个 `W3` 做「门控」——`silu(W1x)` 决定「要不要过」，`W3x` 决定「过多少」。**

**实测参数量对比（dim=128, hidden=344）：**

```
SwiGLU          参数: 132,096
普通 FFN         参数:  88,064      ← SwiGLU 多 50%
```

**所以真实模型里，SwiGLU 层的 hidden 维度会调小（约普通 FFN 的 2/3），让总参数量持平。**

**为什么有效：** 门控机制让网络能「选择性放行」信息，表达能力强于单纯的激活函数。

**PaLM 论文首先系统验证，LLaMA 跟进，现在成了标配。**

### 改动四：RoPE（旋转位置编码）

**原版 Transformer 用「绝对位置编码」——给每个位置加一个固定的向量。**

**问题：**

```
训练时最长 2048，推理时来了 4096 → 位置 4096 没见过，模型懵了
```

**RoPE 的做法：不是「加」位置，是「旋转」Q 和 K。**

```
把 Q 和 K 的每两个维度看成复数，按位置 t 旋转 t·θ 角度
```

**为什么这样好：**

| 特性 | 好处 |
|---|---|
| **相对位置** | 两个 token 的注意力只取决于它们的**距离**，不是绝对位置 |
| **外推** | 理论上能处理训练时没见过的长度（实际还需要调） |
| **不占额外参数** | 纯计算，没有可学习参数 |

**实测：位置 0 的旋转是恒等变换：**

```
位置0旋转后是否等于原值: True
```

**这条验证很重要**——它说明 RoPE 不改变序列开头的信息。

```python
def precompute_freqs(dim, max_len, base=10000.0):
    freqs = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
    t = torch.arange(max_len).float()
    freqs = torch.outer(t, freqs)
    return torch.cos(freqs), torch.sin(freqs)

def apply_rope(x, cos, sin):
    B, H, T, D = x.shape
    x1, x2 = x[..., :D//2], x[..., D//2:]
    cos, sin = cos[:T].unsqueeze(0).unsqueeze(0), sin[:T].unsqueeze(0).unsqueeze(0)
    return torch.cat([x1*cos - x2*sin, x1*sin + x2*cos], dim=-1)
```

**注意：这是简化实现（把维度对半切）。真实实现用的是「交错」排布（把相邻两维当一对）。**

## 三、Qwen / DeepSeek 和 LLaMA 的差异

**总体架构几乎一样（都是 LLaMA 系），差异在细节。**

### Qwen 系列

| 特性 | Qwen | LLaMA |
|---|---|---|
| 位置编码 | **RoPE**（同） | RoPE |
| 归一化 | **RMSNorm**（同） | RMSNorm |
| FFN | **SwiGLU**（同） | SwiGLU |
| **词表** | **15 万+**（中文优化） | 3.2 万 |
| **GQA 分组** | 更激进（更少的 KV 头） | 相对保守 |
| 注意力偏置 | **QKV 有 bias** | 无 |

**词表大小是最实际的差别。**

**15 万词表意味着：同样的中文，Qwen 用的 token 数明显更少。**

```
同一个句子：
  LLaMA 分词后：18 个 token
  Qwen 分词后：  9 个 token
```

**这就是为什么中文任务用 Qwen 比 LLaMA 便宜。**

### DeepSeek 系列

**DeepSeek-V2/V3 引入了两个比较大的改动：**

| 技术 | 干什么 |
|---|---|
| **MLA（Multi-head Latent Attention）** | 把 KV 压缩成低维潜变量，**KV Cache 再降一个数量级** |
| **MoE（混合专家）** | 每个 token 只激活部分专家，总参数大但计算量小 |

**MLA 是它最有特色的地方：**

```
标准 GQA： KV Cache = 序列 × 层 × KV头 × 头维度
MLA：      先把 KV 投影到低维潜空间（比如 512 维），缓存这个
```

**效果：KV Cache 进一步缩到 1/10 左右，而且效果不掉。**

**面试时如果被问「你知道哪些 KV Cache 优化的方法」，答 MLA 会很加分。**

## 四、怎么读 config.json

**每个 HuggingFace 模型都带一个 `config.json`，读懂它就知道模型多大、多长。**

```json
{
  "hidden_size": 1536,
  "num_hidden_layers": 28,
  "num_attention_heads": 12,
  "num_key_value_heads": 4,
  "intermediate_size": 8960,
  "max_position_embeddings": 32768,
  "vocab_size": 151936,
  "torch_dtype": "bfloat16"
}
```

### 六个字段的含义

| 字段 | 含义 | 用途 |
|---|---|---|
| `hidden_size` | 隐藏维度 | 算注意力参数量 |
| `num_hidden_layers` | 层数 | 算总参数量 |
| `num_attention_heads` | **Q 头数** | —— |
| `num_key_value_heads` | **KV 头数** | 判断是不是 GQA |
| `intermediate_size` | FFN 中间维度 | 算 FFN 参数量 |
| `vocab_size` | 词表大小 | **直接影响 embedding 参数量** |

### 估算单层参数

```python
def count_block(dim, n_heads, n_kv, hidden):
    head_dim = dim // n_heads
    # QKV 投影
    qkv = dim*dim + 2*dim*(n_kv*head_dim)
    # 输出投影
    o = dim*dim
    # SwiGLU 三个矩阵
    ffn = 3*dim*hidden
    return qkv + o + ffn

print(count_block(1536, 12, 4, 8960))
```

**实测输出：**

```
47,579,136
```

**约 4760 万参数一层。**

**乘以 28 层 = 13.3 亿。加上 embedding（15 万词表 × 1536 维 = 2.3 亿），总共约 1.57 亿……**

**等一下，15 万 × 1536 = 2.3 亿，加上 13.3 亿 = 15.6 亿。**

**所以叫「1.7B」是对的。**

**这就是估算的作用——不用下载模型，看 config 就能算出规模。**

## 五、权重格式

**下载模型时会看到几种文件，各有用途。**

| 格式 | 特点 | 用在哪 |
|---|---|---|
| **`pytorch_model.bin`** | 老格式，pickle 序列化 | 有安全风险（能执行代码） |
| **`.safetensors`** | **新标准**，纯张量，安全 | HuggingFace 默认 |
| **`.gguf`** | 量化格式，单文件 | llama.cpp / Ollama |
| **`.onnx`** | 计算图 | 部署 |

### 为什么现在都用 safetensors

**`.bin` 用 pickle，加载恶意的 `.bin` 可以执行任意代码。**

**`.safetensors` 只存张量数据，加载时不做任何反序列化，安全。**

**而且它支持「只加载部分张量」——这让 LoRA 训练时只读需要的部分成为可能。**

### 一个模型目录里有什么

```
Qwen/Qwen3-1.7B/
├── config.json                   ← 结构参数
├── generation_config.json        ← 生成参数（temperature 默认值等）
├── model.safetensors             ← 权重（可能拆成多个分片）
├── model.safetensors.index.json  ← 分片索引
├── tokenizer.json                ← 分词器
├── tokenizer_config.json
├── special_tokens_map.json       ← <|im_start|> 这类特殊 token
└── vocab.json / merges.txt       ← BPE 词表
```

**`special_tokens_map.json` 在做 SFT 时很重要——对话模板依赖它。**

## 六、跟着做

### 任务：手搭一个 LLaMA block

**不加载真实权重，只搭结构。**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
import math

class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x):
        rms = x.pow(2).mean(-1, keepdim=True).add(self.eps).rsqrt()
        return x * rms * self.weight

class SwiGLU(nn.Module):
    def __init__(self, dim, hidden):
        super().__init__()
        self.w1 = nn.Linear(dim, hidden, bias=False)
        self.w3 = nn.Linear(dim, hidden, bias=False)
        self.w2 = nn.Linear(hidden, dim, bias=False)

    def forward(self, x):
        return self.w2(F.silu(self.w1(x)) * self.w3(x))

class LlamaBlock(nn.Module):
    def __init__(self, dim=512, n_heads=8, n_kv=2, hidden=1376):
        super().__init__()
        self.n_heads = n_heads
        self.n_kv = n_kv
        self.head_dim = dim // n_heads

        self.norm1 = RMSNorm(dim)
        self.q_proj = nn.Linear(dim, n_heads * self.head_dim, bias=False)
        self.k_proj = nn.Linear(dim, n_kv * self.head_dim, bias=False)
        self.v_proj = nn.Linear(dim, n_kv * self.head_dim, bias=False)
        self.o_proj = nn.Linear(n_heads * self.head_dim, dim, bias=False)

        self.norm2 = RMSNorm(dim)
        self.mlp = SwiGLU(dim, hidden)

    def forward(self, x):
        B, T, D = x.shape
        h = self.norm1(x)

        q = self.q_proj(h).view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(h).view(B, T, self.n_kv, self.head_dim).transpose(1, 2)
        v = self.v_proj(h).view(B, T, self.n_kv, self.head_dim).transpose(1, 2)

        # GQA：把 KV 头复制到和 Q 头一样多
        repeat = self.n_heads // self.n_kv
        k = k.repeat_interleave(repeat, dim=1)
        v = v.repeat_interleave(repeat, dim=1)

        # PyTorch 2.0+ 的原生注意力，自动用 flash 或 memory-efficient 实现
        out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        out = out.transpose(1, 2).contiguous().view(B, T, D)

        x = x + self.o_proj(out)
        x = x + self.mlp(self.norm2(x))
        return x
```

**跑一下：**

```python
block = LlamaBlock()
x = torch.randn(2, 16, 512)
y = block(x)
print(y.shape)
print(f"参数量: {sum(p.numel() for p in block.parameters()):,}")
```

**验收：**

- [ ] 输出形状和输入一致
- [ ] 参数量能算出来
- [ ] **能解释 `repeat_interleave` 那一行在干什么**

**最后一项是关键：它就是 GQA 的实现方式——把 4 个 KV 头复制成 12 个，让每个 Q 头都能找到对应的 KV。**

## 十、常见错误

| 错误 | 现象 | 改法 |
|---|---|---|
| 混淆 Pre/Post-Norm | 说反 | Pre 是「先归一化再进子层」 |
| 以为 RMSNorm 是近似 | 担心效果 | 作者验证过损失很小 |
| SwiGLU 直接用原 hidden | 参数暴涨 | hidden 调成 2/3 |
| RoPE 实现维度排布错 | 结果不对 | 注意「对半」vs「交错」 |
| 不查 `num_key_value_heads` | 估错显存 | 这个字段决定 KV 头数 |
| 用 `.bin` 加载未知模型 | 安全风险 | 优先 safetensors |
