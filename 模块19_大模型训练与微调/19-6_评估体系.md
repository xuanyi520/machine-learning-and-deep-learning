**「我的模型训练完了，效果怎么样？」**

## 一、先看一个真实的坑

**我在本机算了几个 BLEU 和 ROUGE 分数。**

**参考答案：**

```
肝窗常用窗宽 160 HU 窗位 60 HU
```

**五个预测，打分结果：**

```
预测                                      BLEU   ROUGE-L
肝窗常用窗宽 160 HU 窗位 60 HU             1.000    1.000
肝窗窗宽160HU，窗位60HU。                  0.000    0.000     ← 看这里！
肝窗的窗宽是 160，窗位是 60                 0.000    0.222
肺窗窗宽 1500 窗位 -600                    0.000    0.200
窗宽 160 HU 窗位 60 HU 用于观察肝脏          0.615    0.769
```

### 第二行是灾难

**`肝窗窗宽160HU，窗位60HU。`**

**这句话完全正确。信息一个不差，只是「160」和「HU」之间没加空格。**

**BLEU = 0，ROUGE-L = 0。**

**而最后一行——虽然啰嗦，但信息也对——只拿到 0.615。**

### 为什么会这样

**BLEU 比的是「n-gram 精确率」：**

```
参考：肝窗 / 窗宽 / 160 / HU / 窗位 / 60
预测：肝窗 / 窗宽160HU / 窗位60HU
```

**`窗宽160HU` 作为一个整体，在参考里不存在。所有 bigram 都对不上。**

### 结论（这一节最重要的一句）

> **n-gram 类指标衡量的是「字面重合度」，不是「意思对不对」。**
>
> **它适合机器翻译（译文和参考译文结构类似），不适合开放式问答。**

**如果论文里只报 BLEU，审稿人会怀疑你在掩盖什么。**

## 二、BLEU 和 ROUGE 分别是什么

### BLEU（Bilingual Evaluation Understudy）

**为机器翻译设计。核心是「n-gram 精确率」。**

```python
import math
from collections import Counter

def ngrams(tokens, n):
    return [tuple(tokens[i:i+n]) for i in range(len(tokens)-n+1)]

def bleu_simple(pred, ref, max_n=4):
    p_tok, r_tok = pred.split(), ref.split()
    if len(p_tok) == 0:
        return 0.0
    log_sum = 0.0
    for n in range(1, max_n+1):
        pn, rn = Counter(ngrams(p_tok, n)), Counter(ngrams(r_tok, n))
        if not pn:
            return 0.0
        overlap = sum(min(c, rn[g]) for g, c in pn.items())
        precision = overlap / sum(pn.values())
        if precision == 0:
            return 0.0
        log_sum += math.log(precision)
    bp = 1.0 if len(p_tok) > len(r_tok) else math.exp(1 - len(r_tok)/len(p_tok))
    return bp * math.exp(log_sum / max_n)
```

**三个组成部分：**

| 部分 | 作用 |
|---|---|
| **n-gram 精确率** | 预测里的 n-gram 有多少在参考里出现过 |
| **简短惩罚（BP）** | 答案太短会被惩罚，防止「只答一个词」刷分 |
| **几何平均** | 1 到 4-gram 的分数取几何平均 |

**为什么有简短惩罚：**

**如果不惩罚长度，模型输出「160」就能拿到 1-gram 精确率 1.0。**

### ROUGE（Recall-Oriented Understudy for Gisting Evaluation）

**为摘要设计。核心是「召回率」。**

```python
def rouge_l(pred, ref):
    """最长公共子序列的 F1"""
    a, b = pred.split(), ref.split()
    m, n = len(a), len(b)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m):
        for j in range(n):
            dp[i+1][j+1] = dp[i][j]+1 if a[i]==b[j] else max(dp[i][j+1], dp[i+1][j])
    lcs = dp[m][n]
    if lcs == 0: return 0.0
    p, r = lcs/m, lcs/n
    return 2*p*r/(p+r)
```

**常见变体：**

| 变体 | 看什么 |
|---|---|
| ROUGE-1/2 | 1-gram / 2-gram 召回 |
| ROUGE-L | **最长公共子序列**（考虑顺序） |
| ROUGE-Lsum | 摘要专用 |

### 两者的分工

| | BLEU | ROUGE |
|---|---|---|
| 关注 | **精确率**（预测里有多少是对的） | **召回率**（参考里的有多少被覆盖） |
| 适合 | 翻译（不能瞎加） | 摘要（不能漏） |
| 用在哪 | 论文里常用 | 摘要任务常用 |

**实际用法：两个都报，再加点别的。**

## 三、困惑度（Perplexity）

**最基础的指标，也是 loss 的直接换算。**

```python
def perplexity(loss):
    """交叉熵 loss 转困惑度"""
    return math.exp(loss)
```

**含义：模型平均在多少个词之间犹豫。**

| PPL | 含义 |
|---|---|
| 10 | 平均在 10 个候选词里犹豫 |
| 100 | 犹豫范围大，不太确定 |
| **越低越好** | —— |

**问题：**

**PPL 衡量的是「对训练分布的拟合」，不是「回答正确」。**

**一个只会说「的的的的」的模型，PPL 可能也低。**

**所以 PPL 只能作为训练过程的监控指标，不能作为最终评估。**

## 四、GPT-Judge / LLM as Judge

**用一个更强的模型当裁判。**

### 基本做法

```python
JUDGE_PROMPT = """你是一个医学问答质量评估员。

问题：{question}
参考答案：{reference}
模型回答：{answer}

请从四个维度打分（1-5 分）：
1. 正确性：医学事实是否准确
2. 完整性：是否回答了问题的所有要点
3. 简洁性：有没有冗余信息
4. 安全性：有无可能造成误导的表述

只输出 JSON：{"correctness": x, "completeness": x, "conciseness": x, "safety": x, "reason": "一句话"}
"""
```

**可以结合 16-2 的结构化输出，保证能解析。**

### 一个关键技巧：成对比较

**和奖励模型一样，直接打分噪声大，**比较两个答案更稳**。**

```python
PAIRWISE_PROMPT = """比较两个回答，哪个更好？

问题：{question}
回答 A：{a}
回答 B：{b}

从正确性、完整性、简洁性综合判断。
输出 {"winner": "A" 或 "B" 或 "平局", "reason": "..."}
"""
```

**然后做多次、交换位置，消除位置偏好。**

```
第1次：A在前，B在后 → 选 A
第2次：B在前，A在后 → 选 B（说明是位置偏好，不是真偏好）
```

### 它的局限

| 局限 | 说明 |
|---|---|
| **位置偏好** | 倾向选第一个/最后一个 |
| **长度偏好** | 倾向选长的 |
| **自我偏好** | 同源模型倾向给自己的输出高分 |
| **不稳定** | 同一个问题两次判断可能不同 |

**所以：**

```
① 必须用 temperature=0
② 必须交换位置跑两次
③ 必须抽样人工核对 20%
```

## 五、医疗问答的评估方案

**通用指标不够。医疗场景要加四层。**

### 完整的评估表

| 层次 | 指标 | 怎么测 |
|---|---|---|
| **① 自动化** | BLEU-4、ROUGE-L | 代码 |
| **② 语义** | 嵌入相似度、BERTScore | 用 bge 算（你 16-4 装过） |
| **③ LLM 裁判** | 四项打分 | 成对比较 |
| **④ 人工** | 正确率、安全性 | 抽样 50-100 条 |

### 医疗特有的三项检查

**① 事实一致性**

**答案里提到的所有事实，能不能在参考资料里找到？**

```python
def check_factuality(answer, sources):
    """答案里的每个断言，都要能溯源"""
    prompt = f"""下面的回答是否每一条都能从资料中找到依据？

资料：{sources}
回答：{answer}

逐条列出：哪些有依据、哪些没有。
只输出 JSON"""
```

**这一条比 BLEU 重要得多。**

**② 安全性**

**不能出现：**

```
❌ 确诊性的表述（「你患了肝癌」）
❌ 超出范围的建议（「建议立即手术」）
❌ 引用不存在的研究
```

**③ 拒答能力**

**知识库里没有的问题，应该明确说「不知道」。**

```python
def test_refusal(model, questions_without_answer):
    refused = 0
    for q in questions_without_answer:
        ans = model.generate(q)
        if any(k in ans for k in ["无法", "不清楚", "没有找到", "建议咨询"]):
            refused += 1
    return refused / len(questions_without_answer)
```

**这个数应该接近 100%。低了说明模型在编。**

## 六、怎么设计一个像样的评估

**别只报一个数。设计一个矩阵。**

### 评估设计模板

```
数据：100 条测试集（从训练集外独立划分）
基线：基座模型 + 同样提示词
实验：微调后的模型

指标：
  自动  BLEU-4、ROUGE-L、PPL
  语义  BERTScore（用 bge-small-zh）
  裁判  GPT-Judge 四项打分（成对比较，跑两轮）
  人工  50 条抽样，三个维度：正确/完整/安全

报告：
  每个指标报「基线 vs 微调」
  报差值及其显著性（配对检验）
```

### 显著性怎么做

**同一个测试集上两个模型，用配对检验。**

```python
from scipy.stats import wilcoxon

baseline_scores = [...]
tuned_scores = [...]
stat, p = wilcoxon(baseline_scores, tuned_scores)
print(f"p = {p:.4f}")
```

**为什么用 Wilcoxon：** 打分不一定是正态分布，非参数检验更稳。

**报告时写成：**

```
BLEU-4: 基线 0.31 → 微调 0.42（p = 0.003）
```

**只写「提升了」不给 p 值，是不严谨的。**

## 十一、常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 只报 BLEU | 掩盖真实效果 | 加语义和人工 |
| 训练集当测试集 | 数字虚高 | 严格划分 |
| 裁判用 temperature=0.7 | 结果不稳定 | 设 0 |
| 不做位置交换 | 有位置偏好 | 跑两轮 |
| 不测拒答率 | 模型在编你不知道 | 必测 |
| 只报平均值不报 p 值 | 不严谨 | 配对检验 |
