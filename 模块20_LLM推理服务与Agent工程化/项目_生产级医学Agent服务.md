# 毕业项目 · 生产级医学 Agent 服务

**建议用时：20 小时（约 1-2 周）**

---

## 〇、项目定位

**一句话：把模块 16 那个「能跑」的医学影像 AI 助手，升级成一个「能扛并发、有评测、可监控」的服务。**

**区别在哪：**

| | 模块16 的版本 | 这个版本 |
|---|---|---|
| 面向的人 | 你自己 | 别人 |
| 跑在哪 | 你的 notebook | 一个服务端口 |
| 慢不慢 | 不知道 | **有 P50/P95 数字** |
| 准不准 | 感觉还行 | **有 20 条评测集和成功率** |
| 改坏了怎么办 | 不知道 | **回归测试会拦住** |

**这个项目做完，你就有了「工程能力」的证据，而不只是「会写算法」。**

---

## 一、为什么这个项目对实习有用

**JD1（数据工程）：「熟悉 API 调用、自动化流程」**
**JD4（分割）：「使用 Claude Code 等工具，完成代码编写、调试和文档整理」**

**面试官问「你做过什么项目」，你说「我训了个模型」，和说「我做了个服务，有评测、有监控、能扛 7 个并发」——分量完全不同。**

**而且这个项目零成本**：评测用本地 Ollama，服务跑在自己机器上。

## 二、四个阶段

### 阶段一：服务化（6 小时）

**把模块 16 的 Agent 包成 FastAPI 服务。**

- [ ] `/health` 健康检查
- [ ] `/chat` 对话接口（流式）
- [ ] `/stats` 调用统计
- [ ] 请求/响应模型用 pydantic 定义
- [ ] 错误处理（400 / 500 / 503）

**验收：**

```
curl -X POST localhost:8000/chat -d '{"question":"肝窗的窗宽窗位是多少"}'
```

**能返回，并且 `/docs` 能打开。**

---

### 阶段二：性能（4 小时）

**测出三个数字，并优化。**

- [ ] 测 TTFT、P50、P95
- [ ] 测并发 1/2/4 的吞吐
- [ ] 算出你这台机器的「甜点并发数」
- [ ] **至少做一项优化**（前缀缓存、上下文压缩、或换更小模型）

**验收：**

| 指标 | 优化前 | 优化后 |
|---|---|---|
| TTFT | | |
| P95 | | |
| 甜点并发 | | |

**没有「优化后」这一列，这个阶段就是没做。**

---

### 阶段三：评测（6 小时）

**建立 20 条评测集，跑出成功率。**

- [ ] 20 条测试用例（12 正常 + 4 拒答 + 4 边界）
- [ ] 用本地 Ollama 当裁判
- [ ] 算宽松/中等/严格三个成功率
- [ ] 人工核对 5 条，算裁判和人工的一致性
- [ ] **做成 pytest，能一键跑**

**验收：**

```
宽松成功率: XX%
中等成功率: XX%
严格成功率: XX%
裁判-人工一致性: XX%
```

**四个数都有了才算完成。**

  20 条评测集上严格成功率 XX%

  从 10K 降至 5K，P95 延迟下降 XX%
- 本地 Ollama 部署 qwen2.5:7b，实测 TTFT 0.03s、生成 74 tok/s，
  1/2/4 并发下吞吐分别为 XX/XX/XX tok/s

  并固化为 pytest 回归门禁

## 七、面试怎么讲

### 3 分钟版

```
问题：多数学术项目的模型只在 notebook 里能跑，没法交付。
方法：我把整个链路包成服务，重点做了三件事。
     第一，性能明确——测了 TTFT 和 P95，发现在 8 GB 显存上
     甜点并发是 4，再高单请求延迟翻倍。
     第二，上下文可控——发现一次调用 10K token，
     其中检索和历史各占 45%，做了摘要和工作记忆压缩，砍到 5K。
     第三，效果可验证——建了 20 条评测集，用本地模型当裁判，
     不花钱，跑一次两分钟。
发现：最有意思的是并发不一定提速。短请求并发反而慢 16%，
     因为瓶颈在调度不在 GPU。长请求才有效，提升 44%。
```

### 必被追问

| 问题 | 你要能答 |
|---|---|
| **你的成功率怎么定义的？** | 报三个版本，说清区别 |
| **裁判可信吗？** | 人工核对一致性 XX% |
| **没做过压力测试吗？** | 做了，并发 4 之后开始劣化 |
| **为什么不用 vLLM？** | 讲 Windows 装不了 + Ollama 的取舍 |
| **这个能上线吗？** | 老实说：单卡、无 K8s、无鉴权，是原型不是产品 |

## 九、常见失败模式

| 失败 | 表现 | 预防 |
|---|---|---|
| 只做接口不做评测 | 说不出效果 | 阶段三必做 |
| 性能只报平均 | 掩盖长尾 | 报 P95 |
| 优化了但没测前后 | 说不清收益 | 留对比数据 |
| 评测集只有正常问题 | 掩盖拒答失败 | 必须有边界和拒答 |
| 裁判不核对 | 不知道准不准 | 人工抽 20% |
| 吹成「可上线」 | 一追问就露馅 | 老实说「原型」 |
